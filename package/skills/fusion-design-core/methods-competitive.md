# 竞品与类比样本方法库

竞品分析独立于用户研究、流程设计和交互设计。它提供类别认知、可借鉴模式和待验证假设，不能证明目标用户需要什么，也不能因为别的产品采用某种方案就直接照搬。

三类样本分别回答不同问题，可单独调用：

- `CMP1 行业竞品`：同一行业或同一价值问题通常怎样被解决，类别门槛和差异机会是什么。
- `CMP2 同类操作竞品`：不同行业中，同一种用户操作怎样组织流程、反馈、异常和恢复；严格说属于跨行业类比样本。
- `CMP3 服务同类用户的竞品`：服务同一行为群体的产品培养了哪些术语、导航、信息和操作习惯。

## 共用证据纪律

每个样本必须记录：

```text
产品 / 服务：
样本类型：行业竞品 / 同类操作竞品 / 服务同类用户的竞品
选择理由：
平台 / 市场 / 版本 / 日期：
观察入口与任务：
证据：链接 / 截图 / 录屏 / 实际操作记录
观察到的事实：
对事实的解释：
待验证假设：
```

选样本前，按 [methods-resource-routing.md](methods-resource-routing.md) `RR` 把任务拆成场景，每个场景先搜内部资产，再按 adapter 检索真实产品（Mobbin 已授权则用 MCP，否则只打开搜索页）。记录仍用下面的模板。

规则：

1. 先写本次要支持的设计决定，再选样本；不能先堆竞品截图再寻找结论。按场景和交互问题检索，不按「整个竞品」照搬。
2. 官方宣传、可见界面、实际操作和外部评价分别记录，不能混成同一证据。
3. 比较相同任务、状态和用户条件；不同年份、市场、平台或版本不能直接当作一组等价结论。
4. 观察完整链路和关键状态，不用一张首页截图代表产品体验。
5. “竞品都这样做”只能形成候选模式，不能成为设计完成证据。
6. 不复制受保护的品牌资产、文案和独特视觉表达。

## CMP1 行业竞品

**触发问题**：同一行业或价值问题的基本门槛、类别惯例、替代方案和差异机会是什么？  
**最低输入**：行业/市场范围、目标用户问题或价值主张、本轮要支持的决定。  
**跳过**：行业结构与替代方案已有有效近期材料，或本轮是严格执行且不改变产品/设计方向。

**选样**

- 直接竞品：服务相同市场和相近用户问题。
- 间接竞品：用不同产品形态解决同一结果。
- 当前替代：用户不用产品时采用的人工、线下或拼接方案。

不要求固定数量；样本必须覆盖本轮真正存在的主要替代类型。新增样本不再改变结论时停止。

**步骤**

1. 比较目标用户、核心任务、价值主张和当前替代。
2. 比较核心对象、业务边界、主链路和收费/转化位置。
3. 比较行业特有的信任、风险、凭证、合规表达和失败恢复。
4. 区分：
   - 类别基础门槛：缺少就难以被理解或信任。
   - 常见但未证明有效的惯例。
   - 可感知差异。
   - 可能造成体验或信任损耗的做法。
5. 将发现写成机会或风险假设，不直接变成功能清单。

**产出**

```text
类别基础门槛：
主要替代与差异：
常见惯例及证据限制：
信任 / 风险 / 合规模式：
可验证的差异机会：
不应照搬：
影响 D1–D9：
```

**完成证据**：每条结论会改变问题定义、价值、范围、信任要求或方案取舍，并能回溯到具体样本。  
**不得替代**：竞品规模、融资、下载量或功能数量不能证明用户价值；行业竞品不能代替目标用户研究。

## CMP2 同类操作竞品

**触发问题**：某个具体操作怎样组织才容易理解、可控并能从失败中恢复？  
**最低输入**：操作目标、对象、前置条件、后果和待解决的流程/交互问题。  
**跳过**：现有项目已有适用且确认的交互模式，本轮只需复用；或该操作没有可比较的交互决策。

**选样**

跨行业寻找相同操作原理，而不是只找相同页面名称。例如：

- 搜索、筛选、比较和选择。
- 创建、编辑、保存和恢复。
- 转账、支付、提交、审批和撤销。
- 上传、导入、同步和结果未知。
- 监控、提醒、异常处理和人工接管。

**步骤**

1. 固定同一个操作目标和后果，再比较样本。
2. 逐步记录：
   - 入口和前置条件。
   - 用户每一步的意图。
   - 系统即时、成功、失败和结果未知反馈。
   - 默认值、确认、撤销、返回和中断恢复。
   - 权限、异常、极限内容和无障碍处理。
3. 提取模式成立的条件与失效条件，不能只记录“用了什么组件”。
4. 将候选模式分为：
   - `USE`：条件与本任务一致，可以采用。
   - `ADAPT`：原理可用，但需按风险、平台或用户能力调整。
   - `AVOID`：会导致误解、越权、不可恢复或额外负担。
   - `TEST`：有潜力但缺证据，需要原型验证。
5. 映射到 D4–D6、D8 和 D9。

**产出**

```text
同类操作：
样本与成立条件：
步骤 / 状态 / 反馈 / 恢复比较：
候选模式：USE / ADAPT / AVOID / TEST
适用于本任务的理由：
失效条件：
影响决定与验证要求：
```

**完成证据**：每个采纳或拒绝的模式都有适用条件、失效条件和验证方式；不是截图偏好投票。  
**不得替代**：类比操作不能覆盖本项目的业务规则、权限、数据能力和设计系统。

## CMP3 服务同类用户的竞品

**触发问题**：服务同一行为群体的产品，已经培养了哪些可迁移的语言、信息、导航、反馈和操作习惯？  
**最低输入**：行为群体、当前任务，以及该群体实际使用某类产品的证据或明确的选样依据。  
**跳过**：没有任何可支持的用户—产品关系，且当前任务可由项目内部模式解决。

**选样**

- 目标行为群体高频使用的产品或服务。
- 同一角色在工作/生活中依赖的工具。
- 同一能力条件下长期使用的数字或线下系统。

不能仅凭年龄、职业或地区推定用户一定使用某个产品。没有真实使用证据时，样本只能标为待验证候选。

**步骤**

1. 记录该群体使用样本完成什么任务、频率、熟练度和使用年限。
2. 观察：
   - 对象和术语。
   - 导航、返回和跨端衔接。
   - 信息密度、阅读顺序和内容语气。
   - 输入、选择、确认、反馈和凭证。
   - 无障碍与辅助方式。
   - 建立信任或控制感的线索。
3. 区分哪些是平台通用习惯、产品独特表达和任务特有规则。
4. 将习惯分为：
   - `PRESERVE`：保持熟悉模式，避免无意义学习成本。
   - `ADAPT`：保留心智模型，按当前领域、风险或平台调整。
   - `TEACH`：必须引入新模式，提供渐进学习和可恢复路径。
   - `AVOID`：熟悉但会在当前任务中造成误解、越权或高风险。
5. 映射到 D2、D4–D8，并写最小验证方式。

**产出**

```text
行为群体：
样本及用户—产品关系证据：
对应任务 / 频率 / 熟练度：
已学会的对象、术语和模式：
处理：PRESERVE / ADAPT / TEACH / AVOID
迁移理由与风险：
影响决定：
最小验证：
```

**完成证据**：每条习惯有目标群体使用证据，并能改变当前设计的学习成本、命名、流程、组件、反馈或视觉表达。  
**不得替代**：服务同类用户的竞品不能证明当前产品的价值主张，也不能把一个产品的品牌风格当成整个群体的审美偏好。

## 三类样本合并规则

若同时调用三类方法，结论必须保持来源：

- 行业竞品说明类别和价值竞争。
- 同类操作竞品说明交互模式及成立条件。
- 服务同类用户的竞品说明已培养的习惯。

同一模式在三类样本中重复出现，也不能直接称为“最佳实践”；只有与本项目事实、设计原则和验证结果一致时，才进入最终方案。
