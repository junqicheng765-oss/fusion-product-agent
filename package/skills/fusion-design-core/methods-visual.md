# UI 界面视觉方法库

本文件属于 Figma UI 设计，处理界面中的视觉系统与资产应用，不是 UI 后必须追加的独立阶段。视觉方法不改变已确认的路径、职责和主行动含义。实现设计参考时必须以正式主稿和真实资产为准，不得近似降级。

界面中的插画、图片、图标和品牌图形属于所属界面任务。独立非界面成品或明确拆出的独立资产按 [methods-tool-routing.md](methods-tool-routing.md) `TR4` 分流；DS1 主视觉、V3 静态表达文字及 V5 表达性小图可作为页面子资产处理，在 TR0 已确认且覆盖当前动作的路线内选择制作方式，不要求另开独立委托。Figma 路线将真实资产导入对应主稿；不得用占位或近似资产代替正式生产。

所有视觉方法同时遵守以下记录规则：

- 把正式来源、设计推导、待确认候选和人的决定分开记录；候选不能写成品牌事实或已确认规范。
- 每个实现值必须给出准确来源与版本、正式系统引用，或标为 `CANDIDATE_PENDING_CONFIRMATION`；不能凭常识补品牌值。
- 来源缺失且不同答案会改变成品时暂停受影响部分：可由本轮设计探索解决且已有授权时标 `MISSING/RESOLVE_NOW`；必须等待正式来源、资产或授权时标 `BLOCKED/WAIT_EXTERNAL`。只有明确委托或可追溯依据时才形成候选。
- 实现或还原设计参考时，布局、字体、间距、颜色、真实内容、真实资产和交互均须忠实应用，不用近似值、占位符或简化替代品冒充完成。只有用户方才有的正式素材、真实数据或权限缺失时才停止受影响部分；功能图标与表达资产按 V5 分别判断复用或制作，真实摄影按 [methods-image.md](methods-image.md) 检索，不用生成内容冒充指定真实资产。
- 所有产出都写适用页面、组件、平台、主题、表面、状态和版本，使新会话能够直接实现并逐项验收。

## 补充：先接住概念，再落实风格

按 [methods-creative-concept.md](methods-creative-concept.md) CC1–CC4 核对本轮设计性质与选定概念。下文存量延展/跳过重选风格须有本次适用的已批准基线，不能仅因提供了待优化 HTML 就跳过设计判断。活动页内的主视觉、参与区和功能组件可以采用各自适用的资产与实现方式，仍在同一页面职责、风格确认和工具合同内验收。风格预设、材质与图库用于实现概念，不能代替概念推导；原有资产、调库和确认规则保持。

## V0 0→1 视觉风格库与 6 维决策漏斗

主视觉承担主题表达且页面需由此延展时，按 [DS1](methods-style-engine.md)「主视觉引领分支」承接本节语境筛选及 V7 的表现语汇，先结合活动目标、参与机制与感知目标筛方向，再制作完整首屏/KV样张、自审并供人看图选择；未定方向时默认比较2–3个实质不同的匹配方向，已有方向或局部委托按 DS1 范围复用。DS2 从选定主视觉推导规格，不再重复选整页方向。风格池/参数提供可比较语汇或功能底座，不由预设、素材物件或技术标签提前锁定画风，也不能覆盖已确认主视觉；功能组件按任务和状态使用适当材质，不将主视觉纹理机械铺满所有控件。其他任务保留本节原分流。

**触发问题**：在页面职责、信息层级（U1–U3）与所用组件（U4）已确认、且经 `U0` 判定属于 **C 端或强品牌差异化产品从 0 到 1 新建** 时，如何系统地帮用户选定风格并敲定具体视觉构件？  
**最低输入**：已确认的页面结构与组件选型、市场生态（国际化 / 国内）、行业与任务严肃度、目标人群。  
**跳过**：
- 有现成相关页面或既有设计系统（走 `U0` 路线 1：存量延展模式，直接提取现有 5 个视觉常量复用）；
- 纯 B 端/企业中后台从 0 到 1（走 `U0` 路线 2：直接绑定 `Ant Design` / `Arco Design` / `TDesign` / `shadcn/ui` / `MUI` / `Fluent UI` 等公开组件库快搭）。

### Step 1：依据语境展开与筛选（硬约束、适配风险和表达机会分开）

下列信息帮助查找和比较，不凭品类、受众标签或风格名称自动删掉整类视觉语言。按 DS1 先展开不同感知侧重及画面组织，再核对具体约束；硬排除须有可指认的冲突依据。

1. **市场生态与品类池**：A（`INT`）、B（`CN`）、D（`GAME`）描述常见语境，C（`TEX`）提供表现手法，均可跨池检索、转化；表中适用场景及适配风险用于提醒核对，不是互斥路由或行业禁令。不能因地域或产品类别先锁一池，再把剩余语汇当成不适用。
2. **品牌、规则与风险底线**：核对有效品牌约束及具体判断任务，排除会掩盖必要信息、混淆状态、误导承诺或妨碍操作的表现。高后果交易与宣传展示的需求可不同，行业名不足以证明某种色彩、渐变或图像媒介必然不适用；视觉气质也不能反推存在未定义的竞技、随机或奖励机制。
3. **任务形态**：高频重操作、高密度数据比对需保障查找、比较与稳定辨识；浏览、内容消费、品牌或活动表达可探索不同氛围、空间和视觉重心。将这些需求落实到实际区域，不让功能区的限制提前覆盖整张主视觉。
4. **目标人群与阅读条件**：依据真实设备、能力和使用情境保证字号、对比、标签及操作可辨，不从年龄、地域或消费层级推定唯一审美。未知偏好按 CT7 处理，不能用人群刻板印象补成硬约束。
5. **按传达效果比较，不按标签定风格**：同一目标可有不同成立的感知侧重与视觉解法。分别说明各案如何表达信息和支持任务，再判断保留、转化或淘汰；情绪词、季节和主体物件不自动固定色温、场景或媒介，技术标签也不直接指定视觉语言。

### Step 2：在前置用研、竞品与交互方案汇报后，推导 2–3 个视觉风格方向征求用户选择（严禁未做前置推导就一上来锁死风格）

**风格决策铁律（先交互后视觉，0→1 必给选项征求用户意见）**：
1. **严禁一上来就宣布视觉风格**：在尚未完成并汇报本类型必要前置（界面含使用者/任务、流程复核、架构、内容层级与具体交互）前，不提前锁定风格或制作方向样张；前置完成后按 DS1 在独立草稿制作并自审候选，供人看图选择，未确认不正式应用。
2. **0→1 新产品（用户原话未指定具体视觉风格时）：提供 2–3 个差异化风格方向让用户选**：
   - 结合前面的用研与竞品调研，思考这个 UI 要传达什么意思、通过什么视觉手段表达，从下方风格池（`INT-01..08` / `CN-01..08` / `GAME-01..10`）中筛出 **2–3 个合理的差异化风格方向**，说明每个方向与本轮目标的对应及区别；
   - 两分支均按 [DS1](methods-style-engine.md) 从匹配理由和完整视觉提案形成实际样张；主视觉引领分支先完成同样的方向筛选，制作包含必要背景、空间与图文控件的首屏/KV供人看图选择，不叠加整页方向候选。均保留明确选择来源；
   - 一旦用户选定大方向，底下的 **6 个具体视觉技术参数（主色 Hex、底色冷暖、容器材质、圆角数值、字阶密度、图标网格）全部由 Agent 按专业最优解自动配齐**，不再逐项追问技术参数。
3. **汇报与提问禁令**：向用户描述风格时，**一律只用纯粹的视觉语言、色彩、材质与排版特征命名和描述，严禁出现“像某某品牌 / 某某大厂 / 某某游戏一样”的点名表述**；同时严禁把本 Skill 的内部术语（风格编号、六维/6 维、参数组合、决策漏斗、token、`V0`、`D1–D9` 等）写进给用户看的问题、选项或汇报里。此禁令只管给用户看的文字；发给生图模型、Figma 的提示词片段和字体、色值等技术参数**应保留**厂商与产品参照（如 `Apple HIG`、`Clash Royale`、`Supercell-Magic`），以保证生成效果准确，不要删改。

#### C. 通用视觉质感手法标签（6 种，可单选或与 A/B/D 组合）

1. `TEX-01 极简扁平（Clean Flat）`：纯色块 + 留白 + 细线，无复杂光影，开发还原最稳。
2. `TEX-02 毛玻璃通透（Glassmorphism / 液态玻璃）`：半透明背景模糊 + 1px 高光细边，适合悬浮导航、卡片叠层、深浅过渡。
3. `TEX-03 Bento 便当盒分块（Bento Grid）`：规整圆角矩形模块化拼图，适合首页总览、功能聚合、数据看板。
4. `TEX-04 轻质感微立体（Soft UI）`：极柔和多层投影与微渐变表面，按钮和卡片有细腻触感（禁用老式厚重拟物）。
5. `TEX-05 弥散光氛围（Aurora / Mesh Gradient）`：底层柔和多色高斯模糊光晕，上层承载干净界面，适合首屏 Hero、AI 状态、情绪类应用。
6. `TEX-06 杂志感大字报（Editorial Typography）`：弱化框线，靠超大标题字重反差与严密网格撑起气场。

### Step 3：由 Agent 自动推导并配齐 6 个具体视觉维度（专业细节默认代填，不拿技术选项烦用户）

本轮视觉方向或候选依据明确后，先按 [CI](methods-color.md) 形成整页色彩关系，再推导文字、图像、图标及控件的实际表现；不等素材全部完成才选色。候选配色保留来源和待确认状态，已有有效品牌与系统先复用，确认后纳入 DS2。以下 6 维共同承接该框架，不逐项新增技术参数问答：

1. **主色与色彩表现**：
   - 引用 CI 的有效品牌、预设或本轮候选色彩框架，明确主色、辅助色、中性色及语义状态色各自的作用、面积与前景/背景关系，不凭素材下载原色或固定色相区域代替整体选择。
   - **主色表现形式**：根据语义角色、品牌或本轮视觉方向，判断纯色、渐变及材质层次的适用性；不因未指定渐变就默认所有表面纯色，也不以复杂度作为完成标准。高后果任务的关键内容与状态须保持稳定可辨，不采用妨碍判断的表现。
   - **辅助色策略**：`单色系克制` / `双色冷暖平衡` / `多色分类标签`，依据内容作用、品牌与可读性决定各色职责。
2. **背景底色与中性色冷暖**：
   - **明暗模式**：`亮色清爽底` / `暖纸人文底` / `深色沉浸底` / `上深下浅混合底（按信息权重及阅读对比安排明暗分区）`。
   - **中性色与冷暖倾向**：依据品牌、主题、实际表面及阅读需要选择中性或带色中性色，并核对与主辅色的关系及对比度；不强制所有灰色混入固定比例色相，也不因采用纯黑白或中性灰就判定缺少设计。
3. **容器分隔与表面材质**：
   - `无框留白 + 1px 细分割线` / `浅灰底配纯白无阴影卡片` / `微阴影悬浮卡片` / `毛玻璃半透明叠层`。
4. **圆角与几何性格**（全套圆润与尖锐必须统一，不得混用）：
   - `0–4px 利落直角/微圆角` / `6–10px 理性标准圆角` / `12–16px 现代亲和圆角 + 胶囊按钮` / `20px+ 超圆角软萌`。
5. **字体气质与排版密度**：
   - **字体组合**：按文字作用、更新与表达需要选用可用字体，承担表达的主标题、副标题与眉题另按 V3/TY 判断排版或独立字形资产；联动字形、粗细、颜色、字距、行高及排列，不将字体类别或字阶当作完整表达决定。
   - **信息密度**：`紧凑高效型` / `均衡标准型` / `舒展留白型`。
6. **图标风格与配图边界**：
   - **选择与分组**：统一按 V5 从内容作用、信息层级、图文主次和实际尺寸推导图标形态，再检索来源。线/面/双色、2D/3D、线宽、材质等是可组合的表现维度，不凭风格名称或关键词直接决定。
   - **组内与组间**：同页可按不同作用配置多组图标；同用途、同表现语言的一组优先来自同一真实套系，组内核对线宽、边角、光学尺度及状态，组间通过整体色彩、视觉权重、空间和适用材质建立协调，不把全页图标强制成同一种形式。动效是否需要及其正式格式另按对应路线判断。
   - **现实对象的表现形式**：界面里用户认得的对象（卡牌、票据、商品、地图、文件、角色等）按 [methods-ui.md](methods-ui.md) `U7` 先定识别特征和各尺寸档的形式，再在这里配素材和风格。
   - **配图与空状态图形**（按行业严肃度过滤）：高严肃行业只推 `纯文字与数据图形 / 克制几何抽象图形 / 真实专业摄影`（屏蔽卡通手绘）；消费/社区可选 `高清真实场景摄影 / 扁平现代矢量插画 / 3D 质感元素 / 温暖手绘风`。其中**真实专业摄影 / 高清真实场景摄影**必须先走 [methods-image.md](methods-image.md)，不得先 AI 生一张「像照片的图」。

**贯穿 6 维的要求：视觉语言落实到关键文字、标签、按钮、面板与图标。** 从同一方向推导各角色适用的几何、色彩与材质规则，并检查实际画面中最弱的元素，不能只有背景和主视觉体现设计。参数未覆盖的组件依据本轮视觉规格补足，保留实际采用或有依据不采用某种工艺的判断。

共同视觉语言不等于所有组件使用同一表面，也不要求所有候选只换主色。按动作层级、品牌或候选主视觉推导按钮的轮廓、边缘、填色/渐变、厚度、光影、字形、图标与状态反馈；预设和配方是适用起点，不能仅改圆角或颜色便跳过这些判断。实际选择可保持克制，仍需在合成画面中证明与整体相符、可辨且可操作。

### Step 4：单页先行与模块化提炼

先按 DS1 的适用路径确认视觉方向（普通方向样张或主视觉引领分支）。方向选定后完成 **1 个完整核心代表页**及适用状态，QA0 自审通过后请用户确认；明确批准该版本作为基线后，才提炼共享组件并扩展其余页面，全部完成后再整套终审与最终确认。

### Step 5：Agent 怎样调用选定的视觉风格（直接选定 → 写入任务包 → 自动拼进 Figma/生图指令）

用户进入 C 端 0→1 视觉决策后，**Agent 严禁只拿一个风格名字去凭感觉画图或写代码**，必须严格执行以下 3 步闭环：

主视觉引领分支按 DS1 的确认顺序执行，并在下列参数/指令位置填入 DS2 的任务规格和确认主视觉版本；所采用的预设 ID 仅指真实功能底座。未采用预设不虚构编号、不为执行命令套回近似风格；不改共享库。此适用关系同样覆盖下方参数字典及“材质覆盖”的要求。

1. **Step 5.1｜先向用户汇报前置推导（用研+竞品+交互方案）并提供 2–3 个风格方向让用户选，选定后再加载参数包**：
   - **普通 0→1 新产品分支（用户原话未指定风格时）**：完成本类型必要前置后，按 DS1 制作独立方向样张并自审，再用提问工具给出 2–3 个可查看的方向；主视觉引领分支按 DS1 直接制作主视觉、自审后供人看图选择。均用大白话说明感受、差异和推荐，不出现内部方法编号，不把无人回复记作批准。
   - **主色 Hex、底色、卡片阴影、圆角数值、字体、图标网格这些具体技术细项一律不问**，在用户选定风格大方向后由 Agent 自动配齐；用户主动提出要改某一项时再改。
2. **Step 5.2｜查表加载参数包并写入任务包（唯一视觉数据源）**：
   - 预设路线从下方「可执行参数字典」读取所选编号的精确数值配方，并用已确认的适用调整覆盖；主视觉引领分支从 DS2 的任务规格取实际色彩、字形、排版、组件与图形应用规则，不强制字典中的近似风格。
   - 同一份数值已打包成可直接应用的预设文件 `style-presets/dto/<编号>-*.json`。运行 `python3 scripts/style_preset.py show <编号>` 读取，并一起取出它所属风格族在 `style-presets/registry.json` 里绑定的资源：
     - 最接近的 Tweakcn 主题；
     - 对应的系统预设（Apple / Material 3 / Ant Design）；
     - 通用组件配方标签（`recipes`，所有技术栈先用）、React 区块库与动效库。
     选完风格不只用参数表：组件先从 [component-recipes/](component-recipes/registry.json) 取；React 项目缺的再从区块库补；本地缺的再按 [methods-style-engine.md](methods-style-engine.md) `DS6` 去线上补。
   - 立即写入当前任务的 `V0 视觉方向与 6 维决策卡`（或 `DESIGN-<模块>-任务包.md`），锁死为本轮唯一视觉数据源。
3. **Step 5.3｜自动拼进 Figma / 组件库 / 生图执行指令**：
   - **按已确认路线组装制作指令**：本模板仅组织风格与内容参数，不决定用 Figma Agent、原生编辑或代码。先按 TR0 推荐并确认；选择 Figma 时由同包工作流按旧页/新增页及实际能力编辑，选择代码时在目标项目落实参数和素材。下列提示词为可复用输入，不等于工具能力已存在：
     ```text
     [Figma 视觉执行指令组装模板]
     - 绑定风格：{style_id} {style_name}
     - 画布与表面色：Page Canvas = {bg_hex}；Card Surface = {card_hex}；Text Hierarchy = {text_primary} / {text_secondary} / {text_muted}
     - 品牌主色与表现：Primary = {primary_hex}（表现方式：{solid_or_gradient}）；Accent = {accent_hex}
     - 容器与材质：Border = {border_spec}；Shadow = {shadow_spec}；Blur = {blur_spec}
     - 圆角阶梯：Card Radius = {card_radius}；Button/Input Radius = {control_radius}
     - 字体与字阶：Font Family = {font_family}（数字规则：{numeric_font_rule}）；Scale = {type_scale_and_spacing}
     - 图标与配图规范：Icon = {icon_spec}；Imagery = {imagery_rule}
     - 风格 Prompt 注入：{style_prompt_snippet}
     ```
   - **调用公开组件库（纯 B 端 `U0` 路线 2）**：直接连接对应组件库（如 `user-shadcn-ui` MCP 或 Ant Design / Arco / TDesign 规范 token），将 `colorPrimary`、`borderRadius`、`fontSize` 与 `compact/default` 密度一键写入主题配置。
   - **写成 HTML / 代码（含 C 端）**：不在页面里逐个写色值。预设路线用 `python3 scripts/style_preset.py apply <编号> --css <全局 CSS>` 或导出对应格式；主视觉引领分支按 DS2 将任务 token 写入一个实际主题位置。页面和组件引用同一来源，多页面验收按 DS5 区分脚本覆盖与任务规格的逐项核对，不强制无对应的预设编号。
   - **仅当 `V7` 已经判定必须生图时**：才把该风格的 `{style_prompt_snippet}`、主色 `{primary_hex}` 与底色冷暖追加进生图模型的 `prompt`。真实摄影仍先走 [methods-image.md](methods-image.md)，不因本条直接生图。

## V1 视觉依据

**触发问题**：本次视觉决定依据什么？  
**最低输入**：设计系统、正式主稿、品牌材料、用户委托或允许探索的范围。  
**跳过**：任务不包含视觉。

**步骤**

1. 为每项来源记录来源 ID、类型、所有者、准确文件或节点、版本或日期、适用范围及状态；优先引用正式设计系统或主稿。
2. 写清哪些值已锁定、哪些允许探索、哪些不得改变，以及谁有权确认。
3. 无基线时记录用户委托及可追溯依据。0→1 没有品牌规范时，`V0` 风格库参数或组件库默认值就是可追溯依据，Agent 直接采用并标注“可替换为品牌值”，不请求输入、不阻断；只有用户声明已有正式品牌规范但未提供文件时，才按“缺了就无法开工”处理。
4. 区分参考文件和可编辑目标，记录目标版本、允许修改范围和验收对象。
5. 只有用户方才有的真实资产缺失时，停止受影响部分并向用户要；图标/图形按 `V5` 判断必要性、形态、分组及适用来源，真实摄影按 [methods-image.md](methods-image.md) 检索。可制作的表达资产沿 `V5/V7` 和有效工具路线取得，不用占位、近似或简化替代后称完成。

**产出**：视觉依据卡。  
**完成证据**：每项实现值都能回到正式来源、系统引用或待确认候选；允许范围、确认人和阻断项明确。  
**不得替代**：用“类似品牌风格”伪造规范。

## V3 文字表达、字形资产与密度

**触发问题**：每项文字承担什么作用、是否变化，应怎样通过排版或独立字形资产与本轮视觉语言共同表达？
**最低输入**：U1/U3 的信息作用、主次、关联及准确内容，更新与语言要求，以及 CT7/DS1 的有效视觉依据。
**跳过**：本轮文字表达和密度均由有效正式系统锁定且不得修改；仍核对适用性与真实渲染。不因正文有指定字体就默认其他文字也已设计完成。

### 先辨作用与变化，再选制作方式

- **文字作用与动态性分别判断**：接续同一内容记录识别主标题、副标题、眉题、说明、标签、数据与操作等角色，确定阅读顺序、与谁共同理解，以及内容是否固定、更新频率、目标语言和可编辑要求。不能因已有文案无需改写，就省略视觉设计。
- **静态表达文字**：承担主题或氛围的主标题、副标题与眉题均可使用合适字体排版、矢量字形或独立生成的字形资产。按表现需要、可读性、更新成本与工具能力选择；固定文案不等于必须生图，副标题也不自动只能用普通正文。明确需要特定造型而普通字体不能达到时，应制作对应资产，不停在已换字族或放大字号。
- **已明确指定的方式优先落实**：用户明确要求独立字形资产或其制作、分层方式时，在有效路线内实际制作对应资产并进入组合画面；上述可选判断只适用于未指定部分。不能以活字更易维护、普通字体也可读或仅是方向样张为由静默改回通用排版。能力或效果失败时保留未满足状态，修正资产或按 CT0 说明需改变的方式；不得把替代方式直接记作已满足。仅指定字体时沿用实际字体，不据此追加图像资产。
- **正文、控件与动态信息**：保持真实文本、语义、可维护性和可访问性，优先沿用品牌或实际可用字体，按钮始终是真实控件；装饰性图层不能替代其操作与状态。字体包是可选输入，按 [TY](methods-resource-routing.md) 核对语言、文件、字重及使用条件；动态特殊字形组合另按 V7。
- **眉题与标签的表达**：依据其识别、归属或阅读引导作用，判断字距、排列、底板、边缘及辅助图形是否有助于表达。装饰与主视觉的几何、材质和疏密一致，静态说明不能被装成假控件；没有作用的装饰不添加。
- **图上文字承托**：在准确合成、目标尺寸和适用状态同时检查可读性与自然接合：阴影、渐变或底板是否与背景的明暗、空间组织及字形边缘相合或形成有意分界，是否产生无意的硬黑块、脏斑或光晕。对比度达标不能抵消接合失败；必要时改落位、重排文字或修正背景，再校正承托的强度、范围与边缘。有依据的阴影、渐变或硬边表达可以保留，仍须通过实际接合检查。
- 制作字形资产继承 [TR0](methods-tool-routing.md) 的有效路线，实质变化再确认。准确原文、角色、目标尺寸和视觉依据先成立；不随机生字后命名风格，也不另开独立海报、字体项目或固定审批。

**步骤**

1. 沿用有效字族、fallback、字体文件及版本，记录授权或系统可用性。没有正式系统时，依据本轮任务和视觉方向提出候选，不能把默认选择写成品牌字体。
2. 制作前联动判断字形/字宽、字号与比例、真实字重、颜色或表面处理、字距、行高、行宽、断行、排列、材质及与图像的关系。说明实际采用哪些变量、支持什么作用；不要求每项变化，但不能仅套系统粗字、衬线体或预设字阶就认定表达完成。文字需要保持原文时，只改表现不擅自改写。
3. 每个排版角色沿用以下记录，使用字形资产时补充对应资产项，不另建平行报告：

```text

适用范围：页面 / 组件 / 平台 / 语言 / 宽度 / 状态 / 版本
```

4. 排版与密度共同落实组内、组间和组件空间。常规排版优先有效系统、V0/组件主题或 TY；表达文字可按本轮方向推导比例、间距与排列，保留依据和实际渲染，不被有限预设锁成一种通用表达。目标语言有真实字形覆盖，不能仅靠拉丁字体加泛用 fallback 宣称完成中文风格。
5. 在准确合成画面检查文字自身是否达到表达目标，以及主图、主副文字、标签和操作的权重是否协调。字形、断行及其与图像的关系要实际支持本案主张和感受；独立生成、换了字族或附加材质都不是表达完成的证明。字形资产需要时必须实际制作并合成后再判定，不能用计划代替；普通排版足够时也以真实画面说明，不以未报错当作审美证据。文字内容的质量与批准按 U1/U6 另核对，字形好看不能抵消内容含混；也不为体现两案不同强制改写同一文案。
6. 常规与动态内容在本轮真实变化范围、最窄受支持宽度及适用状态检查换行、溢出、截断、辨识、触控区与邻接关系，记录准确版本、尺寸和修复结果；缺少真实最长内容标缺口，不用短假文案代替。
7. 对目标语言核对实际文件、字形覆盖、真实字重、标点、混排、文本扩张及适用方向；字形图片逐字复核。不把静态单字重声明成完整可变字重，不把缺字回退隐瞒为同一字体，未覆盖语言如实标记。

### 静态字形资产合同与复核

需要时接续同一排版/资产记录，补充准确原文、换行与标点、视觉依据、目标及最小尺寸、参考主视觉版本、制作来源、真实文件/格式/可编辑性、透明通道、安全区、图层落位、等价文字与替换方式。主标题、副标题和眉题分别按独立修改或控制需要组织，不把整段文案烘焙成不可维护的整页底图。

生成字形时引用本轮主视觉或适用视觉依据，明确字形、材质、光影、排列、原文与透明输出要求，优先取得真实透明资产；只有工具确需有底生成时再执行背景移除，并检查透明通道、边缘残留与文字细节，不能把白底或棋盘格当透明。按 V7 独立合成，逐字检查错漏、笔画粘连、顺序、标点与断行，在实际最小尺寸核对清晰度、裁切、对比及主次；失败时修改或改用其他制作方式。

字形工艺另按 V7「生成资产的工艺目标与精修」检查笔画结构、字面比例、内部负形、轮廓、字间与行间节奏、立体边缘和材质尺度。文字准确、透明输出或字形与主图同类均只是部分条件；不规则、手工感和夸张须有明确组织，不能以随机斜切、抖动或堆叠效果代替造型设计。

网页保留等价语义文字，避免重复朗读；需检索、选择、频繁更新或跨语言维护的内容优先真实文本。特定文案的字形图片不冒充可输入任意文字的字体或矢量源，实际编辑限制如实记录。常规控件、动态数据及正文不因表达文字采用图像而全部栅格化。

**产出**：接续内容作用的文字实现与排版/密度记录；适用的真实字形资产、校对及合成证据；真实内容、语言与窄宽检查记录。
**完成证据**：各文字角色、变化与表达需要有实现判断，关键变量有依据，所需资产已制作并进入准确画面；主副文字、眉题和主视觉共同表达方向，最小尺寸可读且主次成立。普通字体或单纯加大字号不自动构成通过。
**不得替代**：信息层级、真实内容与业务规则。

## V5 图标与图片

**触发问题**：哪些图像承担识别、行为提示或内容表达，需要怎样与本轮视觉语言配合？

**跳过**：无图任务。

### 图标选择与分组：唯一决策入口

适用于内部资产、IconScout、其他成熟图标库及主视觉派生小图。接续 I3、U1/U3、DS1/DS2 的视觉依据及 CI 整体色彩框架的同一内容/组件记录，候选保留状态；不为调库另开专业阶段、审批或平行报告。已有有效系统、套系和局部范围先复核复用。

1. **从内容决定是否使用及其作用。** 对本轮相关区段写清需要帮助的识别、定位、操作指引、内容理解或表达任务；文字已足够、图形无实际增益时不添加。分开记录内容重要性、操作状态与期望视觉重量，再决定图标和文字谁主谁次、阅读顺序、相对比例、落位及实际最小尺寸；选中不等于业务层级更高，图形更重也不自动使内容更重要。不把固定图文比例或作用到形态的单一对应当作模板。
   - 检查本轮关键内容区的表达任务，而非只列操作控件所需图标。内容关系、主题识别、参与感和气氛也可以构成图形增益；“文字能读懂”不等于这些目标已达到。明确要求的内容图形必须落到对应区段，箭头、关闭或状态图标的采用不能替它们交差。
   - 关系性内容先辨顺序、依赖、分支、累积或动作与结果，再决定图形主次、形态变化、连接和阅读节奏，由本轮视觉母题组织成组。编号只承担索引；仅把编号和说明排成等宽栏，不自动完成步骤表达。沿同一内容记录说明采用或省略图形的实际依据，不强制固定栏数、每项加图标或用无关装饰填空。
2. **先定义组，再选形式。** 按共同用途、同一交互层级、需要彼此比较的内容和状态关系形成图标组；一组需覆盖的语义与状态先列齐。线性/面性是与尺寸、颜色对比、密度、线宽和光学尺度共同作用的重量变量，不能一概认定面性层级更高。结合整体语言和目标辨识选择平面/立体、线/面/双色、几何比例、细节、材质及适用光影/透视；组内既定状态变体须写清触发和表现对应，不逐项随意换形。不同组允许不同形式，但须有职责依据，不因每段各自检索而随机混搭。
   - 体系依据：[Fluent 2 图标](https://fluent2.microsoft.design/iconography) 将填充用于选中强调或需要更多重量与辨识的情况；[Material Symbols](https://developers.google.com/fonts/docs/material_symbols) 将填充、字重、grade 和光学尺寸作为可分别调节的维度。借鉴其状态与重量判断，不把某一系统的具体样式推广为所有产品的层级规则。
3. **把语义检索与风格筛选分开。** 检索词描述要表达的对象、动作或概念；资产类型、表现风格及已定组规范用于筛选和看图。优先核对既有可用资产，再按当前 MCP/API/脚本实际支持的参数检索，不把返回排序当设计推荐，也不把同一关键词、同一作者或同一风格标签当作同套系证明。Lottie 是动态格式，仍需判断其造型语言及组别；静态/动态、2D/3D与线/面不是一组互斥选项。
4. **比较成组覆盖，再确定集合。** 从候选真实集合检查本组所需语义、状态、格式、尺寸、可修改性和许可覆盖，优先选能形成一致组的套系，不逐个主题挑单张拼组。记录实际可回查的 Pack/集合 ID、链接、作者及版本；当前渠道不返回这些字段时明确未知并以可取得来源核实，不凭文件名补造 ID，不虚构按集合下载的接口。调用与下载仍受实际能力、权限、费用及 TR0 范围约束，不为比较囤积无关素材。
5. **以真实尺寸审组内一致与组间关系。** 实际取得必要候选，在相同目标尺寸和对应文案/控件中并排看图；核对语义辨识、视觉重量、线宽、边角、细节、透视/光影、透明边缘及颜色，不以外框尺寸或同色替代光学校准。检查多组的权重、对齐、间距与整体色彩是否协调，图文含义及主次是否成立；低辨识的精细大图不能直接缩成小图充数。
6. **缺项按组处理。** 先核对同集合是否有可用变体或替代语义；确需补项时，比较有依据的跨集合补充、按组规范定制/生成或更完整的适用集合。功能图标优先可靠成品；需要定制时，先核对正式系统允许的扩展、语义惯例、目标格式和可用制作能力，必须由现有 TR0/权限覆盖，不能把缺项当作自动生成授权。不能静默混入另一种画法，也不强迫替换已批准的整组；记录缺口、取舍、来源及实际复核。影响已确认方向或工具能力时只重开受影响决定，能力或必要来源不足则暂停该缺项，其他有效结果继续复用。

同组“优先同集合”不代替适用性与质量判断：集合一致但语义、尺寸或状态不适用时仍不能采用。生成资产记录共同主视觉/母体版本及组规范，不伪称第三方 Pack；具体资产引用组 ID，公共规范只记一次。

**按承担的任务验收，不能只按来源验收。** 功能符号核对操作与状态辨识，可以沿用成熟通用图标；表现图形须在实际区域中支持本案主题、参与感受或内容关系。营销/活动表达先承接 CC3 的核心想法，再决定图形意象、形态、尺度和图文组织，不能从题目关键词各取一张图便称创意成立。仅与名词对应、同色同套或多加一组小插画，只能证明部分语义和资产条件，不能替代主题表达；需要继承本案独有语言时按原路线改造、定制或生成，再看实际效果。用“换到另一无关活动是否仍同样成立”辅助检查关键表现区域，区分必要的通用功能与缺乏针对性的表达，不强求所有图标独特、夸张、立体或生成，也不把增加数量当作活泼。

### 图标颜色与 SVG 适配

1. **从整体色彩到组和状态。** 下载原色是资产初始表现；可改色的普通图标按 CI/V2 的主辅色、中性色和语义角色，确定各组及状态的实际颜色与对比关系，不逐项凭喜好取色。颜色用于强调、状态、分层或识别时，仍保留必要的文字、形状或其他线索。正式系统、品牌识别及来源明确锁定的颜色优先，不因 SVG 可编辑就擅自改色。
2. **先核实真实结构与可编辑范围。** 检查实际文件是否为可用矢量、路径及分层的 `fill`、`stroke`、样式、透明度、渐变色标、遮罩和裁切；保留 `none`、留空结构及识别特征。按实际载入方式和工具能力映射语义变量、`currentColor` 或明确的路径/色标，不以宿主 CSS 已写 `color` 就宣称外部 `img` 内的 SVG 已完成改色，也不凭扩展名认定取得可编辑源。
3. **选择适用着色组织。** 按表达与资产结构决定单色、同色分层、有限调色板或保留固有多色；层级和调色板只处理实际可分层部分，不能全局替换多色路径破坏含义或材质。渐变采用 CI 的对应关系和真实支持的色标/方向，不能为追求丰富度使小尺寸图标失去辨识。该分类借鉴 [SF Symbols 渲染模式](https://developer.apple.com/sf-symbols/)，不承诺任意 SVG 支持对应平台接口，也不代表取得 Apple 资产的跨平台使用权。
4. **颜色适配不冒充形态改造。** 优先选择组内已有的合格线/面变体；不能仅改 `fill` 就称线性图标已变成合格面性图标。以真实几何与最小尺寸看图验证，[Lucide 的填充说明](https://lucide.dev/guide/react/advanced/filled-icons) 也明确填充并非对全部图标正式支持。技术取色依据见 [SVG 2 Painting](https://www.w3.org/TR/SVG2/painting.html) 与 [Lucide Color](https://lucide.dev/guide/react/basics/color)，代码能力不能代替设计判断。
5. **保存适配依据并实际验收。** 保留原资产、许可/品牌约束、组规范、原色到语义色映射及适配后准确版本，真实制作的修改不伪称原集合的官方变体。在目标背景、亮暗主题、实际最小尺寸及适用默认/选中/交互/禁用状态中检查辨识、对比与组内/组间关系；复合背景按 CI5 补充实际检查，不以一颗颜色或一个状态通过代表全部完成。

**步骤**

1. 按上方决策入口完成本轮图标的必要性、图文主次、形式与分组判断，再获取资产。标志、照片和插画同样先核对作用及真实内容要求；图标不承担唯一信息，不因文字前有空位就机械配图。功能图标优先复用可用内部或成熟图标库，表达性小图按下方规则决定复用或定制，不把两者机械绑定为某种形态。
   - 表达性小图先明确它怎样辅助识别、分组、阅读节奏或行动，再判断适用资源是否满足。需要继承本轮主视觉独有的造型、材质或绘制语言时，可引用准确主视觉版本定制生成独立资产，锁定几何比例、材质、光影、透视、色彩与边缘处理；不为形式下载未采用的素材，也不把所有文字都加图标当作丰富度。

   - **Step 1｜在第一轮提问时先确认用户想要的头像画风（不要擅自生成写实真人头像）**：
     - 凡界面包含玩家或用户头像，在第一轮征求视觉风格时，顺带问清用户偏好哪种头像表现形式：**① 3D 潮玩 / Q 版卡通头像**、**② 国风 / 精致半身插画头像**、还是 **③ 写实人物肖像**。
   - **Step 2｜素材库检索后的「两问判断门（Library Fit Gate）」**：
     - 从 IconScout（MCP 或 API）检索候选素材并调用 `Read` 读图检查，同时回答两问：
       1. **符合用户选定的画风与产品文化语境吗？** 不符合则判定不匹配；
       2. **同屏多个头像能凑齐同一套系（100% 同一画风、同一头肩比、同一打光与底色）吗？** 画风割裂或套系不完整则判定不匹配。
   - **Step 3｜判断通过 vs 不通过的自动分流**：
     - **✅ 两问皆通过**：直接采用素材库中该同一套系（Same Pack）的资产；
     - **❌ 任一问不通过（库里没有符合该画风或凑不齐同风格成套头像）**：**立即放弃素材库结果，严禁将就硬塞，严禁用“名字首字圆圈”充数，自动按用户选定的头像画风切换走「AI 同母体成套生图（Batch Style-Locked Generation）」**！
   - **Step 4｜AI 同母体成套生图的锁死规则**：
     - 固定一套完全相同的 **【母体风格前缀词（Master Style Prefix）】**：严格按用户选定的画风（Q版3D潮玩卡通 / 新中式国风插画 / 写实人物）锁死画风、人物文化特征、构图（居中胸像占 75%）、光影与背景底色（与界面色彩一致，禁死板纯黑底）；
     - 仅替换每个角色的人设变量，成套调用生图模型（宿主 `GenerateImage` / `imagegen`）生成，保证一个界面上的所有头像 100% 像同一个美术主笔画出的一整套！
8. 界面资产沿所属页面已确认的路线完成：图标/图形先按上方决策确定组别、形态与可用来源；真实摄影仍按 [methods-image.md](methods-image.md) `IM` 检索并取得实际文件，再导入主稿或代码。需要制作的表达资产按 V5/V7 执行。工具能力变化按 TR0 处理，只有用户独有或指定正式资产缺失时向用户补准确输入，不擅自找相似物替换或扩范围。DS1 主视觉、V3 字形及本节表达性小图可作为页面子资产，沿同一 manifest 交接与验收，不要求另立独立项目。

**产出**：接续内容/组件记录的图标必要性、图文主次、组别与表现规范；资产 manifest、集合覆盖与缺项取舍、实际复核及恢复清单。独立委托按其合同附对应工具动作与准确成果。
**完成证据**：每项已用资产的作用、组别、真实来源/许可、准确文件、尺寸与状态可回查；内容重要性、操作状态和视觉重量未混为固定形态规则。颜色适配有 CI/V2 依据、真实结构及原/适配版本，目标背景和状态已实际检查；同组集合优先及缺项处理有依据，组内同尺寸和组间协调已实际看图核对。未知集合元信息不冒称已验证，同风格标签不冒充同集合；缺失项明确影响范围，没有假内容或占位符冒充成品。
**不得替代**：版权和品牌授权。

## V6 同结构单变量比较

**触发问题**：需要比较同一结构下某个局部视觉参数，并判断该变量差异。整体视觉方向样张走 DS1，可比较成套表达，不强制拆成单变量。
**最低输入**：已成立的同一内容、结构、状态和代表页面，以及待比较的单一参数与判断标准。
**跳过**：整体方向探索走 DS1；不需要局部参数比较、已有有效参数依据，或严格还原不改变参数时不做本方法。

**步骤**

1. 每轮先冻结内容、信息层级、结构、行为、资产、数据、平台、视口、页面状态及不在本轮比较的 token，并记录准确版本。
2. 每条比较记录只能有一个唯一变化变量；为该变量提供 2–3 个有依据且标为待确认的候选值。若需比较另一个变量，另开一轮并重新冻结基线。
3. 使用关键任务的代表页面及实际相关状态，至少覆盖正常状态和会暴露差异的 hover、pressed、focus、disabled、空、错误或长内容状态；不用闪屏或纯情绪板代替。
4. 在同一设备、视口、内容、状态和资产条件下，比较主行动可见性、关键判断、状态辨识、对比、内容承载和品牌边界，并保留结果证据。
5. 每轮填写：

```text
比较 ID 及待回答问题：
固定变量及准确版本：
唯一变化变量：
候选 ID、值、依据和状态：
代表页面、视口及状态：
比较标准：
逐候选比较结果及证据：
结论：推荐 / 不推荐 / 无结论
确认人及其权限：
当前状态：DRAFT / READY_FOR_REVIEW / PENDING_CONFIRMATION / CONFIRMED / REJECTED / NO_CONCLUSION / BLOCKED
选择来源、适用范围及可吸收部分：
```

6. 未经有权的人确认，结果保持 `PENDING_CONFIRMATION`。如果一轮同时改变了多个变量，该轮不能把结果归因到任何一个变量，也不能据此确认 token；必须拆分并重做单变量比较。

**产出**：每轮 2–3 个同结构、单变量真实候选及完整比较记录。  
**完成证据**：固定变量、唯一变化变量、代表页面与状态、比较结果、确认人和当前状态完整；候选差异可解释，未确认前不称确认。  
**不得替代**：用三套结构不同的方案假装视觉比较。

## V7 视觉素材拼装与图片生成双路径协议（IconScout 快拼 / 真实摄影 / 必要时才 AI 生图）

### 生图执行前置：参考图片与提示词一起提交

本 Skill 中采用生图制作方向样张、主视觉、静态字形或表现图形时，**每次生成调用必须通过工具真实的图片输入通道传入适用参考图，同时提交本次提示词**。看图后只写文字提示、附上网址、填写参考文件名或事后再补参考，都不算垫图；内部探索也遵守这条要求。

1. **先选对图，再生成。** 新方向先按 RR 实际搜索和看图，选与本轮题材、传达目标及完成度匹配的成熟作品；已有适用正式稿或经过质量核验的主视觉/母体可复用。说明具体借鉴的构成、字形、色彩、材质或光影，不把相关题材、热门排序或任意一张图当作合格依据。不同方向分别选适用图片；不为制造差异强制更换已适用的共同资料，也不以同一参考机械生成同向变体。
2. **取得模型能读取的真实图片。** 依来源使用条件取得图像或清晰截图并打开检查；核对当前生成工具实际支持的文件、会话图片或上传 ID 方式，以及本次输入是否确实可达。网页链接、搜索缩略图定位和本地文件存在，分别不证明模型已收到图片；多图和透明底能力按当前工具合同核实。
3. **图片和提示共同限定本次制作。** 在同一次调用中传入图片，分别说明风格/工艺参考、构成参考、准确主体资料和编辑目标的角色；提示词仍由本轮构成、真实内容和分层要求推导，说明借鉴什么、按任务改变什么、不得复制什么。独立标题和表现图形须传适用主视觉或专项参考，不能只用“与主图同风格”几个字代替图片。参考中已有文字不自动进入本次文案，独特资产、Logo和整套构图不直接复制。
4. **缺图或传图失败，先补输入。** 取得失败回 RR 换可用来源；工具收不到图时修正输入方式，能力不足时按 TR0 说明受影响制作及替代路线。依赖部分保持未完成，其他独立工作可继续；不得退回纯文字生图或把失败调用记成已垫图。沿同一资产记录留实际参考文件/图像 ID、图片参数引用、提交提示及结果版本；重试或换工具时重新核对本次图片输入。

垫图只证明输入方式成立。输出仍按下方工艺与合成检查判断，未达到目标就修正，不能以“已传参考图”证明画面好看。

### 生成资产的工艺目标与精修

嵌入原 DS1/V3/V5 制作与 QA0，不增加阶段、审批或独立报告。按本轮范围处理生成字形、主视觉与表达图形；已有合格资产直接复用。

1. **生成前建立可观察的工艺目标。** 参考检索先沿 RR 从同题材/主体及实际活动展开，再细化当前媒介、构成与工艺，不只用泛材质词寻找灵感。内容、方向和完成度标杆分别注明作用，可来自同一实际作品并共同支撑方案；实际看目标尺寸下适用的成熟画面，指出借鉴手法和边界。已有适用正式稿、质量参考或经验证母体按范围复用。把目标落实为形体与负形、细节密度、纹理尺度、边缘、光源、色彩层次及合成关系，不仅写“高级、精致、高清”。风格匹配不等于人已喜欢或工艺达标；未通过的生成母体不能自动成为质量标杆。
2. **从构成决定推导生产提示。** 接续 DS1 的主导关系或视觉事件，把期望效果及已看参考中的具体手法，转成焦点、主辅权重、比例、空间、图文衔接与必要细节，再决定物件和材质。物件、表面和排除项须能回到该决定或真实约束；不把业务关键词逐一具象化，不以一串质感词或“不要罗列”的否定句替代构成。不得为简化生成而加入没有依据的表现禁令。各层提示引用同一组合画布、目标尺寸、邻接关系及本层职责，主图、字形和内容小图共享必要语言，按阅读作用调整细节和重量。跨案生成前横看实际简报、提示和参考：非必要的场景母题、色温、光线、空间及标题构图是否已令候选同源；若是，回 DS1 重推受影响方向。生成前先满足上方真实垫图前置，核对本次实际传入及作用，不把风格名或事后补取的标杆写成生成前已采用的依据。其他工艺依据尚待验证时，可在垫图已具备的条件下做有明确验证问题的内部探索，补足后重新判断或制作，不能直接列为完成候选。
3. **先审资产，再审合成。** 在源图实际尺寸检查轮廓、结构、边缘、透明残留、纹理和光影的有意处理与意外缺陷；再按目标显示尺寸检查辨识、细节是否糊成噪点及与文字的关系。回到完整组合核对字形、主图、小图和控件的比例、节奏、主次与共同空间，不能只凭色调相合、像素够大或alpha存在就通过，也不把必要笔触与材质一概抹平。
4. **按缺陷精修并保留有效成果。** 定位问题来自方向、源资产还是合成，分别回 DS1、相应资产制作或布局调整。只编辑或重做受影响资产，明确本轮要修的造型/材质/光影问题，保留已成立的内容、层级和较优素材，再按相同尺寸复核。首张合格可以采用，不强制固定生成数量；不合格须实际修改，不以写下不足结束，也不靠放大像素或无目标反复抽样解决。实际能力或来源不能达到目标时按 CT0/TR0 说明影响与替代方式，既有明确制作要求不静默降级。

在现有资产/设计记录接续目标、参考作用、实际输入、准确资产及组合版本、源尺寸与目标尺寸看图证据、缺陷和修正结果；未达到的如实记未通过。此处检查工艺与表达完成度，不将自审冒充人对风格的选择或真实用户验证。

### 生产分层与动态合成

**先定完整组合，再拆生产文件。** 在本轮完整画布上确定重心、视线、疏密、背景延展，以及标题、主体与相邻内容如何连接；使用现有组合草稿或最低有效的局部试合成，不另增阶段或人审。独立图层不等于独立矩形分区：边缘、光线、色场和深浅关系需要延续时，按目标采用场景延展、透明边缘、遮罩、渐变淡出、穿插或共同表面；需要清晰分界时有意设计边界。纯色、渐变或硬边都须服务本案，不能所有层各配一块底色后机械上下相接，也不为消除接缝统一加模糊或渐变。

方向样张可展示完整合成预览；已明确要求的独立字形、图像与程序信息仍须实际制作。正式界面制作前，结合信息作用、更新频率、语言、独立修改和动画需要，规划背景、主体图像、标题、装饰与程序文字/控件的分层。主图与文字分别取得并合成，需要独立替换或控制的图层分别制作、导出或生成；将上述接合关系写入各层输入，而非取得所有资产后才临时找位置。无独立控制需求的固定背景装饰可合理合并，不强制每个装饰逐一拆层；只交静态成品或精确还原时沿本轮合同，不擅自增加完整源文件/动画委托。

- **程序管理的信息**：日期、目的地、剩余天数、余额、状态、问题/回答和控件内容按数据或文本渲染，记录来源、更新规则和边界。倒计时由日期数据及约定日界计算，不把某个数永久画进背景，也不每天重新生成整张主视觉。
- **静态视觉与表达文字**：按需要分别取得背景、主体/照片、表达小图、装饰及静态字形；主标题、副标题和眉题是否独立制作按 V3 判断。叠加资产保留真实透明通道、适用分辨率及安全区，并按独立换字、换语言或控制需要合成；频繁修改时优先可用字体/矢量，特定文案图不冒充字体文件。外部资产复用仍核对来源与许可。
- **特殊数字造型**：普通数字优先用真实字体；确需专门字形时按实际格式准备可复用数字及必要单位/符号，记录字距、对齐、缺字和拼接方式，由程序组合，并保留当前值的等价可访问文本。阿拉伯数字可复用0–9，汉字数值按实际组合规则补所需字形；不为每一天重做一张含完整数字的海报。
- **合成合同与检查**：在同一任务/资产记录写层 ID、内容职责、动态或静态、文件/节点、格式/透明性/可编辑性、参考画布与尺寸、锚点/层次、相邻区域的延续或分界、实际遮罩/渐变/混合等处理及适用依据、更新或动画依赖和来源。按目标尺寸检查裁切、可见轮廓、层间遮挡、字体/图像比例、可读性及边界接合；透明通道存在或颜色近似不证明已融为整体。替换一项动态值或一层素材时，其余层无需重新生成，单独改文案也不破坏构图。需要动画时再验证独立控制、交互反馈及减少动效状态，不为证明分层而新增未委托动画。

DS1 主视觉引领任务完成必要方案推导后制作样张，自审后让人看图选择。本节只提供图文构图、素材/摄影与必要生成方法；页面内主视觉可按路径 B 制作，但以本轮方案推导和参考为输入，不先要求一套已锁定 UI 预设，不重复要求相同垫图选择或未委托的动效升级。主视觉确认后由 DS2 延展界面，不能整页栅格化冒充可操作 UI。

静态表达文字需要字形设计时，按 [V3](methods-visual.md) 的作用、变化及资产合同判断，在本轮有效路线内独立制作并合成；不因它是副标题、文案不变或字体库没有合适造型，就一概退回普通正文。表达性小图按 V5 继承主视觉或适用套系。两者均是当前成果的一部分，不自动启动独立海报流程，也不豁免准确内容、真实尺寸及语义检查。

**触发问题**：当任务需要人物头像、图标、3D 元素、插画、真实摄影配图，或需要制作独立运营图/海报/主视觉（KV）时，何时用 IconScout、何时用真实图库、何时才调 AI 生图？  
**最低输入**：视觉用途（UI 内部元素 vs 独立海报/主视觉交付）、核心传达信息与尺寸比例。  
**跳过**：纯文字/纯组件界面且无任何图标、头像、图片或海报需求。

> **核心选型铁律（分清每个库管什么，不走无用功，更不跳过必调库）**：
> 1. **实际复用适用配方，不锁死默认外观**：决定采用组件配方时，执行 `copy <配方ID...> --to <目录>` 落盘并复用适用结构、行为与状态；实际采用预设时再带对应 `--preset`，任务派生规格不强制套 ID。只运行 `show` 不算已采用。配方的用途标签及变体建议用于检索，不是已批准的本轮外观决定；外观按 DS2 与完整构成保留、改造或替换，记录采用部分，次要动作不默认描边。不能因“完整复用”而保留不适用的边框、色条、表面或空间，也不能把功能状态在改造时丢掉。
> 2. **禁止在 0→1 空白 Figma 文件里白搜 `search_design_system`**：新建的空白 Figma 文件没有业务组件库（只会搜出无关的 Material 通用卡片），0→1 任务直接跳过 `search_design_system` / `get_libraries`。
> 3. **图标先选组再取用**：统一按 V5 决定作用、图文主次、形式及分组，再从实际渠道取用；表达性小图可按共同主视觉/母体定制。页面可多组，组内优先同集合并实际复核，组间服从整体权重与色彩。真实文件、采用位置、集合/来源及版本必须可核对，未采用的下载不算设计证据，不用粗糙自绘或无关剪贴画替代。
> 4. **人物头像（User Avatar）**：**必须实际执行检索或成套生成，严禁用“名字首字文字圆圈”回退充数！** 先搜 IconScout 并过 `V5` 第 7 条「文化风格 + 同套系判断门」；库内无匹配同套系头像时，立即用统一风格前缀调用 AI 生图成套生成真实头像图片。
> 5. **真实世界摄影 vs 游戏/UI 表面材质（边界分清，不白跑）**：
>    - **真实世界摄影（风景、城市地标、建筑、人物生活）**：必须走 [methods-image.md](methods-image.md) `IM`，用 `scripts/real_image.py` 检索下载；
>    - **游戏/UI 表面纹理材质**：不属于真实风景摄影，**不需要跑 `real_image.py`**，直接用预设纹理或原位生图生成局部材质贴图。
> 6. **海报 / 主视觉（KV） / 运营图先有构成，再选来源**：按下方路径 B 的同一组合稿判断现成素材、真实摄影或定制生成，实际来源须能支撑本轮表达。真实摄影沿 IM 核对；已明确的独立字形/图像制作按 V3/V5 落实，不被“先快拼”改回通用排版。取得方便不等于可直接成稿，最终仍审实际组合。

### 路径 A：UI 界面内头像 / 图标 / 配图 / 背景（IconScout + 真实摄影；必要时才原位生图）

适用：元素是 UI 页面的一部分，服务于用户资料、金刚区入口、卡片、Banner 位、头部背景或空状态。

1. **优先按「文化风格匹配 + 同屏成套判断门」获取头像与透明底道具/图标**：
   - **人物头像（先搜库做文化与成套判断 → 不匹配立即转 AI 同母体成套生图）**：先识别产品的文化语境与人物表达要求；若素材库（IconScout）中没有符合该文化风格且同一套系（Same Pack）的高颜值成套头像，**立即放弃素材库结果，改用统一风格前缀词调用 AI 生图成套生成**（严禁拿欧美豆豆眼 3D 泥人或代码手画 SVG 简笔人脸充数）！
   - **功能图标与表达小图**：按 V5 唯一决策入口从作用、图文主次到形式与分组，再复用实际可用库/适配套系或引用主视觉生成独立小图。最小尺寸核对识别、透明边缘和图文对齐；同组核对套系与表现规范，多组核对整体协调，不以同色、同关键词或同作者冒充同集合。
2. **真实摄影配图 / Hero / 氛围背景（先 Real Image Library，禁止跳过直接生图）**：
   - 主题、构图、比例、冷暖明确后，运行 `python3 scripts/real_image.py search "<主题>" --role hero|card|background|place --tone <warm|cool|neutral|dark|green>`；
   - 用 `Read` 看预览，按角色选图（Hero 要横构图和叠字留白，卡片要主体清楚，地点要能认出那个地方）；
   - `get` 到本地，写入资产 manifest（作者、许可证、作品页），再填进 Figma 图层或 HTML。
3. **按已确认路线生成并导入资产（真实摄影无匹配、必须虚构或需 V3/V5 定制表达时）**：
   - 读取实际目标尺寸、宽高比及有效品牌、主视觉或候选视觉版本，明确继承的色彩、材质、光影与裁切要求，不把候选写成已确认规范；
   - 已选 Figma 且具备对应原位能力时，在准确图层制作；代码或其他有效路线则生成真实文件并导入目标合成。按实际能力保留图层、透明资产和版本，不因本段另行更换工具路线。

### 路径 B：独立海报 / 运营图 / 主视觉 KV（先定结构草图 → IconScout 快拼 / 真实摄影 / 必要时才 AI）

适用：最终交付物本身是一张运营图、活动海报、宣发主视觉（KV）或社媒配图；也提供 DS1 主视觉子资产的制作方法，确认顺序和范围按该分支，不额外启动独立海报委托。**严禁跳过版面结构分析直接写一段提示词盲目生图。**

#### Step 1：先判断图文角色与占比（谁是主角？）

引用 RR 中已实际看过的同题材及适用近期案例，结合核心信息和 DS1 构成决定，判断由图像、标题/信息或图文关系承担主要传播任务，说明主焦点、辅助内容和视线去向；这是分析方式，不是必须三选一的模板。面积和比例由实际表达决定，不预设固定占比。文字可进入图像空间、参与造型或与主体有意穿插，也可分区；关键含义、阅读顺序与可读性必须成立，不能把独立素材理解成图文各守矩形一区。

#### Step 2：画出「海报版面结构草图（Layout Sketch）」并选择制作方式（快拼 / 真图 / 必要时才 AI）

根据 Step 1 形成可查看的 **组合草稿**，可复用已有有效稿或用当前授权工具低成本表达，供本轮内部判断，不另设用户审批。除了主副标题、必要信息、品牌和行动的主次，须能看出主焦点、层间前后、疏密、背景延展或分界及内容区衔接；只有文字框和配图矩形不足以判断整体。再据所需效果、编辑和来源条件选择制作方式：

- **制作方式 1｜现成素材合成（真实资源能支撑本轮构成时）**
  - **适用依据**：可取得的素材在内容、形体、工艺和编辑条件上足以支持组合稿，才选择复用；取得方便不等于表达合适。文字沿 V3 使用真实排版或已明确要求的独立字形，分层能力不能替代整体完成度。
  - **怎么拼装**：
    1. 在有效制作路线的画布中按组合稿建立背景、色场、图文空间与内容层级，引用 CI 的色彩关系；不先套通用底板再往上填元素，真实文字与字形资产按既定角色组织；
    2. 调用 IconScout（MCP 或 `scripts/iconscout.py`）检索拉取高清透明底的 **主视觉 3D 模型（`--asset 3d`）、主题插画（`--asset illustration`）、嘉宾/人物头像（`user avatar`，须先过 `V5` 第 7 条判断门，不通过改为 AI 成套生成）或装饰角标（`--asset icon`）**；
    3. 按组合稿中的焦点、前后与边界关系合成素材、文字和背景，检查实际尺度、疏密、光线与接合；不默认把物件摆到标题四周。先修正完整画面，再按所需格式导出；
    4. **若需动效版海报**：可直接从 IconScout 拉取同主题 **`--asset lottie` 动态元素** 嵌入版面并导出为 `MP4 / GIF / 动态 WebP`，连生视频模型都无需调用即可获得丝滑动态海报。
- **制作方式 2｜真实摄影、定制生成或编辑所需资产**
  - 表达真实地点、场景或人物摄影时，先按 [methods-image.md](methods-image.md) 核对真实来源与使用方式，按组合稿裁切、适配及合成文字，不能以虚构图冒充实景。
  - 现成来源不适用、必须虚构，或已有明确的定制字形/图像要求时，按 Step 3–Step 4 制作所需资产；不强制整图、不假定工具支持双图输入，分层与精确文字要求继续有效。

#### Step 3：按表达效果查适用参考，风格表仅作检索语汇

1. 按 RR 视觉分支先搜同题材、主体与实际活动，比较目标市场成熟案例、相关品牌近期活动及社区原作，再用构成、字形、材质或光影词细化。下方表仅作可选检索语汇，不是封闭候选集，不要求凑风格；语义检索不等于把关键词逐一做成画面物件。内容与工艺用途分别注明、共同进入当前方案，业务截图或只有质感相似的图都不能单独证明运营图完成度。
2. **独立海报未有有效参考选择时，把 2–3 张参考图并排展示给用户挑 1 张**作为风格参考垫图（`style_ref.png`）；用户已提供适用参考时直接引用。DS1 主视觉分支引用本轮 AI 推导与参考，不重复同一方向审批；确有实质方向变化时回该分支说明和确认。描述观感用大白话，给出推荐，不出现内部风格编号。
3. 怎么垫（只垫材质光影与色调 / 垫构图+画风 / 垫真实产品白底原图生成周边场景）、主色调与标题质感由 Agent 按选中的图和主题直接决定，不另外追问。

#### Step 4：把构成决定转成当前资产的实际输入

在已确认工具路线内，先满足上方“参考图片与提示词一起提交”的执行前置，再按真实图片能力传入组合草稿、适用风格/工艺参考及必要主体资料，注明各自用途，不复制参考的独特资产或整套构图。使用 RR 中已看过并按允许方式取得的实际图片；沿同一来源记录保留文件/图像 ID、实际图片参数引用和结果版本。图片作为风格参考、构成参考或编辑目标的角色分别明确，不混用；没有实际提交不写“已垫图”。已明确的分层要求优先，不能将标题、动态信息与控件烘焙进主图。取得或输入受限时回 RR 补图，无法满足时暂停依赖生成，实质路线变化按 TR0，不退为纯文字生成，也不虚构工具参数：

```text

- 组合草稿：主焦点、阅读关系、层次与边界接法

- 必要主体资料：准确形态或内容约束（适用时）
```

#### Step 5：静态海报/单图交付后的「动效版升级判断与预期对齐」（场景支持时必须用提问工具问用户）

当用户的原始需求是生成一张海报、运营图或单图时，Agent **必须主动判断该图的使用场景是否支持动图、以及做成微动图是否效果更好**：

1. **先判使用场景是否支持并受益于动图**：
   - **不支持或不宜动（直接只交静态图，不提）**：媒介无法播放、阅读需要持续稳定或动作会妨碍信息理解时。
   - **支持且预期受益**：渠道支持目标格式，且运动有助于传播目标、不会削弱阅读与操作时。
   - **用户原话已要求动图**：不重复询问是否需要动态版；制作工具路线仍须按 TR0 明确推荐并确认，已有适用选择则复用。
2. **支持动图时，交付静态图后用宿主提问工具确认是否追加动态版**，给出基于本任务的推荐和静态交付选项：
   - **问题里用一两句大白话说明真实效果预期（管理预期，不夸大）**，按以下标准判断能做什么：
     - **能做到的高质感效果（微动氛围 Loop）**：
       - 仅承诺实际工具可实现且经过验证的光影、材质、主体与镜头运动，说明各自幅度、稳定性和循环边界。
     - **明确不能靠生视频模型硬做的（防翻车说明）**：
       需要准确识读的信息若直接交给生视频模型运动，容易出现结构扭曲或模糊。因此最佳实现方案是：**拿无字/少字的主体底图作为【首帧垫图】送入生视频模型做背景与主体微动，保持文字层清晰稳定（或后期叠字），最后导出为高清 `GIF` / `动态 WebP` / 循环 `MP4`**。
3. **用户选择“需要动效版”后的无缝衔接执行**：
   - 直接复用 Step 4 已确认的静态图（或去字版底图）作为 **【首帧静帧垫图】**，转入 [methods-tool-routing.md](methods-tool-routing.md) `TR5-B`；
   - 按实际画面写运动对象、幅度、镜头、结构稳定及循环约束，不复用固定成品提示词；
   - 调用生视频模型生成 3–5 秒动态视频后，按投放渠道一键转码交付 **高清 `GIF`、`动态 WebP` 或循环 `MP4 / WebM`**。

**产出**：
- 路径 A：按 IM 或 V3/V5 适用规则取得并导入的真实图像/表达资产、来源许可、适配与节点/代码版本记录。
- 路径 B：图文职责及构图依据、实际采用的素材/参考与制作参数、准确版本成品。独立成品按其适用参考选择和已委托动态范围执行；DS1 主视觉样张引用同一候选和来源，不重复垫图审批或动效升级。

**完成证据**：实际图文、语义色与容器/尺寸相合，真实摄影来源可核对，生成/适配资产有对应依据及准确版本。独立成品完成其适用构图、参考与静态/动态检查；DS1 样张执行本轮组合自审和真实看图选择，不冒称完整页面通过，不追加相同参考审批或未委托动态制作。
**不得替代**：构图与准确内容先成立，不能随机生图；按真实适用范围保留工具和方向确认，不将独立成品门禁套到页面子资产，也不把需准确识读的信息直接交给视频生成而不检查。
