# 资源路由与设计资产记忆

方法负责判断怎么设计。外部库和内部资产负责提供真实案例、成熟方案、可复用代码和验证手段。

本文件负责把资源接到已有方法和专业环节，每个资源用 adapter 描述，不为新增一个库另开 U8 / V8。专项方法尚缺时按 [成果、环节与子任务目录](methods-deliverable-routing.md) 补足专业依据；增加资源入口本身不代表补齐方法。

四个登记库已经在 Skill 里，先用它们：
- **Reference**：`resource-adapters/registry.json` 里 `capability=reference|spec`（Mobbin、Page Flows、ARIA APG…）
- **Style**：`style-presets/` + `color-presets/`；整体配色与可选渐变资源入口见 [CI](methods-color.md)，Open Props 仅为按需 CSS 资源，不宣称已自动装入本地路由或项目
- **Component**：shadcn / Magic UI / Origin UI / Figma 套件（风格引擎 + 本文件）
- **Asset**：IconScout（`V5`，图标/3D/插画/Lottie）+ Real Image Library（`IM`，真实摄影）+ SVG Repo 降级

复用资源优先按下列渠道核对；需要建立新视觉方向时，参考搜寻沿下方 RR 的视觉分支，不先锁定本地预设再找图片背书：

1. 内部资产记忆（`scripts/asset_memory.py search`）
2. 本地预设（风格、配色、字体目录、ARIA APG 索引）
3. 可自动调用的 adapter（CLI / 脚本 / 不需付费的公开接口）
4. 已授权的 MCP（Mobbin、IconScout、Figma、Playwright）
5. 参考链接（用实际可用搜索/浏览器查看公开内容，按允许方式取得必要截图或参考图；不虚构自动接口或绕过受限访问）

```
python3 scripts/resource_router.py list --stage <阶段>
python3 scripts/resource_router.py show <资源ID>
python3 scripts/resource_router.py apg <交互模式>
```

## Adapter 合同

每个资源必须写清，缺一项就不能标「已接入」：

| 字段 | 含义 |
| :--- | :--- |
| mode | `auto` / `mcp` / `cli` / `api` / `reference` |
| search | 怎么检索 |
| returns | 回来的是什么数据 |
| acquire | 怎么用到项目里（复制源码、插 Figma、只作参考） |
| license | 授权与禁止项 |
| fallback | 没权限、没接口、失败时做什么 |

`mode=reference` 或没有公开接口，表示没有登记可自动调用的取图/安装能力，不等于不能使用现有搜索或浏览器公开看图。按真实渠道与使用条件取得必要截图或图像输入，记录实际文件和方式；不得假装已接API、绕过验证/付费墙或批量抓取受限内容。只取得链接不算已看图，公开可见也不等于素材可直接进入成品。接入库不等于复制网址，具体站点当前能力须实查。

图标资源的专业选择统一按 V5：先有基于内容、作用、图文权重、尺寸与产品风格的分组规格，再选择检索渠道。adapter 只说明工具能力，不替代选择判断；核对当前渠道能否筛选类型、提供集合/作者/许可信息、按组取得真实文件。当前本地 IconScout CLI 不提供按集合检索/整包下载，简化结果也不能证明集合身份；需要的来源字段从实际详情或可核验集合页面补齐，拿不到就如实标缺口。预览、源文件和实际采用分开记录，不因下载或风格标签存在就宣称已取得同套系成品。

## RR 设计参考智能（接到 CMP，不是新的竞品方法）

**触发问题**：当前任务的流程、界面、主题或视觉表达，有哪些实际案例能支持判断？

**最低输入**：要支持的决定与委托范围；交互参考含用户任务、情境和相关状态，视觉参考含题材/主体、成果及渠道、传达与感知目标、已有有效约束。

**跳过**：依 RT0 判断已有适用且可回查的案例足以支持本轮设计，或本轮问题不需要新增外部样本；写明复用/不展开理由。新界面也先判断已有依据是否充分，不能仅因“从零新建”重复调研，也不能未经判断直接套模板。

交互案例按用户任务和状态检索解法，不照搬整个竞品。新视觉表达还须沿下方视觉分支寻找同题材的实际画面，回答这类页面第一眼靠什么成立；两类证据用途分清，但可共用来源与设计影响。

**流程与交互参考步骤**
1. 按进入条件、操作、系统反馈与后续任务拆分场景。每个场景写要解决的问题，不写产品名。
2. 仅当项目目录已有 `.design-memory/index.json` 沉淀时才跑 `asset_memory.py search <场景>`；0→1 新项目且内部资产库为空时直接跳过此步，不浪费命令调用。
3. 检索外部真实竞品界面：
   - 有 Mobbin 授权（Pro 及以上）：MCP `search_screens` / `search_flows` / `search_sections`。按实际场景和状态构造检索词，不以指定产品的外观作为检索目标。
   - 无授权：自己看公开页面，不停工。用网页搜索找同类产品，打开应用商店页面（App Store、Google Play 的截图区）和产品官网，用浏览器截图或读图，按待回答问题选择同类产品及相关状态，范围由覆盖和新增信息是否改变判断决定。只看公开页面，不登录、不绕过付费墙、不批量抓取。也可以请用户导出 Mobbin / Page Flows 案例，但不等用户才开工。
   - 每个案例写：产品、页面、来源链接；第一眼是什么画面、占屏多大；信息怎么分区；主行动在哪；我们学什么、不学什么。
   - 交互样本须与任务的设备、页面职责和状态可比较；不同媒介或用途的宣传材料不能替代交互证据。样本不足以支持判断时写清缺口和下一动作，不许用海报凑数；跨媒介表达参考按 CC4 另记。
   - 流程视频：Page Flows 无公开 API，只作参考链接。
   - 交互行为：`resource_router.py apg <模式>`，对照键盘与角色。
4. 每个案例按 [methods-competitive.md](methods-competitive.md) 的样本模板记录。观察到的是事实，解释与假设分开。「别的产品都这样做」只能当候选，不能当完成证据。
5. 不复制品牌资产、文案和独特视觉。

### 视觉参考：先搜同题材与实际活动，再扩展表达

需要新建或调整营销、品牌、主视觉及其他视觉方向时使用本分支；有效正式方向、局部限定或已有充分适用参考按范围复用。不新增研究阶段、参考账本或人审，来源与证据用途仍接 CMP/CC4，方向选择沿 DS1。

1. **从任务语义起检索。** 从题材/主体、成果类型、活动或参与任务构造检索词，按结果分别展开近义表达、中文与英文，再增加品牌、平台、构图、媒介或质感词。语义检索用于发现真实解法，不等于把每个词做成成图物件。方向未定时先看题材相关且视觉语言不同的成熟作品，再推导候选；已有有效方向时才据其筛选，不先自定画风再仅搜同类图证明它正确。
2. **优先核对目标市场的同类活动。** 查垂类成熟产品/品牌及相近活动的实际主视觉、活动页与系列延展；国内任务可扩到抖音、快手等平台的公开活动及设计团队/实际制作方案例。以具体设计质量和本轮相关性判断借鉴价值，知名度、搜索排序和点赞不自动证明适配，不凭品牌名就称头部或优秀设计。官方、实际制作方和作者原作优先，采集/转载页追溯原出处。
3. **扩展社区与成熟品牌的表达。** 用同一题材、主体或活动词检索花瓣、站酷、Dribbble、Behance等视觉社区，再结合设计成熟的相关品牌近期活动，比较构图、字形、图文接合、空间、色彩与工艺手法。品牌实际上线案例和社区概念稿分别标明；同一图片可以同时支持题材、方向及工艺等判断，但逐项说明用途，不能因区分证据而割裂转化。按决定需要选择来源，不要求每个站点或固定品牌都搜一遍。
4. **核实近期性并实际看图筛选。** 以当前日期和本轮运营周期查找近期作品；需要时扩展检索时间范围并说明。分别记录活动发生/原作发布、转载或收藏更新、查阅日期及证据；收藏时间、标题年份和搜索爬取时间不能替代原作日期，未知如实标记。旧作可补充技法，不单独支撑“近期/当下风格”的判断。打开详情和足够清楚的实际画面，结合目标尺寸审相关性、构成、字形、色彩/接合及工艺；只有摘要、标签或小缩略图的保留为线索，不能称完成视觉参考。题材对得上也可能质量不足，应淘汰而非照单采用。
5. **由实图形成候选与生产输入。** 对选中参考指出可观察手法、为何适配、怎样转化及不可复制部分，交给 CC/DS1 的构成决定；保留多方向选择空间，不直接复制独特资产、文案、Logo或整套构图。采用生图时须按 [V7 生图执行前置](methods-visual.md) 取得适用图片，并与提示词一起通过真实图片参数提交；主视觉、独立字形和表现图形均适用，不只在 Agent 判断“需要垫图”时执行。取得或传入失败先补图或修正输入，无法满足时暂停依赖生成并说明缺口，不退为纯文字生成；不能只把链接或风格词写进提示便称已垫图。

沿用同一来源记录，将**发现、已看图、已取得输入、实际已传图**分别留证：检索词/来源类别 → 原始详情链接与发布主体 → 各日期及证据 → 看图方式与图片/截图定位 → 观察、适配及转化边界 → 支持的候选/资产 → 输入文件或图像ID → 工具及实际参数中的图片引用、用途和结果版本。未完成的环节不能由前一步自动推定，参考图不得混标为编辑目标或可直接复用的产品素材。

上述社区在此为公开参考入口，不声明专用自动接入：`mode=reference`；`search`为实际站内UI或公开搜索；`returns`为可见作品/采集页及可追溯出处；`acquire`为按当前渠道允许方式看图、截图或取得参考输入；`license`依实际来源区分参考与成品复用；`fallback`为其他公开来源，登录或人机验证需使用者参与时保留待处理，不绕过。能否搜索、看大图、取得文件分别实查，不因列入此处就记为已可调用。

看过的同类截图存进页面目录的 `refs/`（文件名写产品和页面），`VT` 出目标稿时当质感参考，`QA0` 并排对比时当标杆。

Mobbin MCP：`https://api.mobbin.com/mcp`，OAuth，需要付费套餐。有套餐时像 IconScout 一样发起授权，告诉用户点一下。没有套餐或授权失败，走 fallback，不停工。

**产出**：场景/视觉判断 → 实际案例与观察 → 可迁移条件和边界 → 当前候选/资产及真实输入，接入同一 `design-decisions.md` 来源记录。

**完成证据**：交互关键场景有来源可核对的案例，或写明未找到及按方法自写的范围；视觉分支有真实看图、筛选及当前方案的影响依据，需要垫图时还须有取得/传入证据。只有链接或未找到的声明不能证明视觉参考已完成。结论支持本轮判断，重要缺口已标明；样本量不设统一下限。后续 QA0 并排审美验收所需参考仍遵守原要求，不因研究复用或不展开而豁免。
**不得替代**：用户研究；不能用案例证明目标用户需要什么。

## TY 智能排版（接到 V3，不是新的视觉方法）

**触发问题**：正文、控件与主标题各需要怎样的字体或字形，才能兼顾阅读、语言覆盖及已确认的表达？
**最低输入**：文字角色、准确内容/目标语言、品牌及 CT7 偏好依据、密度与实际尺寸；风格族是检索线索。
**跳过**：本轮各文字角色均由有效正式规范锁定；仍检查实际文件与覆盖。正文已锁定不等于主标题的创意表达也已解决。

```
python3 scripts/typography_intelligence.py pick --family <风格族> --langs <语言列表> --density <密度>
python3 scripts/typography_intelligence.py pick --family <风格族> --langs <语言列表> --css
```

规则：
- 先按品牌、已确认偏好、文字角色及内容决定要解决什么，再用风格族和字体库检索候选；不能把风格名称机械绑定为某种字族，或把小型本地目录当作全部设计选项。
- 用户提供的正式字体/字体包可作为输入，先核对文件、版本、真实字重、中文覆盖与允许用途，再决定项目引用/嵌入方式；没有字体包就查实际可用的在线资源，不要求使用者先替 AI 完成字体选型，也不自动安装系统字体。
- 目标语言含中日韩时，正文和需要中文造型的标题必须有适用字形；只支持拉丁文的搭配不能充当中文标题方案。
- Google Fonts 的已知字体可通过 **CSS2 URL** 加载，无需目录 API key。本地 `resource-adapters/fonts/catalog.json` 与 `typography_intelligence.py` 是检索起点；不够时可查 [Google Fonts](https://fonts.google.com/)、[Google Fonts 官方字体源](https://github.com/google/fonts) 或其他实际可访问的官方目录，核实具体字体与来源再使用。完整目录 API 按实际能力和配置处理；没有该 API key 不等于没有其他可查证的字体。
- 中文商业字库可按需查看 [方正字库](https://www.foundertype.com/) 等官方目录；品牌/团队已有授权字体优先核对。它们在此是检索参考，不宣称有自动接口、已登录、已购买或可直接嵌入所有字库。使用条件、文件和能力不足时如实说明，沿用原权限与工具路线。
- 不嵌入 SF Pro。苹果风用系统字体栈。
- 字体、字号、行高、字重写入 `V3` 记录；检查实际加载文件、静态/可变字重及子集覆盖，不能以 CSS 名称/声明代替字体已生效的证据。
- Fontshare 等站点按具体文件与使用条件核对后推荐；涉及账号、付费或授权范围取舍时再请有权的人决定，不强迫使用者代做字体选型，也不把能浏览样字当作已取得字体文件或使用权。
- 主副标题、眉题等静态文字需要专门表达时，返回 [V3](methods-visual.md) 按角色、更新与维护需要选择排版或独立字形资产；可使用矢量/图像制作或生图，不强制选库内通用字体，也不把特定字形当作一套字体。常规正文、控件及动态信息按其角色保持语义和可维护性。

**产出**：按角色的字体候选/采用依据、来源与实际文件或 CSS 引用、真实字重及覆盖、字阶；需要字形资产时交接 V3 的静态表达字形合同。
**完成证据**：每种目标语言有实际字形覆盖，字重与文件匹配；V3 记录可追溯。普通字体或创意字形均按实际页面检验，不以“已调字体库”代替文字设计。
**不得替代**：`V3` 的内容压力测试和窄屏检查。

## VE 验证引擎（接到 QA0，不是新的验收方法）

交付前在现有 QA0 上加三类可执行检查，能跑的必须跑：

| 检查 | 命令 / 工具 | 没有工具时 |
| :--- | :--- | :--- |
| 几何 / 分区 / 图标 | `ui_geometry_audit.py` | 不能交 HTML |
| 跨页风格 | `style_consistency_audit.py` | 单页可跳过跨页项 |
| 对比度 | `color_intelligence.py contrast`，实际复杂表面另按 CI5 核验 | 按 CI5 以实际前景/合成背景和状态补充可回查检查，明示脚本未运行及覆盖范围，不能只目测 |
| 无障碍 | `python3 scripts/a11y_audit.py <页面>`（axe-core） | 键盘走主路径 + 对比度；并写「axe 未跑」 |
| 主路径 | Playwright MCP 或浏览器里实际点一遍，含一个失败分支 | 必须人工点，不能只截静图 |
| 视觉回归 | `npx chromatic`，仅当存在 `CHROMATIC_PROJECT_TOKEN` 且项目有 Storybook | 并排截图；**不写「已做视觉回归」** |

axe 报出的 `critical` / `serious` 必须修好再交。Chromatic 没 token 不是失败，是不适用。

## AM 设计资产记忆（闭环，长期价值最高）

每次做完：设计执行 → 自动验收 → **用户确认** → 入库 → 下一次优先复用。

```
python3 scripts/asset_memory.py search 相机权限
python3 scripts/asset_memory.py deposit --type pattern --title "权限被拒可重试" \
  --conditions "系统权限、必须有设置入口" --files permission.html \
  --validation a11y.json --confirm
```

可入库的类型：交互模式及适用条件、页面模板及组件映射、风格 / 配色 / 字体预设、动效代码及参数、已通过验收的组件及测试记录。

规则：
- 没跑验收、验收未通过、用户没确认，都不能入库。
- 默认写入当前项目的 `.design-memory/`。可复用到其他项目的，再拷进 Skill 的 `asset-memory/`。
- 检索时两个目录都搜。
- 命中内部资产后，仍要用当前任务的约束核对适用条件，不能无条件套用。

**产出**：`index.json` 中的一条资产。  
**完成证据**：有验收记录和确认标记。  
**不得替代**：本轮仍要按方法做判断；记忆是输入，不是答案。

## 环节—方法—资源对应表

由 [成果、环节与子任务目录](methods-deliverable-routing.md) 和 RT0 先判断本轮需要解决什么，再查下表。它不是所有任务必须跑完的检索清单；独立委托与嵌入任务使用同一方法入口，区别在范围和下游用途。已有材料足够时复用并写依据，无需为每个子成果重新取证。

### 资源身份与实际可用性

- `style-presets/`、`color-presets/`、字体目录、组件配方，以及同包 [Pro Max](../fusion-design-ui-ux-pro-max/SKILL.md) 的 UX/字体/图表等数据是本地资源；同包 [Impeccable](../fusion-design-impeccable/SKILL.md) 是可按需调用的界面方法参考。两项辅助 Skill 不接管主流程、产品事实或原确认规则。
- Mobbin、IconScout、Figma 等是外部入口；参考链接、可自动调用资源和需授权工具按 adapter 合同区别记录。登记存在不代表已连接、已有付费权限或已取得素材。
- 内部记忆仅在对应目录有真实条目时检索；随包的空索引只是机制，不可报告为已命中历史资产。确认并通过验收后再按 AM 沉淀。
- 品牌、服务蓝图、视频叙事/声音、文稿出版和印刷生产的完整专项仍有缺口；上表部分方法或素材可支持它们，不能据此宣称专项已齐备。按目录补足实际专业依据，不为补一个库另开平行流程。
- 查询结果需在实际成果中采用、说明不适用，或形成明确设计判断；只运行搜索或列库名不构成方法完成。每一步的具体输入、停止和交接仍以原方法及 N5 合同为准。
