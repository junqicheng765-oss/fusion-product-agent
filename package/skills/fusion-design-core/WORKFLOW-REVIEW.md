# 设计师接到任务后到底怎么做

这是一份给人审阅的白话稿。它不新增第二套流程，只把 Skill 的运行规则翻译成容易讨论的设计师工作过程。内部编号、状态码和方法 ID 仍留在执行文件中。

## 一句话流程

```text
接到上游任务
→ 弄清真正要改善的结果
→ 判断这次需要哪种设计支持
→ 把产品信息翻译成设计要求
→ 确定本轮具体交付物
→ 找出会改变交付物的未解决问题
→ 只调用解决这些问题所需的方法
→ 按最终产物调用必要工具，不把所有工具跑一遍
→ 制作、验证或验收
→ 把结果、证据和新发现交回上游
```

这不是固定的“先调研、再流程、再交互、再 UI”。每次从哪里开始，由任务当前缺少的决定来定。

## 设计师先回答六个问题

### 1. 用户真正要改变什么

先分开“目标”和“用户点名的手段”。

例如：

- “提升落地页”不是目标，可能的目标是提高合格注册、减少误解或提高有效咨询。
- “做一个首页”不是完整目标，要继续确认首页需要帮助谁完成什么任务。
- “按这个正式 Figma Frame 和指定版本还原，资产与行为规格齐全且不改设计”才是明确制作任务；只有一句“把这个 Figma 做出来”仍需核对对象、版本、范围和允许改变的内容。

如果用户只给了手段，先找它服务的用户结果和产品结果；不能确定时标为缺失或假设，不能自行编造。

### 2. 这次最终要交什么

在开始方法前，先把本轮终点说具体：

- 问题诊断；
- 用户与使用语境结论；
- 流程方案；
- 交互规则和异常状态；
- 测试就绪原型；
- Figma UI 方案或正式主稿（包含全部界面视觉）；
- 非界面视觉成品，或用户明确拆分的独立视觉资产委托；
- UI 交互动效规格、Figma 原型预览或正式 UI 交互动效；
- 视频 / 动态图形成品；
- SVG、Lottie、图标或其他格式特定动画；
- 验证结论；
- 按指定来源完成的成品；
- 可交接的设计包。

“优化一下”“做得更高级”“出个页面”都不是合格交付定义。必须明确范围、载体、保真度、允许改变的内容、禁止改变的内容和完成证据。

### 3. 哪些内容已经知道

已知信息必须保留来源和适用范围，例如：

- 上游已经确认的目标用户、核心问题和业务目标；
- 已有研究、行为数据和客服反馈；
- 已冻结的产品范围、流程或方案；
- 当前项目里的共享对象、术语、组件和资产；
- 正式设计系统、Figma 主稿和准确版本；
- 技术、数据、权限、运营和合规约束。

已有有效答案直接复用，不因为进入设计流程就重新问一遍。

### 4. 哪些未知会真正改变设计

不是所有未知都要在本轮解决。只处理“答案不同会让本轮交付明显不同”的问题。

例如：

- 不知道用户为什么没有注册，会改变是否应该改页面，因此必须先分析。
- 不知道一个范围外页面的历史原因，但它不影响本次按钮文案替换，可以暂不处理。
- 不知道共享组件能否修改，会影响整个项目，必须先取得所有者授权。
- 缺正式图片或字体会导致无法准确还原，必须停止相关制作，不能用占位内容冒充完成。

### 5. 这次该从哪种设计工作开始

根据已知和未知，选择真实起点：

- 问题和原因未知：从证据与问题诊断开始。
- 用户、任务或成功标准未知：从用户与语境分析开始。
- 目标已确认但任务路径未知：从流程开始。
- 路径已确认但页面职责、反馈或异常未知：从交互开始。
- 交互规则已确认，但信息、组件、状态或界面视觉未知：进入 Figma UI；不要求把 UI 和界面视觉拆成两个必经阶段。
- 界面中的插画、图片、图标和品牌图形仍在 Figma UI 中完成；缺正式输入时先阻断。只有用户明确把某项资产拆成独立视觉委托，才调用视觉工具，确认后可回到 Figma。
- 已确认的 UI 反馈、状态转换或空间关系确实需要运动表达：定义 UI 交互动效规格；Figma 只可做预览，正式成品调用能在目标环境实现和验收的动效工具。
- 最终要交视频或动态图形：从传播目标、脚本、分镜、关键帧、正式素材和输出规格开始，不默认创建 Figma，也不套用 UI 动效方法。
- 最终要交 SVG、Lottie、图标等格式特定动画：从矢量源、图层、行为、格式和运行环境开始；只有其运动表达 UI 反馈、状态转换或空间关系时，才补已定稿 UI、D5 与 UI 动效方法。
- 方案已经存在，只是不知道是否成立：从验证开始。
- 所有决定都已确认，只需要应用批准内容：直接制作。
- 正式主稿已冻结：按主稿还原，不重新设计。

### 6. 做完以后怎样证明

开始前就定义证据，不能画完以后再临时找理由。

证据有三种执行方式：

1. **工作本身就是证据**：例如访谈、观察、可用性测试和人工价值验证。
2. **先做成品，再验收**：例如局部优化回归、正式稿对照和精确还原检查。
3. **本轮只准备验证条件**：例如只交测试原型；必须写清下一责任人、样本、触发条件和测试程序，不能声称已经验证。

## 五种接单方式

### 直接制作

适用：修改对象、来源、范围和结果都已明确，没有新的设计取舍，并且任务局部、可逆或已有低风险依据。高风险、影响范围未知或不可逆时，先完成风险评估、授权和相称证据要求；关键输入未知则阻断。

设计师做：

- 核对准确来源和版本；
- 写清允许与禁止改变的内容；
- 执行指定修改；
- 对受影响页面、状态或组件做回归。

设计师不做：

- 为了显得完整而补访谈、竞品或视觉探索；
- 擅自“顺便优化”冻结内容。

### 局部优化

适用：问题位置已经确认，但具体解法尚未确定。

设计师做：

- 定位受影响的流程、交互、UI 或视觉决定；
- 只补这些决定所需的证据；
- 比较修改前后；
- 回归相邻路径、失败状态和共享组件。

设计师不做：

- 因为一个局部问题重新研究整个产品；
- 用静态稿通过冒充行为指标已经提升。

### 问题探索

适用：不知道问题发生在哪里，或者用户、价值、情境和成功标准仍会改变方向。

设计师做：

- 审计现有数据和材料能说明什么、不能说明什么；
- 确定行为群体、任务、情境和当前做法；
- 找到证据支持的问题位置；
- 形成可证伪假设和下一步决定。

设计师不做：

- 先画一个改版，再倒推理由；
- 用竞品、审美偏好或人口标签冒充用户证据。

### 方案验证

适用：已有概念、路径、界面或原型，需要判断它是否成立。

分两种：

- **验证准备**：只把方案做成可测试版本，完成预测试和验证合同；本轮不声称方案有效。
- **验证执行**：冻结版本后取得真实观察证据，再决定继续、修正、重定义或停止。

### 设计还原与交付

适用：正式主稿、规范和目标版本已经确定。

设计师做：

- 核对文件、节点、版本、资产和动态行为；
- 忠实制作；
- 逐项对照布局、字体、颜色、间距、资产、状态和交互；
- 记录覆盖和残留差异。

设计师不做：

- 把还原任务变成个人改版；
- 缺资产时用近似品或占位符降级交付。

## 产品输入怎样变成设计语言

上游信息不能直接跳成 UI 结论。设计师需要做以下翻译。

### 用户信息

不能从年龄、职业或地区直接猜常用产品、能力和审美。

需要进一步得到：

- 用户在当前任务中的角色；
- 任务频率和熟练程度；
- 已经学会的对象、术语、操作和反馈；
- 感知、理解、操作或设备能力；
- 用户怎样判断完成、失败和可信。

### 任务与情境

需要得到：

- 什么事件触发任务；
- 用户现在怎样完成；
- 使用什么设备，是否移动、分心或被打断；
- 有哪些参与者、审批者和交接；
- 失败后怎样恢复；
- 结果什么时候才真正成立。

### 行业与风险

不能因为是金融、医疗或企业产品就直接指定颜色和风格。

需要从真实后果推出：

- 哪些信息必须准确、完整和可追溯；
- 哪些操作需要确认、授权或凭证；
- 哪些错误必须预防、允许撤销或提供申诉；
- 哪些结论需要专业责任人确认；
- 验证深度必须达到什么程度。

### 项目内部连续性

如果任务属于一个大项目，先核对：

- 上下游模块怎样进入和离开；
- 是否共享对象、术语、状态、权限和凭证；
- 现有流程、组件、变量和资产能否复用；
- 本次是直接复用、允许扩展、仅供参考还是必须新建；
- 共享修改会影响哪些页面、角色和端。

### 外部竞品

竞品分三类，不能混成“找几个类似 App”：

1. 行业竞品：看类别门槛、替代方案、行业信任模式和差异机会。
2. 同类操作竞品：看相同操作的步骤、反馈、异常、恢复和适用条件。
3. 服务同类用户的竞品：有真实用户关系证据时，判断目标群体已经学会的语言、信息和操作习惯。

竞品只能提供候选和风险，不能证明目标用户需要什么，也不能替代方案验证。

## 方法怎样被调用

方法不是按阶段全部执行，而是用来回答具体问题。

- 不知道现有证据够不够：先做证据审计。
- 不知道是谁在什么情境遇到什么问题：形成问题卡，必要时做情境访谈或观察。
- 已有多来源材料但矛盾杂乱：用同理心地图整理“想、说、做、看到”，不能在没有材料时凭空填写。
- 不知道任务怎样走到结果：做范围、场景和主路径。
- 不知道页面职责、反馈和失败恢复：做交互规则、页面职责和异常矩阵。
- 不知道信息如何被找到、理解和操作：做信息分级、主行动、组件、状态和界面文案。
- 不知道正式界面视觉怎样表达已确认内容：继续在 Figma UI 中核对视觉依据，再处理颜色、字体、密度、图像应用和候选方向。
- 界面需要插画、图片、图标或品牌图形：在 Figma UI 中定义并完成；没有正式资产或授权时阻断，不自动扩成另一项视觉任务。
- 不知道界面变化是否需要运动表达：只为已确认的反馈、状态转换和空间关系定义 UI 交互动效；静态已足够时跳过。
- 要交视频或动态图形：使用传播 brief、脚本、分镜、关键帧、品牌与音视频素材、渠道及编码规格组织制作。
- 要交 SVG、Lottie 或图标动画：使用可编辑矢量源、图层/路径、起止或循环行为、格式、运行环境和性能要求组织制作；若运动不表达 UI 反馈、状态转换或空间关系，不调用 UI 动效方法。
- 不知道方案是否成立：准备最小测试载体，选择能直接回答当前判断的验证方法。

## 工具怎样被调用

工具也不是全部执行：

- 流程和问题分析：使用能保留来源和关系的文档、图表工具，不默认创建 Figma。
- 交互：先交规则、状态或最小原型；允许用 Figma 做低保真稿，但必须标明不是正式 UI 主稿。
- UI：调用 Figma。页面、组件、状态、响应式，以及所有界面内颜色、字体、间距和图像应用都在 Figma 完成。
- 非界面视觉成品，或用户明确拆分的独立视觉资产委托：调用视觉工具。若下游进入 UI，确认后的真实文件才能导入 Figma。
- UI 交互动效：Figma 原型只可作 `FIGMA_MOTION_PREVIEW`；正式成品最终通过写代码实现（CSS / JS / GSAP / 客户端代码），并在目标运行环境测试中断、返回、减弱方案和性能。
- 复杂 3D / 光影 / 流体动态图与宣传视频：先确认首尾关键帧垫图，再调生视频模型或专业视频工具，按场景导出或转码为 `MP4 / WebM / GIF / 动态 WebP`；出现任何产品 UI 画面时引用已定稿 UI，只有画面中的运动表达 UI 反馈、状态转换或空间关系时才补 D5 与 UI 动效规格。
- SVG、Lottie、图标等轻量矢量动画：先从 IconScout 拿现成 Lottie / 动态图标，库里没有再基于专业矢量图标用代码/矢量工具加动画（不手画简陋图形，不调像素级生视频模型）；只有运动表达 UI 反馈、状态转换或空间关系的部分才引用已定稿 UI、D5 和 UI 动效规格。

例如产出合同同时要求 Figma UI 和一份独立插画成品时，才形成多工具分支：

```text
产出合同明确独立插画委托
→ Figma UI 确认插画职责和尺寸
→ 视觉工具生产并审核插画
→ 将确认文件导入 Figma
→ 完成 UI 布局、状态和响应式
```

## 进入 UI、生图与动效时的具体执行规则

当流程前面的页面职责、信息层级（L1–L4）和所用组件类型已经确定，真正进入 UI、生图或动效落地时，按下面三套实战机制执行：

### 1. UI 阶段的三路分流与风格决策漏斗

先做两问分流，不把所有项目都拉去重选风格：

```text
前面的页面职责、信息层级、所用组件已确定
  ├─ 第 1 问：有没有现成的相关页面或既有设计规范？
  │   └─ 有 ──► 【路线 1：存量延展模式】
  │             直接提取现有页面的色板、背景与卡片层级、圆角、字号阶梯、图标风格，
  │             复用已有组件拼装新页面，不重新选风格。
  │             用户明确要求换风格时转风格引擎：先探索 3 个方向，用户确认后再批量改代码。
  │
  └─ 没有（从 0 到 1 新建）
      └─ 第 2 问：是纯 B 端/中后台，还是 C 端/强品牌差异化产品？
          ├─ 纯 B 端 ──► 【路线 2：公开组件库快搭模式】
          │             直接绑定成熟公开组件库：
          │             - 国内标准中后台：Ant Design
          │             - 国内现代清爽办公/数据台：Arco Design / TDesign
          │             - 国际化 SaaS / AI 工作台：shadcn/ui
          │             - 海外传统企业系统：MUI / Fluent UI
          │             不问用户：Agent 按技术栈与场景直接定「用哪套库、主色（有品牌色就换，否则用默认色）、密度（数据密集用紧凑）」后快速搭出，交付时一句话说明。
          │
          └─ C 端 0→1 / 游戏 UI ──► 【路线 3：0→1 风格库（国际化 8 种 + 国内 8 种 + 游戏 10 种 + 通用质感 6 种）与 6 维视觉决策漏斗】
                        Step 1：按「国际化 App vs 国内 App vs 游戏与泛娱乐」+「行业严肃度/世界观题材」+「任务形态与人群」自动过滤违和风格（例如严肃金融直接剔除糖果游戏化、粗野撞色、大促红海和卡通手绘插画；游戏项目则直接进入 GAME-01..10 按题材匹配）。
                        Step 2：在完成并汇报完前面的用研、三类竞品与交互方案后，结合竞品与定位从风格池挑出 2–3 个差异化风格方向，用大白话向用户征求意见让用户选（用户原话已指定具体风格时除外）：
                                - 国际化产品池（INT-01..08）：现代毛玻璃通透、瑞士极简细线网格、暗色微光便当盒、冷灰理性流体渐变、暖纸人文书刊、柔和色阶胶囊亲和、高饱和立体按压糖果、先锋粗黑描边撞色
                                - 国内产品池（CN-01..08）：标准蓝白高效工作台、清爽大图生活卡片、深海藏青稳重财富、轻快白卡直达工具、暖橙红高密导购转化、东方宣纸留白雅致、暗黑酸性机能潮酷、大字高对比普惠直白
                                - 游戏与互动娱乐池（GAME-01..10）：
                                  • GAME-01 史诗暗黑锻金重拟物风（锻造黄铜石材框、发光宝石按钮、古典罗马衬线）
                                  • GAME-02 高饱和粗描边 Q 弹立体卡通风（2.5px 粗黑描边、顶高光条+厚实底阴影 Q 弹按钮、微倾斜描边粗体）
```

### 2. 图标 / 3D 道具 / 插画 / Lottie「MCP + API 双通道」调取与高颜值头像/海报生成链路

> **核心选型铁律（先看文化风格与同屏成套性，库里不匹配立即转 AI 同母体成套生图）**：
> - **工具/装饰图标、3D 图标与道具、徽章、主题物件、标准插画、Lottie 微动效**：优先从 IconScout 拉取成套透明底素材。3D 库是主力素材源，覆盖功能入口图标、行业主题物（机票/行李箱/地标/银行卡/图表）、游戏与活动道具（宝箱/骰子/扑克/奖杯/红包/灯笼/火箭）、等级徽章等；只要求同屏同 Pack、同材质、同打光。
> - **唯一需要额外把关的是人物头像**：库内通用人物多为欧美职场画风，问题是风格不匹配产品，不是 3D 素材本身不能用；风格对得上（如欧美社交/SaaS 产品）就直接用。
> - **人物头像（User Avatar）「文化匹配 + 同屏成套判断门」**：
>   1. 先看产品的文化与视觉母体（例如**掼蛋、麻将、国风产品属于中国风，头像必须是东方人物面孔与新中式/国潮画风**），且同一界面上的所有头像必须 **100% 同一画风、同一头肩比、同一光影与底色**；
>   2. 先检索素材库并用 `Read` 看图判断：若库里没有契合该文化风格的头像（如搜出来全是金发大胡子欧美 3D 橡皮泥人），或凑不齐同一套系（Same Pack），**立即放弃素材库结果，自动转入「AI 同母体成套生图」**（用完全相同的风格前缀词 + 角色变量一次性生成整套统一头像，严禁强塞违和素材或手画简陋 SVG 人脸）。
> - **真实世界摄影（场景、人物生活、建筑、自然、地点）**：先走 Real Image Library（`scripts/real_image.py` / [methods-image.md](methods-image.md)）。没搜过真图，不得把写实摄影直接交给生图模型。
> - **快捷生成海报 / 主视觉（KV） / 运营 Banner**：先看能不能用 **「干净版式底板 + 清晰矢量排版字 + IconScout 透明底 3D 道具/插画素材直接拼装」** 完成。能快拼的直接拼装出稿（文字 100% 锐利、元素可独立微调、零 AI 乱码假字）；需要全画幅真实场景时先取真图再叠字；只有虚构合成或图库无匹配时，才走整图 AI 生图。

## 交付前最后一步：不只查规范标准，必须同时过「用户可用性 × 审美与品位 × 设计标准」三大验收筛

做完流程、交互、Figma UI、海报或动效后，**绝不能只做机械的“设计标准/像素规范检查”**（因为很多页面即便 8px 网格、字号和对比度全部合规，真人用起来依然别扭费劲，或者视觉上依然呆板、满屏 AI 模板味）。

交付前必须同时过 **三大维度综合验收筛（`QA0`）**；哪一维不及格，就精准退回哪一步重改：

```text
做出设计初稿 / 成品
   │
   ▼
【三大维度综合验收筛（逐维判定 PASS / FAIL）】

  维度一：【用户可用性审查（好不好用、顺不顺、累不累）】
    - 零解释与低认知负荷：新用户 3 秒内能否看懂“这是哪、能干嘛、下一步点哪”？做决定所需信息是否在手边（无需跨页靠脑子记上一页的数字或规则）？
    - 心理模型契合与零黑话：标题、分类和按钮是否是用户日常自然语言（无内部系统黑话）？点击预期与实际结果是否完全一致？
    - 物理顺手度与省力原则：能默认带出或点选的内容（如当前定位、上次设置）是否避免了让用户手动打字或多余跳页？有没有为了视觉对称把不同性质的按钮做成同款、或把不可点标签做成按钮外观导致误触？
    - 情绪安全感与受挫自救：涉及付钱/授权/删除时是否直接给清风险与保障？报错是否保留了用户已填内容并给清人话自救动作？有无打断主任务的弹窗或假倒计时损耗？

  维度二：【审美与视觉品位审查（好不好看、有没有气场与质感、去 AI 廉价感）】
    - 留白气场与正负形呼吸感（「间」与减法美学）：留白是积极引导视线的呼吸空间，还是因为不敢留白而用边框、底色块塞满全屏？删掉外框或装饰块会不会反而更高级（严禁卡片套卡片套娃）？
    - 视觉重心与视线韵律（聚焦层 × 信息层 × 色彩层）：有没有一眼抓人的视觉重心（Hero Focus）？主标题与正文字号反差是否足够有张力？视线滑动是否自然，还是满屏四五个同权重色块在打架？
    - 色彩同频与画面干净度（防“脏、俗、粉、腻”）：底色（60%）、容器色（30%）、强调色（10%）比例是否协调？配图色调、背景灰与按钮色是否处在同一个冷暖/明度纯度频率上（同频法则）？
    - 去 AI 塑料感与「1 个 120% 亮眼细节」：是否彻底规避了廉价蓝紫霓虹渐变、每行前塞 Emoji/小彩标、假 3D 圆球等 AI 俗套？在 80% 安静克制的基础上，整页是否有 1 处做到 120% 精致度的视觉锚点（如考究的头卡质感、极佳主视觉光影或张力排版）撑起品位？

  维度三：【设计标准与工程规范审查（准不准、齐不齐、能不能 1:1 落地）】
    - 平面四要素与栅格精度：对比、亲密（组内<组外）、对齐轴、跨页重复是否严密？4/8px 倍数间距与最小可点尺寸（主按钮≥44pt / 标签≥20pt）是否达标？
    - 风格参数字典与字标规范：Hex 色值、圆角、阴影/毛玻璃、字阶是否严格符合所选风格编号的参数包？是否采用原生字重（无描边假加粗）、金额用等宽数字（DIN）、全套图标粗细/圆角/透视三统一且像素对齐？
    - 生图与动效技术合规：海报是否还原了结构草图图文占比且零 AI 乱码假字？UI 动效是否有真实代码？真 Lottie 是否由矢量生成（未拿视频帧伪装）？生视频转出的 MP4/GIF/WebP 循环是否顺滑且文字清晰？
   │
   ├─► 三大维度全部 PASS ──► 允许正式交付或进入真人验证
   │
   └─► 任一维度 FAIL ──► 【按所属维度与病因精准退回对应节点修改，改完重审】
         - 【可用性不过（累/懵/繁琐）】 ──► 退回【流程与交互 D4–D5】砍多余跳页、合并跨页记忆信息、改打字为默认/点选
         - 【可用性不过（误触/黑话/无安全感）】 ──► 退回【交互与文案 D5–D6】换自然语言、拆开不同性质按钮样式、补风险说明与自救出口
         - 【审美不过（满/闷/呆板/套娃）】 ──► 退回【UI 构图与减法 D6–D7】删多余外框与嵌套卡片、用留白（「间」）分层、拉大字号反差重塑唯一焦点
         - 【审美不过（脏/俗/AI 塑料味）】 ──► 退回【视觉风格、真实摄影与生图 D7/V7/IM】收拢 60-30-10 色彩比例并统一冷暖同频、该用真图的改走 Real Image Library、清除 AI 俗套、打磨 1 处 120% 核心视觉锚点
         - 【设计标准不过（规范偏差/不精致）】 ──► 退回【UI/视觉/动效规范收尾 D6–D8】对齐参数字典、统一图标三属性、换等宽数字、补真实动效代码或无字底图重生
```

## 方法被选中后怎样真正执行

每个方法都要形成一张执行记录，而不是只勾选“做过”：

1. 它要回答的唯一问题是什么；
2. 最低输入来自哪里，是事实、推导、假设还是人的决定；
3. 本轮具体分析哪些用户、材料、路径、页面或状态；
4. 过程中观察到了什么，怎样解释，最终选择了什么；
5. 产物是什么，准确版本是什么；
6. 什么条件出现就停止；
7. 产物交给下一个哪个设计决定使用；
8. 前提被推翻时暂停哪些下游，并回到哪里重新路由。

方法产物不是自动确认。例如画出一条流程只能证明“已经形成候选流程”，不能证明用户能完成；做出原型只能证明“测试对象已经准备好”，不能证明方案有效。

为了防止 AI 把计划冒充结果，每个动作还要标真实状态：

- 只有计划或脚本：尚未执行；
- 对象、样本或材料已准备：测试就绪，但没有外部证据；
- 已真实执行：必须有场次或检查记录；
- 没有结论：不能挑一个方便的答案继续；
- 被阻断：写清缺什么和从哪里恢复；
- 完成：产物、证据和下游交接都已记录。

因此“写好了访谈提纲”不等于“做了用户研究”，“原型可以点击”不等于“验证通过”，“实现了动效”也不等于“用户已经理解”。

## 示例一：提升落地页转化

### 原始请求

“把这个落地页改一下，提高注册转化。”

### 不能立即得出的结论

- 不能直接认定是 UI 不好。
- 不能直接改 CTA、配色或首屏结构。
- 不能只看注册率就解释用户为什么没注册。

### 先形成待确认的目标假设

- 用户结果假设：目标用户理解价值、判断是否适合并顺利开始。
- 产品结果中只有“提高注册”来自原始请求；“提高合格注册”需要上游确认，不能直接当作既定事实。
- 反指标候选：后续流失、投诉、错误预期或无效注册不能恶化，同样需要确认数据定义和责任人。

如果“注册数量”与“合格注册”会导向不同页面策略，在上游确认前把成功标准标为缺失或待决策，不提前用其中一个替代另一个。

### 读取已知信息

- 当前页面和版本；
- 流量来源及不同来源的意图；
- 曝光、滚动、点击、注册和后续激活数据；
- 当前价值主张、证据、表单和加载表现；
- 已有反馈、访谈或销售记录。

### 本轮关键未知

“注册损失主要发生在哪里，为什么？”

可能是：

- 流量和产品不匹配；
- 用户看不懂价值；
- 缺少可信证据；
- 信息存在但看不到；
- 注册成本或流程过高；
- 性能、技术或埋点问题。

这些答案会导向完全不同的工作，因此本轮终点先定为“问题诊断”，不是“UI 改版”。

### 调用的方法

1. 审计漏斗和现有证据，区分事实与不能推断的原因。
2. 按来源、行为或任务分组，检查损失是否集中在特定人群或步骤。
3. 数据不能解释原因时，再补真实用户材料、访谈或观察。
4. 需要外部样本时，按待回答问题选择行业竞品、同类注册操作或服务同类用户的竞品中的一类或多类；已有材料足够时全部跳过。
5. 将证据收敛为一条最危险、可证伪的主假设。

### 不同结论怎样路由

- 流量错配：返回产品或投放，不进入页面设计。
- 价值不成立：返回产品价值与内容，不先润色 UI。
- 价值存在但用户扫不到：进入 UI 信息层级。
- 缺少信任证据：进入内容、反馈和信任设计。
- 注册步骤或失败恢复有问题：进入流程与交互。
- 页面性能问题：进入技术修复，并以行为数据验收。

### 本轮完成证据

- 问题位置有来源；
- 主假设可以被证伪；
- 明确下一轮从哪个设计决定开始；
- 没有用改版稿冒充原因证据。

## 示例二：替换已批准按钮文案

原始请求已经包含准确文案、文件、节点和范围。

因此：

- 不重新研究用户；
- 不调用文案设计方法重新判断含义；
- 直接执行指定替换；
- 检查按钮各状态、相关实例和页面回归；
- 文案与批准来源一致且行为未变，即可完成。

## 示例三：现有大项目新增一页

先检查项目内部：

- 新页从哪里进入、完成后去哪里；
- 使用哪些共享对象、术语、状态和权限；
- 哪些组件和资产直接复用；
- 哪些需要扩展以及谁有权批准；
- 会影响哪些上下游模块。

如果流程和页面职责已经确认，只在 Figma 中解决仍未确认的 UI 决定，包括全部界面视觉；若 UI 也已确认，就直接按来源制作，不为形式重新调用方法。如果连新页承担什么职责都不清楚，则必须先回到交互，不能拿组件拼出一个看似完整的页面。缺少界面资产时先阻断或请求正式输入；只有用户明确增加独立视觉资产委托，才另建视觉工具动作。

共享对象、组件或规则需要扩展或新建时，必须取得所有者授权；没有授权就阻断相关部分。完成后验收不只看新页，还要覆盖上下游入口、共享组件、受影响模块、关键状态和权限连续性。

## 示例四：按正式 Figma 精确还原

所有设计决定已经冻结，本轮不是设计探索。

执行顺序：

1. 核对文件、Frame、版本、设计系统和真实资产。
2. 写清允许修改和禁止修改。
3. 按主稿制作，不自行优化。
4. 冻结成品版本。
5. 对照布局、字体、色彩、间距、状态和关键动态行为。
6. 未经授权差异为零才算完成；缺主稿或资产就阻断。

## 示例五：已有原型，想验证是否值得开发

先判断本轮是哪一种：

- 只需要把原型准备到可测试：属于验证准备。交冻结原型、预测试记录和下一轮验证合同，不能说“已经验证”。
- 本轮要取得用户证据：属于验证执行。保持被测方案稳定，选择概念理解、任务走查、内容与信任或人工价值交付中的一种主验证。

验证后只能基于证据决定：

- 继续投入；
- 修正方案但保留问题定义；
- 重写问题定义；
- 停止。

## 示例六：制作一支独立宣传视频

本轮终点是视频成品，不是 UI，也不是界面状态转换。

- 先确认传播目标、受众、渠道、时长、画幅、核心信息和审核人。
- 准备脚本或旁白、分镜、关键帧、品牌规范、正式音视频素材、字幕与授权。
- 按分镜、剪辑、声音、合成、编码、分辨率、帧率和源工程要求选择专业视频 / 动态图形工具。
- 不为了“完整流程”创建 Figma，不默认调用界面反馈、状态转换和空间关系方法。
- 视频出现任何产品 UI 画面时，都引用该段已批准的 Figma UI；只有画面中的运动表达 UI 反馈、状态转换或空间关系时，才为该片段补 D5 与 UI 动效规格。

完成证据是准确版本的视频成品、合同要求的源工程、素材与授权记录，以及画面、声音、字幕和技术规格验收；分镜或 Figma 预览不能冒充正式视频。

## 示例七：制作一个 Lottie 图标动画

先判断它表达什么：

- 若只是独立装饰或品牌动画：直接按矢量源、图层/路径、起止或循环行为、尺寸、颜色、文件大小、目标格式、运行环境和兼容约束制作，不要求 Figma UI，也不调用 UI 动效方法。
- 若其运动表达界面反馈、状态转换或空间关系：先引用已定稿 UI 和已经确认的 D5 语义、状态、触发与空间规则，再补对应 UI 动效规格；动画不能自行发明成功条件、错误恢复或导航关系。

两种情况都由能输出和检查目标格式的动画工具完成，并在真实运行环境验收循环、触发、性能、文件大小和兼容性。只有运动表达 UI 反馈、状态转换或空间关系的情况才要求与已定稿 UI、D5 和 M1–M3 一致。
