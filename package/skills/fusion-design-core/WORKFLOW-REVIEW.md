# 设计师接到任务后到底怎么做

这是一份给人审阅的白话稿。它不新增第二套流程，只把 Skill 的运行规则翻译成容易讨论的设计师工作过程。内部编号、状态码和方法 ID 仍留在执行文件中。

工具路线统一见 [TR0](methods-tool-routing.md)：完成必要专业前置后，由 AI 解释推荐工具、理由、修改位置和预期成果，请人确认后才制作（含方向样张）。已有有效明确选择直接引用，同一路线内不逐操作提问；只读核对可先做。下文列举的 Figma、代码、素材和动画能力均是已确认路线内的执行方法，不是自动开工或更换载体的依据。

## 一句话流程

```text
接到上游任务
→ 弄清真正要改善的结果
→ 明确主成果或独立环节、本轮范围和子成果依赖，另记工作方式与载体
→ 把产品信息翻译成设计要求
→ 确定本轮具体交付物
→ 找出会改变交付物的未解决问题
→ 只调用解决这些问题所需的方法
→ 按最终产物调用必要工具，不把所有工具跑一遍
→ 制作、验证或验收
→ 把结果、证据和新发现交回上游
```

这不是固定的“先调研、再流程、再交互、再 UI”。每次从哪里开始，由任务当前缺少的决定来定。

研究深度由 AI 按主要问题、已有证据、模式成熟度、影响及试错代价逐项判断。每次先明确使用者、情境、任务与已有预期，再选择并真实执行合适的方法；桌面调研、同理心地图、访谈、观察、旅程及三类竞品都保留。已有有效结论可引用，重要未知无法自行解决时，说明影响和推荐，请使用者补充事实、真实材料或作选择；人的决定不冒充用户研究。执行依据见 `methods-routing.md` 的 RT0 和 `methods-research.md` 的 R0.1。

任务范围按 [成果、环节与子任务目录](methods-deliverable-routing.md) 组织。研究、流程、信息架构和交互可以是项目环节，也可以单独委托；图表、图标插画、动效、视频可以独立交付或用于其他成果。常见主成果有产品界面与网站、营销活动、平面传播与物料、品牌系统、设计系统、演示文档与出版、视频与动态图形；它们允许按范围组合，主任务和子任务由本次委托决定。数字传播和印刷物料共用主入口，印刷包装另接生产规格检查。新建、优化、还原、评审等是工作方式，Figma、HTML、PDF 等是载体。已有流程、结构、内容和交互先核对，再复用；“按需”决定研究方法和深度，不允许跳过适用的必要判断。只委托研究、流程、图表、图标等局部成果就到该终点，不补做上级项目。

每个实际环节都写清：要解决的判断、何时调用哪些已有方法、查哪个库及其可用性、形成什么结果和怎样检查。方法与库仍沿用现有文件；共同证据只取一次并引用，不把方法名单或库名当作已经执行。

产品界面与网站已在 [详细流程](workflow-product-interface.md) 展开九个工作环节，按已有状态选择新做、修改、复核或复用；每个环节先用原方法的完成证据自审，再交给下游。工具确认跟随实际制作，必要原型可提前分支，样张选择、完整代表页批准和最终确认分别执行。其他主流程仍保留概览，详细细则待逐条确认。

试跑反馈作用于本轮明确委托的对象：评估/改进 Skill 时，试跑作品是取证载体，反馈用于定位并修订规则；普通成果制作则按授权范围改稿。不能在二者间静默切换。当前已补：CT7 先核对已有风格、参考、偏好与禁区；DS1 展示前检查候选的实际表达差异，物件/颜色变化不足时如实标变体；V3/TY 按文字作用、更新与维护需求区分排版和静态表达字形，字体资源按实际能力核对；DS2/V5 把同一视觉语言落实到文字、标签、控件及适用图标，QA0 查看实际完整组合。具体试跑中的风格偏好不写成所有任务的默认风格。

信息层级继续落实到画面：先说清关键内容分别帮助用户理解什么、主次和关联怎样，再把这些判断变成分组、位置、比例、字体与必要图形，在实际尺寸的真实画面中检查是否看得出来。沿用 U1/U3/V3 的同一记录和 QA0，不为每条信息强配卡片、颜色或装饰；留白和对齐同样可以形成清楚的分组。只改本轮范围，保留原有确认节点。

需要由主视觉带动整页的任务，先理解产品、受众、传达目标、已有偏好并查看参考，由 AI 推导方案并先按 CI 形成当前候选的整体色彩框架；必要输入和工具路线成立后制作主视觉及所需元素、合成校正，自己先审、修改，再让人看图选，不先要求从无图文字方案中选择。确认后提取整页规则，并按 V3/V5/V7 拆分图像、静态表达字形、适用图标/装饰与程序信息再合成，动态内容不靠每天重生整图更新。具体见 DS1/DS2 与 V7；完整代表页和最终确认保留，普通工具、局部和还原任务按本轮范围。

## 独立试跑与方向溯源

- 测试 Skill 的自主判断时，使用不继承本聊天的独立执行者/新会话；给出原始任务、原始输入及当前有效的明确制作要求、否决点和验收标准，注明各自来源，再给待测版本和必要工具/权限边界。剥除旧方案、推荐、预期答案及未要求沿用的历史风格，不以“无前文”删除有效需求；输入文件原有样式仍属原始输入。
- 用用户反馈验证修复时，将反馈转成有来源的本轮要求与可观察验收项，称回归测试；复用既有作品的称连续迭代。二者都可由无聊天上下文的执行者完成，但不能冒称只用初始委托的自主发现。任务交接与成品对照仍沿 CT0 同一记录，不把测试要求写成通用项目默认。
- 原始输入与后来才由测试者查到的产品/品牌资料分别留来源；每个会改变方向的决定注明来自用户、本轮材料、公开参考或 AI 推导。保留关键的“依据 → 判断 → 方向”过程与准确版本，不在成图后补造理由；只向使用者展示有助理解取舍的摘要。
- 输出放独立试跑目录，测试者不读上一轮试跑成果或设计记忆来继承答案；不要把针对该测试任务的现成候选写入通用方法当作独立发现。连续修改已有作品可复用有效上下文，但必须称连续迭代，不能冒称独立测试。
- 不能取得真正无前文的执行上下文时，说明独立性限制，不以口头“忘记前文”代替；分析计划、图像样张、可操作页面和实际用户验证按真实完成范围记录。工具确认、关键业务取舍及制作范围仍照常，不用独立测试绕过权限。

## 设计师先回答六个问题

### 1. 用户真正要改变什么

先分开“目标”和“用户点名的手段”。

目标应说明谁在什么情境下需要取得什么结果；明确制作任务还须有准确对象、版本、范围、正式输入和允许改变的内容。

如果用户只给了手段，先找它服务的用户结果和产品结果；不能确定时标为缺失或假设，不能自行编造。

### 2. 这次最终要交什么

在开始方法前，先把本轮终点说具体：

- 问题诊断；
- 用户与使用语境结论；
- 流程方案；
- 交互规则和异常状态；
- 测试就绪原型；
- Figma UI 方案或正式主稿（包含全部界面视觉）；
- 非界面视觉成品，或用户明确拆分的独立视觉资产委托；
- UI 交互动效规格、Figma 原型预览或正式 UI 交互动效；
- 视频 / 动态图形成品；
- SVG、Lottie、图标或其他格式特定动画；
- 验证结论；
- 按指定来源完成的成品；
- 可交接的设计包。

模糊的改进意愿或产物名称不是合格交付定义。必须明确范围、载体、保真度、允许改变的内容、禁止改变的内容和完成证据。

### 3. 哪些内容已经知道

已知信息按以下维度保留来源和适用范围：

- 上游已经确认的目标用户、核心问题和业务目标；
- 已有研究、行为数据和客服反馈；
- 已冻结的产品范围、流程或方案；
- 当前项目里的共享对象、术语、组件和资产；
- 正式设计系统、Figma 主稿和准确版本；
- 技术、数据、权限、运营和合规约束。

已有有效答案直接复用，不因为进入设计流程就重新问一遍。

### 4. 哪些未知会真正改变设计

不是所有未知都要在本轮解决。只处理“答案不同会让本轮交付明显不同”的问题。

逐项判断未知的影响和责任：

- 会改变问题归属、任务目标或方案方向：先补证或请求必要决定。
- 不影响本轮交付：记录后暂不处理，不扩展范围。
- 涉及共享对象、权限或授权：核对有权决定者，不由设计师代答。
- 缺少会影响准确制作的正式输入：停止依赖部分，不用占位内容冒充完成。

### 5. 这次该从哪种设计工作开始

根据已知和未知，选择真实起点：

- 问题和原因未知：从证据与问题诊断开始。
- 用户、任务或成功标准未知：从用户与语境分析开始。
- 目标已确认但任务路径未知：从流程开始。
- 路径已确认但页面职责、反馈或异常未知：从交互开始。
- 交互规则已确认，但信息、组件、状态或界面视觉未知：在按 TR0 明确确认的制作载体中完成 UI；不要求把 UI 和界面视觉拆成两个必经阶段。
- 界面中的插画、图片、图标和品牌图形在已确认的界面主稿/实现中完成；缺正式输入时先阻断。只有用户明确把某项资产拆成独立视觉委托，才调用视觉工具，确认后可回到 Figma。
- 已确认的 UI 反馈、状态转换或空间关系确实需要运动表达：定义 UI 交互动效规格；Figma 只可做预览，正式成品调用能在目标环境实现和验收的动效工具。
- 最终要交视频或动态图形：从传播目标、脚本、分镜、关键帧、正式素材和输出规格开始，不默认创建 Figma，也不套用 UI 动效方法。
- 最终要交 SVG、Lottie、图标等格式特定动画：从矢量源、图层、行为、格式和运行环境开始；只有其运动表达 UI 反馈、状态转换或空间关系时，才补已定稿 UI、D5 与 UI 动效方法。
- 方案已经存在，只是不知道是否成立：从验证开始。
- 所有决定都已确认，只需要应用批准内容：直接制作。
- 正式主稿已冻结：按主稿还原，不重新设计。

### 6. 做完以后怎样证明

开始前就定义证据，不能画完以后再临时找理由。

证据有三种执行方式：

1. **执行直接产生证据**：按研究或验证方法取得真实材料，保留过程、对象、来源和适用范围。
2. **先做成品，再验收**：按事先定义的程序核对成品、基线、规格及受影响范围。
3. **本轮只准备验证条件**：写清下一责任人、样本、触发条件和测试程序，停在测试就绪，不能声称已经验证。

## 五种接单方式

### 直接制作

适用：修改对象、来源、范围和结果都已明确，没有新的设计取舍，并且任务局部、可逆或已有低风险依据。高风险、影响范围未知或不可逆时，先完成风险评估、授权和相称证据要求；关键输入未知则阻断。

设计师做：

- 核对准确来源和版本；
- 写清允许与禁止改变的内容；
- 执行指定修改；
- 对受影响页面、状态或组件做回归。

设计师不做：

- 为了显得完整而补访谈、竞品或视觉探索；
- 擅自“顺便优化”冻结内容。

### 局部优化

适用：问题位置已经确认，但具体解法尚未确定。

设计师做：

- 定位受影响的流程、交互、UI 或视觉决定；
- 只补这些决定所需的证据；
- 比较修改前后；
- 回归相邻路径、失败状态和共享组件。

设计师不做：

- 因为一个局部问题重新研究整个产品；
- 用静态稿通过冒充行为指标已经提升。

### 问题探索

适用：不知道问题发生在哪里，或者用户、价值、情境和成功标准仍会改变方向。

设计师做：

- 审计现有数据和材料能说明什么、不能说明什么；
- 确定行为群体、任务、情境和当前做法；
- 找到证据支持的问题位置；
- 形成可证伪假设和下一步决定。

设计师不做：

- 先画一个改版，再倒推理由；
- 用竞品、审美偏好或人口标签冒充用户证据。

### 方案验证

适用：已有概念、路径、界面或原型，需要判断它是否成立。

分两种：

- **验证准备**：只把方案做成可测试版本，完成预测试和验证合同；本轮不声称方案有效。
- **验证执行**：冻结版本后取得真实观察证据，再决定继续、修正、重定义或停止。

### 设计还原与交付

适用：正式主稿、规范和目标版本已经确定。

设计师做：

- 核对文件、节点、版本、资产和动态行为；
- 忠实制作；
- 逐项对照布局、字体、颜色、间距、资产、状态和交互；
- 记录覆盖和残留差异。

设计师不做：

- 把还原任务变成个人改版；
- 缺资产时用近似品或占位符降级交付。

## 产品输入怎样变成设计语言

上游信息不能直接跳成 UI 结论。设计师需要做以下翻译。

### 用户信息

不能从年龄、职业或地区直接猜常用产品、能力和审美。

需要进一步得到：

- 用户在当前任务中的角色；
- 任务频率和熟练程度；
- 已经学会的对象、术语、操作和反馈；
- 感知、理解、操作或设备能力；
- 用户怎样判断完成、失败和可信。

### 任务与情境

需要得到：

- 什么事件触发任务；
- 用户现在怎样完成；
- 使用什么设备，是否移动、分心或被打断；
- 有哪些参与者、审批者和交接；
- 失败后怎样恢复；
- 结果什么时候才真正成立。

### 行业与风险

不能凭行业或产品标签直接指定颜色和风格。

需要从真实后果推出：

- 哪些信息必须准确、完整和可追溯；
- 哪些操作需要确认、授权或凭证；
- 哪些错误必须预防、允许撤销或提供申诉；
- 哪些结论需要专业责任人确认；
- 验证深度必须达到什么程度。

### 项目内部连续性

如果任务属于一个大项目，先核对：

- 上下游模块怎样进入和离开；
- 是否共享对象、术语、状态、权限和凭证；
- 现有流程、组件、变量和资产能否复用；
- 本次是直接复用、允许扩展、仅供参考还是必须新建；
- 共享修改会影响哪些页面、角色和端。

### 外部竞品

竞品分三类，不能混成“找几个类似 App”：

1. 行业竞品：看类别门槛、替代方案、行业信任模式和差异机会。
2. 同类操作竞品：看相同操作的步骤、反馈、异常、恢复和适用条件。
3. 服务同类用户的竞品：有真实用户关系证据时，判断目标群体已经学会的语言、信息和操作习惯。

竞品只能提供候选和风险，不能证明目标用户需要什么，也不能替代方案验证。

## 创意概念只探索和记录一次

同一个问题的概念候选、比较与选择只形成一份记录。流程方法从任务中的障碍看怎样改变行为，创意方法按需补充用什么主题或形式组织体验；进入后一个方法时引用已有概念并补充，不重来一套。候选数看实际需要，不因少于三个卡住，也不制造陪选。选定概念以后，流程、信息架构、内容、具体交互和视觉仍分别落实与检查。

## 方法怎样被调用

方法不是按阶段全部执行，而是用来回答具体问题。

- 不知道现有证据够不够：先做证据审计。
- 不知道是谁在什么情境遇到什么问题：形成问题卡，必要时做情境访谈或观察。
- 已有多来源材料但矛盾杂乱：用同理心地图整理“想、说、做、看到”，不能在没有材料时凭空填写。
- 不知道任务怎样走到结果：做范围、场景和主路径。
- 不知道页面职责、反馈和失败恢复：做交互规则、页面职责和异常矩阵。
- 不知道信息如何被找到、理解和操作：做信息分级、主行动、组件、状态和界面文案。
- 不知道正式界面视觉怎样表达已确认内容：继续在 Figma UI 中核对视觉依据，再处理颜色、字体、密度、图像应用和候选方向。
- 界面需要插画、图片、图标或品牌图形：在 Figma UI 中定义并完成；没有正式资产或授权时阻断，不自动扩成另一项视觉任务。
- 不知道界面变化是否需要运动表达：只为已确认的反馈、状态转换和空间关系定义 UI 交互动效；静态已足够时跳过。
- 要交视频或动态图形：使用传播 brief、脚本、分镜、关键帧、品牌与音视频素材、渠道及编码规格组织制作。
- 要交 SVG、Lottie 或图标动画：使用可编辑矢量源、图层/路径、起止或循环行为、格式、运行环境和性能要求组织制作；若运动不表达 UI 反馈、状态转换或空间关系，不调用 UI 动效方法。
- 不知道方案是否成立：准备最小测试载体，选择能直接回答当前判断的验证方法。

## 工具怎样被调用

工具也不是全部执行：

- 流程和问题分析：使用能保留来源和关系的文档、图表工具，不默认创建 Figma。
- 交互：先交规则、状态或最小原型；允许用 Figma 做低保真稿，但必须标明不是正式 UI 主稿。
- UI：按 TR0 推荐并确认工具路线，随后在已定主稿/制作载体内完成页面、组件、状态、响应式、颜色、字体、间距和图像应用。
- 非界面视觉成品，或用户明确拆分的独立视觉资产委托：调用视觉工具。若下游进入 UI，确认后的真实文件才能导入 Figma。
- UI 交互动效：Figma 原型只可作 `FIGMA_MOTION_PREVIEW`；正式成品最终通过写代码实现（CSS / JS / GSAP / 客户端代码），并在目标运行环境测试中断、返回、减弱方案和性能。
- 复杂 3D / 光影 / 流体动态图与宣传视频：先确认首尾关键帧垫图，再调生视频模型或专业视频工具，按场景导出或转码为 `MP4 / WebM / GIF / 动态 WebP`；出现任何产品 UI 画面时引用已定稿 UI，只有画面中的运动表达 UI 反馈、状态转换或空间关系时才补 D5 与 UI 动效规格。
- SVG、Lottie、图标等轻量矢量动画：先从 IconScout 拿现成 Lottie / 动态图标，库里没有再基于专业矢量图标用代码/矢量工具加动画（不手画简陋图形，不调像素级生视频模型）；只有运动表达 UI 反馈、状态转换或空间关系的部分才引用已定稿 UI、D5 和 UI 动效规格。

产出合同包含多项成果时，分别建立工具动作和交接依赖：先定义各项内容职责、尺寸、状态与下游要求，再制作并审核真实文件，导入对应主稿后完成整合验收。中间工具输出不等于整个任务完成。

### 2. 图标 / 3D 道具 / 插画 / Lottie「MCP + API 双通道」调取与高颜值头像/海报生成链路

> **资产选型按用途分组；人物头像另执行其专业一致性判断**：
> - **图标与表达资产**：统一按 V5 的上游依据、必要性、作用、图文权重、尺寸及分组规范检索和取用。页面可有不同表现组，组内优先同一可核验集合和适用变体，缺项按真实覆盖与组合证据处理；风格标签不证明同套系。Lottie 的运动及输出格式另按已有合同，不替代视觉分组。
> - **唯一需要额外把关的是人物头像**：依据本项目的文化与视觉要求判断素材适配性；适配且有授权时复用，不因资源来自通用库就排除。
> - **人物头像（User Avatar）「文化匹配 + 同屏成套判断门」**：
>   1. 先核对有依据的产品文化与视觉要求，且同一界面上的所有头像必须 **100% 同一画风、同一头肩比、同一光影与底色**；
>   2. 先检索素材库并用 `Read` 看图判断：若库里没有符合该文化与视觉要求的头像，或凑不齐同一套系（Same Pack），**立即放弃素材库结果，自动转入「AI 同母体成套生图」**（用完全相同的风格前缀词 + 角色变量一次性生成整套统一头像，严禁强塞违和素材或手画简陋 SVG 人脸）。
> - **真实世界摄影（场景、人物生活、建筑、自然、地点）**：先走 Real Image Library（`scripts/real_image.py` / [methods-image.md](methods-image.md)）。没搜过真图，不得把写实摄影直接交给生图模型。
> - **快捷生成海报 / 主视觉（KV） / 运营 Banner**：先看能不能用 **「干净版式底板 + 清晰矢量排版字 + IconScout 透明底 3D 道具/插画素材直接拼装」** 完成。能快拼的直接拼装出稿（文字 100% 锐利、元素可独立微调、零 AI 乱码假字）；需要全画幅真实场景时先取真图再叠字；只有虚构合成或图库无匹配时，才走整图 AI 生图。

                  ├─► 【方式 1：IconScout 素材快捷拼装模式（默认优先推荐，免整图 AI 生图）】

                  │     若需动效版，直接嵌入 IconScout 同主题 `--asset lottie` 动效元素即可一键导出动态海报！

                        - 2b 仅当图库无匹配或必须虚构时，才走 AI 双垫生图：
                          Step 3：从运营图专用风格表（KV-01..08）挑 2–3 个方向，【搜索直观的美学/材质/光影风格参考图（非竞品业务图）并排展示给用户看】，由用户挑 1 张作为【风格参考垫图（style_ref.png）】；垫法与主色由 Agent 按选中的图直接决定。

### 3. 动效的三条实现链路

```text
需要交付动效
  ├─ 路线 1：【UI 交互动效 & 组件状态过渡】
  │   （按已确认的反馈、状态转换或空间关系定义运动）
  │   └─► 最终落地直接【写代码实现】（CSS / JS / GSAP / Framer Motion / SwiftUI 等）；Figma 连线仅作 FIGMA_MOTION_PREVIEW 预览。
  │
  ├─ 路线 2：【轻量矢量图标 / 真 Lottie (.json) / 动态 SVG】
  │   （按矢量源、图层、行为、触发、尺寸及运行环境定义运动）
  │   └─► 先从 IconScout 拉现成 Lottie / 动态图标（改色、改时长即用），库里没有再基于专业矢量图标用代码/矢量动画工具加动画，不手画简陋图形；保证体积小、边缘清晰、透明背景和可改色；不调用像素级生视频模型。
  │
  └─ 路线 3：【代码写不出的复杂 3D / 光影 / 流体动态图与宣传视频】
      （按传播目标、分镜、主体运动与输出规格定义运动）
      └─► Step 1：已交付的静态图直接作为【首帧静帧垫图】；没有时先生成首帧并自检后直接继续（有明确落幅要求时再加【尾帧垫图】）
          Step 2：Agent 自定镜头与主体运动方式，将【首尾帧垫图 + 运动提示词】喂给生视频模型（如 Seedance / Kling / Veo / Weave 等）
          Step 3：生成视频后按使用场景导出或转码为标准 MP4、循环 WebM、高清 GIF 或动态 WebP
          （技术边界：生视频模型产出像素画面，可转 GIF/WebP/MP4，但不能直接做成真正的矢量 Lottie，严禁用视频序列帧位图冒充轻量矢量 Lottie）。
```

## 交付前最后一步：不只查规范标准，必须同时过「用户可用性 × 审美与品位 × 设计标准」三大验收筛

做完流程、交互、Figma UI、海报或动效后，**绝不能只做机械的“设计标准/像素规范检查”**（因为很多页面即便 8px 网格、字号和对比度全部合规，真人用起来依然别扭费劲，或者视觉上依然呆板、满屏 AI 模板味）。

交付前必须同时过 **三大维度综合验收筛（`QA0`）**；哪一维不及格，就精准退回哪一步重改：

```text
做出设计初稿 / 成品
   │
   ▼
【三大维度综合验收筛（逐维判定 PASS / FAIL）】

  维度一：【用户可用性审查（好不好用、顺不顺、累不累）】
    - 零解释与低认知负荷：新用户 3 秒内能否看懂“这是哪、能干嘛、下一步点哪”？做决定所需信息是否在手边（无需跨页靠脑子记上一页的数字或规则）？
    - 心理模型契合与零黑话：标题、分类和按钮是否是用户日常自然语言（无内部系统黑话）？点击预期与实际结果是否完全一致？
    - 物理顺手度与省力原则：能默认带出或点选的内容是否避免了让用户手动打字或多余跳页？有没有为了视觉对称把不同性质的按钮做成同款、或把不可点标签做成按钮外观导致误触？
    - 情绪安全感与受挫自救：涉及付钱/授权/删除时是否直接给清风险与保障？报错是否保留了用户已填内容并给清人话自救动作？有无打断主任务的弹窗或假倒计时损耗？

  维度二：【审美与视觉品位审查（好不好看、有没有气场与质感、去 AI 廉价感）】
    - 留白气场与正负形呼吸感（「间」与减法美学）：留白是积极引导视线的呼吸空间，还是因为不敢留白而用边框、底色块塞满全屏？删掉外框或装饰块会不会反而更高级（严禁卡片套卡片套娃）？
    - 视觉重心与视线韵律（聚焦层 × 信息层 × 色彩层）：有没有一眼抓人的视觉重心（Hero Focus）？主标题与正文字号反差是否足够有张力？视线滑动是否自然，还是满屏四五个同权重色块在打架？
    - 色彩同频与画面干净度（防“脏、俗、粉、腻”）：底色（60%）、容器色（30%）、强调色（10%）比例是否协调？配图色调、背景灰与按钮色是否处在同一个冷暖/明度纯度频率上（同频法则）？
    - 去 AI 塑料感、视觉锚点与整体完成度：按 QA0 核对装饰是否脱离本轮表达，视觉重心与其他关键区是否共同完成；不以一张精致主图替其余区放行，不将活泼或丰富的目标统一改成克制。缺少所需表达先回 V3/V5 补齐，再判断减法。

  维度三：【设计标准与工程规范审查（准不准、齐不齐、能不能 1:1 落地）】
    - 平面四要素与栅格精度：对比、亲密（组内<组外）、对齐轴、跨页重复是否严密？4/8px 倍数间距与最小可点尺寸（主按钮≥44pt / 标签≥20pt）是否达标？
    - 风格参数字典与字标规范：Hex 色值、圆角、阴影/毛玻璃、字阶是否严格符合所选风格编号的参数包？是否采用原生字重（无描边假加粗）、金额用等宽数字（DIN）、图标按 V5 核对组内属性、光学尺度和来源，组间协调且实际落位清晰？
    - 生图与动效技术合规：海报是否还原了结构草图图文占比且零 AI 乱码假字？UI 动效是否有真实代码？真 Lottie 是否由矢量生成（未拿视频帧伪装）？生视频转出的 MP4/GIF/WebP 循环是否顺滑且文字清晰？
   │
   ├─► 三大维度全部 PASS ──► 允许正式交付或进入真人验证
   │
   └─► 任一维度 FAIL ──► 【按所属维度与病因精准退回对应节点修改，改完重审】
         - 【可用性不过（累/懵/繁琐）】 ──► 退回【流程与交互 D4–D5】砍多余跳页、合并跨页记忆信息、改打字为默认/点选
         - 【可用性不过（误触/黑话/无安全感）】 ──► 退回【交互与文案 D5–D6】换自然语言、拆开不同性质按钮样式、补风险说明与自救出口
         - 【审美不过（满/闷/呆板/套娃）】 ──► 退回【UI 构图与减法 D6–D7】删多余外框与嵌套卡片、用留白（「间」）分层、拉大字号反差重塑唯一焦点
         - 【审美不过（脏/俗/AI 塑料味）】 ──► 退回【视觉风格、真实摄影与生图 D7/V7/IM】核对整体色彩关系、摄影来源与实际素材，清除脱离表达的通用装饰，建立重心并补齐关键区完成度；表达缺项或单薄另按 QA0 回 CT0/U3/V3/V5，不机械做减法
         - 【设计标准不过（规范偏差/不精致）】 ──► 退回【UI/视觉/动效规范收尾 D6–D8】对齐参数字典、统一图标三属性、换等宽数字、补真实动效代码或无字底图重生
```

## 方法被选中后怎样真正执行

每个方法都要形成一张执行记录，而不是只勾选“做过”：

1. 它要回答的唯一问题是什么；
2. 最低输入来自哪里，是事实、推导、假设还是人的决定；
3. 本轮具体分析哪些用户、材料、路径、页面或状态；
4. 过程中观察到了什么，怎样解释，最终选择了什么；
5. 产物是什么，准确版本是什么；
6. 什么条件出现就停止；
7. 产物交给下一个哪个设计决定使用；
8. 前提被推翻时暂停哪些下游，并回到哪里重新路由。

方法产物不自动确认设计有效。产物完成、测试就绪、真实执行与证据支持是不同状态，必须分别记录。

为了防止 AI 把计划冒充结果，每个动作还要标真实状态：

- 只有计划或脚本：尚未执行；
- 对象、样本或材料已准备：测试就绪，但没有外部证据；
- 已真实执行：必须有场次或检查记录；
- 没有结论：不能挑一个方便的答案继续；
- 被阻断：写清缺什么和从哪里恢复；
- 完成：产物、证据和下游交接都已记录。

计划、制作或技术运行成功均不能替代真实研究、验证结论或用户理解证据。
