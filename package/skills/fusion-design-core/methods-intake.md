# 任务分诊

目的：判断这次需要直接制作、局部优化、问题探索、方案验证，还是设计还原/交付；并标出候选决定缺口。最终设计起点由 N4 在产出合同和依赖确定后生成。不要因为输入里出现“页面、UI、提升”就预选方法。

## 产品输入先决条件

先核对同包[产品启动条件](../fusion-product-agent/references/product-start.md)。产品主线负责校准用途、使用者/情境、核心范围与终点；设计不能把自行推导的这些内容写成用户决定。关键意图缺失时回传产品主线，以具体候选和推荐询问；已有有效依据、明确委托或局部任务直接复用。设计自身的分诊与专业研究继续执行，但不替代这个条件。

## 1. 提取任务事实

从用户原话和已有材料中提取：

```
原始诉求：
期望结果：用户最终要拿到什么，而不是 Agent 要画什么
明确交付物：
用户点名的工具、格式或载体：
修改对象与范围：
现有来源：Figma / 截图 / PRD / 数据 /研究 / 既有决定
硬约束：平台、期限、技术、品牌、合规
软偏好：
明确不做：
```

将“加推荐、改首页、做高级感”等标为 `请求的手段`，不要直接改写成问题或价值。用户点名 Figma、图片或视频时保留为输入；N5 仍按最终产物核对工具职责，不能把一个工具扩张成它不负责的交付。
每项同时标明是 `INPUT_FACT / DESIGN_INFERENCE / ASSUMPTION / MISSING / USER_DECISION`；已有上游任务包时保留原来源和状态，不重新编造。

## 2. 判断工作模式

### 直接制作

以下条件全部成立才进入。新的一屏、或要让用户看懂并完成输入的界面，不因为上游需求写得具体就进入本模式。

- 修改对象和范围确切，并且只是替换已批准文案，或在既有组件内改已定内容。
- 有有效来源或规范。
- 这一屏的信息层级、页面职责和输入方式已经设计过，本次不改变它们。
- 上游产品事实不因本次修改而变化。
- 工作局部、可逆或低风险。
- 完成证据明确。
- 任务不要求依据正式设计主稿做逐项一致性还原；这类任务归入“设计还原/交付”。

例：按已确认文案替换按钮、导出既定资产、在既有组件内改已批准内容。

上游给出了完整字段、页面清单或交互说明时，设计仍要判断：这样排用户能否先看懂、这一屏是否只做一件事、输入是否按用户的决定顺序而不是按需求文档顺序。判断结果写进 `design-decisions.md` 第 2 块。业务事实保持原样；不合理的安排回传上游。

### 局部优化

问题位置已知，但具体解法需要设计判断。仍扫描完整 D1–D9；只对受影响决定及其直接上游展开来源与分析。

上游事实（D1–D3）已确认、要设计新的一屏，也进入本模式。PRD 的字段和页面清单不算 D4–D6 已确认，起点通常是 D4–D6。

例：已确认表单流程，仅改善字段分组和错误反馈；按已确认需求设计一个新首页。

### 问题探索

问题、目标用户、使用情境、价值或成功判断中至少一项缺失，并且不同答案会改变设计方向。

例：做一个新产品、提高转化但原因未知、用户为什么不用尚不清楚。

### 方案验证

已有概念、路径或界面；目标是判断是否被理解、能否完成、是否可信或是否值得开发。

- **验证准备**：本轮只准备可测试载体、脚本和延期合同，不取得真人结论。
- **验证执行**：本轮实际取得观察证据并更新被测决定。

### 设计还原/交付

已有主稿或正式规格；目标是高保真实现、版本对照、交付或验收。除非发现源稿内部矛盾，否则不擅自重开设计。

## 3. 翻译设计语境

若任务需要任何设计判断，读取 [methods-context.md](methods-context.md)，按 N0–N3 通过门执行：

1. CT1 后先执行 N1.5，预扫描 D1–D3；需要研究时先调用 R0/R1/R3/R4/R6/R8 中与缺口相符的方法，不为通过 N3 虚构答案。
2. 用 CT2–CT8 只扫描与本轮产出有关的用户能力、既有习惯、使用情境、任务特征、行业风险、信息、品牌和技术现实。
3. 用 CT9 将上游输入写成“输入 → 行为/条件 → 解释 → 设计含义 → 若错影响 → 受影响决定”。
4. 用 BR1–BR2 形成可改变方案选择的设计目标、原则和关键矛盾；研究或输入补齐后必须重新执行这一步。
5. 缺真实行为证据且会改变设计时，按方法条件调用 [methods-research.md](methods-research.md)；不需要时不得为填卡强制访谈。
6. 需要外部样本时，按问题分别调用 [methods-competitive.md](methods-competitive.md) 的行业竞品、同类操作竞品或服务同类用户的竞品；三类结论不得混写。
7. 设计含义没有证据时标 `DESIGN_INFERENCE` 或 `ASSUMPTION`，不得从年龄、行业或审美词直接跳到组件、颜色和风格。

直接制作或严格还原且不涉及新设计判断时可跳过，但要写明复用依据。

## 4. 扫描设计决定链

逐项记录状态、来源和本轮影响：

| ID | 设计决定 | 状态 | 来源 | 若答案不同，会改变本轮产出吗 |
|----|----------|------|------|--------------------------------|
| D1 | 问题与用户价值 | | | 是/否 |
| D2 | 用户与使用情境 | | | 是/否 |
| D3 | 用户/产品结果与成功指标 | | | 是/否 |
| D4 | 任务流程与范围 | | | 是/否 |
| D5 | 页面职责、交互规则、语义反馈与状态 | | | 是/否 |
| D6 | UI 信息层级、组件与文案 | | | 是/否 |
| D7 | UI 界面视觉系统、品牌与资产 | | | 是/否 |
| D8 | UI 动效表达 | | | 是/否 |
| D9 | 验收或验证程序 | | | 是/否 |

状态只能使用：

- `CONFIRMED`：有来源，可复用。
- `FROZEN`：用户明确不重开；记录风险。
- `TEST_INPUT`：当前方案或假设是本轮测试对象；暂时固定以便验证，不代表正确。
- `ASSUMPTION`：已有暂定答案；必须写“若错会怎样”，并标 `RESOLVE_NOW` 或 `ACCEPT_FOR_NOW`。
- `MISSING`：本轮需要解决，且可由设计工作补齐。
- `BLOCKED`：需要外部事实、资产、权限或授权；受影响工作不能继续。
- `N/A`：不适用。

D3 定义“最终希望发生什么结果及怎样计量”；D9 定义“用什么版本、对象、样本、步骤、阈值或对照取得证据”。静态交付检查不能冒充 D3 的用户或产品结果。

## 5. 标记候选起点

从 D1 向 D9 找第一个同时满足以下条件的决定：

1. 状态是 `MISSING`，或是标为 `RESOLVE_NOW` 的 `ASSUMPTION`。
2. 不同答案会实质改变本轮产出。

它是候选起点，不是最终执行起点。N4 必须先确定本轮主终点、目标决定和必要依赖，再在工作集中确认最终设计起点。

`ASSUMPTION/ACCEPT_FOR_NOW` 只进入本轮风险和后续验证，不在同一工作包内循环触发。若最早的必要决定是 `BLOCKED`，停止受影响部分并向对应责任人取输入；不使用下游设计填空。

若没有这样的决定：

- 直接制作或还原任务：候选起点写“无待解决决定”；由 N4 建立制作动作和 D9 验收。
- 局部优化：候选起点为用户点名且上游已确认的受影响决定；N4 再核对依赖。
- 方案验证：先标“验证准备/验证执行”。只把“待验证判断直接对应的决定”标为 `TEST_INPUT`；作为测试载体但不在本轮判断内的决定保留原状态，必要时标 `FROZEN`。不得覆盖已有 `CONFIRMED/FROZEN/N/A`。验证准备的候选起点为 D9 证据准备；验证执行为 D9 核心证据。

不能因为 D1–D3 没写在当前消息里就自动判缺失；先查已有材料和有效确认。

## 6. 风险与追问

该人拍板的问，设计专业判断不问。按 `SKILL.md`「问人规则」用原生提问工具弹出：

- 两种答案会产生不可逆或明显不同的交付。
- 缺失决定会造成大范围返工。
- 用户必须提供权限、正式资产或业务取舍。
- 设计路线未定：有没有 Figma 主稿、在 Figma 做还是本地出页面。
- 第 2 块判断要删掉、后置、合并或移出上游需求项：给出建议做法让人选。
- `SKILL.md`「问人规则」里固定要问的例外：海报挑风格参考图、静态图交付后问要不要动态版、风格探索挑方向、配色探索挑方向、批量改已有产品代码前确认、验收通过后是否把本轮方案入库复用。

产品启动条件成立后，其余普通可逆设计细节可使用 `ASSUMPTION:` 推进，并写最小补证；不能据此自行确定尚未校准的产品目标、目标用户和核心范围，也不能在等待必要答案时制作受影响的正式成品。

## 完成证据

- 工作模式只有一个主模式。
- D1–D9 均有状态和本轮动作；不适用项写 `N/A/SKIP`。`BLOCKED` 必须写所需输入和责任人。局部任务仍扫描完整链，但只要求受影响决定及其直接上游提供详细来源。
- 需要设计判断时，设计语境卡能解释为什么同一个决定在本任务中要这样解决。
- 候选起点由“影响测试”得出，不由关键词得出；最终起点由 N4 工作集确认。
- 已确认或冻结的上游有来源。
- 未解决但不影响本轮的内容没有被强行展开。
