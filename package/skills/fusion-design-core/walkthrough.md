# 方法路由与执行回验

用途：检查本轮方法选择、依赖与证据是否成立，不预填具体任务、方案或示范答案。主流程、状态与方法细则分别以 [framework.md](framework.md)、[methods-routing.md](methods-routing.md) 和 [methods-execution.md](methods-execution.md) 为准；本文件不新增阶段或审批。

## 1. 核对本轮终点

- 明确主成果或独立环节、本轮范围、允许改变的内容、准确输入和完成证据。
- 区分工作方式、专业环节与制作载体，不从页面名称、行业标签或工具名直接决定设计起点。
- 已有有效答案先复用；冻结内容没有授权不得重开；范围外事项不自动进入本轮。

## 2. 回验决定链

- 为 D1–D9 标来源、适用范围、状态及本轮动作。
- 只将会实质改变本轮产出的未知纳入当前决定工作集。
- 从最早受影响且需要本轮解决的决定开始；没有决定缺口时可直接进入已授权制作或证据动作。
- 将事实、推断、假设、用户决定和缺失信息分开，不用人口标签或审美偏好代替行为证据。
- 外部事实、正式输入或权限不足时阻断依赖部分，保留独立工作。

## 3. 回验方法选择与深度

- 每个方法回答一个具体问题，有最低输入、资源可用性、实际步骤、产物、停止信号及下游用途。
- 同时核对决定缺口与语境要求，按证据、后果、成熟度及可逆性选择深度。
- 已满足跳过条件的方法不为形式执行；共同材料和结论引用同一来源，不重复取证。
- 适用专业前置先设计、复核或复用，再进入依赖它的制作；后续发现问题只回查受影响决定。

## 4. 回验制作依赖

- 实际制作前核对 TR0 的有效路线、对象、能力和授权范围；同一路线内不逐操作重问。
- 需要视觉探索时，按 DS1 完成必要推导并制作、自审实际样张，供人看图选择；不以无图文字审批代替实际方向确认。
- 主视觉引领任务从确认主视觉推导 DS2 任务规格；功能底座和资源不能覆盖其表达来源。
- 正式界面按 V7 分离独立控制的素材、标题和程序信息，检查数据更新、单层替换及实际合成；不把整图样张当作可操作界面。
- 多页面按代表页制作、自审、人工确认、扩展、整套自审及最终确认建立依赖；单页省略扩展门禁。
- 子成果分别验收后接回父成果检查，工具成功或局部通过不能代替整体完成。

## 5. 回验证据与状态

- 制作、测试准备、真实执行和证据支持分别记录，状态不能相互替代。
- `POST_ARTIFACT_ACCEPTANCE` 核对成品与已定条件；`CORE_EVIDENCE` 回答待验证判断；`DEFERRED_NEXT_ROUTE` 写明下一责任人、对象、条件和程序。
- 被测决定保留 `TEST_INPUT`，冻结测试对象、版本、脚本、样本条件及成功、失败和无结论信号后才执行。
- 结论仅在实际证据覆盖的人群、情境和版本内有效；支持、推翻、无结论及受阻分别处理。
- 静态规格或技术运行通过不证明用户理解、任务完成或产品指标改善。

## 6. 回验停止与交接

- 达到本轮终点和停止信号后收口，不自动扩成其他专业环节或上级项目。
- 新证据推翻前提时，暂停受影响下游并回到最早决定；冻结内容须由原授权方决定是否重开。
- 交付准确产物版本、来源、实际执行及验收证据、残留差异、假设、未做范围和接续责任。
- 独立评估使用原始输入与无历史上下文，测试产物留在独立位置，不写入通用方法或发布内容。
