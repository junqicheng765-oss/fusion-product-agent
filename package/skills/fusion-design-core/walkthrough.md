# 路由回验

这些样例验证“为什么从这里开始、为什么不做其它方法”。不要抄业务结论。

## 1. 定稿 Figma 页面还原

**请求**：按指定 Frame 还原网页，不改设计。  
**模式**：设计还原/交付。  
**决定链**：D1–D8 `FROZEN`，来源为指定 Frame、设计系统和“不改设计”的范围要求；D9 `MISSING`，需要建立还原验收。  
**最终起点**：制作动作。主稿、版本、资产和可编辑目标写入动作合同；缺任一关键来源则先阻断，不用 V1 重释已冻结的视觉决定。

**工作包**

- 制作动作：严格按主稿和真实资产还原。
- D9 `POST_ARTIFACT_ACCEPTANCE`：逐项视觉对照 + 关键行为动态检查。

**跳过**：研究、流程、交互重设计、视觉候选。原因：本轮目标是忠实还原，上游已冻结。  
**完成证据**：节点/版本、截图对照、动态行为、残留差异。

## 2. 已确认流程，只优化表单

**请求**：注册流程已定，字段看起来乱、错误反馈差。  
**模式**：局部优化。  
**决定链**：D1–D4 `CONFIRMED`；D5 `MISSING`（错误规则未解决）；D6 `MISSING`（字段层级未解决）；D7 `CONFIRMED`（沿用系统）；D8 `N/A`；D9 `MISSING`。  
**起点**：D5。

**工作包**

- I5 主行动反馈：提交、禁用、错误后的行为。
- I6 异常矩阵：校验、网络、重复提交。
- U1/U3/U4/U5/U6：字段层级、分组、组件、状态和文案。
- 收口 2：前后对比 + 注册路径回归。

**跳过**：访谈、完整主路径、视觉方向、动效。原因：用户、目标、流程和品牌不受影响。  
**完成证据**：字段/错误前后对比，正常与失败路径回归。

## 3. 新功能已有有效研究

**请求**：研究已确认用户需要保存半成品，但尚未设计流程。  
**模式**：局部优化（从产品定义进入设计），不是问题探索。  
**决定链**：D1–D3 `CONFIRMED`；D4 `MISSING`；D5–D8 对当前“先定路径”工作包为 `N/A`；D9 `MISSING`，执行前先定义证据计划，路径冻结后运行静态路径验收。  
**起点**：D4。

**工作包**

- F1 范围：本轮保存什么、不保存什么。
- F2 场景：主动保存、被迫中断是否步骤不同。
- F3 主路径：保存、恢复、完成。
- 需要界面时再进入 I3/I5/I6。
- D9 `POST_ARTIFACT_ACCEPTANCE`：执行前定义验收条件，路径冻结后检查场景、恢复点和结束态。

**跳过**：重复访谈、同理心地图、价值主张重写。原因：已有研究直接回答本轮上游决定。  
**完成证据**：路径可走通，恢复点明确，成功判断落到步骤。

## 4. “提升落地页转化”

**请求**：提升落地页注册转化，但没有原因证据。  
**模式**：问题探索。  
**决定链**：只有业务目标“提高注册”已知；D1–D3 `MISSING`；D4–D7 `ASSUMPTION`（现状可作基线，但是否是原因未知）；D8 `N/A`；D9 `MISSING`。  
**起点**：D1，而不是 D6。

**工作包**

- R0：审计流量、点击、滚动、注册和后链路数据能回答什么，不能推断什么。
- R1：限定谁、从什么来源进入、注册后才算什么。
- R3：数据不能解释原因时，找真实阻碍；若材料跨“想/说/做/看到”再用 R5。
- R6：将证据归纳为问题位置。
- R7：只选一条危险假设。

**跳过**：先做 UI、改主 CTA、换视觉。原因：尚不知道问题是否来自流量、价值、证据、流程、UI 或性能。  

若证据随后指向“关键信息存在但扫不到”，新一轮起点才是 D6，并调用 U1/U2/U3。  
若指向“缺可信证据”，起点可能是 D5/D6 的内容和反馈；若指向流量错配，则不进入界面设计。

## 5. 新产品且用户不清楚

**请求**：做一个帮助人管理习惯的 App。  
**模式**：问题探索。  
**决定链**：D1–D9 均 `MISSING`；按最早缺口推进，后续决定不得抢先固化。  
**起点**：D1。

**工作包**

- R1 问题卡。
- R3 访谈或明确标注的最小工作假设。
- R2 行为分群（只有出现至少两类行为证据后才调用）。
- R6 洞察归纳。
- R7 危险假设。

**跳过**：信息架构、首页高保真、视觉风格。原因：不同用户任务会产生不同产品结构。  
**完成证据**：可设计的问题、行为群体、可观察成功和下一待验证判断。

## 6. 已有方案，只需验证

**请求**：可点原型已经做好，想知道是否值得开发。  
**模式**：方案验证。  
**决定链**：D1–D3 `TEST_INPUT`（目标用户、价值和成功行为是本轮待验证判断）；D4–D8 `FROZEN`（仅作为当前测试载体，不代表质量已确认）；D9 `MISSING`。  
**起点**：D9。

**工作包**

- 选验证类型：任务走查、理解、信任或人工交付价值。
- 写测试脚本，给目标不给操作教程。
- 收口 4：记录行为、证实/证伪和明确决策。

**跳过**：重新做研究、流程、UI 和视觉。原因：本轮先验证现有方案；只有证据指出问题归属，才回到对应决定。  
**完成证据**：测试版本、样本、观察记录，决策为继续/修正/重定义/停止。

## 7. 年龄与金融标签怎样翻译

**上游输入**：目标用户 55–70 岁；任务是完成一笔有资金损失风险的金融操作。  
**不能直接得出**：用户常用哪些 App、数字熟练度低、必须做超大字、必须用蓝色或“冷静风格”。

**N0–N3 工作包**

1. CT0：将年龄、金融任务和实际资金风险分别标来源；不把“做得严谨”当产品事实。
2. CT1：判为问题探索；本轮先形成设计任务、风险原则和补证计划，不直接承诺完整 UI。
3. N1.5：D1 `ASSUMPTION/RESOLVE_NOW`、D2 `MISSING/RESOLVE_NOW`、D3 `MISSING/RESOLVE_NOW`；先用 R1 补问题与成功判断，需要真实过程时再用 R3/R4。
4. CT2：补任务角色、领域/数字熟练度、能力、频率、当前做法和判断完成的标准。
5. CMP3：只分析有用户—产品关系证据的“服务同类用户的竞品”；提取已学会的对象、术语、反馈和凭证，再决定 `PRESERVE / ADAPT / TEACH / AVOID`。
6. CT3（若属于现有大项目）：核对内部对象、流程、组件和资产应 `REUSE / EXTEND / REFERENCE_ONLY / NEW`，并定义关联模块回归。
7. CT4：有近期事件材料时重建触发、设备、参与者、中断和恢复；没有时先补 R3/R4，或整条标假设。
8. CT5：由“资金损失、不可逆或结果未知”等具体后果推出信息精度、风险说明、确认、留痕、恢复和 D9 验证要求。
9. CT7：先定义“信息有依据、操作可控、结果可追溯”的感知目标；具体色彩、字体和视觉气质留到 D7。
10. CT8：核对数据来源、更新时间、权限、结果未知和凭证能力，避免界面承诺系统做不到的事。
11. CT9、BR1–BR2：吸收补证结果，形成设计含义、设计任务和可验收原则。

**只有年龄、没有行为证据时**

- CT2/CMP3 相关内容标 `MISSING` 或 `ASSUMPTION`。
- 不生成虚构的“老年用户画像”。
- 若不同熟练度会改变流程，先补最近一次行为证据；若不影响本轮局部制作，写最小补证并继续。

**可成立的原则示例**

- 因为高后果提交会造成实际资金损失，提交前必须同时显示对象、金额、费用、风险和不可逆后果；不得只写“确认”。
- 因为结果可能延迟或未知，提交后必须提供状态、凭证、查询和异常恢复；不得把等待画成失败。
- 只有证据表明目标群体普遍依赖某一既有模式时，才将该模式写成复用原则；年龄本身不是依据。

**完成证据**：每条原则可回溯到任务后果或真实行为证据；没有从用户标签直接跳到 UI/视觉。

## N4 产出与路由回验

### A. 只替换已批准按钮文案

- 主终点：指定制作或精确还原成品。
- 目标决定：无新增决定；D5–D7 `CONFIRMED/REUSE`，批准文案及其版本是 D6 来源。
- 最终设计起点：制作动作，不从 U6 开始。U6 已满足“文案由上游锁定”的跳过条件。
- 决定工作集：空。
- 制作动作：在指定文件、节点和按钮状态应用批准文案；不改含义、行为、组件样式和范围外实例。
- 风险深度：若来源明确、局部可逆且不涉及共享实例，选 `LEAN`；否则按影响面升级。
- D9：`POST_ARTIFACT_ACCEPTANCE`，本轮运行；核对文案与批准来源一致、按钮行为未变、受影响页面回归。
- 停止：指定范围修改并回归通过。

### B. 提升落地页转化但原因未知

- 主终点：设计诊断 + 问题与语境定义；本轮不承诺 UI 改版。
- 目标决定：D1–D3；D4–D7 当前实现只作诊断对象。
- 最终设计起点：D1。
- 决定工作集：R0/R1；现有数据不能解释原因时才进入 R3/R6，再用 R7/R8 收敛。
- 制作动作：空；不能用先改版代替定位问题。
- D9：`CORE_EVIDENCE`，本轮运行；形成一条可证伪主假设、关键行为、反指标和下一验证决定。
- 停止：证据足以定位问题，或发现应返回流量/产品价值而不进入页面设计。

### C. 已确认注册流程，只优化表单

- 主终点：交互规格 + UI 方案。
- 目标决定：D5–D6；D1–D4、D7 `CONFIRMED/REUSE`。
- 最终设计起点：D5。
- 决定工作集：I5/I6 先解决反馈和异常，再用 U1/U3/U4/U5/U6 表达已确认规则。
- D9：`POST_ARTIFACT_ACCEPTANCE`，本轮运行；修改前后问题对照，正常/失败路径和共享组件回归。
- 停止：点名问题解决且未破坏既有流程。

### D. 现有大项目新增一页并沿用设计系统

- 主终点：Figma UI 正式主稿，包含全部界面视觉。
- 目标决定：D6–D7；相关 D4–D5 必须已确认。
- N4 输入：CT3 已判断内部对象、模式、组件和资产为 `REUSE/EXTEND/REFERENCE_ONLY/NEW`；若未完成，先返回 N2 补齐，不把 CT3 假装成 N4 后置检查。
- 最终设计起点：由首个未解决的 D5 或 D6 决定；若 D4–D7 均确认，则从制作动作开始。
- 决定工作集：只对必须新增或扩展的规则调用相应 I/U/V 方法；U/V 都在同一 Figma UI 分支执行，单纯复用项不重做方法。
- 工具合同：Figma 负责正式 UI 及全部界面视觉；只有用户明确增加非界面视觉成品或独立资产委托时才增加视觉工具动作。
- D9：`POST_ARTIFACT_ACCEPTANCE`，本轮运行；覆盖新页、上下游入口、共享组件和受影响模块。
- 风险深度：共享扩展至少按 `FOCUSED`；没有所有者授权时 `BLOCKED`，不得先改后报。
- 停止：页面完成、内部连续性成立、共享影响关闭；不重新探索品牌。

### E. 已有原型，只验证是否可开发

- 主终点：验证结论。
- 目标决定：本轮待测决定标 `TEST_INPUT`，D9 `MISSING/RESOLVE_NOW`。
- 最终设计起点：D9 核心证据动作。
- 决定工作集：空；`TEST_INPUT` 在测试前不重开。
- 证据动作：按待测判断选择 VAL1/VAL2/VAL3/VAL4；只有现有原型不能承载该判断时，才先用 PROTO1 补成最小测试载体。
- D9：该证据项标 `CORE_EVIDENCE`，本轮运行；测试对象、脚本、样本、成功/失败/无结论信号和版本先冻结。
- 停止：决定为继续、修正、重定义或停止，并更新对应 D 状态。

### F. 按正式 Figma Frame 精确还原

- 主终点：指定制作或精确还原成品；次终点为设计交付包。
- 目标决定：无新增决定；D1–D8 `FROZEN/REUSE`，D9 建立还原验收。
- 最终设计起点：制作动作。正式 Frame、版本、资产和可编辑目标未核实时先补动作合同；缺任一关键来源则 `BLOCKED`。
- 决定工作集：空；不得调用视觉探索或用 V1 重新解释已经冻结的视觉决定。
- 制作动作：按指定 Frame 和真实资产还原布局、字、色、间距、状态及关键动态行为；未经授权不得改良或近似替代。
- D9：`POST_ARTIFACT_ACCEPTANCE`，本轮运行；逐项与同一版本对照，并记录残留差异。
- 停止：未经授权差异为零；缺主稿或资产则 `BLOCKED`，不降级交付。

### G. 本轮只交测试就绪原型

- 工作模式：方案验证—验证准备。
- 主终点：测试就绪原型；用户明确未授权或未安排本轮真人验证。
- 目标决定：被表现的决定保持 `TEST_INPUT`，不能因原型完成而转 `CONFIRMED`。
- 最终设计起点：若没有真正的决定缺口，从 D9 证据准备动作开始；只有某项缺失会令原型无法承载判断时，才先从对应 D 开始。
- 决定工作集：默认空；被测决定不重开。
- 证据动作 1：用 PROTO1 只准备回答指定判断所需的最小路径、内容和状态；原型完整性验收标 `POST_ARTIFACT_ACCEPTANCE` 并在本轮运行。
- 证据动作 2：真人任务验证标 `DEFERRED_NEXT_ROUTE`，明确下一责任人、样本条件、触发时间和待验证决定。
- 停止：原型可执行预定脚本，延期验证合同完整；不得宣称方案有效。

## 路由总检

- 页面名不决定从 UI 开始。
- “提升”不自动要求假设树，也不自动要求改版；看决定链缺口。
- 同理心地图只有在需要综合动机与行为材料时才调用。
- 输入充分的执行任务不会被强制研究。
- 发现上游缺口时只回到会改变本轮产出的最早决定。

## N5 方法执行回验

以下只验证“方法怎样实际衔接”，不预先填写业务结论。

### A. 落地页原因未知：诊断工作包

**动作 1：R0 现有证据审计**

- 主问题：现有材料能否定位注册损失发生在哪里；哪些原因不能从数据推出？
- 输入：页面与版本、流量来源、事件定义、曝光—滚动—点击—注册—后链路数据、现有反馈。
- 执行：逐项记录人群、时间、平台、口径和采样；分开行为事实、用户原话、渠道数据、实验结果与内部判断。
- 产物：可支持事实、不可推断原因、冲突、过期项和缺口。
- 停止：材料已足以定位受影响决定，或已明确需要哪一种补证。

**分支**

- 若问题实际来自埋点、性能或流量错配：把证据交回对应上游，不进入 UI。
- 若损失集中但原因未知：进入 R3 或 R4，问题限定为该行为群体、来源和任务。
- 若已有跨来源材料但结论杂乱：进入 R6；只有材料跨“想/说/做/看到”且需要整理矛盾时才插入 R5。
- 若多个未知都可能推翻方向：用 R7 只选择一条主测假设。

**交接**

- R0/R3/R4 的逐条材料先进入 R6，不直接跳成界面改法。
- R6 输出的问题位置、障碍和预期行为进入 R7/R8 或新的 N4 路由。
- 没有证据支持“信息层级是原因”时，不允许提前调用 U1–U3。

### B. 已有有效研究：形成保存与恢复流程

**动作 1：F1 范围**

- 输入：已确认用户任务、成功判断、业务和技术边界。
- 执行：分做、不做、待定；每项“做”都检查去掉后成功是否仍可能。
- 产物：本轮保存对象、明确不保存内容、待定责任人和逾期处理。

**动作 2：F2 场景**

- 只有主动保存、被迫中断、多设备恢复等情境会改变步骤时才拆场景。
- 选一个主场景；次场景只记录不同分叉，不复制整条路径。

**动作 3：F3 主路径**

- 每步填写用户意图、系统响应、下一状态和失败走向。
- 明确保存成功、恢复成功、主动放弃、系统失败和部分完成。
- 把“用户知道已保存且能继续”绑定到具体步骤，不能只写“流程结束”。

**交接**

- 路径冻结后，I1–I3 才能决定步骤怎样落到页面和每页职责。
- 只交流程时，执行路径完整性验收；不因为没有 UI 稿而判未完成。
- 若技术事实无法支持恢复承诺，暂停对应步骤，回到 CT8/N4，而不是在界面上虚构成功。

### C. 已确认注册路径：修复表单反馈和 UI

**动作 1：I5 主行动反馈**

- 主问题：提交何时可用，提交后即时、成功和失败分别发生什么？
- 产物：可用/禁用条件、禁用原因、0–2 秒反馈、成功/失败去向及撤销规则。

**动作 2：I6 异常矩阵**

- 覆盖校验、网络、重复提交、冲突、权限和部分成功中实际适用的项。
- 每项写触发、可见文案、用户出口、是否阻断和对应路径步骤。
- 失败必须保留可恢复内容，并防止重复提交。

**动作 3：U1/U3/U4/U5/U6**

- U1 只对职责内信息分 L1–L4。
- U3 用对比、亲密、对齐和重复表达该层级。
- U4 根据输入、选择数量、数据量和后果选组件，优先复用现有系统。
- U5 将 I5/I6 已定义的状态画完整，不重新发明失败规则。
- U6 使用对象词表和真实状态写标题、标签、按钮、帮助和错误。

**交接与验收**

- I5/I6 先于 U5/U6；文案和状态不得替交互规则做决定。
- 冻结方案后对比修改前后，走正常提交与关键失败，并回归共享组件和相邻路径。
- 静态回归通过只能证明局部问题按规格解决，不能自动证明注册率提高。

### D. 现有项目新增页面：UI 与视觉工作包

**前置**

- CT3 已给出对象、术语、组件和资产的 `REUSE/EXTEND/REFERENCE_ONLY/NEW`。
- D4–D5 已确认；未确认时先回对应决定。

**决定动作**

- 用 U1/U2 确认页面内信息和主行动层级。
- 只对没有现成适用组件的内容调用 U4；复用项直接引用组件和版本。
- 用 U5/U6 完成真实状态和文案。
- 在同一 Figma UI 主稿中用 V1 锁定设计系统、主稿、品牌材料和允许探索范围。
- 只对实际界面视觉缺口调用 V2–V5；有既定基线时不调用 V6。
- V5 发现界面资产缺失时先阻断或请求正式输入，不自动扩张任务；只有产出合同明确包含独立视觉资产时，才建立视觉工具动作并在确认后导入 Figma。

**共享影响**

- `EXTEND/NEW` 进入共享或全局范围时必须有所有者授权。
- 多处使用的组件不能由不同页面动作并行形成冲突版本。

**验收**

- 冻结新页版本后，检查上下游入口、对象与术语连续性、权限、共享组件、受影响模块和真实内容极值。
- 页面本身好看但破坏其他模块，不通过。

### E. 按批准文案修改或按 Figma 还原

**决定工作集为空**

- 不创建 U6、V1 或视觉探索执行卡。
- 建立制作动作：正式来源与版本、目标节点、允许/禁止、回滚和成品。

**执行**

- 只应用批准来源。
- 若发现来源冲突、缺资产或必须新增判断，暂停对应部分并回 N4。
- 冻结成品后执行 `POST_ARTIFACT_ACCEPTANCE`。

**停止**

- 文案任务：指定范围一致、行为未变、受影响实例回归通过。
- 还原任务：布局、字、色、间距、资产、状态和关键动态行为的未经授权差异为零。

### F. 已有原型：验证准备与执行

**验证准备**

- PROTO1 只补足待验证判断需要的内容、路径、关键失败、返回和结束态。
- 预测试记录断链、主持人解释和不真实内容；修复后冻结版本。
- 原型完整性用 `POST_ARTIFACT_ACCEPTANCE` 收口。
- 正式测试写 `DEFERRED_NEXT_ROUTE`，被测决定保持 `TEST_INPUT`。

**验证执行**

- 已有同版本且预测试通过的载体时跳过 PROTO1。
- 根据主问题只选一种主验证：概念理解、任务走查、内容与信任或人工价值交付。
- 冻结对象、脚本、样本条件和成功/失败/无结论信号后运行 `CORE_EVIDENCE`。
- 结果支持才在适用范围内确认；证伪则回最早受影响决定；无结论不得选方便的解释。

### G. 只交低保真交互原型

- 主终点：交互规格 + 最小可操作原型；本轮不交正式 UI。
- 决定工作集：只解决 D5 页面职责、反馈、状态和异常。
- 工具合同：允许用 Figma 承载，但页面和版本标 `LOW_FIDELITY_INTERACTION`，与正式 UI 主稿分区。
- 执行：只表达结构、真实文案、行动和状态；不建立未经确认的正式颜色、字体、间距和品牌资产。
- 验收：原型能承载预定走查；不能因“在 Figma 里”就称 UI 已完成。

### H. Figma UI + 独立插画委托 + 正式 UI 交互动效

这不是所有 UI 都要经过的固定链，只在 UI、独立插画和正式 UI 交互动效三项产物都被合同要求时成立。

1. 产出合同明确将插画列为独立视觉成品，而不是因 UI 缺资产自动扩张范围。
2. 在 Figma 中完成 D6、可复用的 D7 规则，并确定插画内容职责、尺寸、比例和状态。
3. 建立视觉工具动作生产插画；完成内容、风格、格式和授权验收后，导入准确文件。
4. 在 Figma 中完成全部界面视觉、布局、状态和响应式，冻结 UI 主稿。
5. M1–M3 根据冻结主稿形成动效规格；需要时用 Figma 原型标 `FIGMA_MOTION_PREVIEW` 做评审或预测试。
6. 建立动效工具动作产出正式格式或运行实现，并执行动态、性能、中断和 reduced motion 验收。

完成边界：

- 插画工具输出不等于 UI 完成；必须回到 Figma 应用和验收。
- Figma 原型能播放不等于正式 UI 交互动效完成。
- 只有 Figma UI 节点、独立插画版本和正式 UI 交互动效成品各自通过，整体多工具交付才完成。

### I. 只做非界面视觉成品（如独立运营海报 / KV）

- 主终点：例如活动海报、运营图、KV、品牌图形或独立插画，不包含 UI。
- 执行链路（`V7 路径 B`）：先判断图文角色与占比（画面主导 / 标题主导 / 图文均衡） → 先画出含 L1–L4 信息层级的版面结构草图（`layout_sketch`） → 能快拼则 IconScout 快拼；全画幅真实场景先 `real_image.py` 取真图叠字；只有无匹配或必须虚构时，才从 `KV-01`～`KV-08` 搜风格垫图并双垫生图。
- 跳过：流程、交互、Figma UI 和动效均不自动调用。
- 验收：图文主次、版面结构、视觉依据、尺寸格式、真实资产、授权和源文件满足合同；不要求为了流程完整创建 Figma 页面。

### J. 只做复杂 3D / 光影动态图或宣传视频

- 主终点：例如宣传片、TVC、片头，或代码写不出的 3D 礼盒旋转、流体光影等运营动态图，不包含 UI 设计。
- 决定工作集：传播或视觉目标、受众、场景、核心信息、首尾关键帧静帧垫图、脚本/分镜、镜头与主体运动方式、声音/字幕和输出规格中会改变成品的缺口。
- 工具合同：先确认首帧（及必要尾帧）静帧垫图，再调用生视频模型（Seedance / Kling / Veo / Weave 等）或专业视频合成工具，按需导出或转码为 `MP4 / WebM / GIF / 动态 WebP`（不得把像素视频序列帧伪装成矢量 Lottie）。
- 跳过：不为了流程完整创建 Figma，也不默认调用 D5、D8 或 M1–M3。
- 例外：视频出现任何产品 UI 画面时，都为该片段引用已定稿 UI；只有画面中的运动表达 UI 反馈、状态转换或空间关系时，才再补对应 D5 与 M1–M3。
- 验收：准确视频或动态图版本、合同要求的源工程、素材与授权记录，以及画面、声音、字幕、编码、分辨率、帧率和体积均通过。

### K. 只做 SVG / Lottie / 图标动画

- 主终点：指定格式的轻量可运行矢量动画（动态 `SVG` 或标准矢量 `Lottie .json`）和合同要求的可编辑源文件。
- 默认输入：准确可编辑矢量源、图层/路径命名、动画对象、起止或循环行为、触发、尺寸、颜色、格式、运行环境、兼容、性能和文件大小要求。
- 独立装饰或非 UI 动画：先从 IconScout 取现成 Lottie / 动态图标，库里没有再基于专业矢量图标用代码/矢量动画工具加动画（不手画简陋图形，不调像素级生视频模型）；跳过 Figma UI、D5、D8 和 M1–M3。
- 运动表达 UI 反馈、状态转换或空间关系：引用已定稿 UI、已确认 D5 语义/触发/空间规则和对应 M1–M3；不能由动画自行定义成功、失败、恢复或导航关系。
- 验收：在真实运行环境检查触发、循环/结束、兼容、性能、文件大小和视觉一致性；只有运动表达 UI 反馈、状态转换或空间关系时，才检查与 Figma UI、D5 和 M1–M3 的一致性。
