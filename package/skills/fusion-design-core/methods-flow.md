# 流程方法库

只执行工作包点名的方法。局部优化可以只改受影响步骤，不重写完整流程。

## F1 范围表

**触发问题**：本轮必须做什么、明确不做什么？  
**最低输入**：任务目标或明确交付范围。  
**跳过**：直接制作且范围已在正式任务中冻结。新的一屏不跳过：PRD 字段清单不是范围表，仍要分出这一屏做 / 不做。

**步骤**

1. 分成做 / 不做 / 待定。
2. “做”中的每项都问：去掉后成功是否仍可能；若是，移出。
3. 待定写负责人、最迟决定时间、逾期默认。
4. 一条主路径只服务一个主场景。

**产出**：三列范围表。  
**完成证据**：不做不为空；待定有处理规则。  
**不得替代**：产品负责人对业务范围的正式决定。

## F2 场景卡

**触发问题**：哪些使用情境会让任务步骤发生变化？  
**最低输入**：用户目标、触发或现有路径。  
**跳过**：单一情境且差异不会改变步骤。

**步骤**

1. 写触发、时长、设备、参与者、约束、成功、失败代价。
2. 只有步骤会变化才新建场景。
3. 选一个主场景；次场景最多两个，只写分叉。

**产出**

```
场景 ID / 触发 / 目标 / 约束 / 成功 / 失败代价
与主场景的步骤差异：
```

**完成证据**：每个次场景能指出不同步骤。  
**不得替代**：用人口属性伪造场景。

## F3 主路径

**触发问题**：用户如何从触发走到可观察结果？  
**最低输入**：用户目标、一个场景、关键约束。  
**跳过**：现有路径已确认，本轮不改变顺序或范围；局部任务只画受影响段。

**步骤**

1. 先写用户目标、场景、约束。
2. 一步只写一个用户意图，不写单次点击。
3. 每步写用户行为、系统响应、下一状态、失败走向。
4. 将成功判断绑定到某一步。
5. 定义成功、主动放弃、系统失败；必要时加部分完成。
6. 分支超过 3 条时移入后续范围或拆场景。

**格式**

```
S#：【用户行为】→【系统响应】→【下一状态】
失败时：
```

**产出**：主路径、分支、结束态。  
**完成证据**：未参与项目的人能按文档走通；能说清比现状少了哪一步或不确定。  
**不得替代**：菜单树、页面清单。

## F4 干预点与概念

**触发问题**：路径的哪个位置需要怎样的设计干预？  
**最低输入**：主路径和一个待解决障碍或假设。  
**跳过**：直接还原既有设计，或干预点已确认。

**步骤**

1. 将问题写成：`如何在 S# 把【当前行为或不确定性】改变为【目标变化】？`
2. 至少提出三类作用机制不同的候选；只换文案、位置或视觉表现不算不同机制。
3. 对每个候选记录：要改变的行为或不确定性、作用机制、与其他候选的机制差异。
4. 先用安全、合规、基本可访问性、冻结约束和已确认设计原则做硬门槛；逐项记录通过或淘汰及理由。通过者不足三类时补充候选，仍不足则记录阻断，不拿淘汰项充当备选。
5. 对通过门槛的候选预先确定唯一主排序标准：最能回答假设、价值最高或本轮最可验证；不得临时混用多个标准改写结果。
6. 按同一主标准选一个主概念，保留两个备选；分别写预期可观察行为和会证伪该机制的信号。

**产出**：干预点、当前与目标变化、至少三类机制候选、机制差异、硬门槛结果、唯一主排序标准、主概念与备选、预期行为与证伪信号。  
**完成证据**：每个候选都与具体 S#、障碍、机制、行为和证伪信号相连，选择可由同一标准复算。  
**不得替代**：没有证据的功能清单。

## F5 实现深度

**触发问题**：本轮做到什么程度才足以回答问题？  
**最低输入**：主路径或干预概念。  
**跳过**：任务是按冻结范围直接制作。

**步骤**

1. 列出会影响本轮判断的路径步骤、场景和状态；不适用项写理由。
2. 建立 `路径步骤 / 场景 / 状态 × 不做 / 做轻 / 做满` 覆盖矩阵；每格写覆盖、保留现状或明确排除。
3. 对三档分别记录成本、风险、能取得与不能取得的证据：
   - 不做：保留现状及其代价、风险和证据缺口。
   - 做轻：只覆盖足以触发成功或回答假设的步骤、场景和状态。
   - 做满：覆盖回答问题所需的关键次场景、状态及必要的自动化或角色差异。
4. 选择足以回答问题的最低档；默认推荐做轻，但矩阵显示无法取证或风险不可接受时不得推荐。
5. 写从当前档升级所需的可观察证据、来源或阈值，以及触发后新增的覆盖；日期、资源余量或“以后再说”不算升级证据。

**产出**：三档覆盖矩阵、各档成本 / 风险 / 可得与缺失证据、推荐档及升级证据。  
**完成证据**：推荐档能回溯每个纳入或排除项；升级由证据触发，不由偏好或日期触发。  
**不得替代**：正式排期和资源承诺。

## 流程评审

工作包含任何 F 方法时，至少检查：

1. 谁的哪件事？
2. 比现状少了哪一步或不确定？
3. 失败发生在哪，往哪走？
4. 成功在哪一步可见？

答成“整体更好”不通过。
