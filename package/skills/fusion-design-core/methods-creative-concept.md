# 任务性质与创意概念补充方法

本方法嵌入现有接单、研究、竞品、流程、交互、视觉与终审，不新建阶段编号，不替代 D1–D9，不减少原有门禁、用户确认、调库、资产记录或验证。识别在接单时完成；概念在语境与参考研究后、风格预设和组件拼装前推导，与流程/交互相互校验。若概念影响已确认业务规则或超出授权范围，按原流程回传，不擅自修改。

## CC1 先识别设计任务，不用交付格式替代判断

**触发**：本轮涉及页面职责、体验或视觉的设计判断，包括用户只说“优化一下”的存量任务。
**跳过**：仅替换已批准内容、严格按正式主稿还原且没有新设计判断；记录依据即可。

结合原始诉求、页面内容和进入情境，写明：

- 主导目标与辅助目标：完成工具操作 / 阅读内容 / 营销参与与转化 / 品牌表达 / 游戏参与等，可混合，不按 B/C 端或 HTML/Figma 格式直接推断。
- 用户进入前知道什么、因为什么进入；首次进入、参与后、再次进入分别要做什么。
- 本轮期望行为，以及支撑行为所需的情绪或判断：理解、信任、期待、探索、收集、成就等，必须解释与目标的关系。
- 现状哪些是已批准约束，哪些只是待优化实现。分别记录业务规则、品牌系统、页面结构、视觉样式的来源与确认状态。

已有 HTML、截图、Demo 或组件不自动等于已批准设计系统。“优化”也不自动等于只改 CSS。反之，若用户明确限定只改间距或必须沿用现有结构，就在该边界内执行，不借创意扩大范围。关键信息无法取得时标假设；不同答案会实质改变方案时按原流程澄清。

## CC2 共用概念探索：按问题组织同一套候选

**何时使用**：本轮需要比较行为干预原理，或需要一个组织主题、内容与体验的核心想法时。F4 从具体路径障碍进入；营销、品牌、游戏参与或明确创新任务从 CC1 的目标与语境进入。已确认概念复核后有效则引用，普通工具/表单没有概念缺口时不强制包装。

**共用范围**：F4 与 CC2 共用候选 ID、问题/来源依据、筛选比较及推荐/选择记录，写入现有 `design-decisions.md`，不新增第二套概念账本或固定审批轮次。先进入的方法建立记录，后进入的方法在同一候选补充其负责的部分；一个方法已回答的问题不换名再做一次。

**概念如何推导**

1. 明确本轮想改变的结果和主要问题，区分业务事实、设计推断与假设。行为问题对应 F4 的路径/障碍；纯传播任务对应读者要理解的信息，不强造交互流程和 S#。
2. 结合已有研究和参考，提出有实质差异、能够响应同一目标的候选。数量按问题开放度、约束、证据与新增方案是否仍会改变选择决定；不固定两到三个，也不因不足三个阻断。已有明确适用概念可以只展开该方向；只有一个可行候选时给出充分理由及未解决的风险，不制造陪选。
3. 在同一记录中按任务适用性填写，不要求所有任务写满每一栏：

```text
概念 ID / 版本 / 对应任务：
待解决问题、目标与来源（事实/推断/假设分开）：
一句话核心想法：用什么原理或形式组织本次体验/信息
行为干预部分（F4，适用时）：对应 S#、障碍、目标变化、作用机制、预期行为与证伪信号
主题与组织部分（适用时）：主题怎样组织内容和体验、为什么有助理解/参与；画面承载该想法的初步思路
真实规则与授权边界：不改变什么；建议改变的业务/范围由谁决定
可行性与关键未知：真实内容/能力能否支持，什么结果会推翻当前判断
比较与选择：候选实质差异、约束筛选、收益与代价、推荐及必要备选、选择依据与来源
后续承接：流程、信息架构、内容、交互、视觉各自需要落实/复核什么
```

4. 先按真实规则和硬约束筛选，再依本轮目标比较可行方案。不能用多写方案、换配色或套一个物件造型冒充机制差异；主题概念也不必每次改变业务机制。必要判断尚无证据时保留假设，按 RT0 采取有效补证；可行性或关键事实才决定是否阻断，候选个数不决定。
5. 将推导、推荐和依据写入已有记录，不设必经文字概念审批。适用 DS1「主视觉引领分支」时，由 AI 筛选可成图的方案，在必要输入与 TR0 路线成立后制作实际主视觉、自审并供人看图选择；只委托文字咨询则在其范围结束。关键事实、业务/范围取舍仍按原规则确认，AI 推导不等于人已选方向或代表页已批准；不另建候选账本。

**后续设计仍分开**：核心想法提供设计方向，不把流程、信息架构、内容表达、具体交互和视觉设计合并为一个步骤。F4 落实行为作用，流程检查任务链路，架构检查分类与页面职责，内容检查主次与表达，交互检查控件/状态/反馈，视觉检查画面与细节；每项按原类型路径设计、复核和验收。后续发现概念不成立时回到同一概念记录修订受影响部分，不靠装饰掩盖问题。

**完成证据**：同一问题的概念记录可追溯且无重复候选集，适用部分有来源与选择理由、剩余未知和下游要求；未适用部分说明原因。只写一句口号或选定一种配色不算概念推导完成。

## CC3 营销活动的专项推导

**先形成活动的传播与参与思路，再制作主题资产。** 在同一 CC2 记录中明确本轮进入情境、核心主张、使其可信或有吸引力的内容依据、希望用户采取的行动及参与感受；区分首次邀请、参与过程与回访任务，不能因含日历、余额或任务列表就默认按效率工具组织全页。由这一思路共同决定标题怎样表达、主体图形承载什么、核心参与区怎样组织，以及行动点如何承接，指出它们之间的具体关系。只有题材、风格名或一组主题物件，还不足以成为活动概念；素材选择不能代替这次决定。

感染力的具体形式由品牌、受众、活动目标与有效反馈决定，不能一律热闹，也不能默认克制。人已明确要求的活泼、丰富或其他感受须落实为可观察的图文关系、节奏和参与表达，不能被“容易扫读”“统一风格”覆盖；需要的信息仍清楚、真实。文字内容按 U1/U6 判断质量及角色，必要改写走既有具体批准，不将保留原稿当作完成文案设计。

按适用项回答，不把下列项变成每页必须堆出的模块：

1. **看懂并愿意参与**：活动是什么、为何与我有关、真实利益和参与条件是什么，首屏怎样承接流量入口的承诺？顶图/KV 的作用是表达主题与吸引参与，目的地照片不自动等于活动主视觉；也不强制所有活动都用大图。
2. **参与动作有含义**：核心动作如何表达活动主题，而不仅是按钮换皮？行动区的文案、图形与控件如何一起让用户预判下一步，利益和条件怎样在就近位置支持决定？不把品牌、技术、动作和奖励并排罗列当成行动表达；实际点击与后续结果须按 U6 逐步核对。
3. **完成有反馈**：真实结果、进度、获得物或内容如何呈现，是否形成可感知的积累？
4. **回来有理由**：只有业务确实提供分日内容、进度或后续价值时，才设计期待与揭晓。不伪造奖励、随机机制、稀缺性、倒计时或内容。
5. **创意不妨碍使用**：规则、资格、有效期、失败和退出清楚可达；低性能设备、触控、键盘与减少动效偏好均有可操作方案。复杂度由目标决定，不以动画多或装饰多判断创意。

推导须从本任务的目标、进入情境、内容供给和真实规则出发，说明所选原理怎样组织内容及行为、为什么可行，哪些条件会使它失效。跨媒介只迁移适用原理，不照搬物件造型；没有持续内容、奖励或随机机制的依据，不以装饰制造这些承诺。不能直接复用某次试跑的具体候选充当本轮独立发现。

## CC4 参考与实现怎样支撑概念

保留 CMP1/2/3。按要解决的问题另附表达或机制参考，注明不属于用户研究或竞品行为证据：

- 页面职责、操作、状态：真实活动页面与实机链路。
- 主题、构图、图文关系：运营主视觉、海报、编辑设计等。
- 开启、揭晓、收集或空间关系：实体包装、倒数日历、装置等跨媒介样本。

检索与取得统一沿 [RR 视觉分支](methods-resource-routing.md)：先从同题材、主体及实际活动找图，再按需要扩展目标市场成熟产品/平台、相关品牌近期活动与设计社区，不仅从泛材质词开始。每条写“实际看过的原作/准确版本及日期依据 → 可观察特征 → 可迁移原理 → 本项目如何转化 → 不可照搬部分”，支持当前候选及真实图像输入。同一图片可兼任题材、方向和工艺等用途，分别说明，不把资料分开后失去设计影响。宣传图不能证明交互可用或转化有效；参考独特资产不能直接复制。原流程要求的真实界面样本仍须完成，不用海报替代。

技术载体与设计性质分别决定：HTML 活动页可以同时包含运营 KV、可交互参与区和标准功能组件。按原工具合同为各部分确定真实文件、依赖、用途与验收；界面主体按原 UI 路线，图片资产按原素材/生图规则，实际交互和动效用代码实现，所需 Figma 交付仍按原路线。不得整屏位图冒充互动界面，也不把主视觉缩成无关配图。

主视觉承担页面核心表达时，具体先后和确认按 [DS1](methods-style-engine.md)「主视觉引领分支」：上述语境、研究与概念记录直接提供文字方案依据，主视觉确认后由 DS2 推导整页规格，不先让通用预设决定画面，再给结果补一个概念名称。

组件、风格预设和素材库要求照常执行；库内通用配方负责适合它的功能部分，不应强迫创意主体变成通用卡片。现有规范确有冲突时按原流程解决，不能以创意为由跳过调库、确认或资产标准。

## CC5 记录、终审与回炉

将 CC1 结论、触发/跳过理由、候选比较与选定依据、关键状态和资产计划写入现有 `design-decisions.md` 第 2–4 块，不另建重复账本。将下列适用项加入原 QA0 维度一与二：

- 行为目标、主题与利益在成品中是否可指认，首次与再次进入是否成立？
- 选定概念是否贯穿主视觉、核心操作与完成反馈，而非只写在说明文档或贴一张装饰图？
- 和改前相比，哪些具体变化解决了原问题？若只改变颜色、投影、圆角，是否足以满足用户授权的目标？
- 移除文案和 Logo 后，是否仍能指出与本任务有关的组织与表达特征？这是辅助诊断，不要求所有工具页都独特或游戏化。
- 规则是否真实、操作是否清楚，动效关闭和异常状态是否仍可完成？

每项引用准确成品版本、截图区域或操作状态，按原规则判“过/不过/不适用及理由”，不自造创意分数。不适用项只用于本补充检查，不改变原 QA0 的判定规则。缺少适配目标的概念回 CC1–CC2；概念只停留在口号回 CC2–CC4；操作受阻回原交互阶段；材质、构图或资产实现不足回原视觉阶段。修复后按原 QA0 重审。静态审查只能说明设计判断和实现情况，未做真实用户测试或实验时不得宣称更高参与率、留存或转化。
