# UI 动效方法库

静态状态足以表达时跳过动效。D5 先定义反馈含义、状态、行为、入口和返回规则，D8 只决定是否以及怎样用运动表达；动效不能发明新的反馈语义、导航层级或结果，也不能补救缺失的反馈内容、错误的信息架构或未定义的异常，更不能证明用户价值。

本文件的 M1–M3 处理 UI 反馈、状态转换和空间关系，产生决定与实现规格；`MI` 负责所有要写成代码的动效（含品牌表现动效）从组件库检索源码并集成。Figma 原型只允许作为 `FIGMA_MOTION_PREVIEW` 用于沟通或预测试，不能作为正式动效成品。

### 动效的三条实现链路（按 [methods-tool-routing.md](methods-tool-routing.md) `TR5` 分流）

1. **路线 1｜UI 交互动效与组件状态过渡（`TR5-A`）**：按钮反馈、弹窗/抽屉展开、页面层级转场、列表增删与手势滑动等，按本文件产出 M1–M3 规格，再按 `MI` 先去 React Bits、Aceternity UI、Motion Primitives、Uiverse、21st.dev 找现成源码，合适就审过后拿来改；没有再用项目已有引擎或 Motion / Anime.js 写。**最终交付的是项目里真实运行的代码**，确保与真实组件、实时输入和打断恢复绑定。首屏、背景、文字特效这类品牌表现动效同样走 `MI`。
2. **路线 2｜轻量矢量图标 / 真 Lottie (.json) / 动态 SVG（`TR5-C`）**：导航图标切换、完成打勾、点赞爆花、加载指示器等，**先通过 IconScout 双通道（优先调用官方 MCP `https://mcp.iconscout.com/mcp` 直接下载 `Lottie JSON`，未安装时回退调用内置 `scripts/iconscout.py search -a lottie` API 脚本，`Client-ID: 232598791050530`）检索现成 Lottie 动画及调用 `/v3/convert/`（`svg-to-lottie`、`lottie-to-gif`、`lottie-to-webp`）；库里没有合适的，再基于专业矢量图标用代码/矢量动画工具加动画，不临时手画简陋图形**，不调用像素级生视频模型；仅当其运动表达 UI 反馈、状态转换或空间关系时才调用本文件的 M1–M3。
3. **路线 3｜复杂 3D / 光影 / 流体动态图与宣传视频（`TR5-B`）**：代码写不出的 3D 礼盒旋转开箱、AI 能量球流体变形、液态玻璃折射流动、运营动态海报或 TVC 短片，**走「首帧（及必要尾帧）静帧垫图 → 调生视频模型 → 转码导出 `MP4` / `WebM` / `GIF` / `动态 WebP`」**。生视频模型产出的是像素视频流，可转 GIF/WebP/MP4，但**不能直接生成真正的矢量 `Lottie (.json)`**（严禁将视频拆成序列帧位图塞进 Lottie 冒充矢量动画）。该路线不套用本文件，除非其中某段运动表达 UI 反馈、状态转换或空间关系。

每个候选动效都先回答：

1. D5 已经定义了什么含义，来源和状态是什么？
2. 静态文案、图标、控件状态或页面结构是否已经足够？
3. 运动是否能减少状态、上下文或空间关系的误解？
4. 完整动效和 reduced motion 是否表达同一个含义并允许完成同一任务？

第 2 项为“是”时，记录 `SKIPPED`、静态表达和跳过依据，不继续制作动效。D5 输入可由本轮设计解决时标 `MISSING/RESOLVE_NOW`；必须等待外部事实或授权时标 `BLOCKED/WAIT_EXTERNAL`。不同答案会改变动效时停止受影响规格，不得由 D8 补空。

## 动效入口门

任一 M1–M3 方法开始前，必须同时具备下面三项。品牌表现动效（首屏、背景、文字特效）不走 M1–M3，只需要第 1 项「已定稿 UI」和 `MI` 里的品牌表现动效合同，不需要 D5 输入。

1. **已定稿 UI**：Figma 节点及版本，或（Figma 未连接/做 HTML Demo 时）HTML/代码页面文件及版本，以及会运动的对象、组件状态和起止画面的稳定标识。用户已认可的稿，或 Agent 本轮产出并通过 `QA0` 自检的稿，都算已定稿，不需要另等用户批准。低保真交互稿或只有截图不能替代。
2. **已确认 D5 输入**：反馈含义、状态、行为、入口、返回、异常和恢复规则中与本次动效有关的部分。
3. 以下动效依据之一：
   - **正式基线**：可追溯的动效 token、平台规范、设计系统、主稿或既有实现及准确版本。
   - **探索授权**：用户委托做设计或动效即默认授权 Agent 在目标平台规范与设计系统范围内探索运动变量；写清探索的对象和变量、不能改变的 D5 含义、数值依据、目标环境和动态验证方式即可。只有用户明确要求“只按既有规范、不许改值”时才没有探索授权。

已定稿 UI 缺失时先完成 UI；D5 输入可由本轮设计补齐时先补齐，只有必须由外部事实或授权解决时才在 N4 将 D8 标为 `BLOCKED/WAIT_EXTERNAL`。探索授权只允许探索运动变量，不能绕过 UI 来源或让动效自行补交互规则。

探索时可以直接给出带实际数值的实现值，但每个数值都必须说明依据，例如正式平台资料、同项目可测实现、已确认相邻 token 或可运行原型比较；“常见值、感觉顺滑、模型经验”不是依据。数值在目标环境完成动态与性能检查后即可用于本轮交付，并标注“可按品牌动效规范替换”；不需要另等确认人点头。

- `已确认`：有可追溯来源、版本和适用平台。

### 共用实现规则

- 状态先提交还是动画先结束必须明确。动画本身默认不延迟状态提交、主行动、返回或错误恢复；若确需阻塞，只能引用已确认的 D5 规则，并写解除条件。
- 可打断不等于任意停在中间帧。每个打断、取消、反向、路由离开、对象卸载和新状态覆盖都必须落到一个已定义状态；数据状态、可见状态和焦点不能互相矛盾。
- reduced motion 不是只写“关闭动画”或任意缩短时长。它必须保留同一 D5 含义、终态、操作入口和返回结果；若仍使用时长，也按正式来源或“候选待确认”处理。
- 焦点、手势和返回不适用时仍标 `不适用`；适用时不能只描述画面，必须写动画前、中、后的行为和取消结果。
- 优先使用不会持续触发布局和绘制的实现属性；必须运动布局或大面积绘制时，记录理由并在目标环境实测。不得以视觉录屏流畅代替性能轨迹。
- 无已确认性能预算时标“候选待确认”，不得自行写帧率、耗时、并发数或设备门槛；没有预算与目标环境的性能项不能标 `PASSED`。

## M1 反馈动效

**触发问题**：用户操作后，是否需要在结果产生前确认输入已被接收，或在结果产生后强化已定义的成功 / 失败状态？  
**最低输入**：D5 已确认的操作含义、可用 / 不可用 / 提交中 / 结果状态、重复提交规则和恢复规则；以及满足“动效入口门”的已定稿 UI、稳定对象/状态标识和动效依据。  
**跳过**：静态按下态、可见文案、控件状态或状态切换已足以确认输入和结果。

### 具体判断

1. 分开“输入已接收”“处理中”“结果成功”“结果失败”；不能用成功动效冒充已接收，也不能在结果未知时播放成功或失败。
2. 即时反馈在 D5 确认输入被接收的状态提交点出现，不等待业务结果，也不等待另一段装饰动画结束。是否需要 delay 及其值必须有来源。
3. 只运动被操作对象或与其语义直接相连的反馈对象；若运动远处对象，写清两者关系和必要性。
4. 提交中再次触发时，先引用 D5 / 实现合同确定的策略：禁用、忽略、合并、排队或允许并行。动效只表达该策略，不能自行选择策略，也不能以动画遮挡代替重复提交控制。
5. 鼠标、触控、键盘、辅助技术和程序化提交进入同一逻辑状态时，反馈含义一致；不能只有指针按压才获得确认。
6. 新输入、取消、失败、返回、对象卸载或结果到达打断反馈时，明确视觉落位、控件可用性、焦点和待处理请求状态。不得留下“看似仍提交中”但实际已结束，或“看似可再次提交”但逻辑仍锁定的状态。

先交事件—状态表，再为需要运动的边逐条使用共用实现规格：

```text

输入前状态：
输入已接收状态：
处理中状态：
结果状态：成功 / 失败 / 结果未知 / 不适用
重复触发策略及来源：
取消 / 返回策略及来源：

```

最少覆盖：

- 首次激活后的即时反馈；
- 提交中的快速重复激活；
- 键盘或辅助技术激活；
- 结果在反馈中途到达；
- 取消、失败、返回或对象消失造成的中断；
- reduced motion 下的同一组状态。

**产出**：M1 事件—状态表；按下 / 激活、提交中、成功 / 失败中实际需要运动的实现规格；重复提交与中断动态验收记录。  
**完成证据**：在可运行对象中，输入、处理中、结果和中断均落到 D5 指定状态，重复激活按已确认规则处理，动画不额外阻塞任务；若未执行用户验证，只能称“实现与动态验收通过”，不能声称用户已经理解。  
**不得替代**：I5 主行动反馈、重复提交的逻辑控制、成功 / 失败判定。

## M2 状态转换

**触发问题**：加载、成功、失败、内容替换或结果未知时，静态切换是否会让用户误判当前状态、失去上下文或找不到下一步？  
**最低输入**：D5 已确认的状态集合、每个状态的内容与行动、状态转换条件、结果确定性、焦点和恢复规则；以及满足“动效入口门”的已定稿 UI、稳定对象/状态标识和动效依据。  
**跳过**：静态替换已经完整表达状态，且不会造成上下文、焦点、滚动或行动误解。

### 具体判断

1. **加载**：区分有真实进度来源和只有进行中状态。只能绑定真实进度；不得伪造百分比、匀速推进或用循环暗示确定完成时间。何时显示加载状态由 D5 或正式规范决定；无来源时不得自行补“超过某秒”之类阈值。
2. **成功**：只在结果来源确认成功后进入。若成功后的内容替换、焦点或行动已由静态状态清楚表达，可跳过成功动效。
3. **失败**：失败内容和恢复行动按 D5 保持可读、可聚焦、可操作；动效不能让错误一闪即逝，也不能用自动离场取消阅读机会。自动消失规则没有来源时标缺失或候选待确认。
4. **内容替换**：先确认替换范围、稳定锚点、滚动位置、选择状态和焦点去向。只在运动能说明“什么被替换、什么保持不变”时使用；不得为了转场重建不必要的上下文。
5. **结果未知**：当当前证据不能判定成功或失败时，保留 D5 定义的独立状态；不得借颜色、图标或运动暗示任一结果。重试、查询、取消、等待或离开的入口只引用已确认规则，不由 M2 发明。
6. 新结果覆盖旧状态、用户离开、请求取消、页面进入后台或内容对象卸载时，必须停止旧转换并落到当前真实状态；恢复后不能重播造成结果重复或焦点跳回。

### M2 交付格式

先交状态边表，再为确需运动的每条边填写共用实现规格：

```text

```

状态边至少按实际适用范围检查：

- 初始或已有内容 → 加载；
- 加载 → 成功；
- 加载 → 失败；
- 加载 / 提交中 → 结果未知；
- 已有内容 → 新内容；
- 失败或结果未知 → D5 已定义的恢复状态；
- 任一转换被新结果、取消、返回或对象卸载打断；
- 完整动效与 reduced motion 的等价结果。

不适用的边标 `不适用` 并写理由，不为补齐清单虚构状态。

**产出**：M2 状态边表；加载、成功、失败、内容替换、结果未知中实际需要运动的实现规格；中断、焦点与 reduced motion 动态验收记录。  
**完成证据**：可运行对象中的每条适用状态边都到达正确终态；真实进度、非确定进度和结果未知没有被混写；失败内容、恢复行动、焦点和上下文在中断前后保持可用。未运行理解测试时，不把实现验收写成“用户已理解”。  
**不得替代**：加载、成功、失败和结果未知的语义、文案、判定来源与恢复规则。

## M3 空间关系

**触发问题**：已确认的层级、模态或返回关系，是否需要运动帮助表达来源、去向和可逆性？  
**最低输入**：D5 与信息架构中已确认的入口、目标、层级 / 覆盖关系、关闭与返回目标、焦点规则、手势和系统返回规则；以及满足“动效入口门”的已定稿 UI、稳定对象/状态标识和动效依据。  
**跳过**：没有空间或层级变化，或静态标题、层级标识、遮罩、返回控件和焦点已经足以表达关系。

### 具体判断

1. 先把入口与目标分类为已确认的父子层级、同层替换、模态覆盖或返回关系；分类缺失时停止，不能用运动方向替信息架构作决定。
2. 轴向、方向、深度、缩放、变换原点和前后景关系必须来自已确认的空间模型、平台规范、语言方向或主稿；不存在通用的“进入向哪、返回向哪”。无来源时标候选待确认。
3. 层级进入与退出要表达同一关系，但不强制把退出写成逐帧反放；两者各自仍需明确起止值、焦点、返回和中断状态。
4. 模态需写来源对象、背景是否保持、焦点如何进入、动画中是否可关闭、关闭后回到哪个对象。原对象不存在时，只能使用 D5 已定义的焦点和返回后备位置，不能由动效临时选择。
5. 页面返回、系统返回、Esc、关闭控件和返回手势若能触发同一离开行为，必须指向同一导航结果；视觉路径不同也不能改变返回栈。
6. 交互式手势需定义开始、推进、提交和取消。手势取消后回到完整起态，提交后到完整终态；阈值、速度或距离没有正式来源时标候选待确认，不得编造。
7. 动画中途再次返回、改走其他入口、目标卸载或系统接管时，写清当前导航栈、视觉落点和焦点。不能用不可取消动画锁死出口。
8. reduced motion 下仍用静态层级、模态边界、标题 / 返回目标和焦点变化表达同一来源与去向；不得因移除位移而丢失关闭或返回能力。

### M3 交付格式

先交空间关系表，再为进入、退出、返回和手势取消中需要运动的边填写共用实现规格：

```text
M3 空间关系表
入口 / 触发对象：
起始容器 / 路由：
目标容器 / 路由：
关系：父子层级 / 同层替换 / 模态覆盖 / 返回
空间模型及来源：
进入触发：
退出、关闭与返回触发：
页面 / 系统 / Esc 返回结果：
焦点进入与返回：
手势开始、提交、取消及阈值来源：
中断后的导航、视觉和焦点状态：
静态是否足够：
对应进入 / 退出 / 返回 / 取消规格 ID：
Reduced motion 等价方案：
来源 / 确认状态：
```

最少覆盖实际适用的：

- 从来源对象进入目标；
- 关闭或返回到来源对象；
- 来源对象已不存在时的已确认后备结果；
- 动画中的返回、关闭和新导航；
- 交互式手势提交与取消；
- 键盘、系统返回和 reduced motion。

**产出**：M3 空间关系表；进入、退出、返回和手势取消的实现规格；导航、焦点、中断与 reduced motion 动态验收记录。  
**完成证据**：可运行对象的运动方向、导航结果、焦点和手势落点均与已确认空间关系一致；完整与减弱方案到达相同任务结果。未运行理解测试时，只能证明实现一致，不能声称用户已理解来源与去向。  
**不得替代**：信息架构、模态语义、导航栈、返回规则和焦点规则。

## MI 动效组件检索与集成（先定要做什么，再去库里找）

**触发问题**：这条动效已经写清楚要做什么之后，能不能从成熟组件库直接拿到源码，而不是从零写？  
**最低输入**：
- 本条动效的规格：M1–M3 规格，或下面的品牌表现动效合同。
- 目标页面的技术栈：React 还是纯 HTML，有没有 Tailwind，是不是原生客户端。
- 所选风格参数。
- 性能约束。

**跳过**：静态已足够（已记 `SKIPPED`）；原生客户端（SwiftUI / Android），因为网页组件库不适用，按平台原生 API 写。

顺序固定：**先写清这条动效要解决什么问题**，包括触发条件、起止状态、时长、缓动、退出行为和 reduced motion，**再检索**。不能先逛库，看到好看的再找地方塞。

**品牌表现动效**指首屏标题入场、背景氛围、滚动进场、文字特效这类不表达 UI 反馈的动效。它不走 M1–M3，但同样要写上面这六项。它只用在落地页、活动页、品牌页这类以表达为主的页面，不放在任务操作区背后，不挡主行动。它可以是持续循环的氛围背景，这是对「全局禁止」里「无触发循环」的唯一例外，但必须满足两条：低对比、不干扰阅读；离开视口或开启 reduced motion 时停止。功能性动效优先，品牌表现其次；不为了有动效而加动效。

### 步骤

1. **写检索条件**：动效类型（反馈 / 状态转换 / 空间关系 / 品牌表现）、要解决的问题、触发、起止状态、目标技术栈、风格参数（颜色、圆角、材质）、性能约束。
2. **按技术栈选库**：
   - React + Tailwind：Motion Primitives、Aceternity、React Bits、21st.dev。
   - 纯 HTML 或非 React：Uiverse，或用 Motion `animate()` / Anime.js 实现。React 组件不能直接塞进非 React 页面；要移植时，按它的源码逻辑改写，并记录「改写自」哪个组件。
   - 原生客户端：不用网页库，按平台原生写。
3. **检索并比较 2–3 个候选**：看实时预览。比较时按六个问题筛：解决的是不是同一个问题、能否改成规格里的数值、依赖大小、许可证、能否做 reduced motion、移动端表现。只是好看但解决的不是这个问题的，不选。
4. **先审源码，再装**：
   - 先读组件源码和 registry JSON 里的 `files`、`dependencies`，确认四件事：
     - 没有网络请求或埋点；
     - 没有混淆代码；
     - 没有安装后自动执行的脚本；
     - 依赖体积可以接受。
   - 审完才用 shadcn CLI 安装，或手动把文件写进项目。**不运行没审过的第三方安装命令。**
   - `three`、`@react-three/fiber` 这类大型依赖不自动引入，确需时在交付里写明理由和体积。
   - 付费、需要授权 token、要登录才能看源码的组件不用。
5. **改成项目自己的东西**：
   - 时长、缓动、位移改成规格里的值。
   - 颜色、字体、圆角接设计 token 或所选风格参数。
   - 类名对齐设计系统。
   - 补 reduced motion 分支和卸载时的清理。
   - 页面原有的布局、业务逻辑和事件行为保持不变。
6. **记来源**：在组件文件头注释写来源 URL、作者和许可证；MIT 类许可要保留原版权声明。
7. **库里没有合适的**：用项目已有引擎（没有时用 Motion 或 Anime.js）按规格自己写，来源记为「自写」。**检索不到真实源码时，不得编造“来自某库”。**
8. **跑验收**：按下面「动态验收与性能完成门」逐项验收，并额外在移动端（真机或设备模拟）和开启 reduced motion 时各验一次。代码生成成功不等于验收通过。

**产出**：每条动效一份记录，并且是项目里真实可运行的实现，不是参考链接或描述：
- 解决的问题、触发条件、起止状态、时长、缓动和退出行为；
- reduced motion 方案；
- 来源（库名、组件页 URL、许可证），或注明「自写 + 所用引擎」；
- 新增的依赖及体积；
- 修改了哪些文件；
- 验收结果。

**完成证据**：
- 每条动效都能指出它解决的问题；
- 来源和许可证都可核对；
- 没有引入付费组件或未审源码；
- 动态验收、移动端和 reduced motion 检查都已实际运行。

**不得替代**：M1–M3 规格、D5 交互规则、动态验收。

## 动态验收与性能完成门

正式动态验收必须在动效工具产生的可运行对象或正式成品上执行；Figma 原型、静态稿、时间轴截图或口头走查只能证明预览/规格存在，不能证明正式实现通过。每次验收记录工具动作 ID、对象版本、设备 / 系统 / 浏览器、reduced motion 设置、输入方式和证据文件。

至少检查：

- 正常触发的实际起态、终态、对象、属性起止值、时长 / token、easing、delay 和串并行关系与规格一致；
- 快速重复触发、动画中再次触发、新状态覆盖、取消、返回、对象卸载和后台 / 恢复后，没有中间残态、重复结果、焦点丢失或输入锁死；
- 指针、触控、键盘、辅助技术、程序化触发与手势中适用的入口到达同一 D5 结果；
- reduced motion 被实际开启后，等价方案可完成同一任务并保留同一反馈、错误、层级与返回含义；
- 动画不额外阻塞任务；确有阻塞时，阻塞对象、依据和解除条件与规格一致；
- 在目标环境用性能分析工具检查布局、绘制、合成、长任务、掉帧或平台对应指标，并对照已确认预算；只有录屏观感不能判定性能通过；
- 取消、卸载、路由离开和连续触发后，计时器、监听、动画实例和渲染资源按实现约束释放。

验收结果逐项标 `PASSED / FAILED / NOT_COVERED / BLOCKED`。时长、delay、手势阈值、目标环境或性能预算仍为“候选待确认”时，对应项不能标 `PASSED`；修正后重新运行受影响用例，不以代码已修改代替回归。

## 全局禁止

无触发循环（品牌页的低对比氛围背景按 `MI` 的例外处理）、伪造进度、用成功 / 失败动效表达结果未知、自动轮播或装饰动画挡任务、用延长时长冒充质感、错误一闪即逝、无法取消的锁死动画、在无来源时编造时长或手势阈值、只交静态稿却声称动态或性能验收通过。
