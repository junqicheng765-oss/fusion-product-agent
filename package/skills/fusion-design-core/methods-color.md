# 配色智能（Color Intelligence）

配色模块负责把「几个好看的颜色」变成能铺到整个产品上的语义色系统：背景、文字、按钮、边框、状态色、亮暗模式，以及每条色的 12 阶。它不是调色板浏览工具。

和其他方法的分工：
- [methods-visual.md](methods-visual.md) `V0` 选定风格；`V2` 规定每个语义色 token 必须记什么。
- 本文件负责**找到或生成**那一套色，并验对比度。
- [methods-style-engine.md](methods-style-engine.md) 把颜色连同字体、圆角、组件一起应用到全产品。只换颜色、不换风格时，用本文件的 `CI4` 写入颜色变量即可。

**制作依赖**：视觉方向已有依据后，先用 CI 建立本轮整体色彩框架，再制作/适配主图、文字、图标与控件，在真实组合中校正。探索方向时可依据当前候选形成临时框架，纳入原 DS1 样张一起供人选择；选定后由 DS2 校准固化，不要求先批准文字风格或先有最终主图才能配色。已有有效系统或局部任务引用适用框架，只补受影响角色，不重建全页色板，也不另增配色审批。

框架须说明色彩怎样辅助信息层级、情绪、内容分组和状态：主/辅色、中性色、强调色及语义状态各自的作用、明暗/冷暖/饱和关系、预期视觉重量与大致使用面积。探索阶段先满足当前样张需要的角色与实际值，不为凑完整系统预填未设计状态；正式制作再补齐适用状态。原始色阶与语义角色分开，图标和控件使用角色映射，不默认保留素材下载原色。方法依据见 [Fluent 色彩](https://fluent2.microsoft.design/color)与[语义设计变量](https://fluent2.microsoft.design/design-tokens)，不把某一体系的固定配色复制为所有任务规范。

## 三类能力

| 类型 | 是什么 | 能不能自动化 | 本地 / 线上 |
| :--- | :--- | :--- | :--- |
| 现成配色方案 | 4–5 个好看的颜色 | 不能自动抓。用户挑选或粘贴后，再转成语义色 | Coolors、Color Hunt、Happy Hues、Huemint 网站、Realtime Colors 导出 |
| 产品级语义色系统 | 角色齐全的 token + 亮暗 + 12 阶 | 能。这是默认路径 | 本地 5 套系统、Radix Colors 色阶、品牌色本地插值 |
| 完整 UI 主题 | 颜色 + 字体 + 圆角 + 组件 | 能，但走风格引擎，不在这里单独换肤 | Tweakcn、shadcn 预设 |

第二类最重要。没有语义角色的色板，不能直接写进产品。

## 内置资源

索引在 `color-presets/registry.json`。色阶在 `color-presets/radix/scales.json`（Radix Colors，MIT，许可证在同目录）。5 套产品级系统在 `color-presets/systems/`。

**推荐组合怎么用**

| 库 | 在流程里的位置 | 硬限制 |
| :--- | :--- | :--- |
| Coolors | 灵感。用户从网站复制 5 色或分享链接 | **禁止**爬取、囤积、把色板合集打包装进 Skill（Coolors 许可不允许） |
| Huemint | 灵感。用户在网站生成后把 hex 贴过来 | **禁止**调用 `https://api.huemint.com`（公开 API 仅限非商用） |
| Realtime Colors | 预览。用 `preview` 生成的 URL 给用户打开，或看本地三栏预览页 | 不抓取站点；用户导出的 CSS 可以贴进来 |
| Radix Colors | 自动化底座。所有语义色和 12 阶默认从这里取 | 已离线打包，不现查 |
| shadcn/create、Tweakcn | 完整主题落地。只换颜色时用 `--only theme` 或 `CI4` | 已在风格引擎里 |
| [Open Props Gradients](https://open-props.style/#gradients) | 可选的 CSS 渐变变量与构成资源；借鉴或取用所需定义后映射到本轮色彩框架 | [MIT](https://github.com/argyleink/open-props/blob/main/LICENSE)；锁定实际版本并保留许可，只取所需声明和真实依赖，不默认加载其整套主题、normalize 或按钮样式 |

Open Props 在这里是文档级可选 CSS 资源：`mode=reference`；`search` 为官方 Gradients 文档及对应源码；`returns` 为渐变 CSS 自定义属性；`acquire` 为在已授权制作项目中按需引用或移植实际定义；`license` 按所用版本 MIT 文本；`fallback` 为按下方选择方法使用原生 CSS 或已确认设计工具制作。登记入口不等于已下载、安装或自动接入 CLI。取用默认配色前先核对语义角色，可沿用构成而调整色标；修改后记录派生关系，不冒充原库规范。

UI Colors 的「主色生成完整色阶」由本模块 `from-brand` 在本地用插值完成，不调用它的 API（要 key，且禁止做竞品色阶生成器）。Happy Hues、Color Hunt 只作参考。

**本地 5 套产品级系统**（下列 ID 是本 Skill 的实际预设，不是各网站的官方主题）：

| ID | 观感 | 中性色阶 + 主色色阶 | 默认绑定的风格族 |
| :--- | :--- | :--- | :--- |
| `apple-minimal` | 中性、克制、系统感 | gray + blue（主色覆盖为 HIG `#007AFF`） | 苹果原生、极简 SaaS、玻璃拟态 |
| `warm-editorial` | 温暖、杂志感、高级 | sand + brown | 编辑式、柔和 Soft UI |
| `ai-gradient` | 智能产品、清爽科技感 | slate + indigo（提供基础色阶，渐变需另行构成） | AI 产品、科技感 |
| `nature-calm` | 自然、生活方式、柔和 | sage + green | 柔和 Soft UI、内容信息流 |
| `dark-premium` | 暗色、精密、高对比 | slate + gold（默认暗色） | 科技感、AI 产品 |

每套都含浅色 / 暗色，以及中性、主色、成功、警告、危险各 12 阶。Radix 台阶：1–2 背景，3–5 组件底，6–8 边框，9–10 实心（按 APCA），11–12 文字。**实心按钮、危险按钮必须达到 WCAG 正文对比 4.5:1**；第 9 阶配白字经常不够，此时 `--primary` / `--destructive` / `--success` 改用第 11 阶，第 9 阶留作 `--tint`（链接、图标、选中态）。`sky / mint / lime / yellow / amber` 的 9–10 阶必须配深色字。

工具：`scripts/color_intelligence.py`。

## CI0 先定风格和角色，再找颜色

DS1 主视觉引领分支可从当前候选的主题、感知目标、品牌及构图依据建立临时色彩框架，用于主图及其他元素制作；已有确认主视觉则从其有效关系推导。选中后再与真实资产一起校准 DS2。下面 V0 风格族和本地系统仅作实际采用的底座，不覆盖有效方向，候选推导不冒称正式品牌色；原来源许可与接口限制保留。

每个方向的色彩框架分别响应其感知侧重、光线和空间组织，比较实际大面积背景、明暗、冷暖及饱和关系，不只比较按钮或点缀色。没有有效品牌约束时，不能把首案色板或系统默认底色沿用为所有候选的共同前提；情绪词与材质名也不自动决定唯一底色。按 DS1 检查整组是否只是同一色彩氛围的变体，不为了差异牺牲适配和可读性，也不另增选色审批。

**触发问题**：这套色要服务哪个产品和哪些语义角色？  
**最低输入**：当前候选或已选视觉方向、有效品牌/主图依据，本轮内容与行动层级及适用状态；已有 DS2 直接引用。
**跳过**：已有正式色板且本轮只忠实应用。

颜色跟着风格走，不为了换一套好看的色而改风格。风格族已绑定时，先打开对应的本地系统：

```
python3 scripts/color_intelligence.py list
python3 scripts/color_intelligence.py show <id>
```

再列出必须有的角色：页面底、卡片、主文字、次级文字、主行动、主行动上的字、边框、输入框、焦点环、成功、警告、错误、禁用表面。缺一个就不算产品级配色。

上述是完整界面系统的角色清单；当前样张、独立视觉或局部委托只处理实际适用项，缺少尚未设计的其他角色不能伪称完整系统，也不因此扩张本轮。

**基础角色不是内容表达的上限。** 接续 U1/U3，补齐本轮关键业务内容的作用与强调需要，不将所有信息挤入主文字、次文字或主行动三档。内容强调、可点击行动、选中与反馈状态分别判断；售价不能因缺少现成角色就默认跟随按钮色，也不能把金额一律视作促销、成功或危险。品牌统一约束整体关系，不等于全文同色或只能用同一色相。角色可共用实际色值，但须与字重、比例、位置及分组共同支持辨识；需要区别却实际接近时重新配映，而不是仅登记不同 hex。已有正式系统锁定的范围先复核沿用，扩展角色不擅改品牌色。

金额内容沿 V3 设计数值、币种、计价单位及真实条件的关联和相对权重，保留准确值与含义，不套固定字号比、字体或红色规则。售价、对象名、说明/规格和行动的表现须在同一实际内容组及比较场景中判断；选择其他强调色或保持中性都要由任务、有效规范和准确画面支持。无真实优惠依据不制作促销含义。此判断接回原内容与排版记录，不另开审批或配色流程。

在这些角色上同时决定色彩怎样呈现：纯色、渐变、透明叠层或材质处理按表达目标、品牌、信息层级与实际背景选择，不因默认变量为单色就省略判断，也不为丰富画面强制渐变。此决定在视觉推导/候选中形成，确认后纳入 DS2，不另增一次配色审批。

**产出**：有来源和状态的整体色彩框架、适用角色及视觉重量/面积关系、采用的系统 ID 或设计推导。
**完成证据**：角色与 V2/DS2 可对应，说明颜色服务的理解、层级与感受，足以支持当前元素制作；未覆盖项和候选状态明确。
**不得替代**：`V0` 风格选择。

## CI1 检索：本地系统优先，灵感色板后转化

**触发问题**：从哪里取这一套色？  
**最低输入**：`CI0` 的风格族；若用户给了品牌色或色板，一并带上。

顺序固定：
主视觉引领分支引用当前候选色彩框架或已确认 DS2 的准确版本及推导关系；明确的语义色 hex 可交给 `from-palette` 形成候选系统，再按 CI3/V2、CI5 核对。来源可为有效主图/品牌关系及有依据的本轮设计推导，必须区分事实与候选；这不属于抓取外部色板，不反向要求先确认最终 KV 或另请人挑色。其他分支按以下顺序。
1. **本地系统**：按风格族取上表 5 套之一。语境明确时直接定一套，不逛灵感站。
2. **品牌色**：用户给了主色 hex，运行 `from-brand <hex>`。近 Radix 主色就用该色阶，主色覆盖为品牌色；离得远就用品牌色 + 本地 12 阶插值，中性色仍用 Radix。
3. **用户粘贴的灵感色板**：Coolors / Color Hunt / Huemint / Happy Hues / Realtime Colors 导出，一律等用户把 hex 或导出 CSS 贴进来，再运行 `from-palette bg,fg,primary[,muted][,border]`。**禁止**打开这些站点批量抓色。
4. **完整主题**：用户要的是整站换肤（连字体圆角一起换），转 `DS1`，不用本模块。

检索不到真实来源时，不得编造来源标记。来源为本地系统 ID、Radix 色阶名、品牌 hex、用户粘贴色板，或当前候选/已确认方向的可追溯推导；设计依据与品牌事实分开。

核对工具输出而非照抄其标签：当前 `from-palette` 会自动调整部分深底浅字的顺序，并固定写入用户粘贴色板的来源描述。用于本轮推导时，保留真实输入/来源并核对输出的背景、文字及主色角色；自动变换不符合本轮框架时不能直接采用，也不能把脚本默认描述冒充用户提供的事实。框架和最终色值以实际核验的记录为准。

**产出**：来源记录 + 一套或三套候选的 hex。  
**完成证据**：来源可核对；没有抓取、没有调用 Huemint API、没有编造色板出处。  
**不得替代**：品牌色规范。有官方品牌色时以品牌色为种子。

## CI2 探索：最多 3 套候选，先预览再写入

**触发问题**：要不要让用户看几套再定？  
**最低输入**：`CI1` 的候选。

和风格引擎的「探索 / 应用」同一条规则：
- DS1 正在比较整体方向时，各候选按本节建立所需配色并纳入同一实际图文样张，不另凑色板数量或增加一轮独立选色；只有本轮确需单独比较配色时才用下方配色预览。
- **语境明确的 0→1**：Agent 直接定一套，交付时一句话说明，想换可以说。不问颜色细项。
- **用户要求看看配色、品牌色有 2–3 种合理映射、或给已有产品换色**：生成 3 套不同方向（不要 3 个只差一档明度的变体），运行：

```
python3 scripts/color_intelligence.py preview <候选系统ID列表> -o <配色预览.html>
```

用同一个代表页结构展示浅色卡片、主按钮、次按钮、成功 / 错误，并附暗色小预览。脚本同时给出 Realtime Colors 链接，供用户看整页效果。用提问工具问一次，选项说明实际可见的色彩关系及其感受，不出现内部 ID。
- **改已有产品的颜色变量前**：代表页改前改后对比 + 要改的文件，用户确认后再写（`CI4`）。0→1 不需要。

**产出**：选定的系统 ID 或「品牌色 + 中性/主色色阶名」。  
**完成证据**：该问的问过；不该问的没有拿颜色细项去问。  
**不得替代**：`DS1`。换整套风格仍走风格引擎。

## CI3 转成 Design Tokens

**触发问题**：选定的颜色怎样变成产品里能引用的变量？  
**最低输入**：选定系统或 `from-brand` / `from-palette` 的输出。

**步骤**
1. 映射到 shadcn / 本 Skill 的基础语义变量：`--background` `--foreground` `--card` `--primary` `--primary-foreground` `--muted` `--muted-foreground` `--accent` `--border` `--input` `--ring` `--destructive` `--success` `--warning`，浅色和暗色各一套。本轮 CI0 所需的内容角色引用有效系统的对应语义，缺项在同一任务规格与主题中补映射或别名，记录实际值与适用范围；基础脚本未覆盖的扩展项按实际实现和渲染核验，不宣称已自动生成、应用或检查。
2. 保留 12 阶源色阶（中性、主色、成功、警告、危险），写在 `meta.color.scales`，供 hover / pressed / 图表使用。组件状态优先用台阶，不另手调：
   - 默认表面 3，hover 4，按下 5；
   - 非交互边框 6，交互边框 7，焦点 8；
   - 实心按钮 9，实心 hover 10；
   - 次级文字 11，主文字 12。
3. 每个已使用的 token 按 `V2` 的记录表补全：角色、前景/背景、状态、亮暗、非颜色辅助。成功 / 警告 / 错误除颜色外必须有文字或图标。
4. 基础语义色保留可核验的颜色值；采用渐变或表面效果时，另在 DS2 记录复合效果值/变量及其引用的语义色、色标位置、方向、透明度、作用面积和状态。特定预设的默认渐变范围只约束实际采用的预设策略；按本轮派生规格设计时，可在适用控件及区域使用有依据的渐变，不把某一预设的范围当成全局禁令，不改共享库。实际文字/图标覆盖的最不利背景与状态按 CI5 检查。

### 纯色与渐变的选择和构成

先明确效果需要建立的焦点、方向、空间感、层级或节奏，再决定是否渐变；纯色同样是有效的表达选择。以下是构成维度，不是业务类型或信息层级的固定映射：

| 构成 | 应判断及记录 |
| --- | --- |
| 纯色 | 语义色、面积、前景关系、明度/饱和度和状态，是否已达到表达目标 |
| 线性渐变 | 色标与位置、轴向/角度、过渡节奏及其与构图/光照的关系 |
| 径向渐变 | 中心、形状/尺度、焦点范围、色标及边缘过渡 |
| 锥形渐变 | 中心、起始角度、色标分布及接缝，图形含义是否造成误读 |
| 重复渐变 | 方向、周期和间隔、细节密度及最小尺寸的干扰/条纹问题 |
| 多层弥散或网格感 | 各色域位置、叠加/混合、透明度及实现方式；不虚构通用原生网格函数，按实际 CSS 组合、设计工具或资产能力制作 |

渐变色标继承整页色彩框架；同色相、邻近色或跨色相的选择须解释作用，核对中间色发灰、突变、色带和对原材质/信息的影响。按需要记录实际插值/颜色空间、可编辑性、目标尺寸和兼容回退；平滑程度与支持能力以目标环境渲染为准，不用纯色端点代表整体合格。基础类型和能力依据见 [MDN 渐变](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/gradient)。动效另按已有范围与路线，不因采用渐变自动追加动画。

**产出**：语义色 token 表 + 12 阶源色阶 + `V2` 记录。  
**完成证据**：每个角色都有浅色和暗色值；状态台阶能对上 Radix 用法。  
**不得替代**：`V2` 的记录格式和对比实测。

## CI4 全局应用

**触发问题**：怎样一次改到全产品，而不是逐页改色值？  
**最低输入**：`CI3` 的 token；改已有产品时还要有 `CI2` 的确认。

```
python3 scripts/color_intelligence.py apply <id> --css <全局 CSS>
```

只写入 `/* dto-color:start */` … `/* dto-color:end */` 之间的颜色变量，不改字体和圆角（那些归风格引擎）。页面和组件只引用 `var(--primary)` 这类变量。写死的 hex 按 `DS0` 清点后收口。

该脚本不自动把语义色应用到已有 SVG，也不自动生成或应用复合渐变。图标按 V5 将实际 `fill`、`stroke`、层级透明或色标映射到语义角色；效果变量按 CI3 的真实定义及依赖落位。保留素材结构与既定原色约束，核对默认、选中、禁用及适用主题，不能以颜色变量已导出宣称整页适配完成。

shadcn 项目若要连字体一起换，用 `npx shadcn@latest apply --preset <id> --only theme`；只换本模块的语义色，仍用上面的 `apply`。

**不允许**：逐页改 hex；为了套色板改布局或文案。

**产出**：修改的 CSS / 主题文件。  
**完成证据**：颜色变量只有这一处定义。  
**不得替代**：DS4 的批量应用顺序。整体迭代按 DS1 方向依据 → CI 色彩框架 → DS2 校准规格与 DS3 映射 → DS4 应用，不以零散改色替代这条依赖。

## CI5 对比度检查（必须实测）

**触发问题**：这套色在浅色、暗色、卡片表面上，字和按钮还看得清吗？  
**最低输入**：已写入的 token。

```
python3 scripts/color_intelligence.py contrast --preset <配色系统或风格编号>   # 选色前预检
python3 scripts/color_intelligence.py contrast --css <页面引入的主题 CSS>          # 验收：页面实际用的颜色
# 大字普惠 / 适老化加 --aaa（阈值 7:1）
```

必须测的组合：
- 主文字 / 页面底
- 次级文字 / 页面底
- 主按钮文字 / 主按钮
- 危险按钮文字 / 危险色
- 主文字 / 卡片

正文 ≥ 4.5:1，大字和图标 ≥ 3:1，`CN-08` 和大字普惠 ≥ 7:1。只目测或只测一个背景，不能写通过。未通过就改台阶或换中性色阶，改完重跑，再写入。

当前脚本从 CSS 读取基础十六进制变量及预定义组合，不能据此证明渐变、纹理、图片、透明叠加或所有控件状态已通过。对实际采用的复杂表面，在准确渲染中核对文字/图标所覆盖的最不利背景与相关状态，补充可回查的前景/合成背景取值、比值和位置证据；无法建立稳定对比时，调整效果或提供稳定承托层。不能仅测渐变端点、另一个纯色或无关预设后宣称覆盖整个实际表面。

还须核对原始报告是否保留所需全部组合及主题；当前命令的逐组合打印存在覆盖不足，不能以最后显示的一条比值替代其余证据。缺失项目按实际前景/背景对补齐可回查的比值、状态与取值来源，报告与验收结论分别记录，不伪造脚本已输出的内容。

**产出**：适用组合及实际表面/状态的比值、位置、覆盖范围和 PASS / FAIL。
**完成证据**：脚本实际覆盖的组合通过，未覆盖的渐变、材质与叠加另有实际检查证据；未验证范围不记通过。
**不得替代**：平台无障碍规范；有法定要求时按法定阈值。

## CI6 沉淀

验收通过、可复用的新语义色系统，存进 `color-presets/systems/`，并在 `color-presets/registry.json` 登记：风格族、来源、许可证。来自用户粘贴灵感色板的，如实记录提供者与原始平台，不写成官方主题。没验收过的不进库。

## 配色验收

- 有完整语义角色，不是 4–5 个孤立色块（`CI0` `CI3`）。
- 来源可核对；没有抓取灵感站、没有调用 Huemint API、没有编造出处（`CI1`）。
- 该探索的出过 3 套预览；改已有产品前确认过（`CI2`）。
- 颜色变量只在一处；对比度脚本通过（`CI4` `CI5`）。
- `V2` 记录齐全，关键状态有非颜色辅助。
