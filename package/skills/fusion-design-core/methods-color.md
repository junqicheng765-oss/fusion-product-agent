# 配色智能（Color Intelligence）

配色模块负责把「几个好看的颜色」变成能铺到整个产品上的语义色系统：背景、文字、按钮、边框、状态色、亮暗模式，以及每条色的 12 阶。它不是调色板浏览工具。

和其他方法的分工：
- [methods-visual.md](methods-visual.md) `V0` 选定风格；`V2` 规定每个语义色 token 必须记什么。
- 本文件负责**找到或生成**那一套色，并验对比度。
- [methods-style-engine.md](methods-style-engine.md) 把颜色连同字体、圆角、组件一起应用到全产品。只换颜色、不换风格时，用本文件的 `CI4` 写入颜色变量即可。

## 三类能力

| 类型 | 是什么 | 能不能自动化 | 本地 / 线上 |
| :--- | :--- | :--- | :--- |
| 现成配色方案 | 4–5 个好看的颜色 | 不能自动抓。用户挑选或粘贴后，再转成语义色 | Coolors、Color Hunt、Happy Hues、Huemint 网站、Realtime Colors 导出 |
| 产品级语义色系统 | 角色齐全的 token + 亮暗 + 12 阶 | 能。这是默认路径 | 本地 5 套系统、Radix Colors 色阶、品牌色本地插值 |
| 完整 UI 主题 | 颜色 + 字体 + 圆角 + 组件 | 能，但走风格引擎，不在这里单独换肤 | Tweakcn、shadcn 预设 |

第二类最重要。没有语义角色的色板，不能直接写进产品。

## 内置资源

索引在 `color-presets/registry.json`。色阶在 `color-presets/radix/scales.json`（Radix Colors，MIT，许可证在同目录）。5 套产品级系统在 `color-presets/systems/`。

**推荐组合怎么用**

| 库 | 在流程里的位置 | 硬限制 |
| :--- | :--- | :--- |
| Coolors | 灵感。用户从网站复制 5 色或分享链接 | **禁止**爬取、囤积、把色板合集打包装进 Skill（Coolors 许可不允许） |
| Huemint | 灵感。用户在网站生成后把 hex 贴过来 | **禁止**调用 `https://api.huemint.com`（公开 API 仅限非商用） |
| Realtime Colors | 预览。用 `preview` 生成的 URL 给用户打开，或看本地三栏预览页 | 不抓取站点；用户导出的 CSS 可以贴进来 |
| Radix Colors | 自动化底座。所有语义色和 12 阶默认从这里取 | 已离线打包，不现查 |
| shadcn/create、Tweakcn | 完整主题落地。只换颜色时用 `--only theme` 或 `CI4` | 已在风格引擎里 |

UI Colors 的「主色生成完整色阶」由本模块 `from-brand` 在本地用插值完成，不调用它的 API（要 key，且禁止做竞品色阶生成器）。Happy Hues、Color Hunt 只作参考。

**本地 5 套产品级系统**（示例名是本 Skill 的预设，不是各网站的官方主题）：

| ID | 观感 | 中性色阶 + 主色色阶 | 默认绑定的风格族 |
| :--- | :--- | :--- | :--- |
| `apple-minimal` | 中性、克制、系统感 | gray + blue（主色覆盖为 HIG `#007AFF`） | 苹果原生、极简 SaaS、玻璃拟态 |
| `warm-editorial` | 温暖、杂志感、高级 | sand + brown | 编辑式、柔和 Soft UI |
| `ai-gradient` | 智能产品、清爽科技感 | slate + indigo（渐变只用于 Hero / 生成中） | AI 产品、科技感 |
| `nature-calm` | 自然、生活方式、柔和 | sage + green | 柔和 Soft UI、内容信息流 |
| `dark-premium` | 暗色、精密、高对比 | slate + gold（默认暗色） | 科技感、AI 产品 |

每套都含浅色 / 暗色，以及中性、主色、成功、警告、危险各 12 阶。Radix 台阶：1–2 背景，3–5 组件底，6–8 边框，9–10 实心（按 APCA），11–12 文字。**实心按钮、危险按钮必须达到 WCAG 正文对比 4.5:1**；第 9 阶配白字经常不够，此时 `--primary` / `--destructive` / `--success` 改用第 11 阶，第 9 阶留作 `--tint`（链接、图标、选中态）。`sky / mint / lime / yellow / amber` 的 9–10 阶必须配深色字。

工具：`scripts/color_intelligence.py`。

## CI0 先定风格和角色，再找颜色

**触发问题**：这套色要服务哪个产品和哪些语义角色？  
**最低输入**：`V0` 选定的风格或风格族；主行动、文字层级、状态列表（与 `V2` 相同）。  
**跳过**：已有正式色板且本轮只忠实应用。

颜色跟着风格走，不为了换一套好看的色而改风格。风格族已绑定时，先打开对应的本地系统：

```
python3 scripts/color_intelligence.py list
python3 scripts/color_intelligence.py show <id>
```

再列出必须有的角色：页面底、卡片、主文字、次级文字、主行动、主行动上的字、边框、输入框、焦点环、成功、警告、错误、禁用表面。缺一个就不算产品级配色。

**产出**：风格族、候选系统 ID、角色清单。  
**完成证据**：角色清单与 `V2` 的 token 表能对上。  
**不得替代**：`V0` 风格选择。

## CI1 检索：本地系统优先，灵感色板后转化

**触发问题**：从哪里取这一套色？  
**最低输入**：`CI0` 的风格族；若用户给了品牌色或色板，一并带上。

顺序固定：
1. **本地系统**：按风格族取上表 5 套之一。语境明确时直接定一套，不逛灵感站。
2. **品牌色**：用户给了主色 hex，运行 `from-brand <hex>`。近 Radix 主色就用该色阶，主色覆盖为品牌色；离得远就用品牌色 + 本地 12 阶插值，中性色仍用 Radix。
3. **用户粘贴的灵感色板**：Coolors / Color Hunt / Huemint / Happy Hues / Realtime Colors 导出，一律等用户把 hex 或导出 CSS 贴进来，再运行 `from-palette bg,fg,primary[,muted][,border]`。**禁止**打开这些站点批量抓色。
4. **完整主题**：用户要的是整站换肤（连字体圆角一起换），转 `DS1`，不用本模块。

检索不到真实来源时，不得写「来自 Coolors xxx」。来源只能是：本地系统 ID、Radix 色阶名、品牌 hex、用户粘贴的色板。

**产出**：来源记录 + 一套或三套候选的 hex。  
**完成证据**：来源可核对；没有抓取、没有调用 Huemint API、没有编造色板出处。  
**不得替代**：品牌色规范。有官方品牌色时以品牌色为种子。

## CI2 探索：最多 3 套候选，先预览再写入

**触发问题**：要不要让用户看几套再定？  
**最低输入**：`CI1` 的候选。

和风格引擎的「探索 / 应用」同一条规则：
- **语境明确的 0→1**：Agent 直接定一套，交付时一句话说明，想换可以说。不问颜色细项。
- **用户要求看看配色、品牌色有 2–3 种合理映射、或给已有产品换色**：生成 3 套不同方向（不要 3 个只差一档明度的变体），运行：

```
python3 scripts/color_intelligence.py preview a,b,c -o color-preview.html
```

用同一个代表页结构展示浅色卡片、主按钮、次按钮、成功 / 错误，并附暗色小预览。脚本同时给出 Realtime Colors 链接，供用户看整页效果。用提问工具问一次，选项用大白话（「冷灰配系统蓝，干净克制」），不出现内部 ID。
- **改已有产品的颜色变量前**：代表页改前改后对比 + 要改的文件，用户确认后再写（`CI4`）。0→1 不需要。

**产出**：选定的系统 ID 或「品牌色 + 中性/主色色阶名」。  
**完成证据**：该问的问过；不该问的没有拿颜色细项去问。  
**不得替代**：`DS1`。换整套风格仍走风格引擎。

## CI3 转成 Design Tokens

**触发问题**：选定的颜色怎样变成产品里能引用的变量？  
**最低输入**：选定系统或 `from-brand` / `from-palette` 的输出。

**步骤**
1. 映射到 shadcn / 本 Skill 的语义变量：`--background` `--foreground` `--card` `--primary` `--primary-foreground` `--muted` `--muted-foreground` `--accent` `--border` `--input` `--ring` `--destructive` `--success` `--warning`，浅色和暗色各一套。
2. 保留 12 阶源色阶（中性、主色、成功、警告、危险），写在 `meta.color.scales`，供 hover / pressed / 图表使用。组件状态优先用台阶，不另手调：
   - 默认表面 3，hover 4，按下 5；
   - 非交互边框 6，交互边框 7，焦点 8；
   - 实心按钮 9，实心 hover 10；
   - 次级文字 11，主文字 12。
3. 每个已使用的 token 按 `V2` 的记录表补全：角色、前景/背景、状态、亮暗、非颜色辅助。成功 / 警告 / 错误除颜色外必须有文字或图标。
4. 渐变不是 token 本身。`ai-gradient` 只允许在 Hero 或「生成中」用主色到邻色的短渐变，操作区、正文、表单不用渐变底。

**产出**：语义色 token 表 + 12 阶源色阶 + `V2` 记录。  
**完成证据**：每个角色都有浅色和暗色值；状态台阶能对上 Radix 用法。  
**不得替代**：`V2` 的记录格式和对比实测。

## CI4 全局应用

**触发问题**：怎样一次改到全产品，而不是逐页改色值？  
**最低输入**：`CI3` 的 token；改已有产品时还要有 `CI2` 的确认。

```
python3 scripts/color_intelligence.py apply <id> --css <全局 CSS>
```

只写入 `/* dto-color:start */` … `/* dto-color:end */` 之间的颜色变量，不改字体和圆角（那些归风格引擎）。页面和组件只引用 `var(--primary)` 这类变量。写死的 hex 按 `DS0` 清点后收口。

shadcn 项目若要连字体一起换，用 `npx shadcn@latest apply --preset <id> --only theme`；只换本模块的语义色，仍用上面的 `apply`。

**不允许**：逐页改 hex；为了套色板改布局或文案。

**产出**：修改的 CSS / 主题文件。  
**完成证据**：颜色变量只有这一处定义。  
**不得替代**：`DS4` 的批量应用顺序。整站换风格时先 DS 再 CI，或一次走完 DS。

## CI5 对比度检查（必须实测）

**触发问题**：这套色在浅色、暗色、卡片表面上，字和按钮还看得清吗？  
**最低输入**：已写入的 token。

```
python3 scripts/color_intelligence.py contrast --preset <配色系统或风格编号，如 INT-05>   # 选色前预检
python3 scripts/color_intelligence.py contrast --css <页面引入的主题 CSS>          # 验收：页面实际用的颜色
# 大字普惠 / 适老化加 --aaa（阈值 7:1）
```

必须测的组合：
- 主文字 / 页面底
- 次级文字 / 页面底
- 主按钮文字 / 主按钮
- 危险按钮文字 / 危险色
- 主文字 / 卡片

正文 ≥ 4.5:1，大字和图标 ≥ 3:1，`CN-08` 和大字普惠 ≥ 7:1。只目测或只测一个背景，不能写通过。未通过就改台阶或换中性色阶，改完重跑，再写入。

**产出**：每条组合的比值和 PASS / FAIL。  
**完成证据**：脚本列出的组合全部 PASS。  
**不得替代**：平台无障碍规范；有法定要求时按法定阈值。

## CI6 沉淀

验收通过、可复用的新语义色系统，存进 `color-presets/systems/`，并在 `color-presets/registry.json` 登记：风格族、来源、许可证。来自用户粘贴灵感色板的，来源写「用户提供，转写自 Coolors / Color Hunt / …」，不要写成官方主题。没验收过的不进库。

## 配色验收

- 有完整语义角色，不是 4–5 个孤立色块（`CI0` `CI3`）。
- 来源可核对；没有抓取灵感站、没有调用 Huemint API、没有编造出处（`CI1`）。
- 该探索的出过 3 套预览；改已有产品前确认过（`CI2`）。
- 颜色变量只在一处；对比度脚本通过（`CI4` `CI5`）。
- `V2` 记录齐全，关键状态有非颜色辅助。
