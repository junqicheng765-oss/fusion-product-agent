# 原型准备方法

原型只为回答当前验证问题服务。保真度、内容和可操作范围以“足以产生有效行为证据”为准，不以看起来完整为目标。

## PROTO1 测试就绪原型

**触发问题**：当前验证是否需要用户阅读、判断或操作一个方案？  
**最低输入**：待验证判断、目标行为群体、任务原话；若测任务，还需主路径、页面职责、反馈和关键失败分支。  
**跳过**：已有同版本、已预测试通过的测试原型；或本轮只做无需载体的研究/规格一致性验收。

**步骤**

1. 写清本原型只回答哪一个主要判断，以及不回答什么。
2. 选择最低有效载体：一句概念、故事板、静态内容稿、可点击线框或近真实原型，并按 [methods-tool-routing.md](methods-tool-routing.md) 选择工具。Figma 低保真交互稿标 `LOW_FIDELITY_INTERACTION`；基于正式 UI 的动效预览标 `FIGMA_MOTION_PREVIEW`，两者都不能冒充对应正式成品。
3. 列出必须可用的起点、主路径、关键失败分支、返回/放弃和结束态。
4. 使用真实或有代表性的内容、数字、长度和状态；占位内容不得承担被测判断。
5. 对交互任务，连接全部被测状态，并确保反馈内容先由 I5/I6 定义；动效仅表达已定义反馈。
6. 用测试脚本完整预测试一次，记录断链、主持人必须解释之处和不真实内容。
7. 修复会暴露答案或阻断任务的问题，冻结测试版本并记录版本号。

**产出**

```text
待验证判断 / 不验证：
原型载体与保真度理由：
可用路径与状态：
代表性内容来源：
已知模拟与限制：
预测试问题及修复：
冻结版本：
```

**完成证据**

- 另一位主持人可以只读脚本启动测试。
- 被测主路径、关键失败、返回和结束态没有断链。
- 用户不会因无关占位、缺内容或主持人教学而被迫猜测。
- 原型版本与测试记录可以对应。

**不得替代**

- 原型完成不代表方案有效。
- 点击热区不替代交互反馈、异常和内容规则。
- 高保真不替代真实内容、用户行为或工程可行性。
