# N4 设计任务路由

目的：把 N0–N3 形成的任务、语境和设计原则，转换成一个有明确终点、依赖、方法、证据和停止条件的工作包。N4 不执行具体设计方法；它决定本轮需要解决什么、交什么、按什么顺序做。

输入：

- 上游任务卡与来源。
- 工作模式。
- 设计语境卡、设计任务和原则；不适用时有跳过依据。
- D1–D3 预扫描及已完成补证。
- 正式主稿、设计系统、现状材料和授权。

输出：

- 本轮设计产出合同。
- D1–D9 决定链及本轮动作。
- 最终设计起点、目标决定和依赖决定。
- 决定工作集、制作动作集、证据动作集、方法工作包及执行顺序。
- 产物类型及待由 N5 [methods-tool-routing.md](methods-tool-routing.md) 确认的工具职责。
- 风险深度与 D9 模式、计划和执行时点。
- 阻断、假设、跳过和上游回传要求。

## 产品与设计路由的边界

本文件只路由产品主线中的设计工作，先复用[产品启动依据](../fusion-product-agent/references/product-start.md)。若缺少会改变方向的产品意图，回传产品主线补齐推荐与必要问答，不通过选择“测试就绪原型”或设置候选假设绕过。明确委托的探索性制作可以按其范围执行，不能把探索结论写成正式产品基线。

## RT0 先定本轮终点

不要先从方法或阶段开始。先把用户最终要拿到的设计结果写清楚。

### 终点类型

可多选，但必须标一个主终点：

1. **设计诊断**：问题位置、影响决定、证据缺口和建议下一步。
2. **问题与语境定义**：行为群体、现状任务、洞察、设计任务和原则。
3. **流程方案**：范围、场景、主路径、分支和结束态。
4. **交互规格**：页面/节点职责、进出、反馈、异常和结构线框。
5. **测试就绪原型**：能回答指定判断的概念、内容或可操作原型。
6. **Figma UI 方案或正式主稿**：信息层级、组件、状态、真实文案、响应要求及全部界面视觉。
7. **非界面视觉成品或独立视觉资产委托**：海报、KV、品牌图形、插画、图片、独立图标集；只有用户明确拆分为独立交付时才与 UI 并行。
8. **UI 动效规格或 Figma 原型预览**：界面反馈、状态转换、空间关系、减弱方案，或明确标为预览的 UI 原型。
9. **正式 UI 交互动效**：在目标运行环境中可操作、可中断、可验收的界面动效实现。
10. **视频或动态图形成品**：依据 brief、脚本、分镜、关键帧和正式素材形成的线性/剪辑型成品。
11. **SVG、Lottie、图标或格式特定动画**：依据矢量源、格式和运行环境交付的专用动画成品。
12. **验证或验收结论**：测试/对照证据、决定状态变化和下一路由。
13. **指定制作或精确还原成品**：依据已确认内容、正式主稿或规格完成指定修改、资产、页面或版本。
14. **设计交付包**：准确版本、覆盖、差异、验收、风险和接手说明。

“做一个 App、优化页面、提升体验”不是合格终点。必须写交付范围、载体和证据。

### 产出合同字段

```text
主终点 / 次终点：
服务的用户任务与设计决定：
载体：文档 / 流程图 / 线框 / 原型 / Figma / 位图 / 矢量 / 视频 / 动态成品 / 代码 / 规格 / 报告
工具能力与职责边界：
保真度及其理由：
覆盖：场景 / 路径 / 页面 / 状态 / 端 / 尺寸
必须使用的来源、主稿、系统和资产：
本轮允许改变：
本轮不得改变：
完成证据：
明确不交：
```

### 按工作模式的最低产出

#### 直接制作

只适用于替换已批准文案或既有组件里的已定内容。新的一屏按局部优化路由，不走这里。

- 指定成品或修改。
- 范围和来源核对。
- 修改前后或版本证据。
- 受影响范围基本回归。

不得自动附加问题探索或新设计方向。

#### 局部优化

- 原问题及受影响决定。
- 修改前后方案和选择依据。
- 关键状态与关联路径回归。
- 若声称行为提升，另附相应验证计划或证据。

#### 问题探索

- 问题与证据边界。
- 行为群体、情境、关键洞察。
- 设计任务、原则、危险假设和下一决定。

尚未进入方案时，不要求用 UI 稿证明探索完成。

#### 方案验证

先标子型：

- **验证准备**：本轮只把对象做成测试就绪版本。最低产出为冻结的 `TEST_INPUT`、PROTO1 载体、预测试/完整性验收，以及含责任人和触发条件的 `DEFERRED_NEXT_ROUTE`；不要求真人观察，不更新被测决定为已验证。
- **验证执行**：本轮取得判断证据。最低产出为冻结对象及版本、待验证判断、脚本、样本和成功/失败信号，以及观察记录、决定状态变化和继续/修正/重定义/停止结论。

#### 设计还原/交付

- 正式来源和准确版本。
- 本次范围的高保真实现或交付。
- 逐项对照、动态行为、覆盖和残留差异。
- 未经授权差异为零；缺输入则标阻断。

## RT1 从终点反推目标决定

终点决定本轮必须解决哪些 D，而不是默认从 D1 做到 D9。

| 主终点 | 通常目标决定 / 证据对象 | 最低依赖 |
| --- | --- | --- |
| 设计诊断 | 实际受影响 D | 能定位问题的来源和证据 |
| 问题与语境定义 | D1–D3 | 上游目标、现有材料或补证 |
| 流程方案 | D4 | 与本流程有关的 D1–D3 |
| 交互规格 | D5 | 相关 D4、技术/权限/状态事实 |
| 测试就绪原型 | 被测决定保持 `TEST_INPUT/TEST`；只解决使原型无法承载判断的缺口 | 被测内容、路径和状态 |
| Figma UI 方案或正式主稿 | D6–D7 | 相关 D4–D5、信息/内容要求、设计系统和真实资产 |
| 非界面视觉成品或独立视觉资产委托 | 独立成品按产出合同；进入 UI 时关联 D7 | 内容职责、正式视觉依据、格式与授权 |
| UI 动效规格或 Figma 原型预览 | D8 | D5/信息架构已确认的反馈、状态转换、导航、层级与返回关系；已定稿 UI 起止画面和稳定对象标识；正式基线或探索授权 |
| 正式 UI 交互动效 | D8 + 制作动作 | 已定稿 UI、M1–M3、真实资产、目标运行环境和 reduced motion |
| 视频或动态图形成品 | 按独立产出合同，不默认进入 D8 | 传播 brief、脚本/旁白、分镜、关键帧、品牌/音视频素材、渠道和输出规格；出现产品 UI 时还需已定稿 UI，只有运动表达 UI 反馈、状态转换或空间关系时才需 D5 与 M1–M3 |
| SVG、Lottie、图标或格式特定动画 | 运动表达 UI 反馈、状态转换或空间关系时关联 D8；否则按独立产出合同 | 可编辑矢量源、图层/路径、起止或循环行为、格式、运行环境和性能要求；运动表达 UI 反馈、状态转换或空间关系时还需已定稿 UI、D5 与 M1–M3 |
| 验证或验收结论 | D9 证据程序；被测决定是证据对象，不是待重做决定 | 测试对象、程序和版本 |
| 指定制作或精确还原成品 | 无新增决定或实际受影响 D | 已确认/冻结来源、目标和允许动作；D9 验收 |
| 设计交付包 | 本次全部目标决定 | 当前版本、覆盖和验收 |

“最低依赖”必须有效，但不要求本轮重新生产。已 `CONFIRMED/FROZEN` 的依赖直接引用；只有未解决且会改变产出时才进入工作集。

“目标决定”不等于“决定工作集”。`TEST_INPUT/TEST` 只进入证据动作集；测试前保持冻结，只有证据使其转为 `MISSING/RESOLVE_NOW` 后，才在下一次路由进入决定工作集。

## RT2 扫描决定链

每个 D 必须填写：

```text
决定：
状态：
本轮动作：
来源：
是否属于目标决定：
是否是目标决定的必要依赖：
不同答案会怎样改变产出：
解决责任：设计 / 上游 / 外部专家 / 测试
```

状态：

- `CONFIRMED`：有有效来源，本轮复用。
- `FROZEN`：授权方要求不重开；记录风险。
- `TEST_INPUT`：本轮测试对象，测试前保持版本稳定。
- `ASSUMPTION`：已有暂定答案，标 `RESOLVE_NOW` 或 `ACCEPT_FOR_NOW`。
- `MISSING`：本轮需要且可由设计工作解决。
- `BLOCKED`：需要外部事实、资产、权限或授权。
- `N/A`：本任务不适用。

本轮动作：

- `REUSE`：直接引用。
- `RESOLVE_NOW`：进入工作集。
- `ACCEPT_FOR_NOW`：记录风险和补证，不在本轮循环处理。
- `TEST`：作为验证对象。
- `WAIT_EXTERNAL`：停止受影响工作。
- `SKIP`：不适用或不影响本轮。

## RT3 建立决定、制作与证据三类工作集

### 决定工作集

只包含：

1. 产出合同对应且标为 `RESOLVE_NOW` 的目标决定。
2. 未解决、标为 `RESOLVE_NOW` 且不同答案会改变目标决定的依赖。
3. 由高风险或共享系统新增且必须在本轮解决的决定。

不进入决定工作集：

- 已确认或冻结且仍适用的决定。
- 未知但不会改变本轮产出的决定。
- 只是“以后可能有用”的方法或产物。
- 用户未要求且不能改变本轮判断的全量设计系统、全量页面或全量研究。

### 制作动作集

直接制作、精确还原和依据已确认方案出稿时，即使决定工作集为空，也必须建立制作动作：

```text
动作：
来源与准确版本：
目标文件 / 页面 / 节点 / 资产：
允许改变：
不得改变：
操作范围：
预期成品：
回滚或修正方式：
完成后交给 D9 的证据：
```

制作动作只应用已确认或冻结决定，不重新解释它们。若执行中发现来源冲突、缺资产或必须做新设计判断，暂停受影响动作，将对应决定转为 `MISSING` 或 `BLOCKED`。

### 证据动作集

按 RT5 建立一个或多个证据动作。D9-PLAN 是每个 N4 路由都必须填写的元数据，不因“必须规划”自动进入决定工作集。

`TEST_INPUT/TEST` 及其冻结版本只进入证据动作集。证据动作可以调用 PROTO/VAL 方法来准备测试载体或取得证据，但不得在测试前把被测决定当作 `MISSING` 重做。

### 最终设计起点

从决定工作集的依赖关系中找最早一个：

- `MISSING/RESOLVE_NOW`，或
- `ASSUMPTION/RESOLVE_NOW`。

若最早必要决定是 `BLOCKED/WAIT_EXTERNAL`，暂停其下游；能独立完成的部分可继续，但必须分开报告。

决定工作集为空时：

- 有制作动作：执行起点为第一项制作动作。
- 本轮主终点是测试就绪原型：执行起点为 D9 证据准备动作。
- 本轮主终点是验证结论：执行起点为 D9 核心证据动作。
- 两者都没有：说明产出合同错误或本轮没有实际工作，不得虚构方法。

## RT4 依赖关系

决定链是默认依赖，不是固定执行阶段：

- D1–D3 为设计方向输入；只有会改变本轮方案时才补。
- D4 定义用户怎样走到结果。
- D5 定义节点职责、规则、反馈、状态和恢复。
- D6 定义职责内的信息、组件和文案表达。
- D7 定义 Figma UI 中的界面视觉系统和资产应用怎样表达已确认内容。
- D8 只运动表达 D5 与信息架构已定义的 UI 反馈、状态转换或空间关系。
- D9 定义怎样取得证据，不只是最后做检查。

### 不可跨越的依赖

- D4 未解决：不能用页面清单或导航图冒充流程。
- D5 未解决：不能用组件、文案或动效补交互规则。
- D6 未解决：不能用视觉风格掩盖信息层级。
- D5 没有反馈内容和起止状态：不能进入 D8。
- 没有已定稿 UI 的准确节点、版本和稳定对象/状态标识：不能进入 D8；低保真交互稿、未确认候选、截图或探索授权均不能替代。
- D8 没有正式 UI 交互动效基线，也没有明确探索授权、候选依据、目标环境、验证方式和确认人：标 `BLOCKED/WAIT_EXTERNAL`，取得授权或正式输入前不能进入实现级 UI 动效规格。
- Figma UI 正式界面视觉所需主稿、系统或资产缺失：D7 标 `BLOCKED`，不能用占位成品降级。
- 需要行为验证但没有可测试对象：先进入 PROTO1。

### 可并行条件

只有输入互不等待时并行：

- 已确认结构下，真实内容准备可与视觉资产核对并行。
- 独立页面的局部制作可并行，但共享组件变更必须串行收口。
- 研究材料整理可并行，洞察和原则必须合并后再派发方案。

不得并行：

- 同一共享组件的多个冲突改动。
- 依赖尚未确认的下游高保真制作。
- 同一测试对象在版本未冻结时的正式验证。

## RT5 D9 前置规划与执行时点

D9 位于决定链末端，但证据计划必须在工作开始前定义。D9-RUN 不一定发生在成品之后：研究和方案验证本身就是证据工作。

每个工作包先写：

```text
本轮要证明或验收什么：
证据类型：
测试/验收对象与冻结版本：
对象、样本或检查范围：
成功、失败和无结论信号：
谁有权确认：
D9 模式：
本轮是否执行：
执行时点或延期触发条件：
结果将改变哪个 D：
```

每项证据选择一种模式：

1. **`CORE_EVIDENCE`**：证据产生就是本轮核心工作。
   - 适用：问题探索、访谈/观察、方案验证—验证执行、人工价值交付。
   - D9-RUN 在研究或测试过程中执行，并直接产出本轮结论。
2. **`POST_ARTIFACT_ACCEPTANCE`**：先形成成品，再做回归、对照或验收。
   - 适用：直接制作、局部优化、UI/视觉/动效交付、精确还原。
   - D9-RUN 在冻结成品版本后执行。
3. **`DEFERRED_NEXT_ROUTE`**：本轮只把方案或原型准备到可验证，正式验证明确推迟。
   - 适用：用户明确只要流程、规格或测试原型，且验证不在本轮授权/资源内。
   - 必须写下一责任人、触发条件和待验证决定；本轮不得将相关决定标为已验证或因有效性而 `CONFIRMED`。

同一工作包可以有多项证据，例如“静态规格验收 = `POST_ARTIFACT_ACCEPTANCE`，真人任务验证 = `DEFERRED_NEXT_ROUTE`”。每项分别标模式，不用静态通过冒充行为有效。

所有模式都先完成 **D9-PLAN**。只有前两种在本轮执行 **D9-RUN**；延期模式只交验证就绪条件和明确下一路线。

## RT6 选择最小方法组合

对决定工作集中的每个决定，先写待回答问题，再到 [methods-dispatch.md](methods-dispatch.md) 选择方法。对证据动作集，按待验证判断选择 PROTO/VAL/回归/对照方法；这不会在测试前重开 `TEST_INPUT`。制作动作集按已确认来源直接执行，不得为了“有方法”调用已满足跳过条件的设计方法。

### 方法的三类职责

1. **补输入**：CT / CMP / R，补足语境、证据和设计原则。
2. **形成方案**：F / I / U / V / M，产生流程、交互、UI、视觉或动效。
3. **形成证据**：PROTO / VAL / 回归 / 对照，回答 D9。

同一方法可以回答多个相邻问题时合并执行；不同方法产出重复时只保留证据更直接的一种。

直接应用批准文案、导出既定资产、按正式主稿还原等属于“制作动作”，不是解决设计决定的方法。它们使用 RT3 的动作合同，并由 D9 验收结果。

### 每个方法必须填写

以下是 N4 路由摘要，不是执行账本；N5 必须按 [methods-execution.md](methods-execution.md) `EX1–EX3` 建立完整动作状态、步骤和交接记录。

```text
要回答的问题：
为何此方法能回答：
最低输入及来源：
执行范围：
产出：
完成证据：
停止信号：
结果进入哪个决定：
不得替代：
```

### 停止信号

方法不是“做得越多越完整”。出现下列任一即停止：

- 当前决定已有足够证据转为 `CONFIRMED`。
- 达到产出合同要求，新增材料不再改变选择。
- 发现必须由外部责任人决定，转 `BLOCKED`。
- 证据推翻上游判断，回到受影响的最早决定。
- 本轮只允许 `ASSUMPTION/ACCEPT_FOR_NOW`，已写清风险和补证。

## RT7 按风险调整深度

不用统一问卷或固定研究人数。每个因素必须记录来源和判断依据：

| 因素 | 要判断什么 |
| --- | --- |
| 后果 | 做错是否造成金钱、健康、隐私、权限或声誉损失 |
| 可逆性 | 能否撤销、恢复、申诉或回退 |
| 新颖度 | 用户和项目是否已有可复用且适用的模式 |
| 不确定性 | 关键判断的证据是否直接、近期且适用 |
| 影响面 | 是否涉及共享组件、多模块、多角色、跨端或外部系统 |
| 投入 | 开发、迁移和推广成本是否难以回收 |

每项填写：

```text
因素：
等级：LOW / MEDIUM / HIGH / UNKNOWN
来源状态：INPUT_FACT / DESIGN_INFERENCE / ASSUMPTION / MISSING
证据或判断依据：
若判断错误的影响：
对方法深度和 D9 的要求：
```

等级规则：

- `LOW`：有直接依据，影响局部、可逆、容易回归。
- `MEDIUM`：存在有限影响、部分新模式或证据不完整，但可以在受控范围验证。
- `HIGH`：可能造成重大损失、不可逆结果、广泛共享影响或高投入。
- `UNKNOWN`：没有足够依据。与本轮决定有关的 `UNKNOWN` 不得按低风险处理；标 `MISSING` 或 `BLOCKED`，先补证或限制范围。

选择本轮深度：

- `LEAN`：所有相关因素均有依据且为 LOW。采用规格核对和受影响范围回归。
- `FOCUSED`：存在 MEDIUM，但没有未处理 HIGH/关键 UNKNOWN。覆盖代表链路、关键失败和相邻影响。
- `HIGH_ASSURANCE`：任一相关因素为 HIGH。采用与后果相称的真实内容、关键角色/情境、失败恢复、专业责任方和更完整受影响范围证据。

关键 `UNKNOWN` 存在时不能直接选 `LEAN`。可先建立受限的补证工作包；在缺口关闭前，不执行不可逆制作或宣称高风险决定通过。

**产出**：风险深度记录、所选 `LEAN/FOCUSED/HIGH_ASSURANCE`、方法增减理由和对应 D9 证据强度。
