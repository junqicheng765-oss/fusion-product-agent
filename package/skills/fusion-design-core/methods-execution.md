# N5 方法执行与衔接

目的：把 N4 路由形成的工作包真正执行出来。N5 不重新决定本轮终点，也不把方法清单机械跑一遍；它逐项回答工作包里的问题，把每个方法产出交给明确的下游，并在证据改变前提时及时停止和重路由。

本文件规定所有方法共用的执行合同，不替代各方法文件中的具体步骤、跳过条件和不得替代项；两者同时适用，取证据和风险要求更严格者。

## 输入

- 本轮产出合同。
- 设计语境、设计任务、原则和关键矛盾。
- D1–D9 状态与本轮动作。
- 决定工作集、制作动作集和证据动作集。
- 最终设计起点、风险深度及明确跳过项。
- [methods-tool-routing.md](methods-tool-routing.md) 形成的产物—工具合同及交接依赖。
- 每个已选方法对应的方法文件。

## 输出

- 已完成的方法执行记录及准确产物版本。
- 每项产物怎样改变目标决定、怎样进入下一个方法。
- 已执行的制作动作及修改前后证据。
- 已运行或延期的证据动作。
- 新发现的冲突、阻断、假设和重路由结果。
- 可供 N6/N7 收口与回传的证据包。

## EX0 冻结本轮工作包

执行前先把 N4 结果转换成可执行动作，不在执行过程中悄悄扩大范围。

每个动作先标一个主要类型：

1. **决定动作**：需要通过设计方法回答一个尚未解决的问题。
2. **制作动作**：决定已经确认，只应用指定来源形成成品。
3. **证据动作**：准备测试载体、取得证据或验收成品。

同一次实际执行可以连接两类工作，但不能丢失任一合同。例如 R3 既解决 D2 的未知，也产生 `CORE_EVIDENCE`，执行卡以“决定动作”为主，同时引用对应证据动作 ID；无需把同一次访谈做两遍。制作后的回归则保留为独立证据动作。

为每个动作填写：

```text
动作 ID：
动作类型：决定 / 制作 / 证据
关联动作 ID：（同一次执行同时服务的决定或证据）
动作状态：DRAFT / READY / RUNNING / PREPARED_ONLY / DONE_PREPARED / BLOCKED / NO_CONCLUSION / DONE
外部执行状态：N/A / PLAN_ONLY / PREPARED / EXECUTED
它要回答或完成什么：
对应目标决定：
前置输入及准确来源：
执行方法或指定操作：
所选工具及职责边界：
风险深度：LEAN / FOCUSED / HIGH_ASSURANCE
产物及准确版本：
谁会使用这个产物：
停止信号：
失败、冲突或缺输入时回到哪里：
```

以下情况不能开始：

- 不知道该动作服务哪个目标决定或产出。
- 方法最低输入没有满足。
- 制作动作没有正式来源、目标对象或允许修改范围。
- 证据动作没有待验证判断、对象版本或成功/失败/无结论信号。
- 产物没有下游使用者，只是“做了显得完整”。

### 动作生命周期

- `DRAFT`：动作卡尚缺字段，不能执行。
- `READY`：输入门、范围、停止和证据要求齐全，可以开始。
- `RUNNING`：已发生实际操作，并有步骤账本。
- `PREPARED_ONLY`：脚本、原型、招募条件或检查程序已准备，但外部研究/测试尚未真实执行。
- `DONE_PREPARED`：本轮合同明确只要求验证准备；对象、预测试/完整性验收和延期合同均已完成，但外部证据仍未执行。被测决定保持 `TEST_INPUT`。
- `BLOCKED`：缺外部事实、资产、权限或授权；记录暂停原因和恢复入口。
- `NO_CONCLUSION`：动作已执行，但证据不足或程序失效，不能更新目标决定。
- `DONE`：产物、完成证据、交接和状态更新均已记录。

允许的主要转换：

```text
DRAFT → READY → RUNNING → DONE
                   ├→ NO_CONCLUSION
                   └→ BLOCKED → READY
READY → PREPARED_ONLY → DONE_PREPARED（验证准备本轮终点）
                       └→ READY 或 RUNNING（后续新路线获得执行条件）
```

研究、观察、测试或外部审核另标真实执行状态：

- `PLAN_ONLY`：只有计划、脚本或招募条件。
- `PREPARED`：对象、参与者/检查范围和材料已就绪，但尚无真实场次或审核结果。
- `EXECUTED`：存在可追溯的场次 ID、观察/检查记录和实际结果。

`PLAN_ONLY/PREPARED` 不能产出“用户发现、验证结果或审核通过”。

## EX1 建立方法执行卡

每个已选方法单独建卡。不能只写“做访谈、画流程、优化 UI”。

```text
方法：
待回答的唯一主问题：
为何当前需要它：
触发条件怎样成立：
最低输入及来源状态：
明确不回答什么：
执行对象、样本或页面范围：
适用的设计原则与硬约束：
本轮风险深度怎样改变执行范围：
预期产物：
产物进入哪个决定或下一个方法：
完成证据：
停止信号：
不得用什么冒充结果：
```

### 输入状态检查

逐项核对最低输入：

- `INPUT_FACT`：可直接使用，但保留来源、时间、对象、平台和版本。
- `USER_DECISION`：只在授权范围内使用，不扩大解释。
- `DESIGN_INFERENCE`：允许作为设计推导，但必须能回溯事实和推导过程。
- `ASSUMPTION`：写明若错影响、补证方式和回查时点。
- `MISSING`：不同答案会改变结果时，不能开始依赖它的下游方法。
- `BLOCKED`：记录谁提供、影响什么、恢复节点；受影响动作暂停。

最低输入不满足时，只能：

1. 复用已有有效来源；
2. 调用工作包中已经批准的补输入方法；
3. 将可安全暂用的内容标为假设；
4. 请求外部责任人决定；
5. 缩小范围，使缺口不再影响本轮；
6. 阻断受影响部分。

如果需要的补输入方法不在当前工作包中，先回 N4 更新依赖、范围和证据计划；不能在 N5 临时插入并扩大任务。

不能靠常识、年龄、行业印象、竞品截图或下游视觉自行补空。

## EX2 执行一个方法

### 2.1 保持主问题不变

方法开始时重写一次主问题。执行中出现新问题，先做影响测试：

- 会改变本方法产物：加入当前动作或申请重路由。
- 不改变本方法产物：进入待办池，不扩大本轮。
- 必须由上游或专家决定：标责任人，不由设计师代答。

### 2.2 分开记录材料、解释和选择

所有方法都至少保留三层：

1. **材料**：用户原话、行为、数据、现状画面、正式规则或主稿。
2. **解释**：材料可能说明什么，适用范围是什么。
3. **设计选择**：基于哪些材料和原则选择哪个方案。

不能把解释写成用户事实，也不能把设计选择倒写成“研究表明”。

### 2.3 按方法步骤形成中间产物

不要等到最后只交一张漂亮结果。方法文件中的每一步应留下能检查的中间状态，例如：

- 研究：来源索引、逐条材料、编码或分组、冲突、洞察。
- 流程：范围、场景、步骤、系统响应、失败和结束态。
- 交互：页面职责、入口返回、主行动规则、状态和异常。
- UI：信息分层、行动层级、组件选择、真实文案和完整状态。
- 视觉：依据、变量、资产来源、候选差异和应用范围。
- 动效：触发、对象、属性变化、起止状态、取消和减弱方案。
- 原型：待测判断、可用路径、代表内容、预测试和冻结版本。

每执行一步都追加账本：

```text
步骤 ID：
方法步骤：
输入及来源：
实际操作：
中间产物及版本：
检查结果：
状态：NOT_STARTED / RUNNING / PASSED / FAILED / BLOCKED / SKIPPED
跳过、失败或暂停理由：
恢复入口：
```

没有实际操作和中间产物的步骤不能标 `PASSED`。外部动作没有真实场次、检查或测试记录时，外部执行状态只能是 `PLAN_ONLY/PREPARED`；若本轮是验证准备，动作可在延期合同完成后标 `DONE_PREPARED`，不能标 `DONE/EXECUTED`。

### 2.4 每次关键选择写选择记录

```text
要选择什么：
候选：
硬门槛淘汰了什么；理由：
主排序标准：
选择：
依据：
代价：
仍未证明什么：
谁有权确认：
```

没有人类拍板权限时，Agent 只能给推荐和依据，不能把候选自动写成已确认。

### 2.5 在停止信号处停

出现任一情况即结束当前方法：

- 主问题已经得到足以支持本轮产出的答案。
- 新材料不再改变选择或风险判断。
- 达到本轮风险深度要求。
- 发现问题属于其他决定，需要重路由。
- 需要外部事实、资产或授权，转为阻断。
- 证据推翻当前前提，不能继续制作下游。

“还能继续做得更完整”不是继续执行的理由。

## EX3 方法结果怎样进入下一步

方法完成后必须填写交接，不允许只把文件丢给下游。

```text
本方法回答了什么：
没有回答什么：
关键产物及版本：
哪些内容是事实 / 推导 / 假设 / 人的决定：
更新哪个 D；建议状态：
下一个动作可直接使用什么：
下一个动作仍缺什么：
适用人群、情境、平台和范围：
```

### 研究与语境 → 流程

流程可以接收：

- 已确认或明确标假设的用户任务；
- 触发、情境、当前做法和失败后果；
- 可观察成功；
- 需要降低的摩擦、不确定或风险；
- 技术、权限、运营和范围约束。

流程不能接收：

- 没有来源的通用画像；
- “用户喜欢简洁”一类不能改变步骤的结论；
- 已经包装成页面或功能的伪洞察。

### 流程 → 交互

交互可以接收：

- 主场景和受影响次场景；
- 每一步用户意图、系统响应和下一状态；
- 成功、主动放弃、系统失败和部分完成；
- 已确认的范围与干预点。

如果只有页面清单、菜单树或功能名，不能进入交互。

### 交互 → UI

UI 可以接收：

- 每页职责、主行动和进入条件；
- 对象词表、导航和返回规则；
- 可用/禁用条件、即时反馈、成功和失败去向；
- 空、慢、错、无权限、冲突和部分成功状态；
- 最少信息与真实内容要求。

若页面职责、反馈或异常仍未知，UI 不能用排版和组件自行补齐。

### UI 结构与内容 → Figma 界面视觉

Figma UI 的界面视觉可以接收：

- 已确认的信息层级、主次行动、组件和状态；
- 真实或有代表性的内容长度；
- 正式设计系统、品牌材料、资产和允许探索范围；
- 感知目标与具体禁令。

若信息层级仍不成立，界面视觉不能用颜色、留白或大字假装解决。D6→D7 是同一 Figma UI 主稿内的决定依赖，不要求另起外部视觉工具；只有最终产物是非界面视觉成品，或用户明确拆分了独立视觉资产委托时，才按工具合同建立视觉工具动作。

### 交互 → 动效

动效可以接收：

- 已定义的触发、反馈含义和起止状态；
- 层级、返回、成功、失败和中断规则；
- 是否允许打断、取消和减弱。

动效不能发明新的反馈语义、导航层级或成功结果。

### 任一方案 → 原型与验证

原型可以接收：

- 一条明确待验证判断；
- 被测行为群体与任务原话；
- 为回答判断所需的最少内容、路径、状态和失败分支；
- 不验证的内容和允许模拟的边界。

没有待验证判断时不做原型；原型完成不等于方案有效。

## EX4 决定串行还是并行

默认按依赖串行。只有两个动作互不等待、不会修改同一共享对象，才能并行。

可以并行：

- 已确认结构下，真实文案准备与视觉资产核对。
- 不同独立页面的局部制作。
- 多份研究材料的初步整理，之后统一归纳。
- 同一验证计划中互不影响的招募和原型预测试准备。

必须串行：

- 问题尚未确定时的正式方案制作。
- 流程未确定时的页面职责和高保真 UI。
- 交互状态未确定时的 UI 状态与动效。
- 同一共享组件的多个冲突修改。
- 原型未冻结时的正式测试。
- 测试结果尚未判断时的规模化实现。

并行结果必须在同一个决定节点合并；不能各自形成互相矛盾的“最终方案”。

## EX5 执行制作动作

制作动作不调用用来重新做决定的方法，但必须有完整执行记录。

### 制作前

1. 锁定正式来源、版本和可编辑目标。
2. 确认目标文件、页面、节点、组件或资产。
3. 写允许改变、不得改变和范围外内容。
4. 记录共享影响、回滚方式和验收对象。
5. 关键资产、权限或来源冲突时停止。

### 制作中

1. 只应用动作合同中的确认内容。
2. 记录所有实际改动。
3. 发现必须新增设计判断时暂停对应部分，将其转为决定缺口。
4. 不把个人改良、近似资产或占位内容混入成品。

### 制作后

1. 冻结成品版本。
2. 生成修改前后或来源—成品对照。
3. 按证据动作执行范围回归或精确验收。
4. 未经授权差异未清零时，不能称完成。

## EX6 执行证据动作

EX6 是所有证据动作的唯一执行入口。Framework N6 和 [methods-close.md](methods-close.md) 只规定原型、验证、验收怎样解释和收口；它们读取同一 EX6 动作 ID 与步骤账本，不创建第二次执行。需要本轮运行的证据尚未执行时，必须先回 EX6 将动作从 `READY/PREPARED_ONLY` 推进；`DEFERRED_NEXT_ROUTE` 在准备合同完成后标 `DONE_PREPARED`。已有 `EXECUTED` 记录时禁止重复运行，除非版本、程序或范围变化后由 N4 明确新建证据动作。

每项证据单独执行，不能用一种通过冒充另一种成立。

### CORE_EVIDENCE

研究、观察或正式验证就是本轮核心工作：

1. 先冻结问题、对象、程序和记录格式。
2. 按选定方法取得证据。
3. 同时记录支持、反对、意外和无结论。
4. 只有证据范围足够时才更新对应决定。

### POST_ARTIFACT_ACCEPTANCE

先形成成品，再验收：

1. 冻结成品及准确版本。
2. 按预先定义的检查范围逐项执行。
3. 区分通过、未通过、未覆盖和无法验证。
4. 修正后重新检查受影响项，不能只改不回归。

### DEFERRED_NEXT_ROUTE

本轮不运行正式验证：

1. 冻结待验证对象。
2. 写清责任人、样本或检查范围、程序和触发条件。
3. 记录结果会改变哪个决定。
4. 对象完成只能标“测试就绪”，不能标“已验证”。

## EX7 证据或执行结果改变前提时

### 支持当前判断

- 记录证据适用范围。
- 只更新直接被支持的决定。
- 继续尚未完成且依赖已满足的下游动作。

### 推翻当前判断

1. 暂停依赖它的下游动作。
2. 找到最早受影响的决定。
3. 将被测决定转为 `MISSING/RESOLVE_NOW`。
4. 保留未受影响产物，不从头重做。
5. 回到 N4 生成新的工作包。

### 结果无结论

- 不选择对团队最方便的解释。
- 记录是样本、对象、程序、版本还是事实缺失导致。
- 转为 `ASSUMPTION`、补证或 `BLOCKED`。

### 来源冲突

不能把冲突平均掉。依次比较：

1. 是否回答同一个问题；
2. 用户群、情境、平台和时间是否相同；
3. 行为证据还是态度表达；
4. 来源是否直接、近期且适用；
5. 是否需要上游或专家裁决。

冲突未关闭且会改变产出时，暂停受影响下游。

### 发现范围外问题

- 会造成当前方案不安全、不可完成或明显返工：回到 N4。
- 只影响未来范围：进入回传，不扩大本轮。
- 属于共享或全局问题：记录影响面和责任人，未经授权不修改。

## EX8 按风险深度调整执行

风险深度改变覆盖范围和证据强度，不改变方法的基本逻辑。

### LEAN

适用：相关风险有直接依据且为低风险、局部、可逆。

至少覆盖：

- 本轮指定对象；
- 主路径或正常状态；
- 由本次修改直接影响的失败/边界；
- 修改前后或来源—成品对照。

### FOCUSED

适用：存在中等风险、有限新模式或共享影响。

至少增加：

- 代表性主场景和关键次场景；
- 主要失败、返回和恢复；
- 相邻路径与共享组件回归；
- 关键行为群体或内容极值；
- 对未关闭假设的明确补证。

### HIGH_ASSURANCE

适用：金钱、健康、隐私、权限、声誉、不可逆结果或广泛共享影响。

至少增加：

- 所有高后果步骤、角色和权限；
- 真实或足够代表性的关键内容、数字和状态；
- 预防、确认、凭证、撤销、申诉和恢复；
- 专业责任方、合规或领域审核；
- 跨模块、跨端和上下游影响；
- 与后果相称的正式验证和残余风险签收。

关键风险为 `UNKNOWN` 时不能按 LEAN 执行；先补证、缩小范围或阻断。

## EX9 常见工作包怎样执行

以下是依赖示例，不是固定流水线。

### 原因未知的问题诊断

```text
R0 审计现有证据
→ 能定位问题：直接进入受影响决定
→ 不能解释原因：R3 情境访谈或 R4 观察
→ 多来源材料需要归纳：R6
→ 多个未知争夺资源：R7
→ 需要定义价值行为：R8
→ CORE_EVIDENCE 收口并回到 N4
```

R5 同理心地图只有在已有跨来源材料且需要整理矛盾时插入，不是默认步骤。

### 已确认问题，设计任务流程

```text
复用已确认 D1–D3
→ F1 确定本轮范围
→ 情境会改变步骤时用 F2
→ F3 形成用户行为、系统响应、失败和结束态
→ 需要寻找干预原理时用 F4
→ 需要控制实现投入时用 F5
→ 冻结流程版本并验收
```

局部流程问题只执行受影响段，不重画整条旅程。

### 已确认流程，形成交互与 UI

```text
F3 路径作为输入
→ I1/I2/I3 确定页面边界、命名进出和职责
→ I4 表达结构
→ I5/I6 补齐反馈和异常
→ U1/U2 确定信息与行动层级
→ U3/U4/U5/U6 完成组织、组件、状态和真实文案
→ POST_ARTIFACT_ACCEPTANCE 回归主路径、失败和共享影响
```

若某项已有确认来源，直接复用并跳过对应方法。

### UI 结构已确认，形成 Figma 正式界面视觉

```text
复用 D4–D6
→ 在 Figma UI 主稿中用 V1 锁定视觉依据和允许探索范围
→ 按实际缺口选择 V2/V3/V4/V5
→ 只有需要人选方向且没有基线时使用 V6
→ 界面中的插画、图片、图标和品牌图形仍在 Figma UI 中完成
→ 只有明确存在独立视觉资产委托时，才调用视觉工具并在验收后导入 Figma
→ 冻结 Figma 主稿并做界面视觉和状态验收
```

已有正式系统和主稿时，不运行界面视觉探索；按制作动作应用并验收。需要正式 UI 交互动效时另建动效工具动作；Figma 原型只作预览。视频/动态图形或格式特定动画直接按各自产出合同路由，不强制经过本段。

### 直接制作或精确还原

```text
决定工作集可以为空，但这一屏的分区和材质不能空
→ 核对 design-decisions.md 第 2、3 块已写完
→ 预设整套落地，结构跟风格族走
→ 按正式来源制作
→ 截图对照第 3 块，跑 QA0 维度二第 5 项
→ 差异清零或退回改页面
```

决定工作集为空，只表示不重做调研和已确认的上游。不表示可以跳过分区、风格落地和验收。

### 验证准备

```text
冻结 TEST_INPUT
→ PROTO1 准备最小有效载体
→ 预测试并修复断链
→ POST_ARTIFACT_ACCEPTANCE：原型完整性
→ DEFERRED_NEXT_ROUTE：正式验证合同
→ 停在“测试就绪”
```

### 验证执行

```text
冻结 TEST_INPUT 和测试版本
→ 选择一个能回答当前判断的 VAL 方法
→ CORE_EVIDENCE
→ 支持 / 推翻 / 无结论
→ 更新决定状态
→ 回到 N4 继续、修正、重定义或停止
```

## N5 通过门

- [ ] 每个方法都回答一个具体问题，不是阶段名称。
- [ ] 每个动作有合法生命周期和逐步骤账本；暂停后知道从哪里恢复。
- [ ] `PLAN_ONLY/PREPARED/DONE_PREPARED` 没有被写成真实研究、验证或审核结论。
- [ ] 每项正式产物都有工具合同；低保真 Figma、Figma UI 主稿和 Figma 动效预览没有混写。
- [ ] 非界面视觉成品与各类正式动效只调用必要专业工具；视频/动态图形和非 UI 格式特定动画没有被强制套入 Figma + M1–M3，也没有形成固定工具流水线。
- [ ] 每项最低输入有来源、状态和适用范围。
- [ ] 材料、解释、设计选择和人的决定没有混写。
- [ ] 每个产物都有明确下游或验收用途。
- [ ] 已满足跳过条件的方法没有为了形式执行。
- [ ] 制作动作没有偷偷引入新设计判断。
- [ ] 证据动作按模式在正确时点执行或延期。
- [ ] 方法在停止信号处结束，没有无条件扩大范围。
- [ ] 前提被推翻时暂停了受影响下游并回到最早决定。
- [ ] 完成后可以准确说明做了什么、为什么、证据是什么、仍未知什么。
