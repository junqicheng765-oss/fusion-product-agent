# 设计成果、工作环节与子任务

本目录按使用者要拿到的成果组织设计路径，并说明完成它需要哪些专业环节、可能包含哪些子成果。接入原 N0–N5、RT0、方法库及验收；不另设阶段、状态机或逐步审批。原 T01–T15 的内容与方法保留并重新组织，旧编号仅在文末用于追溯。

下列路径是现有最低依赖和方法入口。[产品界面与网站](workflow-product-interface.md) 已按确认方案细化各环节的方法、资源、产出和自审；其他主流程的详细细则仍需逐条制定、确认。列入目录不代表专项能力已全部补齐。

## 接单先明确成果与关系

- **主成果或独立环节**：本轮最终交付什么。可以是完整网站、活动、报告，也可以只委托研究、流程、图表或动效；独立环节不必先归属于某个更大的项目。
- **本轮工作范围与起止**：哪些环节要新做、修改、复核或复用，到哪里结束。AI 核对前置依据后判断切入点，不要求使用者选内部编号。
- **子成果与依赖**：整体成果包含哪些页面、物料、图表、资产、视频等，它们共享哪些依据、各自需要什么输入，以及怎样回到整体成果检查。主任务或子任务的身份由本次委托决定，不是某项能力的永久分类。
- **工作方式**：新建、优化、还原、评审、验证、交接等动作诉求，仍映射原工作模式。
- **交付载体**：Figma、HTML、文档、位图、矢量、PDF、视频等。在必要设计判断成立后，按 [TR0](methods-tool-routing.md) 由 AI 推荐、说明理由并请人确认，再实际制作；格式不决定专业路径。

“新建”沿用原工作模式：目标、使用者或价值不清楚时走问题探索；上游事实有效、解法待定时走原局部优化模式（也适用于按已知目标设计新成果）；按正式主稿执行走还原/交付；只有已批准内容的指定局部制作才走直接制作。验证已有方案走原方案验证模式，不能因已有通知文案或线框而把尚待设计的成果归为还原。

活动可包含互动页面、海报、插画和视频；报告可包含图表，图表也可带交互与动效。按真实依赖组合路径，不要求从下列七条主路径中互斥选一。只委托图标或研究时，到对应成果结束，不补做品牌系统或整套界面。

## 判断从哪里开始，以及怎样组合

1. **已有不等于已合理。** 检查现有研究、流程、架构、内容、交互或正式稿的来源、版本和本次适用性。通过则按原 `REUSE` 引用；有缺口则进入相应决定，不无故推翻全部已确认方案。
2. **按问题选择深度，必要判断仍需成立。** RT0 判断影响、证据、成熟度、试错代价和研究成本；可以复用可靠研究，不以行业熟悉或有 PRD 为由略过关键未知。直接上游未成立时先补足，不靠下游视觉掩盖问题。
3. **路径表示依赖，不是每次从头跑的流水线。** 同一成果中可同时有复用、复核和新设计。后续发现矛盾时回查最早受影响决定，保留未受影响成果；只做前置分析时不自动派发视觉制作。
4. **共享依据，分别完成专业判断。** 相同研究、概念候选、业务规则与素材来源只记录一次，用原决定/动作 ID 引用。子任务仍完成自己的必要设计和检查，结果回到父成果做整合验收；插入一张图或一段视频不能替代整体验收。
5. **保留已确认的制作与审阅节点。** 实际制作含方向样张前按 TR0 确认工具路线；方向样张按 DS1 隔离制作、自审后请人选择。多页面正式视觉先完成一个完整代表页，经 QA0、自我校正和人工确认后扩展，再整套终审与最终确认。选方向不等于批准代表页；单页面不额外设扩展门禁。纯研究报告不因此被当作多页面视觉设计。

## 七条常见主成果路径

以下路径共享 [全局资源入口](methods-resource-routing.md)，不分别拥有一套限定素材库；按当前内容、载体和表达需要调用，资源阶段标签与检索类型不构成成果白名单。

### 产品界面与网站

- **详细执行入口**：本轮包含界面成果时，按 [产品界面与网站详细流程](workflow-product-interface.md) 定位各适用环节，先核对已有依据，再决定新做、修改、复核或复用。九个环节嵌入原流程，不新增九个全局阶段或逐步审批；工具确认随实际制作动作执行，必要测试原型可按其问题提前分支。
- **成果与关系**：App、小程序、后台、网站或可操作 Demo；可以独立委托，也可以是活动等项目的子成果。下方研究、流程、架构/内容和交互环节共同支持这条路径，并非四个互斥任务。
- **最低依赖概览**：使用者、任务与场景 → 流程设计/合理性复核 → 信息架构与页面职责 → 内容表达和信息层级 → 具体交互、状态与异常 → 视觉方向与制作 → 代表页自审和人工确认 → 扩展与整套终审、最终确认。只做单页或局部时按范围核对直接依赖。
- **已有方法与资源入口**：下方各专业环节的 [CT/BR](methods-context.md)、[R](methods-research.md)、[CMP](methods-competitive.md)、[F](methods-flow.md)、[I](methods-interaction.md)、[U](methods-ui.md)，再接 [V](methods-visual.md)、[DS](methods-style-engine.md)、[CI](methods-color.md)；资源按 [环节—方法—资源对应表](methods-resource-routing.md) 查真实案例、交互规范、字体/风格/配色、组件与素材，按需接图表或动效子任务。
- **验收重点**：各直接上游判断有依据，主路径和适用状态真实可操作；用各方法的完成证据复核，再执行适用 QA0。已有稿不能自动跳过合理性检查，视觉不能替代流程与交互。

### 营销活动与互动体验

- **成果与关系**：活动落地页、专题、打卡、收集或其他参与体验；可包含页面、平面物料、图表、资产、动效或视频。HTML 只是载体，不能据此归为普通界面美化。
- **最低依赖概览**：对象、触达场景与活动目标 → 真实利益、资格和规则 → 参与流程及机制 → 创意概念 → 架构、内容与具体交互 → 各子成果制作 → 参与、完成、再次进入等适用状态与整合验收。不因营销默认加入抽奖或游戏化。
- **已有方法与资源入口**：[R8](methods-research.md)、[CT/BR](methods-context.md)、[F](methods-flow.md)、[I](methods-interaction.md)、[CC](methods-creative-concept.md)；F4 与 CC2 共用候选和选择记录，后续流程、架构、内容、交互、视觉分别设计和检查。按子成果接页面、传播物料与专项资源；机制参考不能代替真实利益或用户证据。
- **验收重点**：活动能被理解，利益与规则真实，概念和动作一致，完成反馈及再次参与理由有依据；子成果放回活动检查，保留适用的代表页及最终确认。

### 平面传播与物料

- **成果与关系**：海报、广告、Banner、封面、社媒图片、折页、展板及包装图形版面。数字展示和印刷物料共用传播设计入口，再按交付条件分支；连续阅读的册页可组合文档/出版路径。
- **最低依赖概览**：传播对象、渠道与目标 → 主信息、支持信息与行动 → 信息主次 → 表达概念 → 构图与图文关系 → 视觉风格与制作 → 实际尺寸和渠道检查。
- **已有方法与资源入口**：[CT6/CT7](methods-context.md)、[CC](methods-creative-concept.md)、[V3/V5/V7](methods-visual.md)、[CI](methods-color.md)、[IM](methods-image.md)、[TR4](methods-tool-routing.md)；查字体、配色、真实摄影及图标/插画资源，必要时接图表、资产子任务。信息设计可复用相关原则，不强制导航栏、控件或卡片。
- **印刷与包装图形分支**：在相应设计前取得用途、成品尺寸、展开/折叠关系及实际生产规格；补足刀模、出血、安全区、色彩输出、材料和打样依据。缺关键参数可继续不依赖它的概念探索，不能把模拟效果标为已可生产，不扩展为结构工程或实际下单。
- **验收重点**：第一眼焦点、阅读顺序、内容完整性、图文关系、裁切与实际尺寸；印刷分支另核对生产条件。选风格或生图不能代替信息和构图推导。

### 品牌识别与视觉系统

- **成果与关系**：Logo、品牌字、色彩、辅助图形及应用规范；可以包含图标、插画、角色或视频，但做这些资产不自动包含品牌定位与识别系统设计。
- **最低依赖概览**：定位、受众与差异 → 识别和感知目标 → 表达概念 → 标识及视觉语言 → 实际应用检验 → 使用规范。
- **已有方法与资源入口**：[CT7](methods-context.md)、[CC](methods-creative-concept.md)、[V](methods-visual.md)、[CI](methods-color.md) 及字体/配色资源可支持部分判断；现包缺完整品牌专项，需补足定位到识别、应用的实际专业依据。风格预设或一张 Logo 图不能证明完成品牌系统。
- **验收重点**：识别、辨识、一致性、缩放与不同媒介应用；未开展的权利检索、业务确认或应用测试如实标注。

### 设计系统与组件库

- **成果与关系**：基础规范、组件、变体、状态、使用规则及维护依据；可单独建设，也可由产品迭代中受授权的共性需求形成。
- **最低依赖概览**：盘点真实页面和现有系统 → 区分共性、语义差异及变体 → 规范与 token → 组件结构、状态和行为 → 代表性应用 → 跨页核验及维护。
- **已有方法与资源入口**：[CT3](methods-context.md)、[U4/U5](methods-ui.md)、[DS0–DS6](methods-style-engine.md)、[CI](methods-color.md)；先核对项目已有规范与组件，再查本地配方、适用的外部组件/设计套件，按需用同包 [Impeccable](../fusion-design-impeccable/SKILL.md) 的系统提炼参考。不新建平行产品正文或绕过共享模式授权。
- **验收重点**：真实场景能复用，合理变体保留，规范与实际表现一致；只整理色板和圆角不足以称完整系统。

### 演示、文档与出版

- **成果与关系**：演示文稿、培训课件、报告、手册及连续阅读材料；可包含信息图、图表、插画或视频，子成果服务整套论证与阅读顺序。
- **最低依赖概览**：读者与讲演/阅读场景 → 内容和论证结构 → 章节及页面叙事 → 信息主次、图文及版式 → 页面节奏与制作 → 整套阅读/演示检查。
- **已有方法与资源入口**：[CT6](methods-context.md)、下方架构与内容环节、适用的 [V3](methods-visual.md) 与字体资源；按实际内容接图表和资产专项。演示、长文分页和出版输出仍缺完整细则，需匹配实际可用的专项方法及文稿/演示工具。
- **验收重点**：整套逻辑、单页可读性、图文依据、分页/溢出与目标尺寸；多页视觉制作保留完整代表页确认，不要求逐页审批。研究结论的内容验收与另行委托的报告排版分别处理。

### 视频与动态图形

- **成果与关系**：宣传片、讲解视频、动态海报、片头等线性动态内容；可以独立制作，也可以是活动、品牌、产品说明或演示中的子成果。
- **最低依赖概览**：受众、渠道与传播目标 → 信息/脚本 → 叙事、分镜和节奏 → 关键画面、文字及适用声音 → 动态制作 → 整段播放和输出检查。静态物料升级可复用已核对的内容和构图。
- **已有方法与资源入口**：[CC](methods-creative-concept.md)、[TR5-B/TR5-C](methods-tool-routing.md)、[MI](methods-motion.md) 和图像资源提供部分支持；完整脚本、叙事、剪辑与声音流程仍需补足。线性运动不强套 UI 起止状态，仅其中表达操作反馈的部分关联交互动效。
- **验收重点**：信息在观看时长内成立，节奏和叙事连续，字幕清楚，声音适用时同步；按真实格式交付，不把像素视频称为矢量 Lottie，不凭首帧和运动提示词宣称完成视频设计。

## 跨主流程的专业环节，也可单独委托

这些是设计中的工作环节，不是进入界面前必须全部从零完成的四个独立项目。主成果决定哪些判断必要，RT0 决定方法与深度；只委托某一环节时，到其成果结束。

### 研究、问题诊断与策略

- **成果与最低依赖**：目标和范围 → 现有证据审查 → 研究/比较方法选择与实际执行 → 支持、反对材料及备选解释归纳 → 问题判断、机会、原则和下一步；不要求制作页面来证明研究完成。
- **已有方法与资源**：[R0/R0.1/R1–R8](methods-research.md)、[CMP1–CMP3](methods-competitive.md)、[CT/BR](methods-context.md)，按问题使用已有材料、公开资料及 RR 的真实案例；同理心地图与旅程用于整理证据或明确假设，不产生新的用户事实。需要验证再按条件接 PROTO/VAL。
- **验收**：来源、解释与假设分开，结论可影响决定，未执行访谈/观察不得写用户发现；人的业务选择不充当用户验证。

### 流程与服务体验

- **成果与最低依赖**：用户任务、参与者及现状过程 → 障碍和责任断点 → 目标流程 → 分支、失败与恢复 → 路径走查，可覆盖线上线下触点。
- **已有方法与资源**：[R6](methods-research.md)、[F1–F5](methods-flow.md)、[CT3/CT4/CT8](methods-context.md)；复用经过核对的项目流程，必要时查 RR / Mobbin flows / Page Flows 的适用案例。
- **验收及缺口**：谁在何时做什么、下一步谁接、结果与异常怎样处理可追溯。服务蓝图及前后台组织接力尚缺完整专项，需补真实运行事实，不用页面跳转图代替服务设计。

### 信息架构与内容

- **成果与最低依赖**：用户要找/理解什么 → 内容盘点 → 分类、命名及关系 → 页面/章节职责 → 主次和阅读顺序 → 实际表达 → 查找与理解检查。
- **已有方法与资源**：[CT6](methods-context.md)、[I2/I3/I4](methods-interaction.md)、[U1/U2/U6](methods-ui.md)；核对项目内容、术语和已有结构，非界面任务取适用的内容原则，不强套控件。真实卡片分类、树测试需补方法和参与条件，不能宣称现包已完成测试。
- **验收**：能找到、能理解，职责不重叠、内容完整，主次和词句服务任务；排版精美不替代内容判断。

### 交互与测试原型

- **成果与最低依赖**：核对流程和信息结构 → 动作与系统响应 → 控件 → 正常、等待、错误、空等适用状态 → 返回、中断和恢复 → 用必要原型承载待验证判断。适用于界面、活动及交互图表等。
- **已有方法与资源**：[I1–I6](methods-interaction.md)、[U4/U5](methods-ui.md)、[PROTO1](methods-prototype.md) 和适用 [VAL](methods-close.md)；按具体操作查 ARIA APG、交互模式及同包 Pro Max 的相关 UX 指导。原型只做到支持当前判断所需程度。
- **验收**：动作有可预期结果，关键分支可表达；AI 走查和原型可点击均不等于真实用户验证，低保真不冒充正式视觉。

## 可独立或嵌入的专项成果

以下专项可成为本轮主成果，也可作为任一适用主流程的子任务。只加载命中的方法与资源，不因一个项目含多种成果就重复跑整套研究；各子成果的范围、版本、输入输出及整合检查写入原工作包。

### 信息图、图表与数据可视化

- **成果与依赖**：读者问题 → 内容/数据来源与口径 → 要说明的关系或比较 → 结构/图形编码 → 标题、图例、注释和顺序 → 制作 → 准确性与理解检查。可用于页面、活动、海报、报告或视频；交互版再接交互与必要动效。
- **已有方法与资源**：[CT6](methods-context.md)、内容层级和同包 [UI/UX Pro Max](../fusion-design-ui-ux-pro-max/SKILL.md) 的图表选型知识可提供支持。已有图表建议不等于具备完整数据口径、编码、统计与误导性审查流程，正式制作需补实际专业依据。
- **验收**：数值、单位、比例和关系忠实，标注可解释；置入父成果后仍能理解，不以装饰性或动效掩盖信息。

### 图标、插画、角色等视觉资产

- **成果与依赖**：实际用途及识别内容 → 造型/构图 → 风格和套系规则 → 素材选择或制作 → 实际尺寸、背景与组合应用检查。服务产品、活动、传播或品牌时引用其有效输入，独立委托不自动扩大为品牌系统。
- **已有方法与资源**：[V5/V7](methods-visual.md)、[IM](methods-image.md) 和原资产合同；按用途查 IconScout、真实摄影或实际可用的生成工具。Logo 及品牌识别系统按品牌路径，原创角色体系超出现有资产检索/生成/落位基础时补足相应方法。
- **验收**：对象可识别、套系一致，边缘/清晰度、尺寸/透明度/格式及实际落位适合用途，来源和使用范围可追溯。

### 界面与交互动效

- **成果与依赖**：成立的任务和交互规则 → 运动表达的含义 → 起止及中间状态 → 时序与运动 → 打断、取消、反向和减少动效方案 → 正式实现与运行检查。可服务产品、活动和交互式图表，也可单独优化。
- **已有方法与资源**：[M1–M3/MI](methods-motion.md)、[TR5-A/TR5-C](methods-tool-routing.md)；按实际静态状态与交互规则查动效源码/素材，先明确目的再检索。纯线性视频按上方视频路径，不强加操作反馈规则。
- **验收**：含义清楚、操作可完成、状态真实，可打断和恢复；预览、规格或录屏不冒充正式交互实现。放回所属成果核对表现与操作一致。

## 每个环节怎样接回现有方法和库

按 [资源路由](methods-resource-routing.md) 的对应表，在原 N4 方法工作包与 N5 执行记录中明确：**要解决的判断 → 所选方法及触发理由 → 对应资源与实际可用性 → 产出和下游用途 → 完成证据**。不另建平行账本，不把列出方法名或链接当作完成。

- 必要研究与比较先按 RT0 判断，实际执行选中的方法；不能强制每个任务访谈、填同理心地图或查完所有库。
- 本地风格、配色、字体、组件数据与外部参考/素材入口分别标明。登记资源不等于已经连接、获得授权或取得素材；内部记忆有真实条目时才检索复用，机制存在不代表已有案例积累。
- 使用各方法自己的完成证据检查结果；视觉和交互成果另按适用 QA0/VE 自审、校正与确认。检查脚本、成熟库或人的同意不替代审美判断或真实用户验证。
- 研究、服务体验、内容等方法可跨主流程复用；UI 专项参考取其适用部分，不把界面规范推广到所有媒介。

## 专项补足与范围边界

品牌、数据可视化、服务蓝图、视频叙事、出版和印刷生产等仍有上述专项缺口。先检查同包或宿主实际可用的方法、专业资料与工具，明确输入、实际操作及可验证成果；可由设计判断补足的部分形成有来源或明确假设的执行方案。不能只因缺一份预写文档就停下所有工作，也不能把通用 UI 模板当作专业成果。

需要外部事实、资产或业务取舍时沿用原补输入规则；本目录不增加安装、外发、生产或其他范围外授权。接单卡、产出合同和步骤账本复用原记录，简记主成果或独立环节、本轮起止、子成果依赖、工作方式、载体、复核结论、所选方法/资源及缺口、验收与确认节点。
