# 设计任务类型与必要环节

本文件定义公司内部设计任务的 15 类覆盖范围，以及各类的最低设计依赖。它接入原 N0–N5、RT0、方法库及验收，不另设阶段或审批，不等于全部专项能力已经配齐。研究深度依 RT0 判断；下列必要环节必须有本轮设计结果，或已有且经本轮核对适用的依据。

## 接单时区分三个维度

- **任务类型**：本次要形成什么专业成果，从 T01–T15 中选主类，可组合次类。
- **工作方式**：新建、优化、还原、评审、验证、交接等动作诉求；仍按接单文件归入原工作模式，不另建状态机。
- **交付载体**：Figma、HTML、文档、位图、矢量、PDF、视频等。载体在设计路径确定后按 TR0 由 AI 推荐并请人确认，再进入实际制作，不决定任务类型。

“新建”按已有决定映射原工作模式：目标、使用者或价值尚不清楚时走问题探索；上游事实有效、设计解法待定时走原局部优化模式（适用于按已知目标设计新页面或新物料，不等于只许微调）；按正式主稿执行走还原/交付；只有已批准内容的指定局部制作才走直接制作。验证已有方案按原方案验证模式处理。不能因为通知内容或线框已给，就把尚待设计的成果归为直接制作或还原。

分类由 AI 根据实际目标、内容和行为判断，不要求使用者选择编号。活动可同时包含参与流程、互动页面、运营主视觉和动效；同一依赖、材料、设计决定和证据只记录一次，标清各部分依赖及整合验收，不为每个类别重跑同一研究。类型不明确且不同判断会改变成果时，先澄清本轮终点。

## 必要环节怎样执行

1. 按任务范围确定适用的设计路径和终点。只委托分析、流程或交互时，到该成果结束，不自动扩成视觉成品；只委托后续环节时仍核对直接上游依据。
2. **已有不等于已合理。** 核对现有流程、架构、内容和交互是否适合当前人群、场景、内容、平台及规则，记录准确来源、具体复核结论和影响。通过则按原 `REUSE` 引用；有缺口或问题按原决定链处理，不默认为通过，也不无故推翻全部已确认方案。
3. **按需调整方法与深度，必要判断仍需成立。** AI 按 RT0 决定用什么方法补足；“没调用新研究”不能等同“没想过使用者”，“有 PRD”不能等同“交互已经设计好”。不适用环节说明原因，不用一句“按需”省略关键依据。
4. 各路径表示输入依赖，不要求先重做一遍所有上游再开始下一项。内容、交互与视觉发现矛盾时回查最早受影响决定；未受影响成果保留，业务取舍和范围变化按原授权处理。
5. 视觉制作前必须具备该类型的内容职责、主次和结构依据。需要视觉方向探索时，按 DS1 在独立草稿制作并自审方向样张，供人看图选择；这不代替完整代表页批准。视觉风格选择、代表页、展示前自审、整套终审和最终人工确认仍按原适用规则执行。以下是设计路径，不重写具体工具、资产或脚本规则。

## T01 设计研究、问题诊断与策略

- **成果**：有依据的问题判断、机会、设计原则及下一步，不要求以页面证明分析完成。
- **必要路径**：目标与范围 → 现有证据审查 → 选择研究与比较方法 → 归纳支持/反对材料及备选解释 → 明确主要问题、方向与验证办法。
- **已有方法**：[研究 R0–R8 / R0.1](methods-research.md)、[竞品 CMP1–CMP3](methods-competitive.md)、[语境 CT9 / BR1–BR2](methods-context.md)；需要验证时按 [PROTO](methods-prototype.md) 与 [VAL](methods-close.md) 的条件调用。
- **验收重点**：来源与假设分开，结论能改变设计决定，不把工作假设或业务选择说成研究验证。

## T02 用户流程与服务体验

- **成果**：任务路径、角色接力、分支与完成/恢复规则，可覆盖线上线下触点。
- **必要路径**：用户任务与参与者 → 现状过程/旅程 → 障碍及责任断点 → 目标流程 → 分支、失败与恢复 → 路径走查。
- **已有方法**：[R6 现状旅程](methods-research.md)、[F1–F5](methods-flow.md)、[CT3 / CT4 / CT8](methods-context.md)。跨触点服务蓝图、前后台组织接力只有部分基础，需按实际任务补充专业方法与运行事实，不以页面跳转图冒充服务设计。
- **验收重点**：谁在何时做什么、下一步由谁接、结果与异常如何处理均可追溯；已给流程也须复核合理性。

## T03 信息架构与内容设计

- **成果**：分类、导航/章节、页面或内容单元职责、信息层级及实际表达。
- **必要路径**：用户要找/理解什么 → 盘点内容 → 分类、命名与关系 → 页面/章节职责 → 主次与阅读顺序 → 实际文案 → 查找与理解检查。
- **已有方法**：[CT6 信息理解](methods-context.md)、[I2 / I3 / I4](methods-interaction.md)、[U1 / U2 / U6](methods-ui.md)。这些入口目前分散在界面方法中；非界面任务取其内容原则，不强制套导航栏、控件或卡片。需要真实卡片分类、树测试等专项研究时先补足方法和参与条件，不宣称现包已完成测试。
- **验收重点**：信息能否找到、职责是否重叠、必需内容是否完整、主次与词句是否服务理解；精美排版不能替代此项。

## T04 交互设计与测试原型

- **成果**：操作规则、控件、状态、反馈、异常及用途明确的原型。
- **必要路径**：核对流程与信息结构 → 定义用户动作与系统响应 → 选具体控件 → 正常/等待/错误/空等适用状态 → 返回、中断和恢复 → 用原型承载待验证判断。
- **已有方法**：[I1–I6](methods-interaction.md)、[U4 / U5](methods-ui.md)、[PROTO1](methods-prototype.md) 与适用的 [VAL](methods-close.md)。
- **验收重点**：每个动作有可预期结果，关键分支能表达；低保真只承担交互验证，不冒充正式视觉或真实用户验证。

## T05 产品界面与网站设计

- **成果**：App、小程序、后台、网站等界面或可操作 Demo。
- **必要路径**：使用者、任务与场景 → 流程设计/合理性复核 → 信息架构与页面职责 → 内容表达和信息层级 → 具体交互、状态与异常 → 界面视觉方向和制作 → 代表页自审与人工确认 → 其余页面 → 整套终审与最终确认。
- **已有方法**：承接 T02/T03/T04 的实际结果，复用 [F](methods-flow.md)、[I](methods-interaction.md)、[U](methods-ui.md)，再进入 [V](methods-visual.md)、[DS](methods-style-engine.md) 和 [QA0](methods-close.md)。只做单页或限定局部优化时按范围核对相关依赖，不重画全产品；单页按原规则省略扩展门禁。
- **验收重点**：所有直接上游依据有效，已有稿不能自动跳过流程、架构、内容与交互检查；不能接单后直接选风格，也不能只靠视觉掩盖上游问题。

## T06 营销活动与互动体验

- **成果**：活动落地页、专题、打卡、收集或其他参与体验，通常是多类型组合。
- **必要路径**：对象、触达场景和活动目标 → 真实利益、资格与规则 → 参与流程及机制 → 创意概念与表达 → 信息架构、内容主次和具体交互 → 主视觉与界面制作 → 参与/完成/再次进入等适用状态核验。
- **已有方法**：[R8](methods-research.md)、[CT / BR](methods-context.md)、[F](methods-flow.md) / [I](methods-interaction.md)、[创意概念 CC](methods-creative-concept.md)，F4 与 CC2 共用同一概念记录，主题与行为部分按需补足，后续流程、架构、内容、交互、视觉仍分别设计和检查；按实际组成关联 T03/T04/T05/T07/T12/T13。不因交付 HTML 就归为普通界面美化，也不因营销就默认需要抽奖或游戏化。
- **验收重点**：活动能被理解、动作与概念一致、利益与规则真实，完成反馈及后续参与理由有业务依据；原代表页与整套确认仍执行。

## T07 平面传播与运营物料

- **成果**：海报、广告、Banner、封面、社媒图片等。
- **必要路径**：传播对象、渠道与目标 → 主信息/支持信息/行动 → 信息主次 → 表达概念 → 构图草图与图文关系 → 视觉风格 → 字体、色彩、素材及制作 → 实际尺寸审查。
- **已有方法**：[CT6 / CT7](methods-context.md)、[CC](methods-creative-concept.md)、[V7](methods-visual.md) 与 [TR4](methods-tool-routing.md)。只取信息设计原则，不强制 UI 的页面导航和控件流程。
- **验收重点**：第一眼焦点、阅读顺序、关键信息完整性、图文关系与渠道裁切；不能拿选风格或直接生图代替内容与构图推导。

## T08 信息图、图表与数据可视化

- **成果**：信息图、关系图、统计图、可视化报告或交互式数据表达。
- **必要路径**：读者问题 → 内容/数据来源与口径 → 要解释的关系或比较 → 选择结构/图形编码 → 标题、图例、注释和阅读顺序 → 视觉制作 → 准确性与理解检查。互动版本另接 T04/T05。
- **已有基础与缺口**：可复用 [CT6](methods-context.md) 和内容层级；现包缺完整的数据口径、图形编码及专业图表验收细则，不能仅用 UI 规则替代。正式制作须按下方专项补足规则找到实际可用的方法与工具。
- **验收重点**：数值、单位、比例与关系忠实，标注可解释，图形不能误导；装饰性强不代表解释清楚。

## T09 品牌识别与视觉系统

- **成果**：Logo、品牌字、色彩、辅助图形及品牌应用规范。
- **必要路径**：品牌定位、受众与差异 → 识别与感知目标 → 表达概念 → 标识及视觉语言 → 实际应用场景检验 → 使用规范。
- **已有基础与缺口**：[CT7](methods-context.md)、[CC](methods-creative-concept.md) 及 [V](methods-visual.md) 可支持部分判断；现包无完整品牌识别专项。风格预设或一张 Logo 图片不能替代品牌系统，需补足相应专业方法、应用和资产要求。
- **验收重点**：识别、辨识与一致性，缩放及不同背景/媒介中的应用；未做的权利检索、业务确认或实际应用测试不得声称完成。

## T10 设计系统与组件库

- **成果**：设计基础、组件、变体、状态、使用规则和维护依据。
- **必要路径**：盘点真实页面与现有系统 → 区分共性、语义差异和变体 → 基础规范与 token → 组件结构/状态/行为 → 代表性应用 → 跨页核验及变更维护。
- **已有方法**：[CT3](methods-context.md)、[U4 / U5](methods-ui.md)、[DS0–DS6](methods-style-engine.md) 及原跨页检查。
- **验收重点**：用真实场景证明复用，合理变体不被抹平，组件规范与实际表现一致；不能仅整理色板和圆角就称完整系统。

## T11 图标、插画、角色等视觉资产

- **成果**：独立图标、插画、头像、角色、吉祥物或背景图；Logo 系统归 T09。
- **必要路径**：实际用途和识别内容 → 造型/构图 → 风格及套系规则 → 素材选择或制作 → 实际尺寸、背景与组合应用检查。
- **已有方法**：[V5 / V7](methods-visual.md)、[IM](methods-image.md) 和原资产合同。具体绘制、生成或检索工具按原路线；资产在 UI 内使用不自动变成独立委托。
- **验收重点**：对象可识别、套系一致、边缘与清晰度、尺寸/透明度/格式及实际落位符合用途，来源和使用范围可追溯。

## T12 界面与交互动效

- **成果**：操作反馈、状态过渡、展开收起、导航与手势动效。
- **必要路径**：已成立的任务和交互规则 → 动效表达的含义 → 起止与中间状态 → 时序与运动 → 打断、取消、反向和减少动效方案 → 正式实现及运行验证。
- **已有方法**：[M1–M3 / MI](methods-motion.md)、[TR5-A / TR5-C](methods-tool-routing.md)；引用对应 T04/T05 状态与界面依据。独立非交互动画归 T13，不强加 UI 起止状态。
- **验收重点**：含义清楚、操作可完成、状态真实、可打断与恢复；预览、规格、录屏不能冒充正式交互实现。

## T13 视频、动态海报与动态图形

- **成果**：宣传片、讲解视频、动态海报、片头或其他线性动态图形。
- **必要路径**：受众、渠道与传播目标 → 信息/脚本 → 叙事、分镜和节奏 → 关键画面、文字与适用声音 → 动态制作 → 整段播放和输出检查。静态物料升级时可复用其已核对内容与构图。
- **已有基础与缺口**：[TR5-B / TR5-C](methods-tool-routing.md) 有格式和工具边界，[MI](methods-motion.md) 有部分品牌动效要求；完整叙事、分镜、剪辑与声音方法仍需专项补足，不能只凭首帧加运动提示词称完整视频设计。
- **验收重点**：信息在观看时长内成立、节奏与叙事连续、字幕清楚，声音适用时同步；像素视频与真矢量动画按实际格式交付。

## T14 演示文稿、文档与出版排版

- **成果**：演示文稿、培训课件、报告、手册及其他连续阅读材料。
- **必要路径**：读者与讲演/阅读场景 → 内容和论证结构 → 章节与页面叙事 → 信息主次、图文及版式 → 页面节奏与制作 → 整套阅读/演示检查。
- **已有基础与缺口**：[CT6](methods-context.md) 和信息层级可复用；演示、长文排版、分页及出版输出缺专项细则，需匹配实际可用的文稿/演示工具与专业方法。多页视觉稿仍执行原完整代表页、自审、人工确认后扩展的门禁，不要求每页分别审批。
- **验收重点**：整套逻辑与单页可读性、图文依据、分页/溢出、显示或打印尺寸；不能用一张长海报冒充演示或文档。

## T15 印刷物料与包装图形

- **成果**：折页、宣传册、包装图形版面、展板等设计文件。
- **必要路径**：用途、观看/使用方式与成品规格 → 内容及必须呈现的信息 → 展开/折叠/观看顺序 → 信息主次和构图 → 图形排版与材质表达 → 出样及生产条件核对。
- **已有基础与缺口**：[CT6 / CT7](methods-context.md) 和 [V](methods-visual.md) 可支持图文设计；刀模、出血、安全区、色彩输出与生产适配缺完整专项，必须取得本次实际生产规格并补足方法。缺关键参数时可继续概念设计，但不能把概念图标为已可生产。
- **验收重点**：实际尺寸、展开关系、内容准确性及生产规格适配。模拟效果图不证明生产可行，不擅自扩展为结构工程或实际下单生产。

## 方法覆盖与专项补足

- T01、T04、T05、T07、T10、T11、T12 可较多复用现有详细方法；T02、T03、T06 的主要方法分散或需组合；T08、T09、T13、T14、T15 的专项仍有上述缺口。这是方法覆盖说明，不是本次任务的执行或验收结果。
- 对缺口，先检查同包或宿主实际可用的专项方法、专业资料与工具，明确输入、实际操作及可验证成果；可由设计判断补足的部分形成有来源或明确假设的执行方案。需要外部事实/资产时沿用原补输入规则，不因缺一份预写方法文档就一概停工，也不能把通用 UI 模板包装成专业成果。
- 本目录不授权安装、联网外发、生产或其他范围外动作，不要求不存在的工具。选定所需能力后才进入原工具路由；实际缺失的格式、工具或事实如实报告，继续不依赖它的工作。
- 接单卡和产出合同简记“主类/组合类型、工作方式、载体、适用必要环节、已有依据的复核结果、所选方法与专项缺口、验收和确认节点”。复用原账本，不增加平行记录或固定问题轮次。
