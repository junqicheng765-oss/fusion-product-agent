# 研究方法库

只执行工作包点名的方法。研究不是所有设计任务的前置。
竞品与类比样本不在本文件混做：行业竞品、同类操作竞品和服务同类用户的竞品分别读取 [methods-competitive.md](methods-competitive.md)。

## R0 现有证据审计

**触发问题**：现有数据、研究、反馈和设计材料能回答什么，不能回答什么？  
**最低输入**：至少一项现有材料或可查询数据。  
**跳过**：没有任何材料，或材料与本轮决定无关。

**步骤**

1. 先写本轮要支持的决定和审计问题；把材料拆成最小可判断主张，一条主张一行并分配证据 ID。
2. 为每条主张填写逐条证据矩阵，不得只给材料做总评：

```text
证据 ID：
主张：
来源及可回查位置：
时间：
人群 / 情境：
平台：
样本 / 方法：
版本：
直接性 / 近期性 / 适用性：（分别写高 / 中 / 低 / 未知及理由，不合成总分）
限制：
冲突：
下一补证：
```

3. 将来源分成行为数据、用户原话/故事、渠道数据、实验结果和内部判断；同一来源支持多条主张时仍逐条建行。
4. 对每条主张分别判断：来源是否直接回答它、时间是否仍能代表当前情况、人群/情境/平台/版本是否适用于本轮；无法判断就写 `未知`。
5. 标出事实、解释和不能推断的内容；相关性、因果和内部判断分开。
6. 冲突证据不平均：核对是否同一问题、时间、人群、平台、样本/方法和版本，保留各自适用范围与待裁决点。
7. 只把会改变本轮决定的缺口写成“下一补证”，注明要补什么、由什么来源回答、结果会改变哪个决定；不重复已回答的问题。

**产出**：逐条证据矩阵、每条主张的可信范围、缺口、冲突和下一补证。  
**完成证据**：每个影响决定的主张都有可回查行；没有混用不同人群/时间/平台/版本；直接性、近期性、适用性分别判断；相关性和因果分开。  
**不得替代**：用滚动、跳出或点击数据推断用户动机；用一个“可信度总分”掩盖限制或冲突。

## R1 问题卡

**触发问题**：究竟在解决谁的哪件事，怎样算成功？  
**最低输入**：原始诉求或现有需求材料。  
**跳过**：D1–D3 已确认且本轮不改变它们。

**步骤**

1. 写用户在任务中的角色、熟练度、是否多人。
2. 写触发、时长、设备和情境限制。
3. 用“在约束下完成结果，以便……”写任务；禁功能名。
4. 分开写当前做法、卡点、失败后果。
5. 分开写用户目标、业务目标、体验目标。
6. 写可观察成功及“怎样不算成功”。

**产出**

```
用户 / 情境 / 任务：
当前做法 / 卡点 / 后果：
用户目标 / 业务目标 / 体验目标：
可观察成功 / 怎样不算：
约束 / 不做：
来源与假设：
```

**完成证据**：第三人能复述任务；成功可以观察；没有“更好用/提升体验”空话。  
**不得替代**：真实用户证据、业务拍板。

## R2 行为分群

**触发问题**：不同用户是否需要不同产品响应？  
**最低输入**：至少两类用户线索或历史材料。  
**跳过**：任务步骤、约束和判断标准相同。

**步骤**

1. 比较任务步骤、约束、成功判断。
2. 只有这些差异会改变设计时才分群。
3. 优先覆盖常做、刚失败、用 workaround 成功的人。
4. 人口属性只有改变语言、合规、渠道或行为时才保留。

**产出**：群体｜行为差异｜设计响应差异｜证据。  
**完成证据**：每个群体都能指出至少一个不同设计响应。  
**不得替代**：用国家、年龄直接造“人物画像”。

## R3 情境访谈

**触发问题**：真实过程、动机、判断“够了”的标准未知。  
**最低输入**：有来源且可复述的任务句（可来自已确认上游输入、N1.5 或 R1）；可接触目标用户。  
**跳过**：已有足够近期行为证据，或本轮不受这些答案影响。

**步骤**

1. 写清主问题、目标行为群体、必须覆盖的情境和不回答的内容；近期经历的时间窗必须来自任务周期或本轮决定，不得随意设定。
2. 建立筛选表：纳入条件、排除条件、条件来源、筛选题、答案证据和覆盖维度。筛选只确认真实经历与情境，不透露希望得到的结论；人口属性只有会改变任务或产品响应时才保留。
3. 给研究和每个场次标真实执行状态：
   - `PLAN_ONLY`：只有筛选条件、招募计划、提纲、同意说明或记录模板。
   - `PREPARED`：合格参与者、排期、材料/设备和记录方式已就绪，但访谈尚未发生。
   - `EXECUTED`：真实访谈已发生，并有场次 ID、场次头、逐步记录和实际结果。
4. 每场先冻结场次头：

```text
场次 ID / 执行状态：
日期、时间、时区 / 方式与地点：
参与者代号 / 行为群体 / 筛选依据：
研究者 / 记录者：
主问题 / 最近经历时间：
材料及版本：
参与同意 / 录音录像同意：
```

5. 开始前用参与者能理解的语言说明目的、会收集和怎样使用哪些信息、记录方式、真实的保存/访问规则，以及可跳题、暂停、退出或撤回的方式；分别记录参与同意和录音录像同意。未获参与同意不开始，未获录制同意不录制，只保留获准的记录。
6. 问最近一次真实经历，不问“一般会怎样”；依次回溯：触发 → 第一动作 → 工具/找谁 → 最难一步 → workaround → 怎样停 → 是否回看。
7. 用中性追问取得可回查细节。用户说“烦/智能”时追问当时在哪里、屏幕或环境中有什么、实际做了什么、随后发生什么；不补答案、不把推测塞进问题。
8. 分栏记录：原话｜行为｜工具/环境｜情绪表达｜研究者解读｜证据位置；材料、解释和设计含义不得混写。
9. 每场结束后记录有效性、已覆盖维度、新增/重复/冲突内容和下一场要补的缺口。筛选失败、中途退出或程序失效的场次保留记录并标原因，不计作支持结论的有效场次。
10. 预先写停止规则并逐场判断：
    - 单场在参与者撤回同意、出现不适/安全或隐私风险、确认不符合筛选条件时停止；记录停止点，不追问原因。
    - 整体在所需行为群体和关键情境已覆盖，继续执行不再改变本轮关键判断，且重要冲突与高后果未知已达到风险深度要求时停止。
    - 仍出现会改变决定的新模式、覆盖缺口或未解释冲突时继续或调整招募；不能仅因达到某个预设人数就宣称完成。

**产出**：筛选与覆盖表、执行状态、场次头、同意记录、逐步访谈记录，以及支持/反对/意外/无结论和停止判断。`PLAN_ONLY` 只产计划材料，`PREPARED` 只产就绪记录，只有 `EXECUTED` 才能产访谈证据。  
**完成证据**：状态与实际执行一致；每个关键判断能追溯到有效场次/原话/行为；隐私同意、覆盖、冲突和停止理由可检查。  
**不得替代**：先展示方案后问喜不喜欢；假意愿问题；用提纲、招募计划、预期回答或 `PLAN_ONLY/PREPARED` 冒充访谈结论。

## R4 观察

**触发问题**：用户说不清，或说法与行为可能不一致。  
**最低输入**：真实或足够接近真实的任务。  
**跳过**：任务纯认知/态度且无可观察行为，或已有近期行为录像。

**步骤**

1. 准备观察合同：主问题、真实任务、可观察起止、环境、必须覆盖的行为群体/情境/平台、材料版本、允许介入范围、隐私同意、事件日志格式、停止规则和下游决定。
2. 标真实执行状态：`PLAN_ONLY` 只有协议和模板；`PREPARED` 表示任务、合格参与者、环境、材料/设备和记录方式已就绪；`EXECUTED` 必须已有真实场次 ID、时间戳事件日志和实际结果。前两者不得产出观察结论。
3. 每场建立场次头：场次 ID、日期/时间/时区、参与者代号与筛选依据、任务与起始状态、地点/情境、设备/平台、对象或材料版本、观察者、参与及录制同意、执行状态。
4. 给出真实目标而不是操作路径，让参与者以自己的正常方式完成真实或足够接近真实的任务；不做操作导游、不纠正、不提示“正确做法”。为安全、隐私或任务无法继续而介入时，记录介入时间、内容和影响。
5. 按发生顺序写时间戳事件日志：

```text
时间戳 / 事件 ID：
任务步骤或触发：
可见行为 / 同时发生的原话：
对象、工具、参与者与环境：
结果 / 下一动作：
观察者介入：
证据位置：
解释或待证假设：（与事实分开）
```

6. 任务结束后才做中性追问，并引用具体事件：“刚才在【事件】时你想完成什么？”“当时你注意到什么？”“你预期下一步会发生什么？”“后来为什么停在这里？”不展示答案、不评价表现、不用功能名替参与者解释。
7. 逐条编码说做关系：`一致`、`说而未见`、`做而未说`、`说做不一致`、`可能受观察影响`、`无法判断`。每条保留原话事件 ID、行为事件 ID、情境和可能解释；可能解释标假设，不能把不一致写成动机或欺骗。
8. 只对有效 `EXECUTED` 场次做跨场归纳：按任务步骤、行为群体、情境和平台比较；每个模式列支持与反对的场次/事件 ID、适用范围和限制。抽样不支持总体推断时，不把场次频次写成发生率。
9. 维护覆盖表：计划覆盖｜已执行｜有效｜未覆盖｜冲突｜下一补证。单场在撤回同意、不适/安全或隐私风险、筛选无效、任务无法继续时停止；整体在必要覆盖完成、追加场次不再改变关键模式或风险判断、重要冲突已处理到本轮风险深度时停止。不得只按固定人数或“看起来饱和”停止。
10. 填交接：回答了什么、未回答什么、适用人群/情境/平台/版本、关键场次/事件、说做差异、覆盖与冲突、更新哪个决定及状态、下游可直接使用什么、仍需补什么。

**产出**：执行状态、场次头、时间戳事件日志、任务后追问、说做差异编码、跨场模式、覆盖/停止记录和下游交接。  
**完成证据**：只有真实执行才标 `EXECUTED`；事实、解释和设计含义分列；关键模式可回查到场次/事件；覆盖、冲突、停止与交接均有记录。  
**不得替代**：用竞品、客服或分析数据冒充现场行为；用观察计划、演示、研究者代操作或受引导任务冒充真实观察。

## R5 同理心地图

**触发问题**：已有多源材料，需要组织想/说/做/看到之间的矛盾。  
**最低输入**：访谈、观察、数据或明确标注的假设。  
**跳过**：没有材料且当前问题可由单一行为证据回答；不得仅为“做用研”而生成。

**步骤**

1. 一张图只服务一个行为群体和一个任务。
2. 四格填写：想/感受、说、做、听到/看到。
3. 每条标来源；“做”优先于“说”。
4. 从四格提取痛点、收获和需要减少的不确定。

**产出**：四格地图 + 设计含义。  
**完成证据**：每个结论可追溯；假设明确标注。  
**不得替代**：直接从地图跳到配色、页面或功能。

## R6 证据归纳与现状旅程

**触发问题**：材料很多，但尚未形成可设计的问题或机会。  
**最低输入**：访谈、观察、数据或工作假设包。  
**跳过**：问题位置和当前路径已有有效结论。

**步骤**

1. 一条事实一张记录，静默归类。
2. 标题写洞察，不写“价格/登录”等文件夹名。
3. 洞察格式：事实 → 动机/障碍 → 方向性机会 → 预期行为。
4. 若任务跨步骤，画现状旅程：行为、触点、想法、情绪、痛点、workaround。
5. 只标一个当前最高放弃点；换一种完全不同解法仍成立才是洞察。

**产出**：5–9 个洞察簇；必要时附现状旅程和问题定义句。  
**完成证据**：每个洞察会改变后续决策；有来源。  
**不得替代**：把解法包装成洞察。

## R7 危险假设

**触发问题**：多个未知中先验证哪一个？  
**最低输入**：问题卡或洞察。  
**跳过**：直接制作、设计还原，或没有方向性不确定。

**步骤**

1. 写：`我们相信【谁】在【情境】会【可观察行为】，因为【原因】。`
2. 为每条假设列现有支持、反对、缺口和若假会受影响的决定，再分别评“若假损伤”和“不确定”：
   - **若假损伤 1**：局部、低成本、可逆，不会使核心任务或下游决定失效。
   - **若假损伤 3**：会造成明显返工、关键任务受阻或有限范围损失，但有可行恢复方式。
   - **若假损伤 5**：会使核心价值失效，或带来金钱、健康、安全、隐私、权限、合规、声誉、不可逆结果或广泛下游失效。
   - **不确定 1**：有近期、直接、适用且相互一致的证据，只剩不改变方向的小缺口。
   - **不确定 3**：证据间接、局部、较旧或互有冲突，不同答案可能改变部分选择。
   - **不确定 5**：没有直接适用证据、关键证据冲突，或当前完全依赖未测试假设。
3. 只有能说明为何介于相邻锚点时才用 2 或 4；不得使用小数、虚构概率或加权系数。分数是排序标签，不是测量值。
4. 用“损伤 × 不确定”只做粗排，不解释数值差距。并列或仅靠主观细分拉开时，依次看：高后果硬风险、是否阻断更多当前下游决定、哪项能用更小的有效测试先消除关键不确定；仍并列则保留并列，由有权责任人选择本轮主测并记录理由，不伪造更精确的排名。
5. 只选一条本轮主测，其余留池；写支持、推翻和无结论信号，以及结果会更新哪个决定。

**产出**：一条主假设、损伤/不确定锚点及依据、并列处理记录、支持/证伪/无结论信号和次要池。  
**完成证据**：评分能回溯证据与后果；排序没有伪精度；一次研究或测试可以推翻主假设。  
**不得替代**：把多个假设同时做成完整方案；把序数乘积当成概率、收益或精确风险差。

## R8 价值主张与关键行为

**触发问题**：价值是否发生、转化/留存是否值得优化？  
**最低输入**：用户任务、当前替代做法、成功判断。  
**跳过**：纯视觉制作且不声称影响用户价值。

**步骤**

1. 写价值主张：谁、情境、结果、当前替代、可指认差异。
2. 定义价值一刻：用户在什么情境、完成什么行为后首次得到且能识别目标结果；写可观察事件和证据位置，不能把页面到达、功能完成或团队交付当成价值已发生。
3. 定义关键行为：谁在什么起始状态，对什么对象做什么，达到什么结束状态；补充计数单位、去重规则、纳入/排除条件和适用人群/平台/版本，并记录该行为为何能代表价值及其证据来源。
4. 定义观察时间窗并写来源：任务自然周期、用户判断“够了”的时间、已有同范围行为数据或已确认业务约束。没有来源时标 `ASSUMPTION`，不得为了可量化随意设天数。
5. 定义阈值及方向，并逐项记录来源、时间、人群、平台、样本/方法和版本。来源可为同范围基线、真实任务成功标准或正式实验；没有可用数据时写 `ASSUMPTION: 待定阈值`、最小补证和证伪信号，不编造数字。
6. 定义反指标：价值行为改善时不得恶化的用户后果、风险或业务结果；同样写行为、时间窗、阈值/判断规则及来源。再明确不看的虚荣指标。
7. 若需定位，画接触 → 价值一刻 → 重复 → 推荐/付费；每段只留一个可观察行为，不把相邻代理指标当成价值本身。
8. 交给 D3：用户/产品结果、价值一刻、关键行为、时间窗、阈值、反指标、适用范围，以及每项是事实、推导还是 `ASSUMPTION`；只更新被证据直接支持的状态。
9. 交给 D9：待验证判断、对象及准确版本、目标行为群体、程序、观察时间窗、样本/方法、支持/失败/无结论信号、对照或基线及结果会怎样更新 D3；本轮不执行时写明延期责任人和触发条件。

**产出**：价值主张、价值一刻、关键行为与时间窗、阈值及来源、反指标、D3/D9 交接；必要时附行为漏斗。  
**完成证据**：团队能演示用户怎样才算得到价值；行为、时间窗、阈值和反指标均有来源或明确标 `ASSUMPTION`；D9 可据此执行且不会把代理指标冒充价值。  
**不得替代**：用 PV、点击、DAU 单独冒充价值；用无数据的任意数字冒充成功阈值；用 D9 的程序完成冒充 D3 的结果成立。

## 无真人材料

可以生成工作假设，但必须：

- 所有无来源结论标 `ASSUMPTION:`。
- 给出最能推翻结论的最小补证问题。
- 不写“研究表明/用户验证”。
- 不虚构参与者、样本数、场次、原话、观察、执行状态或“已饱和”；未真实执行的 R3/R4 只能标 `PLAN_ONLY` 或 `PREPARED`。
