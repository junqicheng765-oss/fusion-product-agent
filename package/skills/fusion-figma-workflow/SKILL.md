# Fusion Figma 设计执行与 Demo 还原

本 Skill 随完整 Fusion Product Agent Plugin 提供，使用同包产品/设计接口与本目录执行手册，不依赖作者电脑上的全局 Figma 工作流、固定应用路径或专用脚本。它提供执行方法，不安装 Figma 服务、账号权益、MCP 服务器或 Computer Use 底层工具，也不自动启用子 Agent。

## 技能与资源定位

跨 Skill 资料以“技能名 + 技能内路径”标识，例如“技能 `fusion-product-agent` 内的 `references/product-start.md`”。先从当前宿主提供的可用技能清单取得目标技能本次实际安装目录，再读取该目录下的指定文件；同名多版本以本会话宿主选中的版本为准。清单未提供路径时，仅在宿主明确配置的技能根目录中定位，不假定技能同级安装或使用固定本机路径。

仅引用资料时读取指定文件，不自动启动目标技能的完整流程；调用目标技能时读取其 `SKILL.md` 并按任务范围执行。依赖缺失或位置无法确定时，说明缺失的技能、文件和受影响能力，继续不依赖它的工作。同一 Skill 内的相对链接按当前文档所在目录解析；跨 Skill 文档的后续相对链接以该目标文档所在目录为准。执行任意 Skill 的脚本时，按脚本所属技能的实际安装目录拼出绝对路径，当前工作目录保持为用户的业务项目。

## 产品主线的执行前提

本模块是产品锤内部的设计执行能力，不是从一句产品想法直接生成正式设计的独立入口。实际生成、编辑或还原前，先核对同包产品启动条件（技能 `fusion-product-agent` 内的 `references/product-start.md`）及任务包的目标/范围来源、有效决定或明确委托。关键意图未定时回产品主线补齐；可以先只读核对工具和已有资产，不能借配置初始化直接开工。已有充分输入、精确还原或局部修改不重复访谈，明确授权的探索制作保留假设边界。

## 执行位置回传

每次成果、修订、提问与回传按同包流程位置展示（技能 `fusion-product-agent` 内的 `references/progress-navigation.md`）保留产品第几/6阶段、适用的设计第几/4步、真实状态及下一动作。配置核对是设计准备，不把认证成功写成设计完成；生成、精修、Demo还原与复核分别如实记录。父任务汇总时同样保留导航，不能只交一个文件或结论让使用者猜下一步。

## 文案就绪后再制作

正式页面生成、编辑或Demo还原前，读取同包产品文案步骤（技能 `fusion-product-agent` 内的 `references/product-copy.md`）及本轮《界面文案基线》。主产品Agent编写、审查和维护内容，设计直接使用已就绪的原文，执行模块不临场补字。设计研究/交互推导可先行；只读配置与资产核对不受此条件阻断。

任务包必须带文案入口/版本、本次页面与状态的COPY ID及原文、动态变量和呈现约束。缺失或有影响本范围的文案阻断，先返回产品文案步骤；不能把自动补字的稿件交作正式设计。本轮适用的方向样张使用同一份就绪的代表页文案。生成提示词与Computer Use均按原文放置，不自行润色；必要增删或缩写返回产品主线更新同一基线后，再同步主稿和Demo。

设计后的QA0及实屏文案/交互复核仍执行，检查基线一致、截断、遗漏和动作结果；文案内容有问题先回文案步骤修订，不维护画布、代码和文案表三套不同文字。

## 文案检查结果的可见回传

按技能 `fusion-product-agent` 内的 `references/product-copy.md` 的“文案审查摘要”，随成果回传基线/设计/Demo版本、本轮复用或检查范围、实际文字变化及理由或未改字说明、内容与实屏/动态验证的不同结论、阻断及下一动作。涉及改字先回产品主线更新同一基线再同步；产品主线最终回复保留本轮摘要，直接交付使用者时本模块展示，不能只有“检查通过”。

## 正式设计与还原顺序

执行技能 `fusion-product-agent` 内的 `references/formal-design-delivery.md`：本轮先形成指定Figma中的有效设计并核验，再按同版Frame/Dev Mode还原Demo，不默认先本地制作再反推正式稿。探索原型、正式设计和按稿还原分别标明；画面采用最终用户的任务结构、就绪文案与合理内容，模拟控制/评审讲解放协作说明。探索或未就绪稿不能靠改名成为正式主稿。送审在既有QA0/专项复核中记录用户视角、源版本和未覆盖；工具或权限缺失先引导恢复，不静默换载体。

## Demo的正式前端交付标准

按技能 `fusion-product-agent` 内的 `references/formal-design-delivery.md`，Demo是与目标生产规格一致的本地正式前端：设计画面、样式/响应、文字及实际交互全部照同一有效规格执行。仅运行与服务接入层使用本地数据/受控返回，不改用户操作、校验、状态变化或反馈；不得加入演示解释、假设和模拟控制。必需体验缺项先修复，前端未完成与服务未接入分别记录，不能以Demo名义降级。

## 共用组件与规则输入

界面制作/还原按技能 `fusion-product-agent` 内的 `references/shared-components-and-rules.md` 承接同一共用基线入口/版本、适用项与允许变体，并带入任务包。先查实际Figma组件实例/变量和受保护范围，生成后核对真实采用；还原映射已有前端组件/Token及行为。共享变更按使用位置回查并回传证据/缺口，不靠提示词或单页截图宣称已全局复用，不另造一套规则或文字。

异常制作/还原前按技能 `fusion-product-agent` 内的 `references/exception-presentation-reuse.md` 完成实际资产核对和本轮执行清单；复用/修改优先于新增整页，新增独立页说明任务依据，状态展示Frame不自动成为路由。将分流与实际结果写回已有对应表/任务包，不另增审批。

## 异常页面与文案对应输入

用户侧异常的正式制作/还原承接本轮对应表或已有等价视图，按技能 `fusion-product-agent` 内的 `references/exception-layers.md` 核对页面/触发、R/状态、共用项、呈现/阻断、操作去向/输入/状态更新、COPY角色/有效版本和AC。设计先补明确呈现，文案先在唯一基线就绪，再制作该范围；只读和无关研究可继续。生成/精修采用该关系，回传实际节点及采用版本；还原和专项复核逐项检查，不依据一行创建一个Frame，不另写文字。

## 还原代码与技术职责

按稿还原前读取技能 `fusion-product-agent` 内的 `references/technical-handoff.md`，区分可写本地体验稿与生产工程。只在已约定本地目录/文件范围制作验证；生产工程改造、真实接入及业务仓库Git写入/发布交给技术Agent。本流程的生成、导出代码或QA通过不授予提交权限；无法区分目录或需改共享工程时回产品主线形成技术任务，记录真实接收状态。

## 输入与职责

主产品 Agent 负责当前事实、业务规则、范围和业务验收；同包 设计专家（技能 `fusion-design-core` 内的 `SKILL.md`）负责交互、风格、组件/素材、提示词及 QA0。本 Skill 负责实际执行、采集设计与实现证据、核验差异并返回；发现业务含义改变时返回产品主线，不在执行中自行决定。

执行输入沿用 [设计任务包](references/task-package.md) 的现有 Markdown 或等价结构，不要求使用者手填 JSON，也不另建一套规则。至少能定位：

- 任务包 ID/版本、产品输入及本次范围、SC/UC/规则与验收引用。
- 用户指定文件、页面/Frame，允许的动作和受保护内容。
- 当前组件/变量/原始资产、页面/状态要求和提示词。
- 当前工具能力证据、路线推荐及理由、人的明确选择来源与范围、执行分流、结果回传和核验要求。

缺专业内容由主 Agent 从当前项目补齐；仅缺使用者才能决定的事实、文件或权限时，按 Question 合同（技能 `fusion-product-agent` 内的 `references/dialogue-and-state.md`） 实际弹出问题。不要让使用者判断内部技术清单或重复批准已有范围。

## 1. 初始化与恢复

读取 [设计能力初始化与复用](references/initialization.md)，先按设计专家 TR0（技能 `fusion-design-core` 内的 `methods-tool-routing.md`） 推荐与确认制作路线。本模块在 Figma 路线已明确选择后执行；只读能力和目标检查可先做。已有本产品主稿优先推荐沿用，但没有覆盖本轮的明确选择时须说明理由并请人决定；已有批准直接引用，不重复确认。首次制作前展示推荐、目标、能力和取舍，未获明确选择不写入或生成。

按本次动作逐项验证，不把全部工具当作所有任务的共同前提：

| 本次动作 | 实际所需能力 | 验证与缺项恢复 |
| --- | --- | --- |
| 读取现状、定位设计 | 可用的 Figma MCP 及目标读取权限 | 读取本次节点的元数据/上下文或截图；失败时区分认证、文件权限和节点问题，用 Question 引导在官方入口完成连接或登录 |
| 旧页直接精修 | 当前宿主可执行的 Computer Use、目标编辑权限及可定位图层 | 核对应用、文件、页面与选区，先观察不写入；缺 Agent 生成能力不阻断该动作 |
| 新整页生成 | 当前可用 Figma Agent/实际插件入口、对应账号能力、编辑权限和执行入口 | 用真实界面或可用工具核对；Computer Use 路线须能操作实际入口，不能从 MCP 已连接推定生成可用 |
| Dev Mode 到 Demo | 准确 Frame/节点与有效设计、MCP 设计上下文/截图/素材、本地代码及浏览器验证能力 | 能读取同版设计并运行/打开 Demo；缺项时仅准备任务与证据，不报已还原 |

具体安装、配置入口或账号权益按当前宿主和官方说明核实后引导，不编造命令、套餐、按钮或权限。账号登录和购买由使用者完成，不索取或保存密码、令牌、Cookie。已有普通文件/节点链接可准确定位时直接复用，不为了 Dev Mode 文案再要求复制一遍。

没有底层工具时，说明本会话无法直接操作哪一部分，通过 Question 引导配置；使用者也可明确选择由协作方在同一 Figma 完成并回传准确节点。尚未交给执行者时不称正在等待回传。已有主稿不能因缺工具自动改成本地独立设计；例外须有使用者明确决定。

## 2. 在 Figma 执行

写入前核对工具路线的明确选择或适用既有批准，再按 [执行前核对卡](references/preflight.md) 引用任务包、有效授权、唯一目标和保护范围。无目标时请使用者指定归属并提供文件，不自行建团队、项目或文件；已有授权范围直接沿用。

专业设计推导与风格选择沿用设计专家的方法和有效决定，不由执行模块重新访谈或自行定风格。

执行前读取 [生成与直接精修手册](references/figma-execution.md)。旧页直接编辑；新整页按已有组件/风格生成后精修；同一区域生成与精修串行。无既定基线且需要选风格时，在工具路线已确认、专业前置成立的条件下，按设计专家 DS1 于授权目标的独立草稿分区制作候选，先自审再让人看图选择。选中方向后完成完整代表页、自审并另确认其扩展用途，再展开其余页面；不能把选择样张当正式代表页批准。

代表链路先形成所需的 Figma 页面/状态，再还原流程 Demo；模块扩展时先更新主稿，再同步 Demo。不用临时视觉、低保真或赶进度跳过主稿，不为检验工具擅自生成页面。

## 3. 设计回传与 Demo 还原

设计形成后由设计专家按 QA0（技能 `fusion-design-core` 内的 `methods-close.md`）核对，并核对本次页面、状态、组件与相邻影响，返回准确文件/Frame、版本和实际截图，不以 Agent 宣称完成代替画面核验。需要人判断的核心体验或视觉取舍由主 Agent 弹 Question，已有有效决定不重复确认。

进入还原前读取 [Dev Mode 到 Demo 手册](references/design-to-demo.md)。使用同版本的准确节点、设计上下文、截图及原始素材还原已有代码，复用项目组件；设计缺失先回主稿补齐。代码还原不包括生产接口、部署或未授权的系统实现。

## 4. 返回与恢复

结果并入现有设计回传、Demo 说明和工作状态，不另建重复台账。每次执行记录任务包版本、本次执行标识/步骤、实际目标、动作、结果节点/证据、核验结论、差异和下一责任方；提交后结果不明时先查原结果，不重复发送。返工保留原证据，仅处理差异范围。

分别报告：工具/目标可用、本次 Figma 设计已形成、审阅依据、Demo 还原与动态核验。部分完成、结果未知或未核验如实保留，不能合并成一句“设计交付完成”。最终回复沿用 流程导航（技能 `fusion-product-agent` 内的 `references/dialogue-and-state.md`），保留主线位置和具体下一动作，进度不进入用户 Demo 文案。

Demo 交付前自动执行 [文案与交互专项复核](references/demo-review.md)，无须使用者额外提出。流程位置与下一动作只在对话/工作记录展示，不放进最终用户页面。

## 存量系统的资产延续

已有本产品正式Figma文件是迭代设计基线，不只取色参考。包括新增页面在内，优先复用其组件实例、Variables / Styles、字体、布局、图标和状态惯例，不重新生成三套风格。确需新增组件或偏离基线时说明缺口、范围与影响，仅对实质性设计取舍收集决定。按[执行手册](references/figma-execution.md)记录复用/新增资产与设计—代码映射；视觉延续不自动证明代码、依赖和真实系统已可直接接入。
