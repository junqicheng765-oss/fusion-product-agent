# Demo 文案与交互复核

版本：v0.2｜用途：在当前范围的 Demo 展示与交付前自动完成当前范围的文案和交互专项复核，防止布局或主流程通过被误报为全部内容通过。

## 1. 执行时点与责任

主 Agent 安排与汇总，同包 设计专家（技能 `fusion-design-core` 内的 `SKILL.md`）执行 QA0 与下列专项复核；业务含义由产品主线按产品方法（技能 `fusion-product-agent` 内的 `references/product-method.md`）及相关正式能力定义判断。它属于已授权制作与修正，不新增人工审批。制作完成 → 专项复核 → 修正与复验 → 展示给人；有阻断时仅交付边界明确的草稿或不受影响部分。

- 代表页面送审前复核该页面及展示状态；代表链路送审前复核链路中全部用户可见文案、关键操作与必要分支，不冒称全系统完成。
- 随模块与状态扩展补齐复核。完整Demo交付前必须覆盖约定交付范围内全部用户可见界面、交互及文案，与目标生产规格逐项对照，不能只验核心/高风险路径或把非核心入口做成静态占位。未覆盖或未实现的约定内容保留缺项，不得自行缩小声明变成通过。
- 后续修改只回归受影响文案、操作、状态和关联任务；共享术语、组件、规则变化须扩展到使用它们的页面。仅内容、行为和依赖均未变化的证据可沿用，记录所对应的版本与依据；不能只改版本号就称已复验。
- 正式交接时核对 Demo 的版本、范围与复核记录一致，保留未验证项。后续 PRD 审计不能倒推为之前的 Demo 已审过。

业务、对象、规则与权限以当前有效产品事实源为准。Agent 可在授权范围内修正不改变产品事实的表达与局部交互问题；出现新业务取舍、责任变化、不可逆后果或规则冲突时，返回产品主线裁决，不用文案掩盖，也不自行扩大实现范围。

## 文案前置输入与问题回流

本复核承接独立文案步骤（技能 `fusion-product-agent` 内的 `references/product-copy.md`）已形成的《界面文案基线》，不是设计现场首次编字。先取得当前基线版本、适用COPY ID和设计/Demo版本对应；缺失时回产品主线编写与审查，不能用事后看一遍代替这个产物。已有文字仍需在实屏检验。

对照实际画面与模板，核查准确用字、状态/位置匹配、遗漏、变量、截断和提示与实际行为。内容缺陷或新增文字返回产品文案步骤，产品主线更新同一基线后同步Figma与Demo；纯呈现问题由设计修正，行为缺陷回交互/实现环节。普通表达修正不新增人工确认，有业务含义变化才回相关决定点。

## 共用项与变更覆盖

按技能 `fusion-product-agent` 内的 `references/shared-components-and-rules.md` 将共用项ID/版本、采用位置与允许变体带入现有覆盖记录。检查同职责的状态/交互/COPY和实际组件映射；共享变更扩展到已知使用页，无法访问或操作的项保留缺口，不以一页通过代表全局通过。不另维护准确文案或产品规则副本，不新增确认轮次。

## 归并后的异常覆盖复核

按技能 `fusion-product-agent` 内的 `references/exception-presentation-reuse.md`，回查原异常触发到当前呈现、源节点、前端状态和验收；不得出现同语义同行为的重复独立页面/实现，也不能丢失结果未知、部分成功等不同处理。检查状态展示Frame没有被误建为新路由。报告实际复用/修改、新增独立页理由及未验证范围；没有运行动态分支不得仅凭静态归并宣称覆盖通过。

## 异常对应的实屏与行为复核

读取本轮实际异常页面规则与文案对应表/版本，按技能 `fusion-product-agent` 内的 `references/exception-layers.md` 核对页面/触发、R/状态、共用项、COPY及AC引用有效可读，展示时机/位置、阻断/提示并存、按钮去向、输入保留与状态更新符合对应关系。未覆盖、断引用/过期或文字行为冲突写回同一记录，按主责回源处理；动态未运行只报静态结论。交付回复给实际对应产物入口/版本与范围，不能以表存在代替验证通过。

## 2. 建立覆盖并检查真实画面

复用当前 SC/UC、页面/状态、规则和验收 ID。结合源码/文案资源/模板和实际渲染画面建立覆盖，不只扫描字符串或只看首页。按页面、状态或共享组件分组，同文案且同语义的重复项可合并并列出位置；措辞相同但对象、结果或条件不同的项分别判断。简单需求可用短清单，不强制逐字符串维护独立台账。

范围包括标题、菜单、按钮、字段名、占位符、说明、工具提示、可访问名称、弹窗、状态、通知、规则与帮助，以及空、载入、失败、无权限、部分完成、结果未知、重试、取消和返回时出现的文案。只检查产品实际需要的状态，不为填清单新增业务分支。

动态文案检查模板、变量含义与约束，并在相关状态用代表值验证，如空值、长值和特殊内容；未能触达的条件分支列为未验证。输入的用户内容与引用原文不作为官方产品文案擅自重写；预置虚构记录检查业务合理性、可读性与用户视角，不强制改成系统口吻。运行限制放在交付材料，不在产品画面插入 Demo 解说。

## 3. 文案判断

文案按同包统一质量标准（技能 `fusion-product-agent` 内的 `references/copy-quality.md`）及其相关正式能力定义判断，结合设计文案与控件方法（技能 `fusion-design-core` 内的 `methods-ui.md`）。承接文案基线中的制作后验证要求，按适用性检查实际画面和行为；规则含义引用当前产品正文，不重复加载全部能力，也不只看P3文字。

逐组核对：

1. **准确**：名称、数字、规则、条件、权限、对象和影响范围与有效事实一致；不编造承诺、时限、可撤销性或操作结果。
2. **易懂**：符合目标用户及使用场景，词义具体、简洁；同一对象和动作术语一致，不用内部术语、抽象结论或评审口吻代替用户表达。
3. **可行动**：按钮说明实际动作，危险或有范围影响的操作明确必要后果；提示区分已收到、处理中、部分完成、成功、失败、结果未知，并在需要时说明可行的下一步。
4. **与目标产品行为一致**：本地前端按正式规则实际完成操作、校验、状态变化与反馈；受控返回只替代后端接入，不能简化用户流程。无动作、未完成或结果未知不得显示“成功”；不可实现的重试、恢复或撤销不能被文案承诺。
5. **上下文可用**：在真实画面检查截断、遮挡、长文本、阅读顺序与状态辨识；不能只靠颜色或一闪而过的消息说明关键结果。交付说明中的模拟边界不能替代画面内正确的产品反馈。

修正需说明问题、依据和效果，不为追求“更好听”改变业务含义。不宣称全部文案是“最好”“唯一最合适”；结论限定为当前目标用户、情境和证据下适用且无已知关键问题。用户能否真正理解仍需实际用户验证。

## 4. 交互判断与实际操作

交互按同包交互与反馈能力（技能 `fusion-product-agent` 内的 `knowledge/product-capability-model/standards/P5/model.md`）与交互设计方法（技能 `fusion-design-core` 内的 `methods-interaction.md`）核验；专业设计建议与业务规则冲突时回产品主线处理，不自行改写已确认规则。

在实际 Demo 中走核心任务及当前范围的必要异常/恢复，核对：

- 角色、前置数据、入口、目标对象与作用范围；操作能否发现、触发，触摸/键盘等适用输入方式是否可用。
- 输入约束、校验、禁用原因、确认和取消；动作是否影响正确对象，不以静态按钮存在证明可用。
- 触发后即时反馈、状态变化、可观察结果及后续路径；等待、重复触发、部分完成、失败和结果未知的处理是否符合已定义规则。
- 关闭、取消、返回与撤销各自的实际作用；上下文、输入保留、恢复及风险是否明确，不能把返回冒充撤销。
- 对适用键盘的界面，检查切换视图或重绘控件后的焦点连续性；隐藏的页面/状态不能仍占据布局或暴露在操作路径中。
- 桌面与适用窄屏的核心操作、弹窗、滚动及相邻/全局入口是否受影响。未覆盖的设备和条件分别说明。

静态阅读、场景推演、截图、实际原型操作和真实系统验证是不同证据。只能看源码或截图时可完成相应静态检查，动态部分必须标“未动态验证”，给出待执行的角色、前提、动作和预期结果；不得宣称已走通。模拟操作通过不证明后端、真实权限、并发或系统集成已实现。

### 键盘与导航的成品检查

本轮包含键盘使用条件或交付了相应入口时，从真实页面状态用Tab定位、Enter/Space激活，核对业务操作、页内定位、弹窗进入/退出及返回后的焦点和上下文。页内定位应到达当前页正确内容；核对锚点、路由解析及重绘是否把定位动作误当页面切换，不能只凭目标ID存在、首焦点可见或鼠标主路径通过判定可用。按当前范围选择实际适用的入口和状态，无相应交互时不追加功能。

在同一复核记录中给出前置状态、输入动作、预期、实际结果和可定位证据。发现错误后保留失败结果，修复并重新操作该路径及共用导航/焦点处理的已知使用页；核对返回、刷新和直接进入等受影响行为。无可用浏览器时执行源码检查并保留动态未验证，不能因受阻删除所需键盘入口或降低原范围。

## 5. 记录与复验

结果写入已有 `prototype/PRODUCT-PROTOTYPE-说明.md` 或 `02-产品评审.md` 并互相引用，不新建规则副本、第二套全量文案库或空文档。引用文案基线版本与适用COPY ID，不另抄全量文案；保留被核设计/Demo版本、范围、覆盖/未覆盖、检查方法、发现、修正与复验；位置使用可定位页面/状态/组件/源码或截图/操作记录，不编造证据。

按风险采用短清单或以下分组记录，已有覆盖矩阵可直接加列：

| 页面/状态/操作及关联 ID | 文案/模板或交互预期 | 实际观察与证据类型/位置 | 问题、修正与复验结果 |
| --- | --- | --- | --- |
| 当前真实位置，可合并同语义共享项 | 对象、动作、结果与下一步 | 静态/推演/实际操作；无法验证的原因 | 严重度、责任与状态；无问题也保留覆盖依据 |

修正后复验问题项及受影响上下文；保留问题与修正轨迹，不删除问题行来表示通过。已有用户确认不替代专项复核证据，也不自动批准新业务规则。

## 本轮文案复核的可见摘要

交付回复按技能 `fusion-product-agent` 内的 `references/product-copy.md` 的“文案审查摘要”展示本轮文案基线与设计/Demo版本、实际覆盖和方法、关键文字前后差异及理由、未改字时的呈现修正或沿用说明、未覆盖/阻断与下一动作，并链接原有检查及修改记录。内容审查、实屏对照和动态行为分别报告；未操作的状态不能写成已验证。回传产品主线时带上摘要，由其在本轮最终可见回复保留，不复制另一份正式文字。

## 正式设计交付专项核对

在上述QA0、文案和交互复核中落实技能 `fusion-product-agent` 内的 `references/formal-design-delivery.md`：检查实际画面的信息与控件是否服务真实用户任务、有无制作/评审口吻及模拟控制混入、内容和资产是否满足正式设计范围、探索稿是否冒充主稿，以及Figma有效源与Demo是否同版且先设计后还原。必要的新手帮助、规则和安全提示保留；合理模拟按真实产品反馈表达，不能无动作报成功。结论随现有成果回复展示产物性质、设计源版本、范围/证据和未覆盖；有缺口的对应范围先修订或如实标草稿，不靠删“Demo”二字宣称正式交付通过。

## 正式前端体验验收

Demo按技能 `fusion-product-agent` 内的 `references/formal-design-delivery.md` 是与目标生产规格一致的正式前端交付。将约定范围内全部实际画面/组件样式/响应、文案和实际交互分别与有效源逐项对照，核验用户操作、校验、等待、状态/结果及返回恢复；不能只验截图或主路径能点。必要体验缺项须修复，对应范围不通过，不因本地数据或后端未接入降低标准。协作/模拟说明与假设不混入用户界面；真实产品本身需要的引导和提示保留。既有记录和最终成果回复分别说明前端已完成/未完成及差异、实际验证证据和服务接入情况；前端验证不冒充后端上线验证。

## 6. 通过与交付表述

严重度按产品评审与交接（技能 `fusion-product-agent` 内的 `references/review-and-handoff.md`）和设计 QA0 处理。阻断/重大问题，或核心/关键风险交互缺少动态证据时，对应范围不得标为“复核通过”；可交付明确标注的待修/待验证草稿。品质问题暂缓须说明理由、责任和影响，不藏在总体通过中。

展示与交付的最终回复必须分别说明：

- Demo 真实入口、版本与本次范围。
- 文案复核：通过/发现问题/未完成；覆盖、未覆盖与记录入口。
- 交互复核：通过/发现问题/未动态验证/部分验证；实际操作范围及证据、未覆盖项。
- 残留问题、阻断范围和下一步；需要人确认时只指出该版本的业务与可见体验判断，给可直接回复的方式。

汇总可简短，但不能用“布局和流程检查通过”“已按用户视角制作”代替两项结论；已写出、Agent 自检、用户确认与真实实现继续分别记录。
