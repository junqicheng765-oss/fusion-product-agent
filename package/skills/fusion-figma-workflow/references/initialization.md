# 设计能力初始化与复用

版本：v0.6｜用途：首次设计时引导配置执行能力、绑定目标并持久复用；初始化是设计执行准备，不增加产品业务阶段，不代替风格选择或实际设计验收。

## 1. 触发与首问

当前任务包含原型/视觉设计，或用户明确要求配置设计能力时，先读取本任务工作状态引用的设计能力配置；单任务默认 `product/00-设计能力配置.md`，已有独立任务目录时保存在该目录。没有本产品 Figma 主稿且没有有效选择时，先问：“这次是否使用 Figma？已有可用环境、需要我引导配置，还是本次先不用？”不要求小白先回答 MCP 等术语；已知回答、链接和授权不重复询问。不在工具条件未知时一律推荐“先不用 Figma”；建议应说明与本次任务、现有设计和可用能力的关系。

**首次制作或修改实际页面/原型前，必须明确本次制作路线。** 发过问题不等于已有答案；未回答的选项、表单预选以及对业务规则的“按这套继续”，不能解释为选择 Codex 或放弃 Figma。路线未定时继续文字形式的目标、规则、场景、流程与页面职责分析；到制作依赖点只补问未回答的路线，不重发完整问卷。已有明确选择或有效委托则直接执行，不再增加确认。

**已有本产品 Figma 设计稿且本次包含设计或 Demo 时，默认以 Figma 为设计主稿：在 Figma 中完成本次范围的设计，再依据对应 Frame 的 Dev Mode 链接与设计上下文还原 Demo。** 不再把“是否使用 Figma”作为未定路线重复询问，也不能仅提取颜色、图片后由 Codex 独立设计页面。用户明确仅作竞品/灵感参考的链接不触发此默认。

已有链接先复用并按授权读取，区分现状来源与本次允许编辑的目标。设计路线明确不等于获得任意写入权限；文件/范围/权限仍不明时，用 Question 补缺，不能擅自改原稿、新建项目或转成本地制作。只读参考结合本地设计仅在用户明确选择该例外时采用；笼统“你来安排”、业务规则或 Demo 流程确认不能代替对放弃 Figma 主稿的明确决定。工具缺项先引导配置，受影响设计暂停，文字分析继续。

选择 Figma 后，引导用户提供已有设计文件链接；没有目标时，请用户在希望归属的团队/项目下创建文件并提供链接。由用户确定归属和唯一目标，不自行创建 Figma 团队、项目或文件。仅在用户明确要求 Agent 代建且归属明确时执行创建；连接成功、已登录或说“继续”，不构成代建授权。存量系统即使不用 Figma，也须满足第 5 节。

是否使用 Figma、现状链接/编辑目标、需人完成的配置及路线选择，都按 [Question 交互合同](../../fusion-product-agent/references/dialogue-and-state.md) 实际弹出问题收集；已有回答不重问。事实或链接输入不能用“按建议继续”代替，用户也无需为每项工具核对结果另行批准。

## 2. 配置引导与验证

同包 [fusion-figma-workflow](../SKILL.md) 提供按动作区分的能力检查及实际执行步骤，不依赖作者本机的全局 Skill；本文件维护唯一配置合同。缺失的 MCP、Computer Use、Figma Agent/插件和账号权益由当前宿主或使用者环境提供，不能把 Skill 已安装当作这些能力已就绪。

先识别当前宿主和实际可用工具，按缺口逐项引导，不一次抛出整份技术清单。提供具体安装命令或界面步骤前，核对宿主配置、当前官方文档及真实入口，不猜版本、订阅权益、按钮或工具。登录、授权和购买由用户在相应服务完成，不索取或记录密码、令牌、Cookie。

| 配置项 | 引导与验证 | 不能据此推定 |
| --- | --- | --- |
| Figma 与账号权限 | 用户登录并指定文件；在授权范围核对目标可读性、编辑权及所需团队/组件库访问 | 登录不证明文件可读可写或具备 Agent 功能 |
| Figma Agent | 识别实际 Agent/插件名称、入口和执行方式，检查可用性及是否需用户开通权限 | 普通 Figma 或 MCP 可用不证明 Agent 可生成 |
| Figma MCP | 按当前宿主支持方式引导连接/认证；读取指定目标的小范围节点、截图或设计上下文，记录结果 | 有配置不等于已认证，可读不等于可写 |
| Computer Use | 核对当前会话工具、允许操作的应用及必要系统权限；在许可范围定位指定文件与 Agent 入口，不提交生成 | 有安装文档或工具名称不等于可实际操作 |
| 文件绑定与操作范围 | 保存稳定文件链接、页面/Frame（已有时）、允许动作依据及受保护内容 | 绑定文件不授权新建、覆盖或删除内容 |

确需写入才能验证某能力时，先按[执行前核对卡](preflight.md) 限定目标及授权，再做最小验证；未授权则记录“连接已验证、写入未验证”，不通过测试擅自创建页面。初始化不强制生成三套风格或建立测试项目。

按实测能力及[执行手册](figma-execution.md)的页面分流选择路线：已有可编辑页用 Computer Use 直接精修，新增整页需要生成时才要求 Figma Agent，再精修。初始化可以记录其他能力未开通，但不强制用户为了旧页修改开通本次不需要的 Agent；后续新增页面再增量配置。缺项只影响相应动作；用户已选择 Figma 时，不静默切到 Codex 并称 Figma 设计完成。本次不用或暂不配置时记录选择，不每轮催问。

## 3. 持久记录与复用

首次形成实际记录时创建本任务的 `00-设计能力配置.md`，从工作状态引用；未完成的配置也如实保存。只记录连接、任务绑定及证据，不复制产品规则或凭据。同一空间多个需求可复用已验证连接，但各自维护文件目标、现状参考和操作范围，不能把另一需求的文件当成本任务已绑定目标。

```markdown
# 设计能力配置｜<版本>
- 状态：<未配置/配置中/完整路线可用/部分路线可用/Codex 路线/待复核>
- 选择与来源：<是否使用 Figma、明确回答或委托位置、当前制作路线；未回答则标未定>
- 环境依据：<宿主、连接方式、实际 Agent 入口；必要的非敏感执行身份别名>
- 能力结果：<Agent/MCP/Computer Use/目标读写权限分别记录结果、证据、核对时间及未验证项>
- 本任务编辑目标：<用户指定的文件链接、页面/Frame及归属；仅作参考或未绑定则说明>
- 操作与保护范围：<允许动作、授权来源及有效范围；受保护页面/组件/资产>
- 现状参考：<新建/迭代；迭代的 Figma/截图/现状页面入口、来源版本及覆盖、有效性和缺口>
- 设计主稿与还原依据：<本次有效 Figma 文件/Frame、设计版本及审阅依据；对应 Dev Mode 链接、MCP 读取及 Demo 对照证据；改走本地设计时的明确例外决定>
- 后续复用：<仍适用的配置；失效项、恢复动作和责任方>
```

宿主连接及认证由宿主管理，本记录引用非敏感结果。后续会话直接读取并复用有效连接、文件绑定及授权，不重走安装、不重复登录或索取链接；恢复执行只核对当前工具可用性、目标是否匹配及授权是否覆盖动作，不重做全套配置。

换设备/宿主、执行身份变化、认证失效、工具不可用、文件或保护范围变化时，仅修复受影响项。连接可跨项目复用，但新项目须由用户指定或确认文件绑定和现状参考，不能默认写入上个项目。仅复用宿主已有或用户显式提供的共享配置，不扫描其他项目找账号和文件。

任务包及[执行前核对卡](preflight.md)引用配置版本及相关条目，只补本次目标、产品输入、动作和回传要求。已有授权仍覆盖时直接沿用；配置成功不意味着永久允许操作任意文件。

## 4. 对用户的完成提示

在首次页面/原型制作前的用户可见回复中，简短展示设计准备结果：**本次路线、现状参考与编辑目标、Agent/MCP/Computer Use/目标权限的已验证或未验证状态、必要缺项及下一动作**。不只写在工作状态或在做完 Demo 后补一句“未使用 Figma”。无依赖缺口时说明后继续执行，不为这条提示另设批准；有缺口时给出使用者现在要提供或选择什么。配置完成后说明后续沿用、只在变化时修复。

分别说明“连接已配置”“目标已绑定”“写入能力已验证”的真实状态，不用一个“配置成功”掩盖缺项。当前是文字分析或仅只读参考时，可以暂不验证写入；进入 Figma 编辑/生成前再补相应验证及操作授权。缺少 Figma Agent 不阻断已具备条件的旧页直接编辑，用户明确选择本次不用 Figma 时也不强制其配置账号、MCP 或 Computer Use。

## 5. 存量迭代的现状界面条件

已有设计稿或界面的系统，在制作、扩展或修改本次原型之前，必须取得足以覆盖本次变化的当前界面参考：可读 Figma、用户提供的截图，或获授权且可访问的现状页面。已有有效参考直接复用，不重复索取；只有文字需求、品牌描述或无法读取的链接不满足条件。

核对来源及是否仍代表现状，至少覆盖修改页和理解其入口、布局、组件与关键状态所需的相邻页面；不要求全系统截图。截图能支持风格和结构延续时可继续原型，无需转换为 Figma；截图不证明未展示的交互、组件参数或完整品牌规范。

缺失时请求具体页面/状态，暂停受影响原型制作和修改，继续不依赖它的目标、规则、流程及影响分析。不能把迭代默认为新建，凭空画一套再称沿用。资料冲突先限定有效范围，关键缺口补齐前不进入受影响页面制作。
