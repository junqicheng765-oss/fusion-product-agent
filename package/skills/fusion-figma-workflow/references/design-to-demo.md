# Dev Mode 定位、设计读取与 Demo 还原

只有当前范围已在 Figma 形成有效设计、所需取舍有审阅或明确委托依据后，才还原该范围。可先覆盖代表链路，再增量扩展；不要求先完成整个系统设计。

## 0. 先明确代码范围与执行职责

按技能 `fusion-product-agent` 内的 `references/technical-handoff.md`，恢复本轮本地体验稿目录、允许修改路径、受保护内容和运行方式。读取现有组件/Token用于映射，不等于授权修改生产工程；既有Demo可在其明确范围增量还原，不顺带改生产源码、共享依赖或工程配置。需要真实工程接入/提升时，回传有效稿/文案/体验稿/验收、映射及缺口，由技术Agent实施。产品侧不自行执行业务仓库的暂存、提交、推送、合并或部署发布；保存本地体验稿与运行验证继续按原标准，不能用分责降低前端完成度。

## 同版文案输入

读取本轮界面文案基线（技能 `fusion-product-agent` 内的 `references/product-copy.md`），核对设计任务包、Figma实际文本与文案版本。Demo按同版设计与文案还原，不在代码中重新撰写或润色；动态值按已定义模板替换。旧稿文字与有效基线不一致时，先由产品主线判断，按有效版本修订主稿后再还原；不能为了照旧稿而保留错误文案，也不能只改本地代码后声称Figma已同步。

## 正式源与用户体验

按技能 `fusion-product-agent` 内的 `references/formal-design-delivery.md` 核对本轮产物性质、有效主稿和范围。探索原型不自动成为正式源；已有本产品Figma或已选Figma时，先完成本轮设计并核验再同版还原，不能用先写本地Demo后补Figma代替。还原用户真正看到的页面、文字和操作，不把步骤讲解、模拟控制或评审提示做成产品功能；运行边界单独说明。未接入不等于已生产可用，未实测不写动态通过。

## 同版共用项

按技能 `fusion-product-agent` 内的 `references/shared-components-and-rules.md` 读取共用基线/版本与页面使用关系，同版映射实际Figma实例/变量、已有前端组件/Token和允许变体；业务/COPY继续引用各自原源。先复用再补缺，避免每页复制组件行为；无法取得结构或代码映射时标明缺口，不声称已共用。共享变更回查已知使用位置，分开记录设计与动态操作证据。

## 状态映射与实现复用

按技能 `fusion-product-agent` 内的 `references/exception-presentation-reuse.md` 读取本轮呈现执行清单及实际稿。页面/路由由产品任务导航决定，不能一个异常Frame生成一条路由或一套布局；组件实例/变体还原为已有组件的状态/配置，保留独立业务结果、COPY、动作及恢复路径。仅状态展示的Frame追溯源页面/状态，必要独立页按其任务/入口/返回还原。复用现有代码映射并回传实际采用，缺少映射写明，不虚报已复用；对原触发→当前呈现/状态→验收逐项回查覆盖。

## 异常对应随同版还原

读取实际页面异常与文案对应及其有效源，按技能 `fusion-product-agent` 内的 `references/exception-layers.md` 逐项落实呈现、阻断/提示并存、操作去向、输入保留和状态更新；COPY角色、原文与版本从同一基线读取。发现稿、规则或文字冲突先回源处理，缺失不靠代码猜补。回传本轮关系的实际设计/前端采用版本、静态与动态证据及未覆盖；一条关系不等于一个新页面或路由。

## 1. 定位与版本

复用使用者提供的 Dev Mode/设计链接或已记录的文件与 Frame，解析准确节点；不要猜测另一个文件或节点。普通链接已包含足够定位信息时直接使用现有授权读取。只有缺少必要节点或无法访问时，才弹 Question 让使用者定位 Frame、复制开发者链接或补齐权限。

记录本次文件/Frame、设计版本或可复核快照及取用时间、任务包版本。链接是定位依据，不自动授予账号权益、编辑权限，也不保证能自动输出完整代码。

## 2. 读取实际设计

使用当前可用的 Figma MCP 读取同一节点的设计上下文和截图；工具可能提供 `get_design_context`、`get_screenshot`、`get_metadata` 或其他等价能力，按真实工具签名执行，不虚构调用。

上下文过大或被截断时，先定位子节点，再分范围读取。提取本次布局/尺寸约束、字体、颜色/变量、间距、组件及状态，取得实际图片、图标和素材来源。仅从整页截图提取配色不足以声称已取得设计结构。

不能读取必需的设计或资产时，说明具体缺口并引导恢复；可独立处理不依赖它的任务，不直接凭感觉补一套页面并报告还原完成。原始素材不可用时，替代方案须说明并遵循现有项目授权与验收要求。

## 3. 还原到现有 Demo

先检查调用者项目现有代码、组件、样式与运行方式，再在本次允许目录内增量实现，保留有效行为。将 Figma 组件/变量映射到项目已有实现，不机械复制工具给出的技术栈或重建整个项目。

Codex负责交付与目标生产规格一致的本地正式前端，页面/样式/响应、文字及本轮必要交互均按有效设计和业务规则完成。本地数据和受控返回仅替代服务接入，输入校验、操作顺序、状态变化、结果反馈及返回恢复必须实际发生，不能用跳页、静态按钮或一句成功提示代替；业务规则仍引用产品事实源。新增支付、异常、无权限等页面/关键状态若没有当前 Figma 设计，先补主稿或标为未覆盖，不在代码中另行设计后称按稿还原。未画出的动态行为仍需产品规则与实际交互验证，不能为截图一致删除功能。

本地 Demo 不包含真实生产接口、扣费或部署；外部写入和后续工程实施按主线授权处理。

## 目标生产前端一致性

按技能 `fusion-product-agent` 内的 `references/formal-design-delivery.md` 逐项对照本轮目标生产规格的画面、组件样式、响应布局、文案和实际交互；已有产品结合正式现状与本轮有效变更，0到1依据有效设计/行为/文案规格，不虚称已和不存在的线上版本比对。正式用户页面不放演示说明、假设或调试控制，服务未接入单写交付说明。未完成必需前端体验先修复或如实保留缺项，不以Demo降低验收；前端完成度和服务接入分别回传。

## 4. 核验与回传

以一致视口比较实际渲染与对应设计截图，核对布局、文字、间距、字体、色彩、组件与素材，记录差异和允许偏差；适用时检查窄屏、长文本及相邻共享组件。不能只检查源码或依赖编译成功。

实际走通本次入口、前置条件、操作、反馈、状态变化、返回及关键异常。交付前调用同包 [Demo 文案与交互复核](demo-review.md)，并由同包设计专家执行 QA0（技能 `fusion-design-core` 内的 `methods-close.md`） 执行文案与交互专项复核。视觉、动态行为、产品审阅分别保留证据。

回传有效设计文件/Frame与版本、Dev Mode/节点定位、上下文/素材读取证据、Demo 入口与版本、页面/状态对应、实际对照及动态核验结果、差异/未覆盖与下一动作。设计变更后只回验受影响范围，但设计和 Demo 必须使用同一有效版本。
