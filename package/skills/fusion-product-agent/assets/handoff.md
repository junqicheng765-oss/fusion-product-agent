# 本次交接说明

## 接收者与当前成果

本轮问题、终点、当前有效正文/界面文案基线/设计/Demo/验收入口和版本组合。单个载体版本不同，列明规则覆盖与差异。

## 如何继续

接收者的下一任务、必须保持的规则、允许探索的实现空间、待决项与返回要求；运行或打开方式。

## 输入、输出与接收

接收任务所需的领域依据、前置状态、输入格式/字段和样例；应产出的结果、接收判据、异常回传与恢复。本次交接怎样连到实施、上线、采用与收益验证；实际覆盖到哪一步。

涉及异常时，给出共享规则、真正不同的状态、异常清单的COPY ID引用、唯一界面文案基线及按页面组织的规则包入口和有效版本；页面以异常 ID 引用清单。研发按规则和页面行为实现，QA按规则扩展数据并用少量代表性例子核对不同结果与恢复路径；未核实的接口能力或文案单列。

## 共用基线与接入

适用时给出共用组件/规则基线入口与有效版本、本轮页面引用与允许变体、实际设计组件/Token—前端映射；来源缺口和未接入项如实说明。共享变更附使用位置、影响范围与实际复核证据，不能用单页通过代替全部使用页。业务规则和准确文字仍回各自唯一来源读取，不在交接另维护副本。

## 异常对应材料（适用时）

当前页面规则—异常—文案对应表/等价视图的可打开入口、有效版本与范围；关联的业务/状态、共用定义、文案基线/COPY及AC，实际设计与前端采用版本。研发能定位呈现、阻断/并存、操作去向、输入保留和状态更新，QA能取得可观察预期。原文可读取或有带源版本的只读展开；断引用、过期/语义冲突、未覆盖及处理方/恢复动作逐项明示，不只写“按异常规范执行”。

## 技术任务与执行职责（适用时）

按[技术分责](../references/technical-handoff.md)填写，可合并到已有任务：

- 技术任务/接收者：生产实现、接入、提升体验稿到工程，或仅提交现有成果；实际可用的Agent/渠道与委派依据。
- 有效输入组合：当前产品/文案/设计/体验稿/验收；适用的共用、异常对应和呈现复用入口/版本，保持唯一源。
- 目标与允许范围：仓库/工作区/分支、可改路径/操作、保护项及现有未提交成果归属；未知明确列出，不猜测或清理他人修改。
- 工程接入与返回要求：组件/Token、接口/模拟边界、依赖/缺口；技术可选空间、必保行为、检查/测试证据；Git或发布按授权回传实际提交/PR/MR/发布状态。
- 接力状态与证据：材料已准备未交接 / 已发出等待接收 / 已接收或执行中 / 已返回待产品核对；当前证据、接收版本、阻断与下一动作。无实际接收不得填写已开工。

产品主线不执行上述业务项目Git写入/发布；本地体验稿代码目录和允许范围单列，不用Demo名义改生产工程。

## 依据与验证

有效决定或委托范围、关键变更与来源；实际检查对象/环境/结果、未覆盖、模拟边界、真实系统依赖和验证责任。

## 状态与停止边界

已准备、实际收到、可据此继续、产品完成、真实实施通过分别说明。只准备本地材料时写已准备未外发；本轮不要求的下游工作不自动启动。
