# 产品到设计的任务输入

## 当前依据

产品正文入口与准确版本；目标用户、使用情境、当前障碍与预期结果；产品形态、本轮范围和成功判断；领域证据与未证实假设；有效决定及确认/委托范围。父任务建议、Agent 推导与用户决定分开标明。

产品启动依据：能定位的用户原话、既有决定或明确委托；本轮目标、核心范围/不做项和终点。候选推断与有效决定分开。按[产品启动条件](../references/product-start.md)记录是否仍有改变当前方向的未决项及受影响范围；不要求新增审批文件，无关键缺口直接承接。

## 任务和规则

对象、角色、权限、关键规则及其引用；用户主任务、必须覆盖的状态/异常与恢复；业务验收预期。本轮必做、不做及终点。涉及异常时，提供共享规则/差异状态、异常ID与COPY ID/文案基线版本、就绪或阻断状态（未成文时只列意图，不作正式制作输入），以及待覆盖页面；设计按异常 ID 形成页面规则包，不把触发 case 逐条变成页面需求。已有页面/交互提案供设计专家审视，不锁死具体控件或视觉。

## 共用组件与规则

[共用基线](shared-baseline.md)或现有等价入口/版本、本轮共用项ID、适用范围/行为引用、允许变体及页面使用位置；业务/COPY/设计库与Token来源；本次新增/变更及影响、实际Figma/代码映射和未知项。小需求可在此内联，不重建资源库。页面引用共用定义，仅补本页参数与有依据的差异；设计回传实际采用/新增/变体及受影响位置。

## 异常页面规则与文案对应（适用时）

[对应表](exception-page-map.md)或现有等价入口/版本、本轮页面/步骤＋异常ID、R/状态与共用项、已就绪COPY角色/ID/版本和原文位置；设计补齐呈现时机/位置、阻断/提示并存、操作去向、输入保留与状态更新后才制作对应正式页面。业务行为或文字未就绪标明影响；无真实稿时不虚填节点，制作后补入采用版本与验收证据。

## 已审查的界面文案

[界面文案基线](interface-copy.md)入口与有效版本、本次适用COPY ID和原文、变量/缺值及呈现约束、审查记录和就绪范围；阻断项及其影响。正文案是设计输入，不能交给设计现场补写。页面动作/状态尚未明确时可先开展设计研究和交互推导，再回产品文案步骤完成此输入。

正式页面制作沿用原文；排版可按约定处理。设计需要增删、缩写或补状态时，回产品主线更新文案版本后再同步，不另存一套不同文字。本轮适用的方向样张采用同一份代表页文案。

## 现状与边界

现有Figma/截图/运行界面、设计系统、组件与素材来源；参考和编辑目标分开；有效文件/节点、允许修改及受保护范围。已有研究、竞品、风格选择和授权记录；缺失资料如实标明。

## 交付合同

Demo按[正式前端定义](../references/formal-design-delivery.md)交付，记录目标生产体验所依据的设计版本、产品行为和文案版本；页面/样式/响应、实际操作/校验/状态反馈及文字分别对照并举证。前端必要体验未完成则标缺项，后端或真实数据尚未接入另列；不能用模拟说明抵消前端缺项。

约定格式、用途与接收者：浏览器高保真/可操作Demo、可编辑Figma或其他成品；必要账号/工具/素材条件与实际状态。设计专家按自身流程建立设计决策与工具合同，不由产品预设旧设计步骤。

实际执行沿用同包设计任务包（技能 `fusion-figma-workflow` 内的 `references/task-package.md`），补齐工具配置引用、唯一Figma目标、生成/精修分流、真实证据及Dev Mode到Demo的同版对应，不另建规则副本。已有本产品主稿或已选Figma时，先更新主稿再还原；本地路线须有明确选择。

按[正式设计交付](../references/formal-design-delivery.md)补明本轮产物性质（探索原型 / 正式设计 / 按稿还原）与当前状态、有效设计源及准确版本/节点、本轮覆盖和未覆盖；承接探索产物时说明需修订的假设与差异。代表内容和文案按真实用户任务组织，模拟/测试控制和运行边界放说明。正式设计检查并入QA0/文案与交互复核，不新设独立批准。

## 设计回传

设计决策记录及用户选择、实际成品/节点和版本；页面/状态—场景—规则—验收对应；涉及异常时回传异常ID—COPY ID/有效文案版本对应及页面规则包，沿用异常ID，页面变体及原因先回产品主线更新同一文案基线，不由设计另定最终文字；组件主题素材来源；QA0三维结论、真实脚本/看图/操作证据、差异与未覆盖；需要回到产品主线处理的业务变化。
