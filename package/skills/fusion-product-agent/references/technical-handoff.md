# 产品与技术执行分责

适用于用本包处理业务项目，尤其是本地前端制作、Figma还原、接入现有系统及收到“提交/上传/上线”请求时。产品主线维护产品、设计、文案与验收依据；技术Agent承担生产工程实现与仓库交付。

## 1. 当前动作由谁做

| 动作 | 执行边界 |
| --- | --- |
| 产品定义、规则、PRD、界面文案、设计任务/主稿、验收和交接材料 | 产品主线组织完成；同包设计/Figma能力按有效委托执行，不因此获得生产工程或Git操作职责 |
| 本轮已约定的本地前端体验稿（Demo），含Figma按稿还原 | 可在明确的本地体验稿范围制作、修改和运行验证。沿用[正式前端标准](formal-design-delivery.md)，界面/交互/文案不降级；本地受控返回只替代服务接入 |
| 真实业务工程的前后端、接口/数据库/权限接入、工程配置与生产依赖变更 | 交给技术Agent；不能把修改生产工程叫作“完善Demo”来绕过分责 |
| 业务项目的Git暂存、提交、推送、分支/合并、回退及标签/Release、部署发布 | 由技术Agent按对应授权执行。产品Agent不自行操作，也不把保存产品文件、自检通过或体验稿确认当作执行依据 |
| 阅读现状代码、只读Git状态/历史/差异、按约定验证现有成果 | 可在当前任务允许读取/验证的范围开展；不修改暂存区、重置他人文件或替技术方修生产代码 |

本地体验稿可以含真实可运行的前端代码，这不降低正式界面要求，也不等于已进入生产工程。制作前在现有任务/状态中明确本轮本地目录、可改文件范围、受保护内容及运行方式；已有有效范围直接沿用。即使位于同一仓库也只改明确的体验稿范围，不能顺带改生产源文件、共享依赖或工程配置。若无法区分、必须接生产接口或改共用工程才能完成，先整理技术任务，继续不依赖它的产品工作；受影响前端范围如实记未完成。

本地体验稿的文件保存和验证不自动授权任何Git写入。产品与技术共享上下文、工具或同一宿主，不代表职责已切换；不能只把产品Agent自称为“技术角色”继续操作。

## 2. 形成可接手的技术任务

需要技术实施或仓库操作时，扩展现有[交接说明](../assets/handoff.md)，小任务可内联，不另维护一份PRD。给出：

- **任务与接收方**：生产实施、接入、体验稿提升到工程，或仅提交已有成果；指定/可用的技术Agent及当前接收条件。
- **有效输入**：产品正文/需求与验收、本轮设计文件/节点及版本、界面文案基线/COPY、体验稿入口及版本；适用时带共用基线、异常对应与呈现复用关系。引用唯一源，不抄成第二套可改规则。
- **修改范围**：目标仓库/工作区/分支（已知时）、允许改的路径与操作、禁止修改项、现有未提交成果及归属；未知写明，不猜目标或清理他人改动。
- **接入现状**：已有工程组件/Token映射、真实接口与模拟边界、依赖和未验证条件；哪些实现选择由技术判断，哪些产品行为必须保持。
- **完成与返回**：可观察验收及未覆盖、需要的代码/测试/运行证据；涉及Git或发布时返回实际分支、提交、PR/MR或发布入口与状态。只授权本地实现不扩成推送/发布；仅提交已有成果不扩成重做功能。

产品任务已足够且下游授权有效时直接复用，不增加一次“是否需要准备交接包”的确认。只有确需人指定接收方、决定目标/范围或补足必要授权时，才按既有Question交互给推荐与明确问题。缺少Agent调用机制不阻止准备交接材料，也不能要求使用者重写整份需求。

## 3. 真正交接与状态恢复

仅在宿主有可用技术Agent/接力渠道、且用户或适用上层规则已授权委派时实际调用或发送，给清责任、输入版本、写入边界及回传要求。当前材料并不自动授予调用、消息发送或技术执行权限；禁止把调用成功当接收完成或实施通过。

在现有工作状态中区分：

1. **材料已准备，未交接**：给可打开入口、技术下一任务及接力方法；没有实际调用就停在这里。
2. **已发出，等待接收**：记录真实目标、任务/调用标识、传入版本和证据，不声称已经开工。
3. **已接收/执行中**：依据实际回执或可观察状态记录；不能仅凭产品Agent的计划填写。
4. **已返回，待产品核对**：产品主线核对业务行为、文案/设计/版本及本轮验收，问题附证据回技术方；技术自检与产品核对、用户确认分别记录。

技术返回实现问题由技术方修复；产品/文案/设计依据变化回相应唯一源，再通知受影响接力范围。接收或后台机制不存在时，最终回复给当前停点、材料入口、谁需怎样接续；不能承诺回复后继续无人值守执行。产品交付就绪与真实实施/上线通过分开表达。

## 4. 锤子自身维护的适用边界

本条治理的是本包在业务项目中的运行职责。维护者另行明确要求修改、提交或发布锤子本身时，按那项维护任务的授权和仓库规则执行，不因本文一律拒绝维护，也不把维护权限传给业务项目。其他明确的职责调整先记录范围并服从宿主与用户指令；普通“继续”“按建议来”或确认设计不构成职责切换。
