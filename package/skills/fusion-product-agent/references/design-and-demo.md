# 产品到设计的交接：专业方法与 Figma 执行

本文件只定义产品与设计的接口。完整产品任务先完成产品入口判断，再交给同包 [fusion-design-core](../../fusion-design-core/SKILL.md) 处理页面、交互、视觉、界面文案或 Demo。用户直接委托修改已定义产品的设计时，沿用已有产品依据进入设计。设计方法仍须实际读取并按适用路线执行，不能只读本摘要后自行制作。

交接前，产品主线应能回答：目标用户在什么情境完成什么任务、当前障碍与预期结果、本轮产品形态和范围、关键对象/规则与来源、主要路径、可观察验收，以及哪些结论已决定、哪些仍是假设。可用短正文，不要求额外审批或固定文档篇幅。关键产品选择未定时，产品主线先澄清或保留受影响方案为候选；设计研究、界面参考和风格选择不能替它作决定。

## 产品交给设计什么

沿用 [设计任务](../assets/design-task.md)，传入当前产品正文和版本、目标用户与设备情境、业务目标、领域依据、对象/规则、必须覆盖的场景/状态与业务验收预期。给出已有设计/截图/素材、有效文件/节点、复用约束、允许修改和保护范围、真实交付终点及工具情况。已有研究和确认记录同时传入，供设计专家评估可复用程度；没有证据的推测明确标注。

产品提出的页面骨架和交互是输入建议，不是不可质疑的设计终稿。页面职责、信息架构、步骤组织、具体控件、文案表达、视觉和组件由设计专家判断；影响业务规则、范围或已确认重大决定时，把冲突和推荐回传产品主线处理。

存量系统的正式Figma文件是迭代基线，包括新增页面也优先延续现有组件实例、变量/样式、字体、布局与状态规范，不只提取颜色，不重选全局风格。设计回传须区分复用资产与新增/变更项，给出当前设计—代码组件/Token映射及接入缺口；未经实现核对不能承诺已能直接部署。

## 进入设计以后

用设计专家自己的接单分流、研究/竞品、流程/交互、风格决策、组件/素材要求和QA0终审，替代旧设计判断方法。产品阶段已有的用户、场景、规则、来源与决定作为上游输入复用，不重做同一问题的访谈或把设计假设写成产品事实。设计专家发现交接缺少会改变产品方向的决定时，将具体问题与推荐退回产品主线；页面表达层面的缺口由设计自行处理。产品方向成立后的0到1视觉推导、原生提问、风格确认及停止点按设计入口执行；存量延展和按正式稿还原不重选已成立的风格。

实际制作前读取同包 [Figma 执行工作流](../../fusion-figma-workflow/SKILL.md)的初始化部分。设计专家将判断落入[执行任务包](../../fusion-figma-workflow/references/task-package.md)，执行模块按有效路线检查工具与权限：已有本产品 Figma 主稿或已选择 Figma 时，先在 Figma 完成本次设计（已有页 Computer Use；新增整页按需 Agent 生成后精修），QA0 后再按同版 Dev Mode / MCP 还原 Demo。缺工具先恢复，不静默降成本地重做。明确选本地路线时才按本地组件方法制作；转换进 Figma 只是实际可用且显式选择的分支。

辅助资料同包提供：[UI/UX Pro Max](../../fusion-design-ui-ux-pro-max/SKILL.md) 用于设计知识检索，[Impeccable](../../fusion-design-impeccable/SKILL.md) 用于对应的视觉制作/审视/精修。它们服务设计专家，不取代其主流程、制作路线和QA0结论。按需加载，不机械连续运行三套工作流。

设计模块的脚本必须从实际Skill目录调用；产物写到用户项目，不写能力包目录。Skill安装不代表MCP、浏览器、生图服务、账号与素材权限已具备。工具与授权按 [接入检查](figma-adapter.md)核实，不伪造调用。

## 设计交回产品什么

- 设计决策及其研究/竞品依据、用户实际选择与适用版本。
- 当前交付格式的成品位置：HTML/代码入口、Figma准确节点/版本、图片或其他约定载体；区分中间产物和正式交付。
- 页面/状态与产品场景、规则和业务验收预期的对应；提出的业务变更及其处理状态。
- 组件、主题、字体、素材及可追溯来源；实际脚本、渲染、点击路径与失败分支证据。
- QA0的可用性、审美与品位、设计标准与工程规范三维PASS/FAIL及回炉修正；未检查项、差异和工具阻断据实说明。
- Figma路线的配置/目标引用、任务版本、真实生成/精修证据、有效Frame与Demo对应；Demo交付前自动完成[文案与交互专项复核](../../fusion-figma-workflow/references/demo-review.md)，无需人另行提出。

产品主线接回后只校对业务目标、规则含义、任务覆盖、版本一致性和下游输入完整性，不另用旧设计标准复判。设计PASS不等于业务规则通过、用户确认或生产可用；脚本PASS也不等于视觉与交互已实际审过。
