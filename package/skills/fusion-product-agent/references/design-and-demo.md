# 设计与Demo：先确定载体，再用体验检验规则

## 设计准备

首次制作前恢复使用端、核心任务、当前规则和范围、现状界面、已有设计系统、素材、目标文件/页面、受保护范围、交付载体和工具能力。已有选择直接复用；存量迭代没有有效截图、设计或可访问界面时先补受影响输入，不拿通用模板冒充延续现状。

有本产品有效Figma主稿，默认先更新当前范围的主稿，再按准确节点还原Demo，具体见 [Figma适配](figma-adapter.md)。用户明确指定本地HTML路线时直接采用；新产品没有路线且工具/成本差异会改变交付时，给出推荐与影响再问。已明确委托普通本地制作时不反复询问载体，未回答不能当作委托。设计工具不具备时继续文字/流程分析，受影响设计或Demo保持待制作。

绑定素材来源及可用边界，不使用来源项目样本作为新项目真实素材。图像可当视觉参考，不能推出隐藏流程；主稿链接不证明编辑权限或已完成还原。

## 逐层制作

1. **结构**：明确角色、对象、入口和页面职责；用低成本骨架确认信息可找到，不急于全量精稿。
2. **代表体验**：对真实使用端做一张代表页和一条高价值任务。优先验证常用操作能连续完成、反馈与状态有因果关系，并纳入影响方向的关键异常。
3. **模块展开**：复用已选结构和组件，覆盖本轮全部核心任务与适用状态。高风险规则先清楚再画；其他细节可由体验发现后局部回查。
4. **视觉收敛**：沿用有效设计系统。没有基线时给少量有实质差异的方向及适用理由，不强制每次三选一；有效委托范围内直接决定。后台、内容、游戏与创作任务按各自操作选择布局。
5. **校对**：按同一场景核对规则、设计与Demo，修复可据依据处理的问题，剩余待决明确受影响范围。

## 产品界面与审阅说明

Demo首页直接落在目标用户的任务入口，不用项目介绍、功能清单、设计理念或评审导航代替产品。标题、按钮、提示、空态与错误按目标用户语境写；只有产品本来需要的帮助才进入界面。运行限制、假数据、未接入项和检查入口放在交付说明或独立审阅页，不混入面客操作。

本地模拟清楚告知接收者，可用合理虚构数据支持体验；如分享方式可能让他人误认为真实系统/交易，先明确用途，在审阅入口和交付材料持续标明参考/模拟性质。涉及外部扣费、正式提交或生产动作不得暗接真实接口。

## 状态与交互

对当前适用状态写清必显、必隐、不可残留、可执行动作、反馈和恢复。处理中防止重复高影响动作；结果未知与明确失败分别呈现；退出、返回、刷新与重入符合规则。错误说明影响及下一步，不只弹“失败”。无范围依据的行为不编造；静态稿只交静态能力，可操作Demo中的可见控件需有真实可见响应。

审查页面和文案的关键检查：

- 用户是否知道当前是什么、发生了什么、下一步做什么；动作与状态用语是否一致。
- 操作、触发时点和核对对象是否与规则一致；不能把读证核对改成填名核对后仍称同一分支。
- 成功/失败/未知、权限与金额文案是否准确；不凭前端提示保证后端不会重复提交。
- 动作区与关键内容是否在目标设备可连续使用；高频操作无需无谓来回滚动。
- 长文本、空数据、键盘焦点、对比、触控目标、弹层与状态切换是否破坏任务。
- 隐藏控件是否残留边框、标签、点击区或键盘焦点；审阅工具是否干扰产品画面。

## 实现与实际验证

先检查现有实现、组件和运行方法，再增量修改；优先语义HTML、布局流、flex/grid、内容自适应与语义tokens，避免固定坐标拼图。共享改动检查受影响页面，不为局部修复重建整个项目。

有浏览器/渲染能力时，实际打开代表页，按目标视口比较设计，走通正常链和关键异常；检查前置、操作、反馈、状态、返回与重复操作，修复再验证受影响部分。只编译或读源码不能证明体验通过。没有工具就记录未验证，不伪造截图/点击结果。

文案、交互、视觉、业务规则分别说明检查覆盖与残留；静态画面不代替动态证据，桌面自动化不等于真机触控。需要可复现状态时可建独立审阅入口，引用同一规则/组件，不把场景切换数量当作完整游戏或业务流程覆盖。

交付：实际入口和启动方法、设计定位/版本、Demo版本、核心场景与状态覆盖、设计差异、真实检查证据、未接入和下一步。规则有意先于设计/Demo时列明差异与责任，不因“已声明”就认定新增行为已通过。
