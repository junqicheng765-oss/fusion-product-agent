# 异常状态的呈现复用与制作分流

涉及异常界面的设计、Figma制作或按稿还原时读取。接续[异常分层与对应](exception-layers.md)和[共用基线](shared-components-and-rules.md)，把判断写回本轮已有对应表/设计任务包，不另建一套异常、文案或审批流程。

## 1. 先查实际资产，再安排制作

只清点本轮受影响页面及必要相邻范围：当前有效页面/Frame、组件实例/变体、页面内状态、同版设计和代码映射。记录真实节点与版本；0到1没有现成资产就如实注明，不要求先建全系统组件库。已有文件但暂不可读时标明“资产未核对”，不能据此断言无可复用内容或重造整套页面。

对当前异常对应关系逐组记录：关联页面/步骤与异常ID、业务后果和允许动作、可复用资产、拟采取动作及新增理由；实际执行后回填节点和采用证据。缺少业务含义或COPY只暂停相关正式制作，按既有就绪规则处理。

## 2. 语义归并与呈现复用分别判断

- 多个技术触发只有在业务结果、允许动作、恢复责任和状态更新依据一致，且角色/权限、数据保留与风险处置无实质差异时，才归并为同一异常处理规则；保留原触发→规则→验收覆盖，不能直接删掉触发项。
- 业务含义不同仍可共用一个提示容器或页面结构，通过有依据的状态/变体、COPY及动作配置表达。共用组件不代表合并业务结果，不把“已失败”与“结果未知”、部分成功与全量失败画成同一种处理。
- 不因概率低就删除必要状态，也不因风险高就一律新增独立页面。是否占整页取决于用户任务、上下文与恢复路径；低频且同后果的异常可用既有兜底呈现，明确其适用边界。

## 3. 为每组关系选择最小充分的呈现

| 判断 | 制作动作与证据 |
| --- | --- |
| 现有页面/组件已支持同一行为 | 复用实例并配置已定义参数/文字/状态，记录目标节点；不新画同义整页 |
| 结构相同但有真实行为或视觉差异 | 扩展已有组件变体或页面内状态，说明差异及共用行为；检查共享影响，不随意拆实例 |
| 需要独立任务承载 | 仅当既有页面内提示/状态无法承载该任务、导航或恢复上下文时，新增独立产品页面；说明不能复用的理由、入口/退出/返回、关联规则与AC |
| 仅需展示或验收某个状态 | 优先切换已有状态/变体取证；工具或交付确需静态状态Frame时，可基于同一组件/画板保留有标识的状态展示，记录源页面和状态。它不自动成为新产品页面、独立组件或路由 |

上述关系可以组合：一个页面内状态可以使用共用组件；一个独立页面也应复用组件。区分“业务页面”“组件/变体”“状态展示Frame”“截图/验收证据”，不要用Frame数量充当产品页面数量或完成度。不要为减少数量擅自删除受保护/已确认稿或必要证据，历史清理遵守已有写入授权。

## 4. 执行与还原

Figma任务清单对每组关系标记复用、直接修改、扩展变体、新增整页或仅取证，带入准确目标及版本。生成提示词仅覆盖确实缺失、需要新建的整页；已存在的状态优先配置/精修，不把异常矩阵逐行交给生成器重画整页。生成与编辑串行；执行结果未知时先查原执行，不能再次生成同批页面。

还原前读取有效稿及上述映射。产品页面/路由来自已确定的任务导航，不从每个Frame自动生成；同页异常通常落实为已有组件的状态/配置，保留各自真实行为与COPY。设计确需独立页面时按其任务、入口和返回实现。状态展示Frame需追溯到源页面/状态，不另造一套布局和行为。

## 5. 归并前后覆盖与回传

在已有对应表/QA0/专项复核中逐项查：原触发与异常仍有明确去向；真正不同的结果、恢复、输入保留、权限及状态更新未丢失；本轮采用的设计节点、组件/变体与前端状态可定位。相同语义和相同行为不得形成重复的独立页面或重复组件实现。无法核对的范围保留缺口，不报全量通过。

成果回复给出本轮复用/修改/新增的实际范围；新增独立页面逐项附理由，状态展示和证据另列；提供覆盖入口、实际验证与未验证范围及下一动作。可从执行记录统计实际数量，未执行不编造节省比例。不增加逐页面确认，只在业务含义、任务结构或共享规范发生需人判断的变化时沿用既有关键确认。
