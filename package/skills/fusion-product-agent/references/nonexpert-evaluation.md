# 非专家任务测评

## 测什么

默认承接人员不了解或仅模糊了解该业务，也缺产品方法。检验锤子能否通过与人交互创意与目标，自行构建专业领域需求、边界和可承接产物，并在已约定范围内推动真实任务与价值验证。

不把Token、阶段数、文件数、对话轮数和篇幅作为能力得分。记录它们仅用于诊断重复、卡顿或资源约束；有效的创意澄清和目标交互不能因轮数多扣分。人工输入中若含专业答案，单独记录其来源与贡献。

## 固定任务合同

试验前固定想法输入、使用者可提供的事实、专业知识水平、原始材料/系统访问权限、模型、工具、规则版本、授权、交付范围及验收场景。多组比较采用同一证据可得条件，合理的自行研究与提问允许继续；不可暗中给某组专业提示。工具受限与能力缺陷分别记录。

有意保留仅能通过研究或推导发现的必需需求与异常；不要将完整专业答案包装为输入。行业标准答案/验收依据由可核对的原始资料、实际业务结果和目标使用者任务确定，评价者保留事先未展示的案例。不仅依赖同一模型生成并评分。

每次人的输入标为：创意/目标、组织事实/原件、经营选择、专业知识答案、纠错、推进或工具支持。分类可以在评估记录中完成，不让业务使用者逐条打标签。若人补入领域规则，报告外部知识依赖；若懂行人员救场，不能归功为锤子自主补齐。

## 核心判断

| 观察维度 | 通过所需证据 | 明显不足 |
| --- | --- | --- |
| 创意与业务目标交互 | 能识别真正受阻任务，提出可比较方向，用业务场景持续校准目标；新增需求可说明与目标关系 | 把模糊Idea直接翻成页面，或要求非专家先交完整需求 |
| 自主领域需求构建 | 主动发现输入未提到的必需知识/规则，有适用来源，落成对象、行为、案例和验收 | 术语堆砌、复制模板、泛写专家确认，或靠使用者逐条喂专业答案 |
| 边界构建 | 职责、权威数据、状态与异常恢复明确，输入/输出与跨系统责任可核对 | 核心对象、责任或结果去向缺失，漂亮界面掩盖业务断点 |
| 上下游承接 | 未参与人员或接收环节能用交接包完成事先约定的下一任务，输出与规则一致 | 仅有文件/回执，下一环节仍要重新研究核心领域或重写规则 |
| 专业任务与价值证据 | 在合同对应层次完成真实或明确标注的模拟任务；关键结果正确；采用、付费或经营收益各有对应证据 | 静态稿、自检或口头“专业”替代任务验证；Demo通过写成上线/变现 |

不设置未经依据的权重或统一平均分。各维度分别给“有证据达到 / 部分达到 / 已证实不达 / 未验证”，附证据、影响及复验动作。总体表述必须带任务范围和验证层次。存在关键规则错误、危险结果、责任断点或依赖伪造事实时，受影响范围不通过，不能靠视觉或其他维度抵消。

资料取不到时，报告锤子是否用尽合理取证方式、是否提供可执行验证任务，以及最终能力仍缺何种证明。不能把未验证计成通过，也不能把所有外部条件一律归因于锤子能力不足。

## 财务场景的试验方法示例

下列是测评设计示例，不是财税制度或适用法律结论。

- 输入只给真实业务痛点、想改善的任务和组织可取得的原始材料；承接人员可回答事实，也可以说“不懂”。
- 观察锤子能否自行发现对象、单据关联、权限职责、结果口径、反向/异常流程及上下游接收要求。哪些适用需由具体任务及证据确定，不能预置成所有财务产品的固定功能。
- 用脱敏或经授权的典型单据、反向案例和事先保留的异常案例检查。由真实目标使用者执行任务，核对实际结果及凭据；使用者主要做任务并反馈结果，不需要全程为锤子设计方案。
- 产品阶段可先测规则、Demo和交接；到了上线验收再测真实环境、权限、数据及业务结果。没有后者时，不宣称已达到“财务上线即可用”。
- 后续验证是否被实际采用，以及对应付费、可核实的经营收益或其他已约定价值；“专业”“愿意用”“实际使用”“产生收益”分别记录。

## 建议保留的测评记录

一个任务记录即可，按规模合并：输入与权限合同、来源/研究记录、专业答案由谁提供、锤子主动补出的必需需求、规则与边界缺陷、当前交付入口、未参与接收者的任务结果、目标用户任务结果、采用/收益证据、未知与下一验证动作。保留原始过程，不让评估结论覆盖原始证据。

既有九个不同终点的案例可作为缺口线索和回归素材，不能直接重排成非专家端到端能力排名。若尚无符合新合同的试验，写待测，不把旧评分机械换权重。
