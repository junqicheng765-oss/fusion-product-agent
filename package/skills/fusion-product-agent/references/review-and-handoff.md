# 评审与交接：按约定范围证明完成

## 评审对象与证据

首先确定接收任务、版本、范围与完成条件。针对当前问题检查，不因局部评审全量重审。作者生成后的自检与实际独立评审分别表述；需要真实用户或专业责任人验证时，不由Agent签字替代。

发现按“位置与证据—受影响任务—后果—建议—复验条件”报告。已观察矛盾/必需规格缺失是文档缺陷，缺上下文是未知；标题/模板差异不是缺陷。问题优先级由影响和可恢复性决定，不以平均分遮住阻断；没有发现不凑优化条目。

## 正式交付前

1. **合同与产品启动依据**：按[产品启动条件](product-start.md)回查目标/核心范围的来源、有效决定或明确委托；不能把候选推断、风格选择或异步问题发送成功当成用户回答。本轮必需成果是否存在、可打开、范围符合约定；明确不适用不等于缺证据。
2. **领域需求与边界**：锤子实际补齐了哪些专业知识、依据是否适用、用户未提到的必需事项是否主动发现；上下游输入/输出、责任、接收与失败恢复是否成立。不能用“待专家确认”代替本可自行完成的研究，阻断未知要有具体取证动作。
3. **专业判断**：完整产品基线/正式交接对七类48项按适用性筛查，细读相关定义；受影响局部任务只筛相关项。筛查依据留在当前评审中，可用简表，不强制48份文档。
4. **任务覆盖**：本轮所有核心任务的角色、入口、对象、动作、结果与必要恢复是否明确；代表链路不足以替代完整覆盖。
5. **跨载体一致性**：核对规则作用对象、触发时点、反馈、恢复与验收。每个载体记录实际覆盖的规则版本，多个版本号不同不自动不一致；存在语义冲突则修正或明确受阻，不能只改版本号。
6. **运行证据**：实际打开/操作了什么，有哪些结果；未接入、未覆盖、真机/接口/生产验证单列。
7. **接手**：入口、当前有效组合、必须保持、允许探索、待决、责任与下一动作是否清楚。

8. **价值路径**：本轮完成到交付、采用、付费或经营收益的哪一步；后续验证有何输入、任务、预期证据及接收条件。产品完成不能写成全链路或变现已验证。

可用机器清单检查路径、引用和声明版本，但语义、来源真实性与质量需审阅。自动检查通过不能写成全部产品验收通过。

评测方法见 [非专家任务测评](nonexpert-evaluation.md)。

涉及设计交付时，接收[设计专家](../../fusion-design-core/SKILL.md)的QA0三维结论及实际证据；失败或未检查不能被主线的“文件齐全”覆盖。产品只复核业务含义、场景覆盖和版本对应，不另设视觉与交互制作规范。

## 当前阅读与接收方

| 接收方 | 重点 |
| --- | --- |
| 业务 | 问题、现行方案、取舍、结果、待决定事项与可行动下一步 |
| 设计 | 页面职责、入口、状态、动作、关键文案、资产与设计边界 |
| 研发 | 对象、字段、权限、规则、状态、异常、接口证据/缺口、完成判据 |
| QA | 前置、操作、可观察结果、不允许结果、场景映射、未覆盖 |
| 维护者 | 当前入口、有效决定、变更影响、历史依据及续做位置 |

按需要从同一规则来源裁剪，不维护五套独立PRD。首次读者无需拼历史才能理解当前方案；复杂接收者能回查有效版本与局部确认范围。

## 完成状态分别表达

- 已准备文件：本地可读取，尚未实际外发。
- 已收到指定版本：有实际接收证据，不等于技术可行或验收。
- 可以据此继续：接收方完成指定任务，有结果和未决；不是一句“收到”。
- 产品范围已完成：约定成果与必要决定/明确委托具备，关键阻断已处理，剩余下游验证明确。
- 实施/生产验证通过：必须有对应真实环境证据，不能由产品文档或模拟结果推导。

最终交付先给成果与入口，再简述关键取舍、实际检查、未完成及下一步。在产品交接终点停止，不额外启动研发、部署或外发。下游接口、组织或现场仍待验证，不必一概判产品未完成；它们若正是本轮约定必需项则不能绕过。
