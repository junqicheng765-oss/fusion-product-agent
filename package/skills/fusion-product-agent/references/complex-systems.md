# 复杂系统：按风险加深

适用于资金/权益、权限变化、不可逆数据操作、异步/并发、跨系统责任及复杂接力。只检查当前任务适用项，不默认增加账号、风控、审批或通知模块。

## 对象和责任

区分用户意图、业务请求、正式业务对象、外部结果与展示状态。一次提交、一次付款、一个订单或一张凭证可能有不同标识与生命周期，不能揉成一个“成功/失败”。对每个动作说明发起者、资格、被操作对象、处理方、结果权威来源、失败后的负责方和对账方式。业务规则与技术实现方案分开，能力代价回对应责任方核实。

## 时间和未知结果

超时不等于失败。明确“未发出、处理中、已成功、明确失败、结果未知”哪些适用，谁能判定，用户看到什么，是否允许重试与以什么身份继续。异步结果迟到或重复时，不自动创建另一笔业务；具体幂等键、锁或接口能力需技术证据，不由产品凭空保证。

每条高影响路径检查：

| 情境 | 必须说清的产品事实 |
| --- | --- |
| 重复点击、刷新、重新进入 | 回到原请求还是新请求；已有结果如何查询 |
| 多人或多系统并发 | 谁可修改、冲突以何种事实裁定，其他人看到什么 |
| 资格/价格/库存变化 | 哪个时点校验与生效；失效提示、重新确认和退出方向 |
| 部分成功 | 哪些子项已发生，剩余如何继续，是否可补偿，谁负责 |
| 结果未知 | 暂停哪些高风险动作；查询/人工核实与后续落点 |
| 迟到或重复通知 | 与当前状态不一致时如何处理；不让旧结果覆盖有效新决定 |
| 取消、撤销或删除 | 实际撤回什么，已完成外部动作是否受影响，不能承诺无法实现的回滚 |
| 权限中途变化 | 既有数据和进行中任务如何处理、可见范围与恢复责任 |

## 专业前提与可实施边界

涉及财税、法律、身份、支付或组织制度时，区分规则建议、正式业务批准、文档接口支持、现有代码支持和真实环境验证。取得哪个层次只宣称哪个层次。缺口按对象与受阻动作列，不笼统判整个项目不可做；也不以批准风险替代事实核实。

## 变更与接力

对已确认规则的改动记录触发来源、原/新版本、作用范围，追到依赖的页面、Demo、字段、状态与验收。交接说明必须保持、允许探索、待决与验证责任。收件回执只证明收到指定组合，不证明技术可行、实现完成或运行通过。

独立复核仅在当前宿主与用户授权允许时采用，给真实评审者原始任务与实际成果，保留其发现和处理结果；不能把作者换角色自问自答写成独立验收。
