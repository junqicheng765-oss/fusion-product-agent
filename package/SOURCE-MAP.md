# 当前来源与设计替换范围

本版`0.3.0`以融合产品锤`0.2.0`为产品底座。设计部分由同事`savvydd/jq-product-agent`的`feat/design-handoff-contract`分支固定提交`6dcc771bb7b5d0c5f4d2ca25fc13994af12c73a1`整体接管。

## 替换，而非双轨融合

| 范围 | 当前责任与处理 |
| --- | --- |
| 领域研究、业务目标、需求/对象/规则、范围、复杂状态、业务验收 | 保留融合产品主线，作为设计输入与结果核对依据 |
| 信息架构、页面职责、具体交互与文案呈现 | 由设计专家接管，上游原型/页面提案可被专业质疑 |
| 风格、颜色/字体、组件/素材、图像、动效、视觉制作 | 旧方法撤换，同事完整模块负责 |
| Figma/代码路线与设计验收 | 旧Figma优先路线与设计清单撤换；执行同事最新路线、QA0及细则 |
| 产品—设计交接 | 薄接口，只传规则/事实/范围/授权，接回结果与证据，不另造设计流程 |
| 产品能力模型 | 原84份文件与摘要保持，48项定义保留；产品判断方法不作为第二套设计制作规则 |

## 导入范围

完整导入`design-thinking-os`234份、`impeccable`127份、`ui-ux-pro-max`73份，共434份文件，分别隔离命名为`fusion-design-core`、`fusion-design-impeccable`、`fusion-design-ui-ux-pro-max`。包括主入口、细则、脚本、组件配方、图标/图片、主题和数据；不只复制文档摘要。不导入同事分支里的另一套产品主入口、A–F阶段或重复能力模型。

[design-source.json](design-source.json)记录每份源路径、固定提交、原摘要、目标路径与适配后摘要；`tools/import_design_core.py`位于仓库根目录，支持从具有该提交的本地Git副本重建导入。

适配32份文本：隔离Skill名称和文档调用路径、父入口名称、移除旧D/E包装别名；设计入口补充宿主权限和内部优先级说明；两份细则中的无条件Figma概括按作者最新版“本地组件高保真→按需转换Figma”澄清。402份文件逐字节不变，全部设计脚本、组件和素材保持源内容。没有用旧融合设计方法覆盖同事方法。

## 已知边界

同事新建UI入口与较早细则存在概括差异，本版以上游最新主入口的开工门禁、第三步及工具路由核心规则为准。已做两处Figma概括的对应适配，并明确记录，不能声称本版是作者分支原封不动的安装包。工具名与MCP声明不等于本机已有权限；缺失工具如实处理。

## 产品底座沿革

继承强子产品Agent`2026.09.30.2`、JQ Product Agent`1.1.5`、Peter Matrix-AI`v0.26`的固定来源。它们在融合0.2.0中的领域方法、任务裁剪、唯一业务正文、复杂规则、版本与交接纪律继续使用；原设计执行内容在本版已被替换。历史原文与知识层摘要仍保存在[provenance.json](provenance.json)，不冒充本轮重新核对所有上游版本。
