# GitHub PR #2 与 rc.6 整合候选

2026-11-07，候选版本 `0.3.6-rc.7`，分支 `codex/integrate-design-rc6`。

本候选把同事的设计更新与本地已确认的产品约束整合到同一份包。GitHub来源为 [fusion-product-agent PR #2](https://github.com/junqicheng765-oss/fusion-product-agent/pull/2)，头提交 `7affdbe1ecabc61cf1d081e8d5d152894c40fa11`；另一来源为原本地 `0.3.6-rc.6` 候选。原rc.6目录单独保留，没有覆盖。

## 合并后的行为

- 保留任务理解、按需研究、创意概念、成果/工作环节/子任务路由及界面条件流程，不增加全局阶段。
- AI推导后实际制作并自审方向样张，由人看图选择；完整代表页经自审与确认后扩展，整套终审和最终确认分别保留。
- 正式素材按独立控制和更新需要分层；动态日期、倒数、数值由程序和真实数据更新，不每天重新生成整张图。
- 保留独立测试与历史隔离规则、方向来源记录；项目试跑答案和产物不进入能力包。
- 产品主线维护唯一界面文案基线、COPY ID与版本，设计负责呈现和修改建议；文案审查摘要继续在成果回复可见。
- 保留异常分层、同一文案引用和正式前端标准；服务接入可以用本地数据，必要界面、交互、校验和反馈仍须完成。
- 工具选择统一到TR0：已有覆盖本轮的有效决定直接复用；已选Figma先完成有效主稿，再按同版还原；缺工具先恢复。实质变更路线才重新确认。

## 冲突处理

处理主入口、工具路由、UI/视觉方法、产品交接和Figma适配中的冲突。将旧“固定三套风格候选”约束改为本轮适用样张；候选数量沿用设计专家DS1，样张选择不充当完整代表页批准。新增界面流程显式接入文案基线和正式前端定义，避免设计环节另写最终文字。

PR原有六份文档摘要和包清单曾失配，本候选按实际整合结果重新生成来源与manifest。原始434份设计来源保留；相对正式main，26份入口/方法文本变化、408份保持字节一致，另有3份显式本地扩展。全部84份产品模型原文保持字节一致。相对rc.6，覆盖层重放24份设计文本和5份Figma文本，另恢复3份新增方法；准确路径和摘要以来源JSON为准。

## 重新导入与验证

原有导入器会重建旧基线，不能直接用于保存PR修改。本候选在rc.6适配后加入固定摘要补丁层，自动重放经过审阅的修订和本地扩展；未知输入拒绝覆盖。原始来源摘要、整合基线摘要与最终文件摘要分开记录。

验证包括包结构/来源/引用检查，24项安装与交付回归、10项导入适配回归、4项跨安装目录引用回归，原始来源两轮重新导入及候选ZIP逐文件核对。它们验证离线结构、安装和重建，不证明模型遵循或真实Figma效果；真实会话、画面与交互仍须另测。第003—006项反馈未因本次整合自动视为已解决，独立v0.3.5-rc.1一致性检查候选未并入。
