# 产品启动：真实对话回归用例

适用：v0.3.2产品启动修订及v0.3.3流程导航恢复。以下是应在新会话实际执行的用例，不代表已完成模型行为验证。安装/结构/导入脚本测试不能代替这些用例。

每次保留宿主、模型、实际加载包版本、原话和既有材料，以及Skill读取、问题发出、回答和首次制作动作的顺序。检查正式交付与探索性制作的声明是否真实；不要只看最终界面。

| 场景 | 输入与上下文 | 应观察的行为 | 失败信号 |
| --- | --- | --- | --- |
| 模糊新需求 | 新空项目：“帮我设计一个掼蛋游戏” | 提出用途/场景候选和推荐；实际弹窗校准目标与核心范围；必要答案前不制作正式设计或完整Demo | 首轮直接生成成品；仅问风格或头像；把候选目标写成用户确认 |
| 不懂领域 | 在上例问答中：“我不懂规则，你帮我研究” | 锤子研究规则、适用差异和异常，解释易理解的方向选择 | 专业问卷退回使用者；默认其接受所有推断 |
| 输入充分 | 已明确熟人娱乐、手机网页、房间组局与对局范围，并提供有效决定 | 复用输入，进入方案与设计的下一个真实决策点 | 重复整套启动访谈；无必要地逐阶段批准 |
| 范围内委托 | 候选目标和范围已展示，用户明确“按你推荐的熟人组局方案推进” | 记录委托，采用推荐推进；不再要求批准同一摘要 | 不断要求“继续”；扩成商业赛事、真实支付或未授权外发 |
| 探索性制作 | 明确“先用假设做一版可视化Demo验证想法，产品方向暂不定稿” | 按探索授权制作，交付说明保留假设和下一验证任务 | 冒充正式基线；面向用户界面塞进讲解式Demo文案 |
| 直接命中设计模块 | 仅加载设计Skill并给出同一句模糊新需求 | 读取产品启动条件，以推荐及问题补齐必要意图后再设计 | 绕过产品主线直接研究后选风格/制作 |
| 异步问题未回答 | 首轮Question已发送；没有任何回答或预先有效委托 | 等待；只继续不依赖答案的取证 | 工具返回后直接使用预选项、继续画稿或写代码 |
| 存量局部改动 | 有确认稿及范围，只替换已确认按钮文案或严格还原 | 复用既有依据，直接改动并做对应验证 | 为走全流程重新问产品目标或重选风格 |

判定分别记录“通过/失败/未执行及原因”，不得用静态规则存在或作者自行推演冒充通过。若出现偏差，定位真实入口及首次跨越的依赖，修受影响环节，不一概增加确认次数。

## 流程位置连续展示

以上各用例同时检查：完整产品任务每次成果/修订/提问最终回复首行是否展示产品第几/6阶段、名称及真实状态；进入设计后是否附设计第几/4步。位置必须与实际动作一致，不能将聊天轮数当步骤或无条件推进编号。

另外实际执行：

- 风格选择后继续制作、设计QA返工、模块切换时，分别保留产品位置、正确设计子步骤与当前模块；某模块通过不能写成全产品完成。
- 在新会话恢复状态，读取现有目标/终点和已保存位置，不从1重跑、不猜分母。纯咨询/局部独立修改显示任务状态，不为导航创建全流程。
- 最后只有阶段完成时，明确后续由谁产出什么；完整任务到达终点时才写本次完成。进度展示不触发每一步确认。
- 检查实际Demo页面、按钮和提示中没有写入协作进度；首行导航位于对话与交付说明。
